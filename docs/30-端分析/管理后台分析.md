# 管理后台分析

> 证据：`apps/web-ele` 页面/API/路由、monorepo 清单和测试文件；检查于 2026-08-31；置信度：已验证（静态结构），浏览器联调未知。

## 定位与技术栈

`aryn-mall-ui` 是基于 Vben Admin 的 pnpm/Turbo monorepo。实际商城应用为 `apps/web-ele`，使用 Vue 3、TypeScript、Vite、Element Plus、Pinia 和自有 `@vben/*` 公共包。

## 入口与目录

| 位置 | 作用 |
|---|---|
| `apps/web-ele/src/main.ts` | 应用启动 |
| `apps/web-ele/src/bootstrap.ts` | 初始化路由、状态、组件与挂载 |
| `apps/web-ele/src/router/` | 路由守卫、静态/动态路由 |
| `apps/web-ele/src/api/` | 按 core/upms/user/product/order/pay/promotion/message/gen/home 分域 |
| `apps/web-ele/src/views/` | 与 API 基本同域的管理页面 |
| `packages/`、`packages/@core/` | 请求、状态、布局、UI 和工具包 |

## 路由与菜单

业务页面路由由 `/upms/menu` 下发 `sys_menu` 生成；`router/routes/modules/*.ts` 用于登记「不应出现在菜单里、但需要走 BasicLayout」的页面。因此页面排查顺序是：

1. 页面组件是否存在。
2. `sys_menu` 的 path、component、permission 是否正确。
3. 当前角色和租户套餐是否授权该菜单。
4. 动态组件路径能否映射到 `views/`。

**核心.ts 与 modules 的区别（易踩坑）**

| 位置 | 挂载方式 | 渲染结果 |
|---|---|---|
| `core.ts`（`coreRoutes`） | 直接 `router.addRoute`，只被 login/预览等无布局页面使用 | **不经过 BasicLayout**，页面整屏渲染 |
| `routes/modules/*.ts` | 作为子路由挂进 `Root` 的 BasicLayout | 保留侧边菜单、顶部导航与标签页 |

2026-09-25 秒杀/折扣「新增活动」页面被整屏显示、遮住侧边菜单与顶部导航，根因就是把编辑页注册进了 `core.ts`：该位置路由不带 `BasicLayout` 父级，`hideInMenu`/`hideInTab` 只能隐藏菜单与标签，不能补回布局。非独立窗口的详情/表单页应放入 `routes/modules/`，用 `meta.hideInMenu` 隐藏菜单、`meta.activePath` 指向对应列表页以保持侧边高亮。守卫 `promotion-edit-layout-contract.test.ts` 会拦截把编辑页写回 `core.ts` 的改动。

注意 `core.ts` 中 `noBasicLayout: true` 是给「商城装修预览」「页面设计器」这类**有意脱离布局**的独立窗口页用的，不要照搬到普通表单页。

## 请求与认证

`apps/web-ele/src/api/request.ts` 创建统一 `RequestClient`：

- Base URL 来自 `VITE_GLOB_API_URL`。
- `satoken` 来自 access store。
- 平台管理员切换租户时加入 `tenant-id`。
- 加入 `Accept-Language`。
- 成功响应要求 `code === 0`，业务数据取 `data`。
- 可选 refresh token 失败后触发重新登录。

`VITE_OPEN_BOOT=true` 时，`/upms/user/page` 会改写为 `/boot/user/page`。新增 API 必须保持第一个路径段为微服务域，否则单体改写会产生错误 URL。

## 业务规模

静态盘点发现 79 个业务 API TypeScript 文件、205 个 views Vue 文件。主要域：upms、user、product、order、pay、promotion、message、delivery、gen，以及 dashboard/home。

页面装修已包含首页装修入口、组件注册表、草稿/发布、模板和预览能力；相关修改仍要与 UniApp `components/diy` 和 `page_design` 后端 schema 联调。

配送管理已增加任务、配送员、出车单、仓库配置和配送范围页面，请求统一使用 `/mall-order/delivery/**`。秒杀与折扣活动页面分别位于 `views/promotion/seckill-activity` 和 `discount-activity`，请求使用 `/promotion/seckill/**`、`/promotion/discount/**`，可按 Boot 规则改写。

消息中心已增加头部未读铃铛、工作人员收件箱、通知管理、客服工作台和一对一私信页面。客服工作台内提供受 `message:service:agent` 控制的“坐席设置”弹窗，可从具备客服/主管权限的工作人员中选择并配置启用状态、自动接待和最大活跃会话数。消息发送先进入本地 optimistic 状态，再按 `clientMessageId` 与 HTTP 返回合并；WebSocket 事件只触发索引、未读和断线补拉，不作为持久化成功依据。业务路由仍由 `sys_menu` 动态下发。

## 开发入口

```powershell
cd aryn-mall-ui
pnpm install
pnpm dev:ele
pnpm check:type
pnpm test:unit
pnpm lint
pnpm build:ele
```

`packageManager` 锁定 pnpm 10.10.0；当前机器全局 pnpm 9.12.3，建议使用 Corepack 切换。应用开发端口是 5777。

## 测试与风险

- 发现 62 个测试文件，仍未发现配送、秒杀或折扣页面/API 的专项测试，不代表 205 个业务视图有直接覆盖。
- 生产 API 配置仍指向 localhost，必须由部署环境覆盖。
- `VITE_OPEN_BOOT` 在 `.env` 中写作带空格的 `true`，虽然 Vite 常可解析，环境切换仍应以实际加载值验证。
- 前端权限不仅是按钮隐藏；后端 Controller 权限校验必须同时存在。
- 修改 `packages/` 共享代码时，影响范围可能跨整个 monorepo，应跑完整 typecheck 和单测。
