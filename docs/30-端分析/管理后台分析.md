# 管理后台分析

## 定位与技术栈

`aryn-mall-ui` 是基于 Vben Admin 的 pnpm/Turbo monorepo。实际商城应用为 `apps/web-ele`，使用 Vue 3、TypeScript、Vite、Element Plus、Pinia 和自有 `@vben/*` 公共包。

## 入口与目录

| 位置 | 作用 |
|---|---|
| `apps/web-ele/src/main.ts` | 应用启动 |
| `apps/web-ele/src/bootstrap.ts` | 初始化路由、状态、组件与挂载 |
| `apps/web-ele/src/router/` | 路由守卫、静态/动态路由 |
| `apps/web-ele/src/api/` | 按 core/upms/user/product/order/pay/promotion/gen/home 分域 |
| `apps/web-ele/src/views/` | 与 API 基本同域的管理页面 |
| `packages/`、`packages/@core/` | 请求、状态、布局、UI 和工具包 |

## 路由与菜单

`router/routes/modules` 当前只有 `dashboard.ts`。登录后通过 `/upms/menu` 获取权限菜单并生成业务路由，因此页面排查顺序是：

1. 页面组件是否存在。
2. `sys_menu` 的 path、component、permission 是否正确。
3. 当前角色和租户套餐是否授权该菜单。
4. 动态组件路径能否映射到 `views/`。

## 请求与认证

`apps/web-ele/src/api/request.ts` 创建统一 `RequestClient`：

- Base URL 来自 `VITE_GLOB_API_URL`。
- `satoken` 来自 access store。
- 平台管理员切换租户时加入 `tenant-id`。
- 加入 `Accept-Language`。
- 成功响应要求 `code === 0`，业务数据取 `data`。
- 可选 refresh token 失败后触发重新登录。

`VITE_OPEN_BOOT=true` 时，`/upms/user/page` 会改写为 `/boot/user/page`。新增 API 必须保持第一个路径段为微服务域，否则单体改写会产生错误 URL。

## 业务规模

静态盘点发现 66 个商城 API TypeScript 文件、157 个 views Vue 文件。主要域：upms、user、product、order、pay、promotion、gen，以及 dashboard/home。

当前工作区正在扩展营销页面装修：首页装修入口和 category-nav、coupon-receive、search-bar、swiper-banner 等组件尚未提交。相关修改要与 UniApp `components/diy` 和 `page_design` 后端 schema 联调。

## 开发入口

```powershell
cd aryn-mall-ui
pnpm install
pnpm dev:ele
pnpm check:type
pnpm test:unit
pnpm lint
pnpm build:ele
```

`packageManager` 锁定 pnpm 10.10.0；当前机器 pnpm 9.12.3，建议使用 Corepack 切换。应用开发端口是 5777。

## 测试与风险

- 发现 31 个测试文件，主要覆盖 core/shared/request/stores/utils，不代表 157 个业务视图有直接测试。
- 生产 API 配置仍指向 localhost，必须由部署环境覆盖。
- `VITE_OPEN_BOOT` 在 `.env` 中写作带空格的 `true`，虽然 Vite 常可解析，环境切换仍应以实际加载值验证。
- 前端权限不仅是按钮隐藏；后端 Controller 权限校验必须同时存在。
- 修改 `packages/` 共享代码时，影响范围可能跨整个 monorepo，应跑完整 typecheck 和单测。
