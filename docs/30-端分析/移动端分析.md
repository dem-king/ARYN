# 移动端分析

> 证据：`src/pages.json`、页面/API/Store、`package.json` 和测试文件；检查于 2026-10-28；置信度：已验证（静态结构），真机联调未知。

## 定位与技术栈

`aryn-mall-uniapp` 是 C 端商城，支持 H5、App 和多类小程序。核心技术为 UniApp、Vue 3、TypeScript、Alova、Pinia、uni-mini-router、Wot Design Uni 和 UnoCSS。

## 入口与分层

| 位置 | 作用 |
|---|---|
| `src/main.ts`、`src/App.vue` | 应用启动和生命周期 |
| `src/pages.json` | 主包、分包、tabBar 和页面元数据 |
| `src/pages/` | home、login 等主包页面 |
| `src/sub-pages/` | order、product、promotion、user 等业务分包 |
| `src/api/` | Alova core + distribution/order/pay/product/promotion/message/upms/user |
| `src/store/` | 认证、字典、商品、搜索历史、购物车、用户状态 |
| `src/components/` | 通用组件和 `diy-*` 页面装修渲染器 |

移动端已增加消息 API、Pinia 状态、通知列表/详情、客服聊天、消息气泡和业务卡片组件，并补充消息合并、游标与装修客服链接的 Vitest 回归。配送工作台、配送进度、秒杀页和折扣页也已进入同一 UniApp 源码；2026-10 起会员专区/会员价、积分、低价捡漏、搜索排行、沉浸式导航与中英文切换（`src/locales`）也进入同一源码。

## 请求链路

`src/api/core/instance.ts` 创建 Alova 实例：

- Base URL 来自 `VITE_API_BASE_URL`。
- H5 开发环境优先使用 `VITE_H5_API_BASE_URL`；当前为 `/api`，由 Vite 同源代理转发到本地 Gateway，避免浏览器 CORS 和局域网真机把 `localhost` 解析为设备自身。
- 每次请求加入 `tenant-id`。
- 登录后加入 `satoken`，可通过 `skipToken` 跳过。
- 按平台加入 `platform-type`；微信小程序额外加入 `app-id`。
- `VITE_OPEN_BOOT=true` 时将业务域前缀改写为 `/boot`。
- 统一处理业务 code、token 失效和错误提示。

普通请求、上传和 WebSocket 共用 `src/api/core/api-base-url.ts` 的地址解析；上传仍走 `uni.uploadFile`，需要保持 tenant/token header 和 Boot 路径改写一致。

## 页面与状态

- TabBar 和主包以 `src/pages.json` 为准，不要仅按文件目录判断是否可访问。
- `authStore.ts` 管理登录、token 和多种登录方式；持久化逻辑在 `persist.ts`。
- `shoppingCartStore.ts` 与订单 API 共同决定购物车状态，修改时检查登录前后同步。
- 首页装修由后端 `page_design` 配置驱动，`components/diy/index.vue` 负责按组件类型选择渲染器。
- **装修组件自带的数据加载必须走 `usePageShowLoad`（onMounted + 页面 onShow），不得只挂 `onShow`**：装修内容是页面 `onLoad` 里异步拉回来才渲染的，组件挂载时页面的 `onShow` 已经跑完；小程序端（`@dcloudio/uni-mp-vue`）对迟到注册的页面钩子**不会补调**（`isRootImmediateHook` 只在 uni-h5-vue 里），于是首屏数据永远等不到，切 Tab 回来才出现——H5 正常，两端不一致且无报错。守卫见 `src/components/diy/decoration-lifecycle.contract.test.ts`，时序行为测试见 `src/composables/usePageShowLoad.behavior.test.ts`。
- 会员专区/会员价/低价捡漏：`utils/member-price.ts` 统一会员价展示判定；多 Tab 商品流支持「按会员价活动自动」与「折扣力度优先」数据源（`retail-query.ts`）。
- 中英文切换：`vue-i18n`，词条在 `src/locales`（17 个域模块约 1842 条 × 2 语言）；入口在登录页/个人中心导航栏/个人信息页，持久化 `ARYN_LOCALE`，请求头透传 `Accept-Language`；只翻 UI 文案，商品/活动等业务数据保持中文。
- 搜索与导航：搜索页/排行组件走真实接口口径（`/product/app/goodsspu/hot-search|sales-rank/top10`）；装修导航支持沉浸式滚动效果与首页搜索框常驻（schema 驱动，画布/草稿/C 端同源守卫）。
- 积分：确认页积分抵扣开关、订单积分抵扣行、个人中心积分明细与兑换（`/mall-user/app/points/**`）。

## 开发入口

UniApp 声明 Node `>=22`、pnpm 9.9.0。当前机器 Node 22.12.0 满足要求；全局 pnpm 9.12.3 与锁定版本不同，建议先通过 Corepack 切换：

```powershell
cd aryn-mall-uniapp
pnpm install
pnpm dev:mp-weixin
pnpm type-check
pnpm test:unit
pnpm build:mp-weixin
```

`package.json` 提供 `test:unit` 与 `test:build`（构建产物 node:test），仍没有 lint 脚本；微信小程序构建依赖原生可选包，缺失 binding 时需要修复依赖环境后重跑。

## 消息与客服

- 个人中心提供通知/客服入口和未读角标，消息分包位于 `src/sub-pages/message/`。
- 聊天支持文本、最多 6 张图片、商品/订单/退款/通知卡片与系统消息；断线期间仍可 HTTP 发送，重连后按最后 `seqNo` 补拉。
- 商品、订单和退款详情会把业务上下文作为服务端允许的卡片发送；`VITE_CUSTOMER_SERVICE_MODE` 可灰度回退微信原生客服。
- 装修 `customer-service` 链接统一解析为站内客服页，业务卡片点击只通过固定端内路由字段跳转。

## 配送与营销页面

- `src/pages/delivery/` 提供配送员登录、任务、出车、异常和个人页；配送工作台仍在 TOC 商城项目内，独立 TOB 发布形态需发布前确认。
- `src/api/delivery.ts` 已统一 `/mall-order/app/delivery` 首段；客户进度走 `/mall-order/app/order/{orderId}/delivery-progress`，Boot 模式由 `rewriteBootUrl` 改写。
- 秒杀和折扣页面通过 `src/api/promotion.ts` 使用 `/promotion/app/**`，符合双模式路径约定；真实库存、支付和退款链路仍需集成验证。

## 已知风险

- 生产 `.env.production` 的 API 地址仍为 localhost，staging 仍是示例域名。
- `.env` 固定了默认租户 ID；不同商家部署或多租户 C 端需要明确租户解析策略。
- 现有 115 个测试文件覆盖请求路径、消息、装修时序、会员价/积分、i18n 与导航材质等；营销页与配送工作台仍应按 H5 + 微信小程序做真机回归。
- 上传请求与普通 Alova 请求是两条链路，认证和路径改写容易漂移。
- 条件编译会产生平台差异；涉及登录、支付、分享和 app-id 的改动必须按目标平台验证。
- **小程序 rpx→px 取整会击穿零余量的两列布局**：`flex-wrap` + 卡宽 `calc(50% - gap/2)` 算出的总宽正好等于容器 100%，取整零头会让每行只剩一张卡、右侧半屏空白；实测 320/360/390/393/412/414/428/430/440 等屏宽均复现（375px 恰好不溢出，所以偶发）。两列必须走 `display: grid` + `repeat(2, minmax(0, 1fr))`（先扣 gap 再分轨道），参考 `src/components/goods-list-panel/index.vue` 与 `diy-goods-group`。守卫见 `src/components/goods-list-panel/layout-guard.test.ts`。
