# 后端分析

## 定位与技术栈

`aryn-mall-java` 是 Maven 多模块后端，基础包为 `com.aryn.cloud`。根 POM 当前版本为 `3.2.1`，使用 Java 17、Spring Boot 3.5.8、Spring Cloud 2025.0.0、Spring Cloud Alibaba 2025.0.0.0、Dubbo 3.3.6、MyBatis-Plus、Sa-Token、Redis、RocketMQ、XXL-JOB、Sentinel 和 Seata。

## 分层与依赖

```text
L0 common-core
L1 log/redis/mybatis/storage/sms/swagger/job/dubbo/datasource
L2 security/sentinel/seata/logistics
L3 *-api：Remote 接口、DTO、VO、Entity
L4 *-biz：Controller、Service、Mapper、Dubbo 实现
L5 gateway/auth/boot/visual
```

不同 biz 之间不直接依赖实现模块。微服务调用通过 `*-api` 的 Remote 接口，单体模式由 Dubbo `injvm`/Spring 容器聚合。

## HTTP 与认证

- 后台 Controller 多在 `controller/admin`，C 端多在 `controller/app`。
- Auth 分 `TobTokenController` 与 `TocTokenController`；Sa-Token header 名为 `satoken`。
- Boot 通过 context path 去掉服务前缀：例如管理端源码 `/product/goodsspu` 在单体模式请求 `/boot/goodsspu`。
- `secure.ignore.urls` 放行登录、验证码、支付通知和部分 app 只读接口；新增公开接口必须审阅越权风险。

## 多租户链路

```text
tenant-id header
  -> ArynTenantContextFilter
  -> ArynTenantContextHolder (TransmittableThreadLocal)
  -> ArynTenantLineHandler
  -> 仅对 hx.tenant.tables 中的表注入 tenant_id 条件

Dubbo 调用通过 ArynDubboRequestFilter 传播 tenantId。
```

应用启动时会通过 JDBC 元数据双向校验实际含 `tenant_id` 的表与 `hx.tenant.tables`；缺配或误配都会拒绝启动。仓库测试还会核对 Boot/Cloud SQL、Nacos YAML 和受控的 `@InterceptorIgnore` 清单。

## 数据访问与事务

- Mapper 使用 MyBatis-Plus，XML 位于各 biz 的 `resources/mapper`。
- 单体/Cloud 分别维护 `db/boot` 与 `db/cloud`。
- Seata 在 Boot 配置中关闭，微服务跨库一致性需检查实际 Nacos 配置和补偿逻辑。
- 多表写入使用 `@Transactional(rollbackFor = Exception.class)`；支付回调、任务和 MQ 消费还需业务幂等。

## 测试现状

后端已形成 Reactor 全量测试基线。消息域测试覆盖 SQL/Mapper 契约、通知分发、会话与消息幂等、自动分配和并发领取、24 小时重开、工作人员私信、WebSocket 鉴权/降级及业务通知消费；Boot 另有消息菜单与双模式租户配置门禁。

## 消息域

- `aryn-message-api/biz` 为独立业务域，Cloud 使用 `aryn_message`，Boot 由 `aryn-boot` 聚合。
- HTTP 是消息写入事实通道，WebSocket `/message/ws` 只发送轻量事件；Redis Pub/Sub 用于跨实例广播，故障时客户端通过 HTTP 游标补拉。
- 用户域和 UPMS 仅通过 `*-api` 的 Dubbo 契约提供受众与客服资格，不允许消息 biz 直连其他业务库或依赖其他 biz。
- 订单创建、支付、退款和领券在事务提交后产生通知命令；消费者显式恢复并最终清理租户上下文。

## XXL-JOB 目录

根目录 `xxl-job-3.2.0` 是独立 Maven 项目（141 个 Java 文件），包含 `xxl-job-core`、`xxl-job-admin` 和 executor samples。它不在 `aryn-mall-java/pom.xml` 的 modules 中；商城业务通过 `aryn-common-job` 与调度 Admin 通信。

除非明确维护上游调度平台，不要为商城需求修改该目录。业务 Job 在各 biz 的 `job/` 中，例如订单关闭、拼团过期、分销结算和优惠券任务。

## 已知风险

- `application-dev.yml` 和 Nacos SQL 种子存在明文敏感配置，需移出仓库并轮换真实凭证。
- 存量数据库增加用户名、手机号和 `app_id` 唯一索引前需先处理重复数据，迁移不会自动清洗。
- Boot 和 Cloud 两套配置/SQL容易漂移。
- 根 POM 与 README/历史文档版本可能不一致，以 POM 和实际依赖解析为准。
- `myabtis` 包名是项目既有拼写，重命名会影响扫描路径和配置，不能顺手修正。
