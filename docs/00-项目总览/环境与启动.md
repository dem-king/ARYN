# 环境与启动

## 推荐运行时

| 组件 | 项目要求 | 当前分析机 | 结论 |
|---|---|---|---|
| JDK | 17 | 17.0.9 | 满足 |
| Maven | 3.6+ | 3.9.9 | 满足 |
| Node.js | UI `>=20.10`；UniApp `>=22` | 20.15.1 | UI 满足，UniApp 不满足 |
| pnpm | UI 锁定 10.10.0；UniApp 锁定 9.9.0 | 9.12.3 | 建议用 Corepack 按子项目切换 |
| MySQL | 8.x | 未验证 | 运行前确认 |
| Redis | 6.x+ | 未验证 | 运行前确认 |

微服务模式还需要 Nacos、RocketMQ；涉及分布式事务时需要 Seata；定时任务需要 XXL-JOB Admin。

## 数据库初始化

单体模式使用 `aryn-mall-java/db/boot/`，微服务模式使用 `aryn-mall-java/db/cloud/`。导入前先审阅 SQL 中的默认账号、密码和 Nacos 配置，不要直接用于生产。

## 后端单体模式

```powershell
cd aryn-mall-java
mvn clean compile -pl aryn-boot -am
mvn test -pl aryn-boot -am
mvn spring-boot:run -pl aryn-boot
```

- 默认端口：`9999`
- Context path：`/boot`
- OpenAPI：`http://localhost:9999/boot/v3/api-docs`
- Knife4j：`http://localhost:9999/boot/doc.html`

启动前修改 `aryn-boot/src/main/resources/application-dev.yml`，优先通过环境变量或本地不提交配置注入数据库、Redis、RocketMQ、短信和任务调度凭证。

## 后端微服务模式

入口端口为 Gateway `9999`。源码配置中的主要服务端口：auth `5227`、upms `5327`、product `6300`、order `6400`、promotion `6500`、pay `6900`、generator `7003`、monitor `7001`、user `7527`。

各服务从 Nacos 读取 `application-<profile>.yml` 和 `<service>-<profile>.yml`。先启动基础设施，再按认证/权限、业务服务、Gateway 的顺序启动。

### IDEA 启动 Java 微服务

Docker 只运行 MySQL、Redis、Nacos、RocketMQ、Seata 和 XXL-JOB，Java 服务由 IDEA 在宿主机启动：

```bash
./dev-tools/start-infra-for-idea.sh
```

脚本会停止 Docker 中的 Gateway、Auth 和各业务 Java 容器，保留数据库卷并释放 IDEA 所需端口；不会删除 Cloud 数据。基础设施默认连接信息：

| 组件 | 地址 | 账号/密码 |
|---|---|---|
| MySQL | `localhost:3306` | `root / 123456` |
| Redis | `localhost:6379`，DB 11 | 密码 `redis` |
| Nacos | API `localhost:8848`，控制台 `http://localhost:8080` | `nacos / nacos` |
| RocketMQ | NameServer `localhost:9876`，Broker `localhost:10911` | 无 |
| Seata | `localhost:8091` | 无 |
| XXL-JOB | `http://localhost:7002/xxl-job-admin` | `admin / 123456` |

在 IDEA 的 Maven 工具窗口启用 `cloud` Profile，重新加载 Maven 后再运行启动类。推荐顺序：

1. `ArynUpmsApplication`
2. `ArynUserApplication`、`ArynProductApplication`、`ArynPayApplication`
3. `ArynOrderApplication`、`ArynPromotionApplication`、`ArynMessageApplication`
4. `ArynAuthApplication`
5. `ArynGatewayApplication`

宿主机模式默认使用 `localhost`，并通过 `docker-compose-idea.yml` 让 RocketMQ Broker 公布 `127.0.0.1`；如果改回 Docker 运行 Java 服务，`docker-compose.yml` 会通过环境变量和容器网络地址恢复整套容器通信。

### 本地一键启动

项目根目录提供统一开发脚本，同时启动 Docker 基础设施、Cloud 后端、XXL-JOB、管理端和移动端 H5：

```bash
./dev-tools/start-all.sh
```

脚本默认复用现有 JAR 和镜像；首次运行缺少 JAR 时会自动打包。需要强制重新打包全部 Java 服务并重建镜像时执行：

```bash
./dev-tools/start-all.sh --rebuild
```

启动地址：管理端 `http://localhost:5777`，移动端 H5 `http://localhost:8888`，Gateway `http://localhost:9999`，XXL-JOB `http://localhost:7002/xxl-job-admin`。管理端和移动端以 Cloud 模式连接 Gateway，日志及 PID 存放在系统临时目录 `aryn-mall-dev/` 中。

### 快速重启单个微服务

修改单个 `*-biz` 模块的实现或资源后，通常只需要重新打包并重启对应服务。例如：

```bash
./dev-tools/restart-service.sh order
./dev-tools/restart-service.sh promotion
```

支持 `gateway`、`auth`、`upms`、`user`、`product`、`order`、`promotion`、`pay`、`xxl-job`。默认命令会执行目标模块及其上游依赖的增量 Maven 打包、重建目标 Docker 镜像，并只替换该容器。没有代码修改、只想重启现有容器时可执行：

```bash
./dev-tools/restart-service.sh order --no-build
```

重启范围按改动类型判断：

| 改动位置 | 需要重启 |
|---|---|
| 单个 `*-biz` 的实现、Mapper 或资源 | 仅该业务服务 |
| Gateway 或 Auth 自身代码 | 仅 Gateway 或 Auth |
| `*-api` 的 DTO、接口或实体 | Provider 以及所有使用该 API 的 Consumer |
| `aryn-common-*` 公共模块 | 所有依赖它的服务；无法快速确认时重启全部 Cloud 后端 |
| Nacos 配置 | 受影响服务；本地开发建议重启以确保配置生效 |
| SQL | 先执行迁移，再按使用该库的服务决定是否重启 |
| POM、依赖版本或 Dockerfile | 必须重新打包并重建镜像，不能只用 `--no-build` |

## 管理后台

```powershell
cd aryn-mall-ui
corepack enable
pnpm install
pnpm dev:ele
```

- 开发端口：`5777`
- 开发 API 前缀：`/api`，由 Vite 代理或部署网关处理。
- `VITE_OPEN_BOOT=true` 时，请求从 `/domain/path` 改写为 `/boot/path`。

最小验证：

```powershell
pnpm check:type
pnpm lint
pnpm test:unit
pnpm build:ele
```

## UniApp

先切换到 Node 22，再执行：

```powershell
cd aryn-mall-uniapp
corepack enable
pnpm install
pnpm dev:mp-weixin
```

常用替代目标为 `pnpm dev:h5`、`pnpm build:mp-weixin`、`pnpm build:h5`。最小静态验证是 `pnpm type-check`；当前 `package.json` 没有 `lint` 脚本，也未发现测试文件。
