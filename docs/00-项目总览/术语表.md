# 术语表

> 详细业务概念参见 [PRODUCT_SENSE.md](../PRODUCT_SENSE.md)。

## 1. 电商领域术语

### 1.1 商品体系

| 术语 | 英文 | 数据表 | 说明 |
|------|------|--------|------|
| SPU | Standard Product Unit | `goods_spu` | 标准化产品单元，如 "iPhone 15" |
| SKU | Stock Keeping Unit | `goods_sku` | 库存保有单位，如 "iPhone 15 / 黑色 / 256G" |
| 商品规格 | Specs | — | SKU 的区别属性（颜色、尺寸等），用 `specs` JSON 存储 |
| 分类 | Category | `goods_category` | 商品类目树，通常 2-3 级 |
| 品牌 | Brand | `goods_brand` | 商品品牌 |
| 评价 | Appraise | `goods_appraise` | 用户对已购商品的评价 |

### 1.2 订单体系

| 术语 | 英文 | 数据表 | 说明 |
|------|------|--------|------|
| 购物车 | Shopping Cart | `shopping_cart` | 用户暂存商品，按 SKU 存储 |
| 订单 | Order | `order_info` | 交易核心实体 |
| 订单状态 | Order Status | — | 待付款→待发货→待收货→已完成 / 已取消 |
| 售后 | After-sale | `order_refund` | 仅退款（未发货）、退货退款（已发货） |
| 物流 | Logistics | `order_logistics` | 快递物流信息 |

### 1.3 支付体系

| 术语 | 英文 | 数据表 | 说明 |
|------|------|--------|------|
| 支付方式 | Pay Type | — | `wxpay`(微信)、`alipay`(支付宝)、`balance`(余额) |
| 支付流水 | Trade Order | `pay_trade_order` | 记录每笔支付请求和回调 |
| 合并支付 | Combined Pay | — | 多个订单合并为一次支付 |
| 支付回调幂等 | Idempotent | — | 通过 `trade_no` 防重 |

### 1.4 会员体系

| 术语 | 英文 | 数据表 | 说明 |
|------|------|--------|------|
| 会员等级 | Member Level | `member_level` | 根据累计消费金额/积分自动升级 |
| 积分 | Points | `points_record` | 消费、签到、注册获取，可抵扣订单金额 |
| 储值余额 | Balance | `balance` | 用户账户余额，支持充值赠送配置 |
| 签到 | Sign In | `sign_in_record` | 每日签到送积分，连续签到额外奖励 |

### 1.5 营销体系

| 术语 | 英文 | 数据表 | 说明 |
|------|------|--------|------|
| 优惠券 | Coupon | `coupon_info` / `coupon_user` | 满减/折扣券，用户领取和使用 |
| 拼团 | Group Buy | `group_buy` / `group_buy_record` | 多人成团享受优惠价格 |
| 分销 | Distribution | `distribution_*` | 多级分销佣金体系 |
| 页面装修 | Page Design | `page_design` | C端首页/活动页面拖拽式配置 |

## 2. 项目特有概念

### 2.1 架构概念

| 术语 | 说明 |
|------|------|
| Boot 模式 | 单体模式，`aryn-boot` 聚合所有 biz 模块 |
| Cloud 模式 | 微服务模式，各 biz 独立部署，通过 Dubbo RPC 通信 |
| L0-L5 层级 | 后端模块的 6 层架构，高层可依赖低层，反向禁止 |
| api/biz 分离 | 每个业务模块分为 `*-api`（接口+DTO）和 `*-biz`（实现） |
| Harness | 自动化验证管道，包含编译、依赖检查、质量检查、测试、端到端验证 |

### 2.2 权限与认证

| 术语 | 说明 |
|------|------|
| RBAC | 基于角色的访问控制：用户 → 角色 → 菜单/权限 |
| 租户 (Tenant) | SaaS 多租户隔离，每个租户独立管理后台 |
| 权限编码 | 格式 `{domain}:{resource}:{action}`，如 `user:member-level:page` |
| SYS_USER | 后台管理员用户类型 |
| MALL_USER | C 端商城用户类型 |
| Sa-Token | 无状态 JWT 认证框架 |

### 2.3 API 路由约定

| 前缀 | 说明 | 认证要求 |
|------|------|----------|
| `/admin/{domain}/**` | 管理端接口 | `@SaCheckPermission` |
| `/app/{domain}/**` | 应用端接口 | `@SaCheckLogin` |
| `/auth/**` | 认证接口 | 无需登录 |
| `/doc.html` | 接口文档 | 网关白名单 |

### 2.4 数据约定

| 术语 | 说明 |
|------|------|
| `tenant_id` | 多租户隔离字段，MyBatis 拦截器自动注入 |
| `del_flag` | 逻辑删除标记：0=正常，1=删除。**严禁** SQL `DELETE` |
| 雪花 ID | BIGINT 主键，雪花算法生成 |
| `BaseEntity` | 公共基类，含 id/tenant_id/create_by/create_time/update_by/update_time/del_flag |

## 3. 字典系统

| 字典 Key | 说明 |
|----------|------|
| `order_status` | 订单状态 |
| `pay_type` | 支付方式 |
| `refund_status` | 退款状态 |
| `coupon_type` | 优惠券类型 |

- 管理后台使用 `<DictTag>` 组件渲染字典值
- UniApp 端通过 `dictStore` 全局缓存

## 4. 特殊业务规则

| 规则 | 说明 |
|------|------|
| 订单超时取消 | 30 分钟未支付自动取消（XXL-JOB 定时扫描） |
| 收货自动确认 | 发货后 7 天自动确认收货 |
| 退款审核 | 管理员审核通过后调支付渠道退款接口 |
| 积分抵扣 | 100 积分 = 1 元，订单结算时使用 |
| 优惠券叠加 | 同一订单最多使用 1 张优惠券 |
| 库存扣减 | 下单时预占库存，支付成功后扣减，取消/退款后恢复 |
