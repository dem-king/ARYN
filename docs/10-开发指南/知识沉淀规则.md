# 知识沉淀规则

## 三类知识载体

| 载体 | 定位 | 适合内容 |
|---|---|---|
| Markdown | 长期记忆和默认入口 | 架构、业务规则、代码索引、风险、验证命令、需求结论 |
| Graphify | 关系与影响范围侦察 | import、调用、实现、引用、路径、共享类消费者 |
| Understand Anything | 大范围架构和导览 | 新模块接手、跨域全景、分层、guided tour、diff 解释 |

## 只读 Markdown 的场景

- 已知页面/API/Controller 的小型 UI、文案或布局改动。
- 文档已明确目标文件、业务规则和验证命令。
- 纯文档或低风险局部配置修改。

## 必须考虑 Graphify 的场景

- 修改实体、认证、租户拦截器、公共请求层、共享工具或菜单。
- 需要知道调用者、实现类、依赖路径或影响范围。
- 共享代码修改后，需要确认图谱是否应刷新。

常用命令：

```powershell
graphify explain ArynTenantLineHandler
graphify path "node A" "node B"
graphify query "question" --budget 1200
graphify update . --no-cluster
```

## 使用 Understand Anything 的场景

- 第一次深入陌生模块或跨多个应用的需求。
- 需要 architecture layers、onboarding tour、domain flow 或 dashboard。
- 用户明确要求 `$understand`、项目图或 UA dashboard。

新会话中执行：

```text
$understand D:\Codes\aryn-mall --language zh
```

## 必须回写 Markdown 的结论

- 新的业务状态机、权限规则、租户规则或跨服务约束。
- 新增/废弃表、接口前缀、页面入口或部署依赖。
- 经验证的故障根因、环境限制和固定排查步骤。
- 图谱发现但以后仍会反复使用的关系。

不要把临时调试输出、一次性堆栈或生成图 JSON 复制进文档。文档写结论和证据入口，生成物保持 Git 忽略。

## 何时创建项目专用 Skill

只有当同一复杂流程跨多个项目重复出现，或需要可复用脚本/模板时再创建 Skill。本项目内的普通约定优先放 `AGENTS.md` 与本知识库，避免双份规则漂移。
