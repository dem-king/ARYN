# 开发工作流

## 用户可以怎样描述需求

可以直接使用业务语言，例如：“首页增加限时拼团楼层”“后台订单列表显示分销佣金”“会员升级时补一条积分记录”。Agent 负责先从 [功能到代码索引](../20-业务与数据/功能到代码索引.md) 找到业务域，再核对接口、实体和数据库。

## 固定读序

1. `AGENTS.md` 与 `docs/README.md`。
2. 对应的端分析文档。
3. `功能到代码索引`、`接口映射`、`数据模型`。
4. 目标源码及同目录测试。
5. 涉及共享代码、租户、认证、实体或跨模块调用时，再用 Graphify 检查调用/依赖范围。

## 管理端定位

1. 在 `apps/web-ele/src/views/<domain>/` 找页面。
2. 在 `apps/web-ele/src/api/<domain>/` 找请求。
3. 检查 `/upms/menu` 返回与 `sys_menu` 数据；静态 route 文件少不等于页面未接入。
4. 检查 `VITE_OPEN_BOOT`：单体模式会去掉原业务前缀并加 `/boot`。
5. 共享组件和请求能力优先复用 `packages/`，保持 monorepo 分层。

## UniApp 定位

1. 从 `src/pages.json` 找主包/分包页面。
2. 在 `src/pages/` 或 `src/sub-pages/` 找页面，在 `src/components/` 找通用组件。
3. 在 `src/api/<domain>/` 找 Alova 请求，在 `src/store/` 检查持久状态。
4. 核对 `tenant-id`、`satoken`、`platform-type`、`app-id` 请求头。
5. 同时验证 H5 和微信小程序条件编译分支；页面逻辑不得下沉到 API 层。

## 后端定位

1. 按 URL 业务前缀选择 `aryn-<domain>`。
2. HTTP 入口在 `*-biz/.../controller/admin|app`；`app` 通常为 C 端接口。
3. 业务实现沿 Controller -> Service -> Mapper/Remote Service 追踪。
4. 跨 biz 数据读取通过 `*-api` 的 Remote 接口和 Dubbo，不直接 import 其他 biz。
5. 多表写入需要事务；删除使用 MyBatis-Plus 逻辑删除并核对 `del_flag`。
6. 新增含 `tenant_id` 的表时，必须同步 Boot 与 Nacos 的 `hx.tenant.tables`。

## 缺失接口处理

- 先在 [接口映射](../40-接口与风险/接口映射.md) 和 Controller 中确认是否仅路径改写不同。
- 再查 API/Biz 是否在其他仓库或未合并分支；不要凭前端调用直接编造后端实现。
- 若确认缺失，需求包必须覆盖 Controller、Service、Mapper、实体、SQL、权限菜单和前端调用，不只补一侧。

## 修改前后验证

窄改动先跑目标模块；共享改动扩大到所有消费者。当前可靠的基础命令：

```powershell
# 后端
cd aryn-mall-java
mvn test -pl aryn-boot -am

# 管理端
cd aryn-mall-ui
pnpm check:type
pnpm test:unit
pnpm lint

# UniApp（Node 22）
cd aryn-mall-uniapp
pnpm type-check
pnpm build:mp-weixin
```

历史 `scripts/validate.py`、`lint-deps.py` 等当前已删除，未恢复前不要把它们写入验收结果。

## 每个需求完成后

- 在 `docs/50-需求文档/YYYY-MM-DD-需求名/` 更新范围、验收和代码核对结论。
- 在 [需求记录](../90-记录归档/需求记录.md) 登记完成状态、修改文件和验证结果。
- 新增稳定业务规则、表或接口时同步更新 `20`、`30`、`40` 层。
- 共享关系变化明显时执行 `graphify update . --no-cluster`。
