# 国内免费演示部署（ChmlFrp + 本机网关）

> 适用：开发阶段给外地同事演示，要求国内访问快、不买服务器、没有备案域名。
> 结论：静态页面、接口、图片全部走一条国内内网穿透，不再用 Cloudflare Pages 作为演示入口。

## 为什么原来的链接慢

- Pages 托管静态资源，`_worker.js` 把 `/api` 反代到 Cloudflare Quick Tunnel，再回源本机 9999；
- 每个接口、每张商品图都要走「国内 → Cloudflare 海外边缘 → 回国内家庭宽带」；
- Quick Tunnel 本身有限速、域名会变，不适合正式演示。

## 方案结构

```text
同事浏览器
   │ 国内网络
   ▼
ChmlFrp 免费节点（宣称国内 8Mbps，需实名）
   │
   ▼
127.0.0.1:8890  dev-tools/demo-gateway.mjs
   ├── /            H5 静态包（history 回退）
   ├── /admin/      管理端（base=/admin/，hash 路由）
   ├── /api/*       → 127.0.0.1:9999（去掉 /api 前缀）
   ├── /boot/*      → 127.0.0.1:9999（图片、上传文件）
   └── /message     → 127.0.0.1:9999（在线消息，含 WebSocket）
```

一条隧道、一个域名：H5 在 `/`，管理端在 `/admin/`，接口同源，不需要改 CORS。

## 一次性准备

### 1. 构建前端

```bash
./dev-tools/build-cn-bundles.sh
```

产物：

- H5：`aryn-mall-uniapp/dist/build/h5`
- 管理端：`aryn-mall-ui/apps/web-ele/dist-cn`（`VITE_BASE=/admin/`，不会覆盖原来的 `dist`）

只改了一端时可以加 `--only h5` 或 `--only admin`。

### 2. 注册 ChmlFrp 并创建隧道

1. 打开 <https://www.chmlfrp.net/> 注册并完成实名；
2. 创建 **HTTP** 隧道：本地地址 `127.0.0.1`，本地端口 `8890`，节点选国内；
3. 记下面板分配的域名；如果提供 HTTPS，优先用 HTTPS。

### 3. 填写穿透配置

```bash
cp dev-tools/cn-tunnel.env.example dev-tools/cn-tunnel.env
```

编辑 `dev-tools/cn-tunnel.env`：

```bash
CN_TUNNEL_CMD="/绝对路径/frpc -c /绝对路径/frpc.ini"
CN_PUBLIC_URL="https://xxxx.chmlfrp.cn"
```

`CN_TUNNEL_CMD` 用面板给出的启动命令；`CN_PUBLIC_URL` 是面板域名，带协议。
该文件含 token，已在 `.gitignore` 中忽略，不要提交。

## 每次演示

```bash
./dev-tools/start-cn-demo.sh
```

脚本会：

1. 启动本机网关（已在运行就复用）；
2. 启动穿透客户端，并等待公网探活；
3. 把数据库里的商品图、装修图和 `sys_storage_config.domain` 切到 `CN_PUBLIC_URL`；
4. 打印 H5 与管理端链接。

停止：`./dev-tools/start-cn-demo.sh --stop`
查看：`./dev-tools/start-cn-demo.sh --status`

首次启动前如果还没构建，可加 `--build` 一次完成构建与启动。

## 验证

```bash
curl -s http://127.0.0.1:8890/__health
curl -s -o /dev/null -w '%{http_code}\n' https://xxxx.chmlfrp.cn/
curl -s -o /dev/null -w '%{http_code}\n' https://xxxx.chmlfrp.cn/admin/
curl -s -o /dev/null -w '%{http_code}\n' https://xxxx.chmlfrp.cn/api/boot/
```

浏览器打开 `https://xxxx.chmlfrp.cn/admin/` 应出现登录页；登录后接口走同源 `/api`。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `/admin/` 返回 503 | 管理端未构建：`./dev-tools/build-cn-bundles.sh --only admin` |
| `/api` 返回 502 | 本机 9999 未启动：检查 `docker ps`，必要时 `docker start aryn-boot` 及依赖容器 |
| 商品图仍指向 trycloudflare | 再执行一次 `./dev-tools/dev-image-tunnel.sh --set-host <CN_PUBLIC_URL>` |
| 8890 被占用 | 改 `CN_GATEWAY_PORT`，并把 ChmlFrp 隧道的本地端口改成同一个 |
| 公网打不开 | 看 `${TMPDIR}/aryn-cn-tunnel/tunnel.log`；免费节点可能维护或更换域名 |
| HTTPS 页面里图片是 HTTP | `CN_PUBLIC_URL` 用面板的 HTTPS 地址，页面与图片保持同协议 |
| 管理端个别图标 404 | 网关已对 `/static/*` 做 H5 → 管理端回退；仍缺时重新构建管理端 |

## 与 Cloudflare 隧道共存

- launchd 的 `com.aryn.demo-env` 仍负责保活 9999 后端和 Cloudflare 图片隧道（供 Pages / 小程序真机使用）；
- Cloudflare 图片隧道重启时**不会**覆盖 ChmlFrp 域名：只有 `--set-host` 才会替换国内穿透域名；
- 想切回 Cloudflare 图片：`./dev-tools/dev-image-tunnel.sh --stop`（还原为局域网地址），
  或 `./dev-tools/dev-image-tunnel.sh --set-host https://<当前 trycloudflare 域名>`。

## 限制与注意

- 免费节点带宽和稳定性不保证，演示前 10 分钟先完整走一遍；
- Mac 休眠或断网会让隧道退出，演示期间保持电源与网络，可用 `caffeinate -dis`；
- 免费节点会经手你的流量，不要使用生产账号或真实客户数据；
- 管理端是 hash 路由，深链形如 `/admin/#/order/list`；
- 如果面板只提供 HTTP：页面、接口和图片都能用，但浏览器的剪贴板、摄像头等安全上下文能力会受限；能开 HTTPS 就优先 HTTPS；
- 1Mbps 的免费穿透（natapp/cpolar）不适合图片多的 H5；换厂商只需改 `cn-tunnel.env` 的两项配置。
