# 真机调试与局域网联调

> 适用场景：微信小程序在开发者工具里图片正常、真机调试时接口数据正常但图片全部空白；
> 或者页面图片空白、点开预览（`uni.previewImage`）却能看到图。

## 结论（实测）

微信小程序真机（Android / iOS 同理）的 `<image>` 组件**只渲染「HTTPS + 受系统信任证书」的网络图片**：

| 图片地址 | 页面 `<image>` | 点开 `uni.previewImage` |
| --- | --- | --- |
| 小程序包内（`/static/...`） | 显示 | 显示 |
| 公网 https | 显示 | 显示 |
| **公网 http** | **空白** | 显示 |
| **局域网 http（`http://192.168.x.x:9999`）** | **空白** | 显示 |
| **局域网自签名 https** | **空白** | 空白（证书不受信任） |
| 域名解析到局域网 IP、但仍是 http | 空白 | 显示 |

说明两件事：

1. **"页面空白但点开预览能看"是正常现象**：`uni.previewImage` 走原生下载通道，在调试模式下可以下载 http 图片；
   `<image>` 走渲染层，http 一律不加载。看到预览有图不代表页面能显示出图。
2. **开发者工具正常 ≠ 真机正常**：开发者工具勾选「不校验合法域名、TLS 版本以及 HTTPS 证书」后 http 也能显示，
   真机只放宽域名校验，不放宽协议和证书。

## 两类问题，对应两个脚本

本仓库本地开发的图片地址经历两层修复，别混淆：

| 问题 | 现象 | 修复 |
| --- | --- | --- |
| ① 数据库存的是 `http://localhost:9999/...` | 开发者工具正常，真机连预览都失败（手机的 localhost 是手机自己） | [fix-dev-image-urls.sh](../../dev-tools/fix-dev-image-urls.sh)：localhost → 局域网 IP |
| ② 图片是局域网 http | 开发者工具正常、预览能看，真机页面 `<image>` 空白 | [dev-image-tunnel.sh](../../dev-tools/dev-image-tunnel.sh)：图片切到受信任 https 隧道 |

> 日常真机调试：直接跑 `dev-image-tunnel.sh` 即可（它会把当前局域网 http 地址一并替换）。
> `fix-dev-image-urls.sh` 用于开发者工具调试、以及隧道停止后把地址还原成局域网 http。

## 方案 A（推荐，真机看图片）：dev-image-tunnel.sh

用 Cloudflare 免费临时隧道（无需注册、域名、证书）把本机后端映射为
`https://<随机>.trycloudflare.com`，再把数据库里的图片地址批量切到该域名；
接口请求仍走局域网 http，不受影响。

```bash
# 前台运行：起隧道 + 改库 + 清缓存；Ctrl+C 自动还原成局域网 http
./dev-tools/dev-image-tunnel.sh

# 后台运行（关掉终端也保持），停止时用 --stop
./dev-tools/dev-image-tunnel.sh --detach
./dev-tools/dev-image-tunnel.sh --stop

# 只读检查当前图片主机 / 隧道进程状态
./dev-tools/dev-image-tunnel.sh --verify
```

脚本行为：

- 首次运行自动下载 `cloudflared`（约 20MB，缓存到 `~/.cache/aryn/bin/`，可用 `ARYN_CLOUDFLARED` 指定已有二进制）；
- 扫描 `aryn_*` 库中图片相关文本/JSON 列，把 `http://<局域网IP>:<端口>`、`http://localhost`、以及**上一次隧道域名**
  统一替换为本次隧道地址（含 `sys_storage_config.domain`，之后上传的新图也生效），并清理 Redis 装修缓存；
- 后台模式用 `--stop` 还原；前台模式 Ctrl+C 自动还原；
- 隧道域名每次启动都会变，重启后重新执行脚本即可（脚本会替换旧域名）。

注意事项：

- 隧道运行期间本机后端会临时暴露在一个随机公网域名上，仅本地开发使用，测完记得 `--stop`；
- 图片会经公网绕一圈，比局域网慢，属正常；
- 数据库里出现的 `*.trycloudflare.com` 是临时开发地址，不要提交进种子 SQL 或发布包；
- 若脚本自检显示 `HTTP 000` 但手机能正常看图：多为本机代理/DNS 拦截新建域名，不影响手机实测。

## 方案 B（开发者工具 / 预览）：fix-dev-image-urls.sh

把开发库里的 `localhost` 图片地址修成当前局域网 IP，并清理装修缓存：

```bash
./dev-tools/fix-dev-image-urls.sh --verify   # 只读检查
./dev-tools/fix-dev-image-urls.sh            # localhost/旧网段 → 当前局域网 IP
./dev-tools/fix-dev-image-urls.sh --revert   # 还原成 localhost
```

开发者工具、H5 预览、`uni.previewImage` 都正常；真机 `<image>` 仍然不显示 http 图（预期行为，
真机要看图请用方案 A）。

## 方案 C（团队长期方案）

- 自有域名加一条 A 记录指向局域网 IP（如 `dev-img.example.com → 192.168.x.x`），
  用 DNS-01 签发受信任证书，本机起 HTTPS 反向代理（443/9443）；手机走局域网即可访问 https 图片。
- 或把开发图片托管到公网 HTTPS OSS/CDN，`sys_storage_config.domain` 填该 https 域名。
- 生产环境本来就是 https 正式域名，不需要这些开发期手段。

## 排查清单

1. 先看图片 URL 的主机：`localhost` / 局域网 http → 真机 `<image>` 必空白；先跑 `fix-dev-image-urls.sh`，
   仍要在真机看页面图片再跑 `dev-image-tunnel.sh`。
2. 如果页面空白但点开预览有图 → 不是数据问题，是 http 协议问题，直接看方案 A。
3. 如果预览也打不开 → 手机和电脑可能不在同一网段/AP 隔离/VPN，或者 URL 主机不可达。
4. 手机与电脑保持同一 Wi-Fi；必要时关闭手机 VPN/代理。
5. 隧道方案下，手机浏览器能打开隧道图片 URL、但小程序还空白 → 重启小程序/重新真机调试拉新数据。
6. 重跑 `db/boot` 或 `db/cloud` 图片种子脚本会重置图片地址（回到 localhost），需要重新执行对应脚本。

## 附：本机服务临时给别的电脑访问（管理端 / 任意端口）

同一条隧道只能映射一个本地端口：图片隧道映射的是后端 `9999`，**不能**用来打开管理端页面（管理端 dev server 是 `5777`）。
按场景二选一：

### 同一局域网

管理端 dev server 已监听所有网卡，另一台电脑直接访问即可（需 Mac 防火墙放行）：

```text
http://192.168.3.14:5777
```

页面里的 `/api` 请求走 Vite 同源代理回本机 `9999`，没有 CORS 问题；图片走图片隧道（https）正常显示。

### 不在同一局域网（临时公网访问）

用 [dev-public-tunnel.sh](../../dev-tools/dev-public-tunnel.sh) 给目标端口单独开一条临时隧道：

```bash
./dev-tools/dev-public-tunnel.sh 5777              # 前台，Ctrl+C 关闭
./dev-tools/dev-public-tunnel.sh 5777 --detach     # 后台，--stop 关闭
./dev-tools/dev-public-tunnel.sh 5777 --stop
```

拿到输出的 `https://xxx.trycloudflare.com`，别的电脑打开即是管理端（API 同源代理、图片走图片隧道）。

### 移动端 H5 临时演示（给外地同事）

C 端 uni-app 也可以跑 H5 并用同样的隧道方式分享。H5 dev 的接口走
`VITE_H5_API_BASE_URL=/api`（Vite 同源代理回本机 9999），所以一条隧道即可，无 CORS 问题：

临时演示推荐用**静态包**（比 dev server 稳定、首屏更快；dev server 会与其它 uni 进程抢写 `src/pages.json`，
并按键需编译，不适合对外演示）：

```bash
# 1) 构建 H5 包（demo 模式：API 基址 = 同源 /api，由演示服务器反代到本机后端）
#    注意：必须用 --mode demo（读取 .env.demo）；直接 `VITE_API_BASE_URL=/api pnpm build:h5`
#    会被 production 模式重新覆盖成 http://localhost:9999，外地浏览器会请求自己的 localhost
#    并显示 "Failed to load. Please try again."
cd aryn-mall-uniapp && pnpm build:h5:demo && cd ..

# 2) 启动静态演示服务器（默认 8890，服务 dist/build/h5，同源代理 /api）
node dev-tools/h5-demo-server.mjs --port 8890 &

# 3) 映射成公网 https 域名，把输出的 URL 发给同事
./dev-tools/dev-public-tunnel.sh 8890 --detach --no-host-rewrite
# 停止：./dev-tools/dev-public-tunnel.sh 8890 --stop
```

> 本地开发想看 H5 时仍可用 `pnpm dev:h5` + `dev-public-tunnel.sh 8888`，但只适合自己看，临时演示建议走上面的静态包。

说明：

- 同事用手机/电脑浏览器直接打开隧道 URL 即可；`/api` 经 Vite 代理到本机后端，
  页面里的商品图/装修图走图片隧道（https），可正常显示。
- dev server 是**按需编译**：第一次点开某个页面会先编译再加载，稍慢属正常；
  HMR WebSocket 在隧道下可能连不上，只影响热更新控制台提示，不影响页面使用。
- **登录说明**：H5 默认「手机号验证码登录」，而本地 `application-dev.yml` 的短信通道是占位配置
  （`accessKeyId: xxxxxxxxx`），收不到验证码；本地 `user_info` 也没有带密码的账号。
  不登录可以演示首页、商品列表/详情、营销活动等公开页面；需要演示购物车/下单时，
  建议提前给一个测试账号设置密码并用「密码登录」，或临时放开验证码校验。
- 若同事在外网，图片隧道和管理端/H5 隧道都依赖这台 Mac 在线，演示期间不要让 Mac 休眠
  （可用 `caffeinate -dis` 临时阻止休眠）。
- 正式发布不需要这些：构建机/流水线产出 H5 静态包后用正式域名部署即可。

注意事项：

- Vite 6 会校验 Host 头，隧道域名直接回源会 403 `Blocked request`；脚本默认带
  `--http-host-header 127.0.0.1:<端口>` 绕过（非 Vite 服务可加 `--no-host-rewrite`）。
- 隧道运行期间该端口暴露在随机公网域名上（管理端仍需登录），仅用于临时演示，用完 `--stop`。
- 临时隧道域名每次启动都会变；Mac 休眠/断网/重启后会断，重跑脚本即可。
- 当前跑了两条隧道时互不影响：图片隧道（9999，给小程序/管理端图片用）+ 管理端隧道（5777）。

页面/JS/CSS 是静态托管，**链接永久固定**；接口通过各站点根目录的 `_worker.js`（Pages Functions
高级模式）把 `/api/*` 反向代理到本机隧道，前端构建里 API 基址保持同源 `/api`。图片由数据库里的
图片隧道 https 地址直接加载（不经过 Pages 代理）。

**更新/重新发布（按情况选）：**

```bash
./dev-tools/deploy-pages.sh                    # 重建两个前端 + 生成 _worker.js + 发布
./dev-tools/deploy-pages.sh --only h5          # 只重建/发布 H5（改 H5 时用）
./dev-tools/deploy-pages.sh --only admin       # 只重建/发布管理端
./dev-tools/deploy-pages.sh --skip-build       # 不重建，只更新 _worker.js 代理目标（隧道换域名时用）
./dev-tools/deploy-pages.sh --only h5 --skip-build   # 只重新发布现有 H5 产物
```

**什么操作会影响 Pages、要不要重新部署：**

| 你的操作 | Pages 链接 | 需要重新部署？ |
| --- | --- | --- |
| 只重启/重建本地后端容器（隧道不动） | 不变；后端重启期间接口短暂失败，起来后自动恢复 | ❌ 不需要 |
| 改数据库/内容数据（商品、装修、素材） | 不变 | ❌ 不需要，刷新页面即可 |
| 重启 Cloudflare 隧道（域名变了） | 页面能打开，但接口/登录/图片失败 | ✅ `deploy-pages.sh --skip-build`（几秒） |
| 改 H5 源码 / 管理端源码 | 线上还是旧版本 | ✅ `deploy-pages.sh`（或 `--only h5` / `--only admin`，约 1~2 分钟） |
| 改 `.env*`、`VITE_*` 等构建期配置 | 线上还是旧配置 | ✅ 同源码改动，必须重新构建 |
| 重新执行 db 种子脚本（图片地址回退 localhost） | 图片挂 | 先 `./dev-tools/dev-image-tunnel.sh`（更新图片地址），必要时再 `deploy-pages.sh --skip-build` |

> 后端重建/重启时注意：不要同时重启隧道进程；如果 `docker compose` 改了端口映射（不是 9999），
> 隧道指向的端口也要跟着改并重启隧道。

前置：`npx wrangler login` 登录过一次 Cloudflare（登录态保存在 `~/Library/Preferences/.wrangler/config/default.toml`）。

**后端隧道域名变化时的完整流程：**

```bash
./dev-tools/start-demo-env.sh                 # 恢复后端 + 隧道（会同步更新数据库图片地址、清缓存）
./dev-tools/deploy-pages.sh --skip-build      # 把 Pages 的 /api 代理目标更新为新隧道域名
```

注意：隧道进程死掉时 Pages 页面仍能打开，但接口/登录/图片会失败；Pages 免费额度约 10 万请求/天，
Functions 不支持 WebSocket（H5 在线客服聊天不可用，管理端消息类实时功能同理）。

### 演示链接为什么又打不开 / 一键恢复

Cloudflare Quick Tunnel 的域名**绑定在 cloudflared 进程上**：进程一结束（Mac 休眠唤醒后网络变化、终端或会话关闭、
系统/工具清理后台进程、Docker 或电脑重启等），域名立刻失效，**旧链接永久恢复不了**，只能重新起隧道换新域名。
典型日志：`Initiating graceful shutdown due to signal terminated ... / no more connections active and exiting`。

```bash
# 一键检查并拉起：后端容器 + H5 静态服务(8890) + 管理端(5777) + 三条隧道，打印最新链接
./dev-tools/start-demo-env.sh

./dev-tools/start-demo-env.sh --status   # 只看状态，不做修改
./dev-tools/start-demo-env.sh --build    # 先重建 H5(demo) 与管理端静态包，再启动
```

建议：

- 在**你自己的终端**里运行，不要挂在 agent 会话里（会话结束可能带走后台进程）；
- 演示期间用 `caffeinate -dis ./dev-tools/start-demo-env.sh` 防止 Mac 休眠；
- 已部署 Cloudflare Pages 时：页面链接固定不变，但要把两个 Pages 项目的 `BACKEND_URL`
  改成脚本打印的「后端/图片」域名，然后 Deployments → Retry deployment；
- 想彻底固定链接：H5/管理端用 Pages（静态链接固定），后端换固定域名的服务器或 Named Tunnel。

### 让演示环境脱离终端/会话常驻（launchd）

会话/终端关闭会带走后台进程，所以用 macOS 原生 launchd 托管（独立于任何终端、IDE、agent 会话）：

```bash
./dev-tools/install-demo-launchd.sh install     # 安装并立即启动（登录后自启）
./dev-tools/install-demo-launchd.sh status      # 查看 launchd 状态 + 最近日志 + 当前链接
./dev-tools/install-demo-launchd.sh run         # 立即手动跑一轮
./dev-tools/install-demo-launchd.sh uninstall   # 卸载自启

./dev-tools/start-demo-env.sh --stop            # 暂停自启 + 停止隧道/前端服务
```

机制：

- LaunchAgent `~/Library/LaunchAgents/com.aryn.demo-env.plist`，登录后自动运行；
- 作业是常驻循环：每 300 秒跑一次 `start-demo-env.sh`（已存活的服务复用，隧道挂了自动重建）；
- 开启 `AUTO_PAGES=true`：隧道域名变化后自动执行 `deploy-pages.sh --skip-build`，Pages 无需人工更新；
- 日志：`~/Library/Logs/aryn-demo/env.log`、`pages-deploy.log`；
- 前置：Docker/OrbStack 需运行（登录后一般自动启动）；Mac 休眠时暂停，唤醒后下一轮自愈（域名会变，Pages 会自动更新）。

> 常驻期间本机 9999/8890/5777 会一直暴露在随机公网域名上；不需要演示时执行 `--stop` 或 `uninstall`。

## 已知边界

- 真机 `<image>` 的 https 限制来自微信渲染层，不是本项目配置能绕开的（「不校验合法域名」也只放宽域名校验）。
- 另有离线备选方案：开发期把 http 图片用 `uni.downloadFile` 下载成本地临时文件再渲染（完全离线），
  但需要改接口响应处理、侵入性大，暂未实施，优先用隧道方案。
