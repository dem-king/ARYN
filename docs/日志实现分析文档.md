# aryn-mall 项目日志实现分析文档

## 一、项目日志架构总览

| 维度 | 实现方式 |
|---|---|
| **日志门面** | SLF4J（Spring Boot 默认引入） |
| **日志实现** | Logback（Spring Boot 默认） |
| **Logger 声明** | 统一使用 Lombok `@Slf4j` 注解 |
| **配置文件** | 各业务模块独立 `logback-spring.xml` |
| **日志输出** | 控制台 + 文件（debug.log 全量 + error.log 仅 ERROR） |
| **滚动策略** | 按大小+时间滚动，50MB/文件，保留30天，zip 压缩 |
| **自定义操作日志** | `@SysLog` 注解 + AOP 切面 + Spring 事件 + 异步监听 + Dubbo RPC + 数据库持久化 |

---

## 二、日志框架

项目基于 **Spring Boot 3.5.8**，默认使用 **SLF4J + Logback** 日志框架组合。未引入 log4j2 相关依赖。

- **日志门面**：`org.slf4j`（通过 Spring Boot Starter 自动引入）
- **日志实现**：`ch.qos.logback`（Spring Boot 默认）
- **注解增强**：`lombok.extern.slf4j.Slf4j`（Lombok 编译期自动生成 `private static final Logger log = LoggerFactory.getLogger(Xxx.class)`）

### 3.2 配置文件完整内容（以 aryn-boot 为例）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration scan="true" scanPeriod="60 seconds" debug="false">
    <!-- 定义参数 -->
    <property name="log.dir" value="logs/aryn-boot"/>

    <!-- 输出到控制台 -->
    <appender name="stdout" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{35} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- debug 日志文件（实际记录 >= INFO 级别） -->
    <appender name="debug" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${log.dir}/debug.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${log.dir}/debug_%d{yyyy-MM-dd}_%i.log.zip</fileNamePattern>
            <maxFileSize>50MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level %logger{35} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- error 日志文件（仅 ERROR 级别） -->
    <appender name="error" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${log.dir}/error.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${log.dir}/error_%d{yyyy-MM-dd}_%i.log.zip</fileNamePattern>
            <maxFileSize>50MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <filter class="ch.qos.logback.classic.filter.LevelFilter">
            <level>ERROR</level>
        </filter>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level %logger{35} - %msg%n</pattern>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="stdout"/>
        <appender-ref ref="debug"/>
        <appender-ref ref="error"/>
    </root>
</configuration>
```

## 六、如何修改日志文件的记录位置

### 方式一：修改 logback-spring.xml 中的 `log.dir` 属性（推荐）

在对应模块的 `logback-spring.xml` 中，修改 `<property name="log.dir">` 的 `value` 值：

```xml
<!-- 修改前 -->
<property name="log.dir" value="logs/aryn-boot"/>

<!-- 修改后：使用绝对路径 -->
<property name="log.dir" value="D:/applogs/aryn-boot"/>

<!-- 修改后：使用 Linux 绝对路径 -->
<property name="log.dir" value="/var/log/aryn-mall/aryn-boot"/>
```

### 方式二：通过 application.yml 配置 logging.file.path

Spring Boot 支持通过 `application.yml` 设置日志路径（优先级低于 logback-spring.xml 中的配置）：

```yaml
logging:
  file:
    path: /var/log/aryn-mall
```

> **注意**：如果 `logback-spring.xml` 中已硬编码了 `log.dir`，则此方式不生效。需将 `logback-spring.xml` 中的路径改为引用 Spring 属性才行，例如：`<property name="log.dir" value="${LOG_PATH:-logs/aryn-boot}"/>`，然后在 `application.yml` 中配置 `logging.file.path` 作为 `LOG_PATH` 传入。

### 方式三：通过 JVM 启动参数覆盖

启动时传入系统属性：

```bash
java -Dlogging.file.path=/var/log/aryn-mall -jar aryn-boot.jar
```

同样需要 `logback-spring.xml` 中引用该属性才生效。

### 方式四：统一所有模块日志路径的最佳实践

1. 在各模块 `logback-spring.xml` 中将硬编码路径改为引用变量：
   ```xml
   <property name="log.dir" value="${LOG_PATH:-logs}/${project.artifactId}"/>
   ```
2. 在 `application.yml`（或 Nacos 配置中心）中统一配置：
   ```yaml
   logging:
     file:
       path: /var/log/aryn-mall
   ```
3. 这样所有模块的日志都会输出到 `/var/log/aryn-mall/{模块名}/` 下。

## 七、日志格式与滚动策略

### 7.1 日志格式

| 输出目标 | 格式 | 示例 |
|---|---|---|
| 控制台 | `%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{35} - %msg%n` | `2025-04-28 10:30:15.123 [http-nio-9999-exec-1] INFO  c.a.c.upms.controller.SysDeptController - 新增部门成功` |
| 文件 | `%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level %logger{35} - %msg%n` | `2025-04-28 10:30:15.123 INFO  c.a.c.upms.controller.SysDeptController - 新增部门成功` |

> 控制台比文件多输出线程名 `[%thread]`，便于开发调试。

### 7.2 滚动策略

| 配置项 | 主业务模块 | xxl-job-admin |
|---|---|---|
| 滚动策略 | `SizeAndTimeBasedRollingPolicy`（按大小+时间） | `TimeBasedRollingPolicy`（仅按时间） |
| 单文件最大大小 | **50MB** | 未限制 |
| 最大保留天数 | **30天** | 未限制 |
| 归档文件名 | `debug_2025-04-28_0.log.zip` | `xxl-job-admin.log.2025-04-28.log` |
| 压缩方式 | **zip 压缩** | 不压缩 |
| root 日志级别 | **INFO** | **info** |

### 7.3 Appender 配置

每个业务模块配置 3 个 Appender：

| Appender 名称 | 类型 | 说明 |
|---|---|---|
| `stdout` | ConsoleAppender | 输出到控制台 |
| `debug` | RollingFileAppender | 记录所有 >= INFO 级别日志到 `debug.log` |
| `error` | RollingFileAppender | 通过 `LevelFilter` **仅过滤 ERROR 级别**日志到 `error.log` |

## 九、自定义操作日志机制（@SysLog）

这是项目最核心的业务日志机制，用于记录用户操作日志并持久化到数据库。

### 9.1 模块结构

```
aryn-common-log/
  src/main/java/com/aryn/cloud/common/log/
    annotation/
      SysLog.java               -- 自定义操作日志注解
    aop/
      LogAopAspect.java         -- AOP 切面，拦截 @SysLog 注解的方法
    event/
      ArynLogEvent.java         -- 操作日志事件（Spring ApplicationEvent）
      ArynLoginLogEvent.java    -- 登录日志事件
      ArynLogEventListener.java -- 事件监听器，异步保存日志到数据库
    config/
      ArynSysLogConfig.java     -- 日志模块自动配置类，注册 Bean
```

### 9.2 @SysLog 注解定义

```java
@Target({ ElementType.METHOD, ElementType.TYPE })
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface SysLog {
    /** 操作标题描述 */
    String value() default "";
}
```

### 9.3 使用示例

```java
@SysLog("新增部门")
@SaCheckPermission("upms:sysdept:add")
@PostMapping
public Result add(@RequestBody SysDept sysDept) {
    return Result.success(sysDeptService.save(sysDept));
}
```

### 9.4 工作流程

```
Controller 方法标注 @SysLog("操作描述")
        │
        ▼
LogAopAspect.around() 拦截（AOP @Around 通知）
  ├── 从 HttpServletRequest 获取请求信息
  ├── 构建 SysLog 实体（IP、URI、方法名、用户名、租户ID等）
  ├── 执行目标方法，记录耗时
  ├── 异常时标记状态为失败，记录异常信息
  └── 发布 ArynLogEvent（Spring ApplicationEvent 机制）
        │
        ▼
ArynLogEventListener.saveSysLog()（@Async 异步监听）
  └── 通过 Dubbo RPC 调用 RemoteSysLogService.saveLog()
        │
        ▼
RemoteSysLogServiceImpl（aryn-upms-biz 中的 Dubbo 服务实现）
  └── sysLogService.save() 持久化到数据库表 sys_log
```

### 9.5 AOP 切面核心代码（LogAopAspect.java）

```java
@Aspect
@Slf4j
@RequiredArgsConstructor
public class LogAopAspect {
    private final ApplicationEventPublisher applicationEventPublisher;

    @SneakyThrows
    @Around("@annotation(sysLog)")
    public Object around(ProceedingJoinPoint point, SysLog sysLog) {
        HttpServletRequest request = ((ServletRequestAttributes) Objects
            .requireNonNull(RequestContextHolder.getRequestAttributes())).getRequest();

        // 构建 SysLog 实体
        com.aryn.cloud.upms.api.entity.SysLog sysLogVo = new com.aryn.cloud.upms.api.entity.SysLog();
        String ip = JakartaServletUtil.getClientIP(request);
        sysLogVo.setMethod(request.getMethod());
        sysLogVo.setIpAddr(ip);
        sysLogVo.setLocation(IpUtils.getWhoisAddress(ip));
        sysLogVo.setRequestMethod(point.getSignature().getDeclaringTypeName() + "." + point.getSignature().getName());
        sysLogVo.setRequestUri(URLUtil.getPath(request.getRequestURI()));
        sysLogVo.setTitle(sysLog.value());
        sysLogVo.setStatus(CommonConstants.LOGIN_LOG_STATUS_1); // 成功
        sysLogVo.setUserName(SecurityUtils.getUser().getUsername());
        sysLogVo.setTenantId(ArynTenantContextHolder.getTenantId());

        // 执行目标方法并记录耗时
        Long startTime = System.currentTimeMillis();
        Object result = null;
        try {
            result = point.proceed();
        } catch (Exception e) {
            sysLogVo.setStatus(CommonConstants.LOGIN_LOG_STATUS_0); // 失败
            sysLogVo.setExMsg(e.getMessage());
            throw e;
        } finally {
            sysLogVo.setRequestTime(System.currentTimeMillis() - startTime);
            // 异步发布操作日志事件
            applicationEventPublisher.publishEvent(new ArynLogEvent(this, sysLogVo));
        }
        return result;
    }
}
```

### 9.6 异步事件监听器（ArynLogEventListener.java）

```java
@Slf4j
@RequiredArgsConstructor
public class ArynLogEventListener {
    private final RemoteSysLogService remoteSysLogService;

    @Async("hxAsyncExecutor")  // 使用自定义线程池异步执行
    @EventListener(ArynLogEvent.class)
    public void saveSysLog(ArynLogEvent event) {
        SysLog sysLog = event.getSysLog();
        log.info("调用远程接口之前: tenantId = {}", ArynTenantContextHolder.getTenantId());
        remoteSysLogService.saveLog(sysLog);  // Dubbo RPC 调用保存
    }

    @Async("hxAsyncExecutor")
    @EventListener(ArynLoginLogEvent.class)
    public void saveSysLoginLog(ArynLoginLogEvent event) {
        SysLoginLog sysLoginLog = event.getSysLoginLog();
        remoteSysLogService.saveLoginLog(sysLoginLog);
    }
}
```

### 9.7 自动配置类（ArynSysLogConfig.java）

```java
@Configuration
@RequiredArgsConstructor
public class ArynSysLogConfig {
    @DubboReference
    private final RemoteSysLogService remoteSysLogService;

    @Bean
    public ArynLogEventListener hxLogEventListener() {
        return new ArynLogEventListener(remoteSysLogService);
    }

    @Bean
    public LogAopAspect logAopAspect(ApplicationEventPublisher publisher) {
        return new LogAopAspect(publisher);
    }
}
```

## 十、XXL-JOB 模块日志

XXL-JOB 使用独立的 `logback.xml` 配置：

```xml
<configuration debug="false" scan="true" scanPeriod="1 seconds">
    <property name="log.path" value="${LOG_HOME:-/data/applogs}/xxl-job/xxl-job-admin.log"/>
    <!-- console + file appender -->
    <root level="info">
        <appender-ref ref="console"/>
        <appender-ref ref="file"/>
    </root>
</configuration>
```

与主业务模块的区别：
- 使用 `TimeBasedRollingPolicy`（仅按时间滚动，无大小限制）
- 日志路径默认为 `/data/applogs/xxl-job/`，可通过 `LOG_HOME` 环境变量覆盖
- 无 debug/error 分级输出
- 配置热加载间隔为 1 秒
