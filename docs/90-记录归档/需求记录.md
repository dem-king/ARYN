- 新增 `components/goods-list-panel/index.vue`：把「查询 + 排序 + 分页 + 卡片 + 快捷加购」抽成可复用面板，分类页与商品列表页共用，避免两套口径漂移。

- `sub-pages/product/goods-list/index.vue` 改为复用面板；新增 `categoryFirstId/categorySecondId` 入参，**保留 `categoryId` 作为二级类目历史别名**（`diy/link-resolver` 装修链接生成的就是它）。

**实施中发现并修复的三个真实缺陷**

1. **访客进分类页被踢到登录页**：分类页在白名单内（访客可浏览），但新增的购物车角标在 `onShow` 无条件调 `fetchCartCount()`，无 token 触发 401 → 统一错误处理跳登录页。加 `authStore.isLoggedIn` 守卫并让未登录角标显示 0。
2. **已填图但域名不可达 → 空白圆**：存量类目（家用电器/手机数码）`category_pic` 指向示例域名。只判断字段非空会渲染空白圆，比无图更糟。图标条与浮层均增加 `@error` 兜底，加载失败同样回落首字色块。
3. **商品流抢跑**：P1 初版未等类目树返回就挂载面板，会先按「全部分类」白查一次商品随即被覆盖。改为 `treeLoaded` 置位后再挂载。

## 2026-09-21 移动端商品快捷加购

### 需求

移动端商品增加快速加入购物车的功能，可快速将商品加入购物车。

### 结果

**新增按需查询接口 `GET /product/app/goodsspu/quick-cart/{id}`**（`aryn-product`）

- 列表接口不返回 SKU 明细，加购按钮**点击时**才查一次，返回三种方式：`direct`（单规格可直接加购）/ `choose`（多规格，附带可选 SKU 与 `specsArr`）/ `unavailable`（售罄，带原因）。
- 单规格取「状态正常且有库存」的 SKU，多行时取库存最充足的一行。
- 数量规则（MOQ/步长/采购单位）取自 `ship_sku_profile`，与 `SharedCartServiceImpl.validateQuantityRules` 的校验口径对齐；未维护资料的商品不返回该字段，前端按 MOQ=1、步长=1 处理。
- **刻意不写浏览足迹**：改直连 `goodsSpuMapper.selectApiSpuById` 而非 `getApiSpuById`，避免「加购意图」污染用户足迹与热搜榜。
- 新增 `QuickCartSkuVO` 只下发购买决策字段，成本价/租户/逻辑删除等内部字段不下发 C 端。

**移动端**

- `utils/quick-cart.ts`：纯规则（方式归一化 fail-safe 为「选规格」、默认数量 `ceil(moq/step)*step`、库存不足返回 0），14 条单测。
- `composables/useQuickCart.ts`：未登录先跳登录（不发必然 401 的请求）→ 查询 → 直购或唤起规格弹层；并发点击去重；失败绝不误报成功。
- `components/quick-cart-button/index.vue`：可复用按钮 + 内部 SKU 弹层，带动画位插槽，装修组件用它换皮而不改交互；`@tap.stop` 保证不触发卡片跳转。
- 接入 4 个商品面：商品列表页、装修组件 `goods`（首页在用的旧组件）、`goods-group`、`goods-waterfall`。装修组件上的购买按钮从**纯装饰**变为可点击加购，运营选择的按钮样式保持不变。
- 规格弹层**懒挂载**（`v-if="skuMounted"` + `nextTick` 打开）：列表页每张卡片都挂一份弹层会让小程序节点数随商品数线性增长，改为只在点开多规格商品时创建。

**顺带修复阻断级缺陷：船供种子 SKU 状态写反**

`62ship_supply_seed_acceptance.sql` 把船供 SKU 的 `status` 写成 `'1'`。该字段语义为 `0=启用 / 1=停用`（管理端 `sku-table` 的 `ElSwitch` `active-value="0"`），而加购与结算链路只取 `status='0'` → **全部 27 个船供验收商品都返回 `60008 库存不足`，完全不可购买**。这是快捷加购的前置阻断，故一并修复：boot/cloud 两份脚本同步改 `'0'`，重新生成 `aryn_boot_full.sql` 并通过 `verify-full-sql.mjs`，新增契约测试固化字段语义。存量库需手工执行一次 `UPDATE goods_sku SET status='0' WHERE id LIKE '965%' AND status='1'`。

## 2026-09-21 购物车页面遮挡与结算入口不可见修复

### 需求

用户反馈小程序购物车页两个缺陷：① 顶部收货地址栏悬浮并遮挡下方「共享购物车」
入口；② 底部看不到「去结算」按钮，无法结算。

### 结果

两处均为 `src/pages/user/shopping-cart/index.vue` 的布局缺陷，与后端接口无关：

- **地址栏遮挡**：`.cart-header` 用 `position: fixed` 却不占位，而模板里的
  `<wd-gap height="80rpx">` 占位块在 2026-09-20 新增共享购物车入口后落在了
  该入口**之后**，导致地址栏压住卡片上半部。改为普通流内布局（去掉 `fixed`），
  地址栏回到文档流自然撑开空间，层级与占位问题一并消除。
- **结算条被 TabBar 盖住**：`.cart-footer` 用 `bottom: 0`，而 H5 的 TabBar 是
  一层 `position: fixed; z-index: 998` 的原生遮盖（结算条仅 `z-index: 2`），
  两者争抢同一 50px 区域，按钮被完全压住。改为 `bottom: var(--window-bottom, 0px)`：
  H5 下该变量为 TabBar 高度（含安全区），小程序下为 0（原生 TabBar，
  视口本身已排除），双端一致。另补 `.cart-footer-holder` 等高滚动占位，
  避免固定结算条遮住「为你推荐」最后一行。

### 验证

- H5 实机（`localhost:8888`）：地址栏回到文档流，共享购物车入口完整可见；
  结算条 `bottom: 50px`、`top: 720px`，稳定落在 TabBar（`top: 762px`）之上，
  `elementFromPoint` 命中「去结算」按钮而非 TabBar；编辑态（移入收藏夹/删除）
  同样完整露出；滚动到底部最后一行商品可完整显示。
- `pnpm type-check`、`pnpm test:unit`（85 用例）、`pnpm build:mp-weixin`、
  `pnpm build:h5` 通过；小程序产物 `index.wxss` 含 `bottom:var(--window-bottom, 0px)`
  与 `.cart-footer-holder` 规则。
- 新增 `src/code-review-contract.test.ts` 用例固化上述三条布局约束，
  已反向验证：回退旧写法时该用例失败。

## 2026-09-21 商品统一与共享采购协作下单改造

### 需求

用户实际业务为「一名海员代表全船集中采购」，单笔 1 万至十几万、涉及大量 SKU。
提出四项诉求：① 不区分船供与个人商品，统一管理、C 端统一展示；② 保留采购场景
（选船、选靠港、内部配送、MOQ/步长、共享购物车）；③ 靠港时间只有海员知道，
应由海员下单时申报、运营接收后管理；④ 共享购物车支持分享到微信群，未注册的船员
点开即可登录/自动注册、绑定当前船舶并参与选购，最终由发起人统一提交；
配送到船时需按人贴标签区分商品归属。

### 结果

- **商品统一**：移除 `sale_scope` 作为商品池闸门（零售列表排除、船供/个人摘要硬过滤、
  发布强制校验），船供属性降级为可选扩展资料，缺省按采购单位=基本单位、MOQ=1、步长=1。
  管理端去掉「船供目录」双视图，移动端去掉「船供采购/个人购买」双入口。
- **订单按人拆行**：订单明细由「按 SKU 合并」改为「按成员拆行」，满足配送逐人贴标签；
  连带修复三处缺陷——`generateOrderItems` 丢弃同 SKU 其余成员明细、库存校验按行数
  误报不足、阶梯价按单行数量永不触发；`contributor_user_id` 逗号拼接溢出问题随之消除。
- **姓名快照**：新增 `shared_cart_member.display_name` 与 `order_item.contributor_name`，
  成员加入时填写一次，下单结转快照，管理端与小程序均展示归属。
- **生命周期**：同一船舶仅允许一个收集中购物车（生成列唯一索引兜底并发），
  有效期改为服务端计算 24 小时，新增 `SharedCartExpireJob` 定时关闭过期购物车，
  订单签收后归档为「已完成」。
- **分享入群**：新增 `share_token` 与分享/加入接口，卡片携带令牌转发微信群；
  加入时自动补建船舶成员关系，新用户无需后台配置即可参与。
- **靠港申报**：`vessel_call` 新增 `source`/`declared_by`，C 端新增申报接口
  （同船 ETA ±72 小时内复用），配送时间窗留给运营排产，管理端标识待处理申报。

### 验证与遗留

- 后端：order 130、vessel 58、product 52、promotion 167 用例全绿；`aryn-boot` clean compile 通过；
  boot/cloud 双份增量脚本（65/66/67）内容一致，全量脚本重新生成并通过 `verify-full-sql.mjs`。
- 前端：管理端 472 用例与 `check:type` 通过，小程序 84 用例与 `type-check` 通过。
- **未覆盖**：以上均为编译、单测与类型检查。订单拆行影响下单主链路（价格、库存、
  优惠分摊），上线前必须真机走通完整下单流程；配送标签打印模板与支付能力
