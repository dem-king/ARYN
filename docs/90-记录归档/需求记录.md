## 2026-07-17 租户会员列表 SQL 歧义修复

### 问题

租户账号访问会员列表时，MyBatis-Plus 在 `user_info` 与 `member_level` 的联表条件中追加了未限定表名的 `tenant_id`，MySQL 因两张表均含该字段而报列名歧义。

### 结果

- `UserInfoMapper.selectAdminPage` 为 `member_level` 增加显式表别名，租户条件生成结果变为 `member_level.tenant_id`。
- 保留 `user_info.tenant_id` 与 `member_level.tenant_id` 双表租户隔离，没有使用 `@InterceptorIgnore` 绕过插件。
- 增加 Mapper 租户联表别名契约测试，防止后续移除别名导致回归。

### 验证

- 回归测试在修复前按预期失败，修复后定向测试 1 个通过。
- `mvn test -pl aryn-user/aryn-user-biz -am` 通过，`aryn-user-biz` 67 个测试通过。
- `mvn test -pl aryn-boot -am` 通过，38 个 Reactor 模块全部成功，Boot 租户测试 10 个通过。
- 本地 Boot 服务重启后，租户会员列表实际 SQL 使用 `member_level.tenant_id` 和 `user_info.tenant_id`，返回 2 条数据；页面无错误提示，浏览器控制台无 error。

## 2026-07-17 分销资金链路加固

### 需求

修复分销佣金、退款、结算、提现、分销员生命周期和三端契约隐患。佣金基数不含运费；提现采用线下打款确认，审核通过必须填写打款流水号。

### 结果

- 支付佣金改为待结算状态，到期后释放并优先抵扣佣金欠款；手工结算只按分销订单 ID 操作。
- 退款按退款号幂等累计回退一级、二级佣金，支持部分退款、退款先于支付和余额不足形成欠款。
- 支付/退款状态在事务内完整更新，成功 MQ 延迟到事务提交后发送；异常恢复为可重试，监听器和定时任务均清理租户上下文。
- 提现账号使用 AES-256-GCM 密文存储，API 返回脱敏 VO；通过审核强制记录流水号、时间和确认人。
- 提现流水保存失败会回滚审核；管理端提供当前租户历史明文账号的幂等批量重加密入口。
- 有未清资金、待审核提现、真实有效下级或可退款佣金订单的分销员禁止删除；安全删除使用行锁，迁移重算并在删除时回补邀请人数，邀请链禁止形成循环。
- 退款补偿按租户、退款记录和订单隔离异常，每条退款使用独立新事务，避免坏数据阻塞后续资金处理。
- 单租户启用配置由生成列唯一键兜底，避免并发启用产生多条有效配置。
- 管理端与 UniApp 补齐待结算、欠款、退款、结算周期和打款信息，提现备注完整落库，UniApp 两份列表使用独立显式分页状态。

### 部署要求

生产环境必须配置 `DISTRIBUTION_WITHDRAW_ACCOUNT_KEY`，值为 Base64 编码的 32 字节密钥，并纳入密钥管理与备份。存量库先执行对应的 `13distribution_financial_hardening.sql`，再由具有提现审核权限的管理员逐租户调用 `POST /distribution/withdraw/reencrypt-legacy-accounts`；接口每批 200 条、可重复执行，返回 `0` 表示该租户已无历史明文账号。

详细设计与验收见 [分销资金链路加固](../50-需求文档/2026-07-17-分销资金链路加固/README.md)。
