# 悦航购船供化完整改造实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将悦航购从普通商城改造成“海员个人购买 + 船供采购 + 公司司机港口/船舶配送”的两端系统，并完成商品主数据、船舶上下文、共享购物车、内部履约、营销扩展和司机小程序模式。

**Architecture:** 保留现有 Spring Boot 3、Vue 3、UniApp、MyBatis-Plus 和 Boot/Cloud 双模式。后端按商品、船舶、交易、履约、配送和营销边界扩展，先在 Boot 模式跑通模块化单体，再保持 API/Dubbo 边界以支持 Cloud 拆分。上线只建设两个端：同一 UniApp 小程序同时提供海员模式和司机模式，Web 管理端负责运营、商品、仓库、订单和调度。

**Tech Stack:** Spring Boot 3、Spring Cloud Alibaba、Dubbo、MyBatis-Plus、MySQL、Redis、RocketMQ/现有事件机制、Vue 3、Element Plus、TypeScript、UniApp、Pinia、Alova、Vitest、JUnit 5。

---

## 0. 执行规则

### 0.1 必须遵守的项目约束

- 后端修改同时适配 `aryn-boot` 单体和 Cloud 微服务。
- 前端 API 第一段必须是微服务域，Boot 模式统一使用 `parseOpenBoot`/`rewriteBootUrl`，页面禁止硬编码 `/boot`。
- 新增或修改数据库必须同时提供 `aryn-mall-java/db/boot/` 和 `aryn-mall-java/db/cloud/` 增量 SQL。
- 每个数据库脚本可重复执行，不使用 `DROP`、`TRUNCATE` 覆盖存量数据。
- Boot 增量脚本必须登记到 `db/boot/build-full-sql.mjs` 并重新生成 `aryn_boot_full.sql`，再运行校验脚本。
- 不同 Java biz 模块之间禁止直接 import，通过 `*-api`、Dubbo 或已有远程服务接口通信。
- 所有逻辑删除使用 `del_flag`，所有跨表写入使用事务。
- 先写失败测试，再实现最小行为；每个任务完成后运行聚焦验证。
- 每个任务完成一个中文 Git 提交，提交前不格式化无关文件。

### 0.2 上线范围

本计划只包含两个端：

| 端 | 角色 | 一期职责 |
|---|---|---|
| UniApp 微信小程序 | 海员、船供采购人、公司司机 | 个人购买、船供采购、共享购物车、订单、配送进度、扫码、拍照签收 |
| Web 管理端 | 运营、商品、仓库、调度、管理员 | 商品主数据、批量导入、船舶、订单、拣货、派车、异常和报表 |

不新建独立司机 App、司机 Web 端或第三个小程序。AI RFQ、多币种、ShipServ/MarineOnline 对接、供应商入驻、企业授信和无人机配送放在本计划最后的后续阶段，不阻塞一期上线。

### 0.3 需要业务负责人在开始编码前确认的默认值

没有确认时按右侧默认值开发，后续只允许通过配置或增量迁移调整：

| 决策 | 默认值 |
|---|---|
| 个人订单配送 | 必须选择船舶、港口和靠港计划，使用内部配送 |
| 船供订单支付 | 一期在线支付后进入配货；需要赊账时后续增加确认支付模式 |
| 首批试点 | 一个港口、一个仓库、一组司机 |
| 共享购物车 | 一期先完成普通个人/船供购物车，二期上线共享购物车 |
| 司机入口 | 同一小程序通过角色进入司机模式 |
| 短装 | 允许部分交付，记录缺货/短装原因并进入售后处理 |
| 普通快递 | 船供租户隐藏；其他零售租户保持兼容 |
| 营销 | 一期保留优惠券/折扣，二期增加船供阶梯价和整船优惠 |
