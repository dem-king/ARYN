# 商品管理安全与一致性加固设计

## 目标

修复商品管理审查确认的租户字段注入、退款库存重复恢复、价格汇总错误、库存并发覆盖、SKU 越权归属、权限缺失和多规格空数据问题，同时保持现有管理端交互和对外商品接口兼容。

## 设计原则

- 客户端只提交业务可编辑字段，租户、审计、销量和汇总字段由服务端控制。
- 商品与 SKU 的库存变化必须使用原子更新，管理端编辑不得覆盖并发订单产生的库存变化。
- RocketMQ 消费按稳定业务号持久化幂等，记录写入与库存恢复处于同一本地事务。
- 后端负责最终校验，前端校验只用于提前反馈。
- Boot 与 Cloud 同时维护基础初始化 SQL 和增量 SQL，不连接或修改实际数据库。

## 后端设计

### 商品写入边界

新增和编辑仍保持现有接口路径，但服务层不再直接持久化请求实体。新增时强制清空主键、租户、审计、逻辑删除、销量、汇总价格和汇总库存字段；编辑时先读取当前租户商品，再只复制允许修改的业务字段。

SKU 新增时由服务端生成主键并绑定当前 SPU。SKU 编辑时必须同时满足 ID、当前 SPU 和版本号匹配，禁止将其他商品 SKU 移入当前商品。所有更新、删除都检查受影响行数。

### 库存并发

SKU 查询补充 `version`。订单扣减和退款恢复在原子修改库存时同步执行 `version = version + 1`。后台商品编辑携带读取到的版本号并按版本更新；若库存已被订单或其他管理员修改，整个商品编辑事务回滚并提示刷新。

SPU 汇总库存不再用表单总数直接覆盖。服务端根据新增、修改、删除 SKU 的库存差值执行原子增减，使其能与订单扣减、退款恢复交换执行而不丢失更新。

### 退款幂等

新增 `product_refund_stock_record` 表，以 `(tenant_id, refund_no)` 建立唯一索引。退款监听器先校验消息，再 `INSERT IGNORE` 消费记录；重复消息直接返回。消费记录和 SKU/SPU 库存恢复在同一事务内，异常时整体回滚并允许消息重试。租户上下文在进入和退出时均清理。

### 校验与权限

后端统一校验 SKU 列表非空、价格和库存合法、规格组合不重复。修正 SPU 原价与成本价汇总。规格和规格值新增接口补齐对应权限；商品状态修改使用编辑权限，统计接口使用列表权限。

## 管理端设计

`form.vue` 继续负责商品表单编排，SKU 子组件继续负责规格组合编辑。新增纯 TypeScript 校验工具，负责多规格 SKU 完整性检查；提交前调用并给出明确提示。服务端库存冲突错误沿用公共请求层提示，不在页面静默覆盖。

## 数据库设计

- Cloud：修改 `8aryn_product.sql`，新增 `19product_refund_stock_idempotency.sql`。
- Boot：修改 `2aryn_boot.sql`，新增同编号增量 SQL，并重新生成 `aryn_boot_full.sql`。
- Boot 与 Cloud 租户表配置加入 `product_refund_stock_record`。

- `GoodsSkuServiceImplTest`：扣减和恢复同步递增版本。
- `ProductRefundListenerTest`：重复消息跳过、异常回滚路径、租户上下文清理和非法消息拒绝。
- Controller 权限反射测试：规格新增、规格值新增、商品状态和统计权限。
- 前端校验工具单元测试：空多规格、非法 SKU、重复规格组合和合法数据。
