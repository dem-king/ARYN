# 微信小程序 · 折叠屏适配程度调研

> 调研时间：2026-11-04 ｜ 范围：中国市场主流折叠屏形态 × 微信小程序（非原生 App）
> 口径说明：市场数据引自 IDC / Counterpoint 等第三方机构（经媒体转述），适配评级为本次调研的**主观评估**，非行业统计口径，详见文末「口径与置信度」。

## 一、一句话结论

**不高，属于「能跑、但不好用」的中等偏下水平。**

拆成三层看，越往「用得好」走，适配越差：

| 层次 | 现状 | 评级 |
| --- | --- | --- |
| L1 平台层：微信客户端 / 基础库 | 小程序能正常启动、不闪退，但折叠屏不是微信明确的适配场景，已知问题长期存在 | B- |
| L2 系统层：厂商分栏兜底 | 华为「平行视界」、荣耀大屏模式对小程序**不生效**，默认全屏拉伸，需用户手动切换 | C |
| L3 商家层：小程序自身布局 | 绝大多数只做了一套手机竖屏布局，展开后留白、整体放大、图片拉伸，几乎不利用多出来的屏幕面积 | D+ |

行业里的真实体感是：**「适配了」= 没崩、没黑屏；「没适配」= 展开后像被人横向拽了一把。** 真正针对折叠屏展开态重排版式的小程序，属于极少数。

## 二、为什么是这个结果：三个结构性原因

### 1）盘子太小，商家没有投入理由

- 2025 年中国折叠屏出货约 **1001 万台**，仅占中国智能手机大盘 **3.52%**（IDC 数据，虎嗅 / 电子工程专辑转述）。
- 2025 年全球折叠屏出货约 **2000–2060 万台**，占全球智能手机出货 **约 1.5%**。
- IDC 预计 **2026 年中国折叠屏市场容量 733 万台，同比下降 26.7%**；2026 上半年全球折叠屏出货同比下滑 21.6%。

对商家来说，这是「3% 的用户、1 套额外设计、还要覆盖 5 种形态」的生意，优先级自然排在最后。

### 2）微信官方没把折叠屏当成独立适配场景

微信《大屏适配指南》（2026-07-23 更新）明确只分三类设备：**小屏手机、中屏平板、大屏 PC**，折叠屏没有独立章节，只能借用「横竖屏旋转 + 媒体查询 + 弹性布局」的通用能力。

更关键的是官方对折叠屏问题的定性：

- 社区提问「折叠屏双屏进入小程序左右大量空白，不能占满屏幕」，微信技术运营回复：**「符合预期」**（2023-03）。
- 华为官方对「平行视界下淘宝 / 微信 / QQ 小程序全屏显示」的回复：**「平行视界与小程序当前实现设计如此」**。
- 荣耀官方对「大屏模式打开微信小程序默认全屏」的回复：**「This is the design of WeChat」**，要分栏得用户自己点右上角「在…中显示」。

也就是说，**小程序在折叠屏上默认不参与系统分栏、也不保证铺满**，这是设计取向，不是 bug。商家若要「好看」，只能自己在代码里做。

### 3）形态碎片化，单一 rpx 等比缩放必然失真

折叠屏不是一种屏幕，而是一族屏幕：

| 形态 | 展开后比例 | 对小程序的含义 |
| --- | --- | --- |
| 竖折（Flip / Pocket） | ≈ 21:9，接近直板 | 天然兼容，问题最少 |
| 横折（Fold / Magic V 类） | ≈ 1.1:1 方屏 | 宽度翻倍、高度不变，竖屏布局被横向拉空 |
| 阔折（Pura X / Pura X Max） | 16:10、√2:1，内外同比例 | 需要真正的版式重排，而非缩放 |
| 三折（Mate XT 类） | ≈ 10 英寸级，接近平板 | 需要平板级分栏，小程序几乎没有 |
| iOS 折叠（iPhone Duo） | 书本比例 | 微信客户端本身尚未适配，展开后大黑边 |

rpx 的本质是「按 750 设计稿等比缩放」，它假设屏幕只有「一种比例、一个宽度」。折叠屏把这个假设打破了：**同一台设备，合上是 390，展开是 700+，还可能被系统塞进一个 4xx 的窗口里。**

## 三、机型形态 × 适配现状

> 评级口径：A 优秀 / B 良好 / C 可用但未利用大屏 / D 明显影响使用。评级为本次调研评估。

| 形态 | 代表机型 | 小程序实际表现 | 适配难度 | 评级 |
| --- | --- | --- | --- | --- |
| 竖折 | 华为 Pura X、三星 Z Flip 系列、荣耀 Magic V Flip | 展开接近直板比例，布局基本不乱；外屏多数场景仍需展开使用 | 低 | B+ |
| 横折（展开竖用） | Mate X5 / X6、Z Fold 系列、Magic V 系列、Find N 系列 | 能看，但左右留白或整体放大，商品图与文字被拉宽，信息密度反而下降 | 中高 | C |
| 横折（展开横用） | 同上 | 最容易翻车：横屏白屏、上下大片空白、底部按钮丢失（社区多例复现） | 高 | D+ |
| 阔折 | Pura X（6.3" 16:10）、Pura X Max（7.7" √2:1） | 内外同比例减少了「展开重排」的跳变，但仍无双栏利用；系统级横屏支持只覆盖了少数 App | 中 | C+ |
| 三折 | Mate XT / XTs 系列 | 屏幕接近平板，却拿不到平板级分栏，页面被放大到「老年模式」 | 高 | D+ |
| iOS 折叠 | iPhone Duo（2026 新形态） | 微信本体尚未适配，展开后黑边（微信客服称「正积极推进适配」；QQ 9.3.77 已修复黑边） | 平台级 | D |
| 外屏 / 悬停半折 | Pura X 外屏、Z Flip 外屏 | 小程序通常需展开使用；半折悬停态无专门布局 | 中 | C- |

**适配重心的现实结论**：2026 年三季度中国折叠屏份额中华为约占 **74%**（三星 8.9%、小米 6%、vivo 5%、荣耀 3%）。所以「折叠屏适配」在中国市场，实质上等于「**华为横折 + 阔折适配**」。

## 四、八类典型失效模式（含技术根因）

| # | 现象 | 技术根因 | 触发条件 |
| --- | --- | --- | --- |
| 1 | 展开后左右 / 上下大量留白，页面「压扁」 | 微信默认不全屏显示；页面容器宽度被写死 | 任意横折展开态 |
| 2 | 字号、卡片、图标整体变大 | rpx 基准按冷启动时的 windowWidth 计算，折叠切换后不重算；开启 `resizable` 后双屏 rpx 更会异常放大 | 冷启动于大屏 / 展开切换 / 平板 |
| 3 | 图片拉伸、主体跑位、被前景遮挡 | 全屏背景用 `mode="widthFix"`（按宽等比算高），与 fixed 前景元素错位 | 展开态、窗口化兼容模式 |
| 4 | 大屏断点不生效，仍走手机布局 | 窗口化 / 兼容模式下 `windowWidth` 长期停在 4xx，`match-media` 大屏分支不命中 | 折叠屏窗口化、分屏 |
| 5 | 横屏页面白屏 / 方向锁失效 | `resizable:true` + `pageOrientation: landscape`，单屏进入时渲染异常 | 单屏进入横屏页 |
| 6 | 没有分栏，宽屏信息密度浪费 | 平行视界 / 大屏模式对小程序不生效，默认全屏 | 华为、荣耀折叠屏 |
| 7 | 内容压在折痕上、半折无布局 | 未为折痕区预留安全边距，未监听折叠状态变化 | 横折、悬停态 |
| 8 | 新形态直接黑边 | 微信客户端未适配该形态（如 iPhone Duo） | iOS 折叠新机 |

其中 **#2 和 #4 是最隐蔽的**：开发者以为写了 `@media (min-width: 600px)` 就适配了大屏，实际在折叠屏上这个断点可能永远不触发。

## 五、三方实测与行业观察（佐证）

- **2026-08 三星 Z Fold8 评测（40 款国行常用 App）**：美团系内屏横屏评级「差」，京东、淘宝「一般」，社交类仅外屏较好。评测原文：「适配了有时只代表界面没有 bug，不等于能利用好折叠屏多出来的面积。」
- **2026-11 定焦 / 36 氪 iPhone Duo 实测**：只有淘宝、小红书等个别 App 完成适配，大部分主流应用展开内屏后仍黑边、拉伸。
- **2026-09 / 2026-10 行业观察文章**：小程序在折叠屏展开态普遍出现布局错乱、按钮过小、图片拉伸；商家「基本未做展开态适配优化」。
- **少数派 VIVO X Fold 5 长测（2026-07）**：小程序层面出现过卡住、画面冻结等可靠性问题。

注意：这些是 **App 层面**的评测证据，小程序只会更差一档——因为小程序既没有原生 App 的独立适配资源，也拿不到系统的分栏能力。

## 六、对悦航购（uni-app 小程序）的行动建议

**核心判断：不做「折叠屏专属设计」，但必须做「展开不翻车」的低成本适配。** 这是投入产出比最高的区间，也是相对同行的差异点。

### P0 · 必做（约 0.5–1 人日，避免现网事故）

1. 全屏背景图统一改 `mode="aspectFill"` + 容器 `100vw/100vh`，禁用 `widthFix` 做全屏底图。
2. 宽度一律用 `100%` / flex / grid，禁止对容器写死 `px` 宽度；固定尺寸只用于图标、按钮最小热区。
3. 按钮、加购、支付等关键热区设最小尺寸（≥ 44px），避免展开后被「相对缩小」点不准。
4. 用 `wx.createMediaQueryObserver` 或 `match-media` 处理 ≥ 600px 宽度分支，并在 `onResize` 里重取 `windowWidth`（不要缓存首次值）。

### P1 · 值得做（约 1–2 人日，形成差异化）

1. **商详页**：展开态走两栏——左商品图 / 右价格、规格、加购；这是折叠屏用户最买账的场景。
2. **列表页**：左列表 + 右详情（或左侧筛选栏），把多出来的宽度变成效率，而不是留白。
3. **底部 TabBar**：宽屏下改为居中限宽或侧边栏，避免 5 个图标被拉成一条横线。
4. **折痕避让**：横向布局在中间预留 24px 安全区，别让按钮正好压在折痕上。

### P2 · 观察即可（暂不投入）

- 外屏卡片、半折悬停态布局、三折专属版式。
- 按机型出多套设计稿（宽度段会无限细分：420 / 440 / 460 / 480…，维护成本失控）。

### 上线前验证矩阵（4 状态 × 3 机型）

| 状态 | 关注点 |
| --- | --- |
| 合上（外屏） | 首屏是否完整、按钮是否可点、是否有横向裁切 |
| 展开竖屏 | 是否留白、rpx 是否被放大、图片是否变形 |
| 展开横屏 | 是否白屏、底部操作区是否丢失、是否无双栏 |
| 展开窗口化 | `windowWidth` 是否命中大屏断点、背景是否跑位 |

建议覆盖：华为 Mate X 系列（横折，份额最高）、华为 Pura X / X Max（阔折）、三星 Z Fold 系列（对照基准）；若用户群含 iPhone Duo，需单独确认微信客户端版本是否已适配。
