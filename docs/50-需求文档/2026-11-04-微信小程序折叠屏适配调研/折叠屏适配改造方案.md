# 悦航购小程序 · 折叠屏适配改造方案（P0 + P1）

> 版本：v1 · 2026-11-04 ｜ 范围：`aryn-mall-uniapp`（仅微信小程序端）
> 前置调研：《微信小程序折叠屏适配调研》（同目录），结论为「能跑但不好用」

## 一、目标与边界

**目标**：折叠屏展开后 ① 不再两侧留白、② 不再是「放大版手机」、③ 商详/分类/列表三个地标页用上大屏。

**不做**（本轮明确排除）：
- 全站 `rpx → px` 迁移（5388 处，回归面过大）
- 外屏卡片、半折悬停态、三折专属版式
- 按机型出多套设计稿
- 后端 / 多租户 / boot-cloud 双模式改动（本方案纯前端，与运行模式无关）

**受影响平台**：仅 `mp-weixin`。H5 与 App 用条件编译隔离，保持现状。

## 二、必须先对齐的技术判断

### 1. rpx 的数学决定了「展开即放大」

`rpx` 基准是「窗口宽度 = 750rpx」。同一台折叠屏：

| 状态 | 窗口宽 | 1rpx | 28rpx 正文 |
|---|---|---|---|
| 合上 | ≈390px | 0.52px | 14.6px |
| 展开 | ≈700px | 0.93px | 26px |

所以只要开启全宽，**所有 rpx 尺寸等比放大 1.8 倍**。这不是 bug，是 rpx 的定义。社区里说的「元素变大很多」就是这个现象。

推论：**宽屏版式不能用 rpx 拼**。rpx 做出来的两栏，每栏只有 350rpx 宽、却配 26px 字，一行放不下 12 个字，比单栏更难看。

### 2. 因此采用「宽屏 px 密度」策略

- 折叠态（< 600px）：`rpx` 原样不动 → **手机端像素级零变化**，回归风险最低。
- 展开态（≥ 600px）：新增一段 px 断点样式，把字号、间距、图片高度、列宽改成「平板密度」（13–14px 正文），实现真正的多栏。
- 断点用 CSS 媒体查询（微信官方《大屏适配指南》即推荐此法），不引入 JS 全局状态。

### 3. 开关在 app.json，不在页面

微信侧要「占满展开态窗口」必须 `app.json` 根级 `resizable: true`（否则官方行为就是手机宽度居中、两侧留白，且回复「符合预期」）。这是全站级开关，所以配一个构建期回滚开关。

## 四、分阶段实施

### P0 · 基础开关与兜底（0.5–1 人日）

1. **开大屏**：`manifest-factory.mjs` 加 `resizable`，默认 `true`，支持 `MP_RESIZABLE=false` 构建回滚。
2. **全局 token**：`App.vue` 加 `/* #ifdef MP-WEIXIN */ @media (min-width:600px){ page{ ... } } /* #endif */`，只放变量，不放业务样式。
3. **背景兜底**：`diy/index.vue` 的 `100% auto` 在宽屏段改 `cover`，避免背景图在宽高比变化时构图漂移。
4. **热区复核**：底部两条栏已 px 且限宽，只需在 700px 窗口下确认不拉伸、不被安全区顶起。
5. **折痕安全区**：定义 `--wide-gutter: 24px`，后续所有两栏间距引它。

P0 结束时手机端应**看不出任何变化**；展开态只是「铺满 + 放大」，为 P1 打底。

### P1 · 三个地标页（2–3 人日）

1. **商详首屏双栏**（主菜）
   - 左：图集（`width:46%`，高 `min(46vw, 420px)`，`position: sticky` 吸顶）；
   - 右：价格渐变条、标题、优惠、规格、服务、地址（字号 13–14px，间距 12–16px）；
   - 首屏以下（装修区、评价、详情、推荐流）保持全宽单栏，避免动到导航栏 tab 锚点。
2. **分类页**：rail 固定 96px（不随 rpx 放大），右侧 3 列；图标 28px。
3. **列表/瀑布**：3 列，卡片标题 13px、价格 15px，图片仍按正方形。
4. **H5 回归**：所有宽屏样式都在 `MP-WEIXIN` 条件编译内，H5 不应有任何 diff。

### P2 · 暂不做（记录备查）

首页装修楼层宽版、外屏卡片、悬停态、三折版式、SKU 弹窗宽屏重排。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| `resizable` 在部分机型偶发不生效（社区反馈需清后台） | 展开仍留白 | 真机先验；不生效即退化为现状，不产生新缺陷 |
| rpx/px 混排导致宽屏横向溢出 | 出现横向滚动 | 宽版容器强制 `width:100%; box-sizing:border-box`，子项全 px |
| 商详价格条依赖 `-top-10px` 与主图重叠，加包裹层后重叠失效 | 首屏视觉错位 | P1 第一步先只加空包裹层跑通视觉，再开双栏 |
| 基础库差异（3.x 之前 media query 行为不一致） | 断点不触发 | 后台设置最低基础库 3.0；不达标时按手机布局降级 |
| iPad / PC 端因 `resizable` 行为变化 | 桌面端体验变动 | 接受（商城主要跑手机）；必要时页面级 `pageOrientation: portrait` 锁向 |
| 回滚 | — | 构建 `MP_RESIZABLE=false`；宽屏样式整段删除即可，无数据/接口副作用 |

## 九、待你确认的两个决策点

1. **是否接受「展开态字号变大到平板密度」**：这是 rpx 架构下的必然结果，也是本方案的前提。若不接受，只能走全站 px 迁移（1–2 周），不在本轮。
2. **商详双栏是否要「左图右信息」而非「左列表右详情」式整页双栏**：本方案只做首屏双栏，首屏以下保持单栏，是为了不动导航栏的滚动锚点；整页双栏属于 P2。
