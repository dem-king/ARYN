# 商城装修实用增强版

## 1. 背景

当前商城装修已支持首页、微页面、管理端可视化编辑和 UniApp 动态渲染，并包含搜索框、轮播图、分类导航、优惠券等 11 类组件。现有实现仍偏向“组件排列与 JSON 保存”，缺少完整的草稿发布、版本回滚、高效编辑、模板复用和安全迁移能力。

本需求以“实用增强版”为目标，首期同时改造首页和微页面，服务通用零售场景。

## 2. 目标与非目标

### 2.1 目标

- 首页与微页面共用同一套编辑器、组件注册表和版本化 schema。
- 建立草稿、预览、直接发布、下线和版本回滚流程。
- 提供撤销、重做、复制、排序、模板和页面级设置等高频运营能力。
- 增加商品分组、商品排行、限时活动、倒计时、营销入口和店铺信息等通用零售组件。
- 保证旧版页面可读、可编辑、可渐进迁移，不因未知组件或失效数据造成白屏。

### 2.2 非目标

首期不建设自由画布、任意层叠、条件编排、审批流、个性化推荐算法和完整数据分析平台。页面仍使用稳定的移动端纵向单列布局。

## 3. 产品结构

### 3.1 页面管理

统一管理首页与微页面，支持：

- 新建、复制、编辑和删除。
- 保存草稿、预览、发布、下线和版本回滚。
- 查看线上版本、草稿修改时间和历史版本。
- 生成微页面访问链接和真机预览二维码。

### 3.2 统一装修编辑器

- 顶部工具栏：返回、页面名称、保存状态、撤销、重做、预览、保存草稿、发布。
- 左侧栏：“组件库”与“页面大纲”标签页，支持搜索、折叠分组和拖拽排序。
- 中间画布：375px 手机预览，支持选中、插入、移动和缩放。
- 右侧栏：组件的“内容、样式、高级”设置；未选中组件时展示页面设置。

### 3.3 编辑交互

- 点击组件追加到页面，拖拽时插入到指定位置。
- 选中组件后支持复制、上移、下移和删除。
- 属性修改实时更新预览，不在每次输入时请求后端。
- 连续输入合并为一次撤销记录，撤销栈保留最近 50 步。
- 定时自动保存草稿，并显示已保存、保存中和保存失败状态。
- 存在未保存修改时，离开页面必须二次确认。
- 发布前展示变更摘要和校验结果。

## 4. 页面与模板设置

### 4.1 页面级设置

- 页面名称、背景色和背景图。
- 导航栏标题、颜色和显示方式。
- 分享标题、分享描述和分享图片。
- 无数据和下拉刷新等基础页面行为。

### 4.2 模板

- 页面模板：首页基础模板、分类商城模板、活动承接页模板。
- 组件组合：轮播图与分类导航、标题与商品排行等常用区块。
- 使用模板时生成新的组件 ID，不与模板共享实例。
- 模板仅保存装修配置，不复制商品、优惠券等业务数据。

## 5. 组件体系

### 5.1 组件分组

| 分组 | 组件 |
|---|---|
| 页面基础 | 搜索框、标题、富文本、辅助空白、公告 |
| 导航广告 | 轮播图、图片广告、图文导航、分类导航、营销入口 |
| 商品经营 | 手选商品、商品分组、商品排行 |
| 营销活动 | 优惠券、限时活动、倒计时 |
| 店铺服务 | 店铺信息、客服入口 |

### 5.2 动态数据源

商品类组件统一支持：

- 手动选择：指定商品和展示顺序。
- 规则选择：按分类、品牌、标签和价格区间筛选。
- 自动排行：按销量、新品、价格或可解释的综合规则排序。

每个动态组件必须设置数据范围、排序、数量、无数据策略、失效数据策略和展示样式。商品价格、库存和活动状态不写入装修 JSON，由 C 端运行时读取。

### 5.3 结构化链接

链接统一保存为结构化对象，支持商品、分类、微页面、优惠券或活动、外部小程序页面、客服和自定义路径。

```json
{
  "type": "goods",
  "targetId": "goods-id",
  "path": "/sub-pages/product/goods-detail/index",
  "params": {}
}
```

## 6. 装修 Schema

### 6.1 v2 结构

```json
{
  "schemaVersion": 2,
  "page": {
    "backgroundColor": "#f5f5f5",
    "navigation": {},
    "share": {}
  },
  "components": [
    {
      "id": "component-id",
      "type": "goods-ranking",
      "version": 1,
      "props": {}
    }
  ]
}
```

### 6.2 约束

- `schemaVersion` 控制页面整体迁移，组件 `version` 控制单组件迁移。
- `props` 取代无类型的 `formData`，每种组件提供类型、默认值和校验规则。
- 组件注册表统一声明名称、图标、分组、默认值、编辑器、预览器和支持终端。
- 管理端与 UniApp 分别实现渲染器，但必须消费同一份 schema。
- 未知组件跳过并记录日志，不得中断整页渲染。

### 6.3 兼容迁移

读取旧 `{ components, formData }` 时通过适配器转为 v2；第一次保存后写入新结构。迁移期保留旧 JSON 备份和回退开关。

## 7. 草稿、发布与版本

### 7.1 数据模型

- `page_design`：页面身份、页面类型、草稿内容、草稿修订号、发布状态和当前发布版本。
- `page_design_version`：不可变的发布快照、版本号、schema 版本、发布人、发布时间和版本备注。

### 7.2 发布流程

1. 编辑器自动或手动保存草稿。
2. 预览时后端生成绑定租户、页面和草稿修订号的短期令牌。
3. 发布前校验 schema、链接、商品、素材和活动状态。
4. 事务内生成不可变版本并切换当前发布版本。
5. UniApp 只读取已发布版本，不读取草稿。
6. 回滚基于历史快照创建新的发布版本，不覆盖历史记录。

### 7.3 并发与容错

- 草稿保存携带 `draftRevision` 使用乐观锁，冲突时禁止静默覆盖。
- 发布失败不改变线上版本，草稿仍可继续编辑。
- 首页最多只有一个有效发布页面；微页面可独立发布和下线。
- 微页面下线前展示对它的引用位置。
- 页面结构使用发布版本缓存；发布事务提交后再清理缓存。

## 8. 权限、租户与审计

权限拆分为查看页面、编辑草稿、发布与下线、回滚版本、删除页面和管理模板。

所有页面、版本、模板、预览令牌和缓存键必须按 `tenant_id` 隔离。预览令牌必须设置短有效期。

审计日志记录操作人、操作时间、保存/发布/下线/回滚动作、变更前后版本号、页面信息以及失败摘要。

## 9. 组件运行状态

每个组件必须支持编辑占位、加载中、正常数据、空数据或失效四类状态。

- 管理端预览明确显示缺失配置和校验错误。
- UniApp 生产端按组件策略隐藏或降级，不展示运营提示文案。
- 业务数据接口短暂不可用时不中断其他组件渲染。

## 10. 验收与测试

### 10.1 验收标准

- 首页和微页面使用同一编辑器，可完成新建、复制、草稿保存、预览、发布、下线和回滚。
- 保存草稿不影响线上页面，发布失败不破坏当前线上版本。
- 撤销、重做、拖拽、复制及删除结果稳定，刷新后草稿一致。
- 现有 11 类组件和新增 6 类组件在管理端与 UniApp 中的字段和核心样式一致。
- 旧版 `formData` 页面可正常打开和渲染，迁移后内容、顺序与链接不丢失。
- 无效商品、失效活动、未知组件和接口失败不造成白屏。
- 不同租户无法访问彼此的草稿、预览链接、模板和历史版本。
- 长页面至少支持 50 个组件，编辑和 C 端滚动无明显卡顿。

### 10.2 测试分层

- Schema 测试：默认值、校验、v1 到 v2 迁移和未知字段兼容。
- 编辑器单测：命令栈、复制、排序、未保存检测和乐观锁冲突。
- 后端测试：草稿保存、事务发布、版本回滚、租户隔离和缓存失效。
- 跨端契约测试：相同 schema 在管理端和 UniApp 选择相同组件和字段。
- 视觉回归：微信小程序与 H5 覆盖常用模板、空状态和长页面。
- E2E：覆盖新建页面、编辑、发布和移动端读取的完整链路。

## 11. 上线策略

1. 先部署数据表升级、v1/v2 兼容读取和新发布接口，暂不切换编辑入口。
2. 验证现有页面后开放统一编辑器，保留旧 JSON 备份和回退开关。

旧页面按“读取时转换、保存时升级”的方式渐进迁移，不执行一次性全量重写。
