## 一、背景与现状诊断

订单详情是商家运营最高频的「读整单」页面，旧版是 2022 年风格的纵向堆叠：订单号/时间碎信息行、整条灰底信息带（配送/付款/买家）、左侧 20px 加粗状态文案 + 右侧 ElSteps、10 列 ElTable（12 行商品里「运费/优惠」整列为 0、「订购人」整列同值）、金额明细右侧浮排。可核实的 7 个问题：

| # | 问题 | 证据（HEAD 行号） |
|---|------|------------------|
| 1 | 状态区没有「下一步做什么」的行动指向，发货按钮埋在被 Grayscale 的信息带里 | `:295-417` |
| 2 | 10 列 ElTable 强制展示空列（`运费/优惠` 均为 0、`订购人` 12 行同值），信息密度高但有效信息少 | `:612-714` |
| 3 | 分类列纵向合并（`span-method`）在 9 个分类 12 行时形成大块空白，且行状态列每行重复 | `:115-120`、`:682-713` |
| 4 | 灰底信息带 + 白色内容 + 表格边框，三层容器底色互相打架，没有卡片层级 | `:909-947` |
| 5 | 金额明细是右对齐漂浮文本，和商品清单、支付信息分离，读不出「商品总价+运费-优惠=实收」的账 | `:948-1000` |
| 6 | 公司配送（到船）只显示船名/港口，`deliveryTask`（配送员、派单/取货/送达/签收时间）完全不展示，商家看不到履约进度 | `:264-273` |
| 7 | 深色模式依赖 `--el-*` 基本可跟随，但表格 + 灰底的层级在暗色下更糊；1280 视口表格需内部横向滚动约 132px（UI 统一文档 §六 已记录） | UI 统一 README §六 |

## 二、目标与非目标

**目标**：让商家打开详情后 5 秒内回答 6 个问题 —— 这单什么状态？该我做什么？买了什么？钱怎么算？发给谁/送到哪？走到哪一步了。视觉对齐仓库既有设计令牌（Element Plus 语义变量 + `PageSection` + `.hx-*` + `--radius`），支持深色模式与 1280/1024 窄屏。

**非目标（明确不做）**：
- 不改接口、不改数据库、不改权限码、不改操作流程（发货/提货/来源共享购物车入口的行为完全保留）。
- 不新增业务动作（货到付款「确认收款」本页仍不提供，见 §七 后续建议）。
- 不引入新 UI 库/新字体/新图标体系（继续 Element Plus + `@element-plus/icons-vue`）。
- 不做移动端适配（管理端桌面场景，最小验证到 1024px）。

## 三、信息架构（新）

```
页头（sticky）: 订单号 20px + 复制 + 场景 chip + 共享购物车入口   [主 CTA] │ [买家：头像/昵称/手机号]
状态卡: 色块图标 + headline + 状态胶囊（+货到付款「待确认收款」胶囊）   4 步流程条（每步带时间）
主栏（minmax(0,1fr)）                     侧栏（sticky 悬浮常驻，380px / 1280 视口 340px）
├ 商品清单（分类分组卡片行）                ├ 金额汇总（小票式回执 + 付款方式/时间/凭证）
├ 物流信息（快递单 + 轨迹时间线）            ├ 配送信息（方式/收货人/电话/地址/船舶/泊位/时段/代办人）
└ 配送进度（公司配送任务里程碑）             └ 订单备注（仅当有备注）
```

- **主栏放「需要阅读与操作的业务实体」，侧栏放「金额 + 只读上下文」**（Shopify/Stripe 范式）。
- 流程条与页头都在顶部，滚动时页头吸顶，主 CTA 常驻视野。
- **右栏悬浮常驻（2026-11-03 追加）**：商品多、主栏很长时，侧栏 `position: sticky` 跟随滚动停留在页头下方，避免往下滚动后右栏整块留白；侧栏 `max-height` 按视口/页头高度推导，常见视口（≥900 高）三张卡一屏放下、无内部滚动，仅在超矮视口才在栏内滚动。
- **买家信息上移到页头右侧（2026-11-03 追加）**：买家从侧栏移到「订单号那一栏」最右侧（头像+昵称+手机号，主 CTA 左侧），右栏只剩金额/配送/备注，正好一屏放完、无需滚动。
- `<1199px` 单栏（侧栏落到主栏之后、取消悬浮）；`<1100px` 状态卡纵向；`<900px` 页头纵向、买家与主 CTA 右对齐换行。

## 四、关键设计决策

1. **弃 10 列 ElTable，改「分类分组卡片行」**：复用 `category-group.ts#groupOrderItems()`（分类拼音序、未分类固定最后、组内保持共享采购按人拆行的原始顺序），删除 `buildGroupedDisplayItems` + `span-method`。行内字段**按数据条件渲染**：运费/行优惠仅 >0、成员备注仅有值、**行状态仅在「与整单主流 item.status 不一致」时显示**（售后 3 / 退款 6 / 部分商品差异才会出现，整单 12 行「已完成」不再刷屏）。
2. **订购人不再逐行重复**：整单只有 1 个订购人时在「商品清单」区头显示一次（`52 件商品 · 9 个分类 · 订购人 微信用户1600`），多订购人（共享采购按人拆行）才逐行 chip，避免旧版「整列同值」与新版「每行 chip」两种噪音。
3. **金额回执按小票顺序重排**：商品总价 → 运费 → 优惠券/会员优惠/积分抵扣/营销优惠（**仅 >0 才展示**，营销优惠下钻 promotionSnapshots）→ 合计。合计标签按口径推导：关闭单=订单金额、货到付款未确认=应收金额、线上未支付=应付金额、已收款=实收金额；`actualPayPrice < paymentPrice`（线下让价）时单独回显应收行。该顺序与后端 `OrderPriceComputeService` 口径一致（`paymentPrice = totalPrice - memberDiscount - coupon - promo + freight`，积分在 `allocatePointsDeduct` 摊入），旧版未把营销优惠放进账本导致对不上账的问题一并修正。
4. **流程条改为手写 stepper**：4 步 + 每步时间（下单/发货/收货/完成），`stepActive` 沿用旧版口径（`status=7→1`，其余 `status-1`）；状态 5/6/11 不套正常流程（退款/关闭/未知状态硬套「交易完成」会误导）。
5. **新增「配送进度」卡片（只读，零新接口）**：公司配送（deliveryWay 3/4）时展示 `orderInfo.deliveryTask` 的配送员/任务号/派单→取货→出发→送达→签收里程碑（时间均来自现有详情接口），与发货抽屉、配送任务页状态文案同口径；快递（way 1）则展示 `orderDelivery` 包裹信息 + 物流轨迹时间线。
6. **状态语义**：hero 图标/胶囊走 `--el-color-{success|warning|danger|primary|info}`；货到付款未收款是独立覆盖态（headline 交易完成 + 灰色「已完成」胶囊 + 警告色「待确认收款」胶囊 + 合计标「应收金额」），不新增 status。
7. **视觉令牌**：卡片 12px 圆角 + `1px --el-border-color-lighter`、无阴影；间距 4/8/12/16/24；字号 12/13/14/15/16（headline 18）/20（订单号，全页唯一）/24（合计金额）；金额 `font-variant-numeric: tabular-nums` 右对齐；**零硬编码色值**，全部 `var(--el-*)` / `var(--radius)`，深色模式自动跟随。
8. **可访问性/交互**：复制订单号（`vue-clipboard3` + `aria-label`）、focus-visible 2px 焦点环、商品图 `error` 兜底图标、空态「订单不存在或已被删除」、`prefers-reduced-motion` 关闭过渡；全页仅 1 个 `type="primary"` 主 CTA。

## 七、边界与后续建议

1. **货到付款「确认收款」主 CTA 未在本页提供**：列表页 `canConfirmPay` + 确认收款弹窗（实收金额 + 付款凭证）已存在，详情页状态卡只提示「待确认收款」。建议后续抽公共组件 `pay-confirm-dialog` 同时接入列表与详情，避免复制 170 行逻辑。
2. **操作记录/审计时间线**：抖店/Shopify 均把操作时间线作为商家后台刚需；当前接口只返回订单各阶段时间，无操作日志接口，暂由状态卡流程条 + 配送进度承担，后续接订单日志接口再补。
3. **物流信息卡**需要 `orderDelivery` 数据，本地无样本，待有快递发货数据后回归。
4. **外链图片**（cloudflare tunnel）在并发/慢网下会出现短暂空白，已加 `ElImage #error` 图标兜底；生产应走 OSS/CDN。
5. 旧版 1280 视口表格内部横向滚动的限制随「弃表格」消失；1280 双栏下主栏约 636px，若后续再压到 1100 以下会转单栏。
