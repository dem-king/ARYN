## 0. 结论摘要（TL;DR）

小象超市（原美团买菜）的设计本质是 **"即时零售效率优先"**：位置与时效前置、商品浏览即加购、订单全链路可视化、模块化卡片低学习成本，视觉上用品牌绿 + IP + 定制字体建立识别度。

当前 Aryn Mall 移动端**功能完整度高（DIY 装修、分类改版、快捷加购、船供/共享购物车等已在迭代）**，但存在三类核心差距：

| # | 差距 | 影响 |
|---|------|------|
| 1 | **无统一设计体系**：主题色散落（tabBar 红 #FF2237 / 价格红 #ff2e4d / 结算渐变橙红 / 勾选绿 #07c160 / uni.scss 仍是默认蓝 #007aff） | 界面观感杂乱，品牌识别弱 |
| 2 | **浏览→加购链路长**：商品流以卡片跳详情为主，缺少"瀑布流内一键加购、SKU 弹层直选"的即时零售模式 | 转化损耗，SKU 多时体验差 |
| 3 | **场景化与信任感表达不足**：首页 DIY 楼层偏通用电商；搜索仅关键词；订单履约无可视化节点；个人中心偏功能列表 | 复购与黏性弱 |

**建议整体策略**：以"即时零售效率 + 品牌感"为双目标，分三期推进 ——
- **Phase 1（P0，2~3 周）**：建立设计 Token 与品牌视觉，重构首页（船舶/靠港前置 + 金刚区 + 瀑布流直加购 + 骨架屏），升级搜索。
- **Phase 2（P1，2~3 周）**：商品浏览链路（列表虚拟化、详情首屏重构、快捷加购全链路）、购物车凑单与结算优化。
- **Phase 3（P2，2~3 周）**：订单履约可视化、个人中心/会员价值化、常购清单、动效与暗色模式完善。

## 1. 调研：小象超市的设计体系

> 说明：小象超市的小程序与 APP 共享同一套美团自营零售设计语言（品牌、组件、交互规范一致），以下分析以其通用设计体系为准。

### 1.1 品牌与视觉语言

- **品牌色**：绿色小象为核心识别元素。2023-12 由"美团买菜"升级为"小象超市"时 LOGO 重构——保留绿色小象，采用圆形与网格绘图法，小象昂首挺胸、鼻子翘起，形象从"菜篮子"（低头）变为"鲜活进取"。
- **字体**：启用美团定制字体（美团体），统一标题/正文层级，跨页面一致性高。
- **IP 化**：小象 IP 贯穿启动页、弹窗、活动 KV、空态/缺省图，情感化强。
- **界面风格**：模块化卡片设计 + 低饱和辅助色 + 统一圆角，首页聚合"限时闪购 / 今日鲜达 / 家庭囤货清单"等**场景化入口**，而非纯类目堆砌。

### 1.2 信息架构

APP 底部 5 个 Tab：**首页 / 分类 / 菜谱 / 购物车 / 我的**（小程序端按场景裁剪）。围绕"浏览—下单—履约—复购"闭环：

| Tab | 核心设计 |
|-----|---------|
| 首页 | 功能区（配送地址 + 搜索 + 消息）→ 活动区（红包/特价）→ 分类区（按购买频次挑 10 个）→ 商品瀑布流（支持直接加购）。**配送地址放首页显眼位置**，因为前置仓模式下商品/库存与位置强相关 |
| 分类 | 上半部分类目，下半部分排行榜；或两级侧边栏 + 商品流（每日优鲜/盒马式） |
| 菜谱 | 瀑布流菜谱，菜谱→食材一键购，服务"买什么/怎么做"（APP 端） |
| 购物车 | 合并结算、缺货自动标红、配送方式（30 分钟达 / 自提 / 预约时段） |
| 我的 | 会员信息、订单、财务（余额/积分）、售后 |

### 1.3 核心页面交互细节

- **首页金刚区**：宫格入口（占屏 22%~25%），按经营目标灵活调整；入口承载"秒杀、领券、签到、常购清单"等高价值功能。
- **场景化导航**：用"早餐速配 / 宝宝辅食 / 加班夜宵"等场景标签替代传统类目树，用户无需层层点击即可直达组合套装（提升客单价）。
- **搜索**：语义理解引擎——模糊词联想、错别字容错、同义词扩展；输入"苹"联想"苹果/苹果醋/苹果汁"，输入"苹果"联动红富士、嘎啦果、蛇果及规格选项。
- **商品卡**：瀑布流双列 + 价格/规格/加购按钮同卡呈现，**浏览即加购**；SKU 多时列表页做虚拟列表 + 图片预加载，保障秒开。
- **购物车**：合并结算、实时库存校验（缺货标红）、优惠叠加（新人券/满减/会员折扣/积分）、一键复购、常购清单。
- **订单履约**：全链路可视化节点——已接单 → 拣货中 → 打包完成 → 骑手已取货 → 配送中 → 已送达；加配送时效与预计送达。
- **会员**：会员专享折扣、免配送费券、积分兑换、生日优惠，并与美团积分/蜂蜜值生态互通。

### 1.4 业务模型对体验的塑造（理解"为什么这么做"）

小象超市 = **前置仓 + 30 分钟达 + 24 小时 + 美团生态**。所有 UI 决策都服务这个模型：
- 位置前置 → 用户第一眼确认"能不能送、多久到"；
- 浏览即加购 → 高频低价品类，路径越短转化越高；
- 履约可视化 → 缓解等待焦虑、建立信任；
- 场景化/菜谱/会员 → 从"应急买"转向"日常囤"，提高复购。
- 行业对比：朴朴做"社区便民"（长辈模式、区域深耕）、叮咚做"品质场景"（菜谱+会员日活）、小象做"生态协同"（跨界、24h、账号互通）。

## 2. 现状诊断：Aryn Mall 移动端

> 依据：`aryn-mall-uniapp` 源码（pages.json / home / category / shopping-cart / user-center / sub-pages / components/diy）逐页核查。

### 2.1 架构与已具备的能力（保留并强化）

- **4 Tab**：首页 / 分类 / 购物车 / 我的，结构合理，不盲目增加 Tab。
- **DIY 装修首页**：diy-* 组件体系完整（轮播、金刚区、商品组、瀑布流、优惠券、倒计时、公告、搜索栏、会员权益、分类导航、排行榜、服务承诺、限时活动、拼团、视频直播等），运营可配，是长期资产。
- **分类页已按小象模式改版**：一级图标横滑条 + 二级侧栏 + 右侧商品流（筛选关系），并支持"全部分类"浮层 —— 方向正确，保留。
- **购物车基础扎实**：管理/编辑模式、圆形勾选、缺货标红、库存提示、SKU 弹层、分组（防串船）、共享购物车入口、为你推荐。
- **特色业务**：船供采购、船舶绑定、共享购物车（同船成员合并采购）、配送员工作台 —— 差异化能力，优化时不可牺牲。

### 2.2 视觉诊断（问题清单）

| 问题 | 位置 | 严重度 |
|------|------|:---:|
| 主题色不统一：tabBar #FF2237、价格 #ff2e4d、结算按钮渐变 #ff8a00→#ff4d2e、勾选 #07c160、uni.scss 默认主色仍是 #007aff | 全局 | P0 |
| 无设计 Token 体系，颜色/圆角/间距散落各页面 | 全局 | P0 |
| 背景 #F8F8F8 与卡片白对比生硬，无品牌氛围色 | 全局 | P1 |
| 无品牌 LOGO / IP / 定制字体，启动页与空态缺情感化 | 全局 | P1 |
| 深色模式仅部分样式支持（wot-theme-dark） | 全局 | P2 |

### 2.3 交互诊断（差距）

| 场景 | 现状 | 与小象差距 |
|------|------|-----------|
| 首页 | DIY 楼层，默认缺"位置/交付状态条"；金刚区可配但无"场景化入口"心智 | 位置与交付信息未前置，信任感弱 |
| 商品浏览 | 商品卡 → 跳详情 → SKU 弹层 → 加购（瀑布流卡片无直接加购按钮） | 路径长 2~3 步，SKU 多时转化损耗 |
| 搜索 | 关键词匹配，无联想/容错/规格联动/热搜 | 效率低 |
| 购物车 | 有管理/缺货标红/分组，缺"满减凑单进度、常购再买、优惠叠加明细" | 客单价抓手不足 |
| 订单 | 订单列表/详情/物流为传统文字节点 | 无履约可视化，等待焦虑 |
| 我的 | 功能列表式（订单5宫格+服务列表），无会员价值感 | 黏性弱 |
| 复购 | 无"一键复购 / 常购清单"入口（有 frequent 页但入口不明显） | 复购弱 |

### 2.4 性能诊断

- 首页由 DIY 装修数据驱动，需验证首屏链路（请求 → 解析 → 渲染骨架）是否秒开；无骨架屏（现为"加载中…"文字）。
- 商品流组件（waterfall-goods / diy-goods-group）需确认是否已做图片懒加载与虚拟列表（小象专项做过懒加载/虚拟列表/图片预加载以提秒开率）。
- 分包结构合理（sub-pages），但需核查主包体积与图片资源体积治理。

## 3. 优化方案

### 3.0 P0 · 设计系统（所有改版的地基）

**目标**：一套 Token 管全部颜色/字体/圆角/间距，品牌可识别。

1. **建立设计 Token（CSS 变量 + SCSS）**，在 `uni.scss` 与全局样式中落地，页面内禁止散落色值：
   - 品牌主色（建议按"悦航购"品牌调性定夺：如深航海蓝 #0B6EF2 系，或保留电商活力橙红系；**需产品确认品牌色板**，当前建议主色 + 辅助色 + 功能色 3 组，含 8 级浅深梯度）；
   - 中性色（文字 333/666/999、边框、禁用）；
   - 功能色（成功/警告/错误/链接）；
   - 圆角（sm/base/lg/卡片）、间距（4/8/12/16/24rpx 阶梯）、字号（12/14/16/20/24px 阶梯）、阴影（卡片/弹层/悬浮）。
2. **品牌视觉基础包**：LOGO 规范、启动页/开屏、TabBar 图标重绘（线性→选中态填充）、空态插画、错误/加载占位。
3. **组件库主题化**：本项目基于 Wot Design Uni（wd-*），统一在 `uni.scss` 注入 `$wot-*` 主题变量，全局生效，避免逐页 patch。
4. **验收**：`rg '#[0-9a-fA-F]{3,6}' src --glob '*.vue' --glob '*.scss'` 检查散落色值清零（白/黑/透明除外）。

### 3.1 P1 · 首页重构（效率 + 场景化）

**目标**：让首页在 3 秒内回答用户三个问题——"能不能送、怎么买划算、买什么"。

| 模块 | 动作 | 对标点 |
|------|------|--------|
| 状态条（新增） | 首页顶部固定条：当前位置 + 切换入口（船供场景展示「当前船舶/靠港 + 交付时间窗」）。**不展示时效承诺**（2026-09-22 决策） | 小象地址前置 |
| 搜索栏升级 | 占位热词轮播、点击进搜索页（联想/热搜/历史）、搜索栏右侧消息角标 | 小象语义搜索 |
| 金刚区 | 8 宫格规范化：秒杀、领券中心、每日签到、常购清单、限时折扣、拼团、船供专区（租户能力开关）、客服 | 小象金刚区 |
| 场景化楼层（新增 diy 组件） | "早餐计划 / 船上补给包 / 家庭囤货"等场景套装入口，运营后台可配 | 小象场景化导航 |
| 楼层重构 | 限时秒杀（倒计时 + 进度条）→ 常购清单（历史高频）→ 今日爆款瀑布流 | 小象"限时闪购/今日鲜达/家庭囤货清单" |
| 瀑布流商品卡 | **卡片内置加购按钮**（有规格弹 SKU 弹层，无规格直接加购），价格/促销标同卡展示 | 小象浏览即加购 |
| 骨架屏 | DIY 数据返回前显示骨架屏（楼层级），替代"加载中…"文字；请求失败给重试态 | 小象秒开 |

> **B 版原型的增量（本文尚未纳入）**：首页把「今日补给单」卡放在金刚区之上，并在底部加常驻操作条（全选 / 已选 N 项 / 批量加购 / 去核对），商品卡增加规格 chip 与勾选方块；金刚区把「秒杀」换成「我的补给单」；分类页改为**左侧一级 rail（含"船供"）+ 右侧二级 chips**。详见 [可行性分析](可行性分析.md) §10。

### 3.2 P1 · 商品浏览链路（缩短加购路径）

1. **分类页（已有基础，继续强化）**：
   - 一级图标条支持"长按/右键管理排序"（运营侧）；
   - 右侧商品流卡片**同步瀑布流直加购能力**（复用商品卡组件）；
   - 增加"筛选/排序"轻浮层（价格、销量、新品）。
2. **商品列表/搜索页**：虚拟列表 + 图片懒加载 + 骨架卡；搜索页加入：热门搜索词、历史记录、联想词（前端词表 + 接口兜底）、规格直达。
3. **商品详情首屏重构**：
   - 首屏信息层级：价格区（现价+划线价+促销标）→ 规格选择（默认展开常用规格）→ 加购/立即购买悬浮条 → 服务承诺（售后/船供配送；不列时效承诺）；
   - 图片走"首屏图 + 详情长图懒加载"；
   - 评价楼层默认展开前 2 条；
   - 可选：底部"同船成员都在买 / 经常一起买"推荐（对标小象社区热销/关联推荐，且贴合船供场景）。
4. **SKU 弹层**：统一 `vk-data-goods-sku-popup` 视觉（品牌圆角、库存/售罄态、阶梯价展示），购物车/详情/瀑布流三处复用。

### 3.3 P1 · 购物车与结算（提客单）

1. **凑单与满减**：底部结算条上方加"满 99 减 20，再买 ¥23 立减"进度条（金额/进度由优惠券接口驱动）；满减/免配送门槛可视化。
2. **常购再买**：购物车顶部"常购清单"横滑条，一键补货。
3. **优惠叠加明细**：结算页展示优惠明细（商品优惠 / 优惠券 / 会员折扣 / 积分抵扣），缺货行标红置灰（已有，保留强化）。
4. **结算页优化**：配送方式（船供：按靠港计划；零售：送达时段）可视化选择；AddressSelector / CouponSelector 弹层视觉统一。
5. **收银台**：支付倒计时（30 分钟）、支付结果页成功态动效（不展示预计送达时间，2026-09-22 决策）。

### 3.4 P2 · 订单履约可视化（信任感）

1. **订单列表/详情**：履约节点可视化（已接单 → 拣货中 → 打包完成 → 配送中 → 已送达），当前节点高亮、历史节点完成态，未来节点置灰。（**不承诺预计时间**，2026-09-22 决策）
2. **船供专属节点**：增加"靠港计划 / 装卸货 / 交接确认"节点（对接 delivery 工作台状态），这是相对小象的差异化表达。
3. **物流页**：H5 端可接地图（若接入三方地图 SDK），小程序端保持节点 + 时间轴（小程序地图受限，不做伪地图）。

### 3.5 P2 · 个人中心与会员（黏性）

1. **我的页头部**：会员卡（等级 + 积分/余额/优惠券三宫格）替代纯文字欢迎语；登录态/未登录态双设计。
2. **订单区**：保留 5 宫格（待付款/待发货/待收货/待评价/退款售后）+ 全部订单入口，加"待收货/待评价"红点。
3. **服务列表分组**：账户（地址/安全/设置）、交易（收藏/足迹/评价/优惠券）、增值（会员中心/分销/消息/客服）。
4. **常购清单**：入口前置到首页金刚区 + 我的页，支持一键加购（frequent 页已有，补入口与视觉）。
5. **会员中心**：等级权益可视化（进度条）、签到日历（已有 sign-in 页，统一视觉）、积分/余额明细卡。

### 3.6 P1 · 性能基线（秒开）

- 首页：DIY 数据与商品流接口并行、缓存上次页面（`uni.setStorage` + 版本号），骨架屏过渡；评估 `diy-goods-group/waterfall` 虚拟列表化。
- 图片：统一走 CDN 尺寸参数（缩略图/详情图分级）；列表图 `lazy-load`。
- 分包与主包体积治理：静态资源（tabbar 图标、wd-icons）体积检查；首屏 JS/CSS 拆分。
- 小程序启动：`onLaunch` 轻量化（避免同步阻塞）；分包预加载配置。

### 3.7 P2 · 动效与情感化

- 加购飞入购物车动画（列表 → 底部 Tab 角标）、倒计时秒杀组件动效、页面转场统一（已有 pop-in）。
- 空态/错误态统一插画（购物车空、订单空、网络错误、加载失败重试）。
- 暗色模式：以 `wot-theme-dark` 为基础全页面过一遍，补充 DIY 楼层暗色样式。

## 5. 验收标准

1. **视觉一致性**：设计 Token 覆盖率 100%，源码散落色值清零（§3.0 检查命令通过）。
2. **加购效率**：无规格商品瀑布流卡内一键加购；有规格商品 ≤2 次点击完成加购。
3. **首页性能**：首屏可交互 ≤ 1.5s（H5 参考），骨架屏兜底，无白屏/文字加载。
4. **搜索**：联想词命中率、热搜/历史展示、错别字容错（如"慌果"→"黄瓜"类词表测试）。
5. **兼容**：boot/cloud 双模式请求路径正确；H5 与微信小程序双端表现一致（验证 `rewriteBootUrl` 输出与小程序真机预览）。
6. **回归**：船供（船舶绑定/靠港/共享购物车）与配送工作台功能不受改版影响；增量 SQL 无新增数据库改动（本方案纯前端）。
