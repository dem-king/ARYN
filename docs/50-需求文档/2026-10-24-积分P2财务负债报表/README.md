# 积分 P2 收尾：财务负债报表（递延口径）

> 日期：2026-10-24 ｜ 依据：`docs/积分方案调研-竞品对标.md` 第 5 节 P2 项（#8）
> 范围：user 域读侧聚合 + 管理后台（零 DDL，无 C 端改动）

## 1. 背景与取舍

- **#8 财务递延与计提**：落地为「积分负债报表」——发放确认负债（面值折算）、抵现/兑券消耗结转营销费用、过期核销转销的三段对账口径，按日拆解并可查全量累计与期末负债。预计消耗率（行业常见 85%-95%）**不做硬编码折现**，报表按面值口径展示，由财务按自身口径表外调整。
- **#9 付费会员联动**：不做。依赖付费会员产品体系（月/季/年卡购买与续期链路），系统尚无此基础设施，属产品决策；已有权益体系（类型 5 等级抵扣上限）已为将来联动留好挂点。
- **#10 游戏化任务矩阵**：依调研结论明确不做（海员低活场景不符、成本高、依赖 DAU）。

## 2. 实现（零 DDL）

- **读侧聚合**：`points_record` 按日 GROUP BY 拆解六列——新发放 / 退款返还 / 抵现 / 兑券 / 过期核销 / 后台扣减；单行全量累计查询；期末负债 = `user_info` 全体 `SUM(point)`（租户拦截器自动过滤）。全部为注解 SQL，无新表无增量脚本。
- **金额折算**：按抵现汇率（`ORDER_DEDUCT` 启用规则 pointValue，新 `getPointsPerYuan()`）面值折算；汇率未配置时金额列为 null 不折算。发放服务与账本服务存在构造依赖环，报表侧用字段注入打破（`@Autowired` 非 final）。
- **接口**：`GET /pointsconfig/liability-report?beginDate&endDate`（yyyy-MM-dd 可选，复用 `user:pointsconfig:page` 权限，零菜单 SQL）。
- **管理端**：积分配置页第 5 个 Tab「负债报表」——日期筛选（默认近 30 天）、六张汇总卡（期末负债/累计发放/累计消耗结转/累计过期核销/区间发放/区间消耗）、日报表（含各列折算金额列）与口径说明脚注。

## 3. 验证

- `mvn clean test -pl aryn-boot -am` 全量绿（新增报表组装 2 用例：按率折算与合计、汇率缺失不折算）。
- web-ele `check:type / test:unit(879) / lint` 绿。

## 4. 边界

- 报表为读侧实时聚合，`points_record` 单租户体量下性能足够；若日后流水过千万级再考虑物化日报表（`stat_daily` 模式）。
- 未做「供应商联营结算单列计提」——系统无供应商分成账单（自营 SaaS 口径，与调研 §2.7 一致）。
