## 1. 已确认决策（2026-11-12）

1. **首单按档位**：满 ¥1000 减 ¥100、满 ¥3000 减 ¥400、满 ¥5000 减 ¥800，单笔封顶 ¥800，可配置（2026-11-13 修订，以 228/240 种子为准）。
2. **企业首单按工厂一次**：按 `buyer_org` 算，不按餐厅重复算。
3. **新建工厂由运营后台审核**：用户自助提交创建/加入申请，运营后台审核。
4. **待审核工厂允许下企业单**：可下单，不享首单；审核通过后才享。

配套默认：

- 加入已有工厂：邀请码/分享卡免审，搜索申请需厂长或运营审。
- 已支付即消耗首单；全额退款不恢复。
- 船供首单按船一次，不按采购员账号。
- 个人新人资格只看 `purchaseScene=1` 的个人已支付单。
- 历史岸上车不强制迁移，显示「主体未绑定」，不参与首单。
- 建议加 `buyerOrgEnabled` 租户能力开关，用于灰度和回滚。

## 5. 关键约束

- **双模式**：所有 DB 改动 boot/cloud 各一份；Controller 路径首段用微服务域，不硬编码 `/boot`。
- **租户隔离**：所有查询带 `tenant_id`；主体只能在同一租户内可见/可绑。
- **不能信任客户端**：`buyerOrgId`、`buyerOrgName` 创建时校验，提交订单时服务端覆盖名称；客户端传的名称不可信。
- **历史数据**：岸上车 `buyer_org_id` 为 NULL 时允许查看/提交，但不享首单；新单必须选主体。
- **索引改造**：`shared_cart` 唯一索引必须先删旧索引/旧生成列，再加新生成列/新索引；生产低峰执行。
- **不提前发首单活动**：P0 只跑 227；228 要等 P1 引擎发布。
- **不碰用户未提交文件**：`222`、`233`、`verify-full-sql.mjs` 既有改动保留。
