# 新人首单双轨与采购主体改造计划

> 日期：2026-11-12  
> 状态：P0/P1/P2 已实施；2026-11-13 审查修复完成并通过真实登录态 HTTP 全链路 E2E（企业/船供首单按主体只享一次、待审核支付不烧首单、业务员可提交/普通船员被拒、个人资格互不影响；MQ 模拟支付，下游真实链路）。H5 实机截图待补（前端本次未改动）。  
> 2026-11-13 审查修复：船供提交权限统一为 `can_confirm` 列（发起人/确认人/业务员默认具备）；企业首单只消耗「下单时主体已审核通过」的已支付单（订单落审核状态快照）；首单活动种子改为默认草稿由运营发布；cloud 租户白名单补 buyer_org/freight_rule。详见 [05-实施拆分与验收清单](05-实施拆分与验收清单.md) §10。  
> 关联需求：[新人专享页优化调研](../2026-11-12-新人专享页优化调研/README.md)  
> 影响端：移动端小程序、后端 `aryn-order` / `aryn-promotion` / `aryn-vessel`、管理后台、数据库（boot + cloud）

## 一句话结论

现有「每人每款限 1 件」的新人价只适合海员个人试买；船供和工厂餐厅采购需要订单级首单权益。正式做法是在租户下增加「采购主体（buyer_org）」层：个人按 `userId`、船供按 `vesselId`、企业按 `buyerOrgId` 分别判定首单资格，三套玩法在同一小程序里按场景分流，互不串味。

## 背景与现状

### 已完成

- 新人专享页前端已整体重写：品牌头卡、资格条、排序、商品卡「省¥X · 限 N 件」、规则折叠、底部购物车结算。
- 活动 `3170000000000000501` 已从 8 款扩到 16 款，蛋奶肉果菜排在最前；每人每款仍限 1 件，注册 30 天内且未下过单。
- 前端全量 165 文件 / 1882 用例、`vue-tsc`、mp-weixin 构建均通过。

### 本轮讨论确认的问题

1. **单品限 1 件与船供批量采购冲突**：船上买鸡蛋是 10 盒起，第 1 件新人价、第 2 件恢复原价，采购员对账麻烦，整单让利感知很低。
2. **「新人」按账号算，不按船/工厂算**：换采购员、一个公司多船多厂、开小号，都会让资格失真。
3. **首单考核点不对**：船供/企业首单看首单金额、复购、时效、账期，不是领几个 1 元钩子。
4. **企业工厂餐厅采购没有主体层**：现在岸上企业车只有 `ownerUserId + 收货地址`，没有「这家工厂是谁」的字段；按租户算会把全平台工厂当成一家。
5. **现有新人价活动 `purchase_scene` 为空**：促销引擎不会按场景过滤，个人新人价可能漏到船供/企业订单，这是必须先修的数据问题。

## 三轨模型

| 场景 | 购买主体 | 首单权益 | 资格口径 | 页面入口 |
| --- | --- | --- | --- | --- |
| 海员个人（`purchaseScene=1`） | 用户 `userId` | 每款首件新人价，每款限 1 件 | 本租户内无已支付个人订单，注册 30 天内 | 「个人自购」tab |
| 船供采购（`purchaseScene=2`） | 船舶 `vesselId` | 订单级满减/免运，按船限一次 | 该船无已支付船供订单，下单人具备采购确认权限 | 「船上采购」tab |
| 企业/工厂餐厅（`purchaseScene=3`） | 采购主体 `buyerOrgId` | 订单级满减/免运，按工厂限一次 | 该工厂审核通过且无已支付企业订单 | 「企业采购」tab |

默认权益档位（2026-11-13 起实际种子）：满 ¥1000 减 ¥100、满 ¥3000 减 ¥400、满 ¥5000 减 ¥800，单笔封顶 ¥800（可配置）；船供可另配「新船开航礼包」，企业可另配「企业首单免运」，均放 P2。早期讨论的 300/50、500/80 档位未采用。

## 目标与非目标

### 目标

- 个人新人价保持现状，但只在 `purchaseScene=1` 生效，不再漏到船供/企业。
- 船供首单改为订单级权益，按船限一次；普通船员不能冒充采购确认人。
- 企业/工厂餐厅可在小程序自助绑定采购主体：创建需审核，加入已有工厂可凭邀请码/申请。
- 岸上企业车、订单落 `buyerOrgId` 快照，首单资格、对账、开票都能追到具体工厂。
- boot / cloud 双模式 SQL、全量 SQL、测试和验收命令齐全。

### 非目标（本期不做）

- 不重做当前 16 款选品、价格、库存和页面视觉，只在页面上增加场景 tab 与 B2B 首单卡。
- 不新建独立优惠券系统；首单权益优先复用现有 type 7 订单级满减链路。
- 不强制迁移历史岸上企业车；历史车显示「采购主体未绑定」，新单才要求主体。
- 不做四段漏斗、A/B、复杂归因；放 P2 之后再评估。
- 不把「租户」当企业买家；租户只做数据隔离和查询范围。

## 核心决策（2026-11-12 已确认）

| 决策点 | 确认方案 | 理由 |
| --- | --- | --- |
| 首单形式 | 按档位满减：满 ¥1000 减 ¥100 / 满 ¥3000 减 ¥400 / 满 ¥5000 减 ¥800，单笔封顶 ¥800（可配置），不用首单免运试水 | 用户确认「首单按档位」；档位以 228/240 种子为准 |
| 采购主体谁维护 | 用户自助创建/加入，运营后台审核新建主体 | 和船舶自助绑定一致，降低运营录入量 |
| 新建工厂是否审核 | 必须审核；审核通过才享首单 | 防伪造工厂薅首单 |
| 加入已有工厂 | 邀请码/分享卡免审，搜索申请需厂长或运营审 | 和船舶成员加入逻辑一致 |
| 首单按工厂还是餐厅 | 按工厂 `buyer_org` 算一次 | 用户确认「按工厂一次」 |
| 待审核主体能否下单 | 可以下企业单，但不享首单；待审核期间的已支付单也不消耗首单（订单落审核状态快照） | 用户确认「允许」；2026-11-13 补快照口径，避免审核通过反而失去首单 |
| 全额退款是否恢复资格 | 不恢复 | 防「下单-退款-再领」套利 |
| 船供首单按船还是按人 | 按船 | 换采购员不影响船的首单，业务员代下单不串船 |
| 个人首单是否受船供/企业单影响 | 不受影响，只看 `purchaseScene=1` 的个人已支付单 | 采购员下船供单不应烧掉个人新人资格 |

## 验收总纲

1. 个人新人：A 用户无个人已支付单，看到 16 款新人价；即使他下过船供单，个人新人资格仍在。
2. 船供首单：船长/采购确认人/业务员（`canConfirm=1`）绑定船舶 + 有效靠港，首单满 ¥1000 减 ¥100；同一船第二单不再减；换一条新船仍可享。
3. 企业首单：采购员自助创建工厂 → 待审核可下企业单但不减、支付也不消耗首单；审核通过后首单满 ¥1000 减 ¥100；同一工厂第二单不再减；同一采购员绑的第二家工厂仍可享。
4. 权限：普通船员（`canConfirm=0`）不能提交船供单；非工厂成员不能选该工厂建岸上车；未审核工厂不能享首单。
5. 数据：`order_info.buyer_org_id` 有快照；`shared_cart` 岸上车唯一索引按「发起人 + 采购主体」去重；历史空主体车不参与首单。
6. 工程：后端 `mvn test -pl aryn-boot -am`、`verify-full-sql.mjs`、移动端 `vue-tsc` + `vitest` + mp-weixin 构建、管理端 `check:type` + 单测全部通过。

## 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 用户伪造工厂领首单 | 预算损失 | 新建主体审核；信用代码租户内唯一；首单仅审核通过主体；单主体首单金额上限 |
| 岸上车唯一索引改造锁表 | 上线窗口风险 | 先在备份库演练；低峰期执行；保留回滚脚本；必要时用在线 DDL |
| type 7 引擎改动影响现有船供活动 | 现有活动算价异常 | `firstOrderOnly` 默认 false；新增字段向后兼容；先跑全量促销单测 |
| `my-vessels` 响应加字段 | 前端兼容 | 只加字段不改结构；旧页面忽略新字段 |
| 历史岸上车无主体 | 首单口径污染 | 历史单不参与首单；新单强制主体；运营可按需补绑 |
| 采购员一人管多厂 | 岸上车被旧唯一索引挡住 | 唯一索引改为「发起人 + 主体」；P0 一起改，不能拖到 P2 |
| 退款/取消口径 | 首单被反复利用 | 已支付即消耗；全额退款不恢复；文档写清 |

## 已确认决策（2026-11-12）

1. **首单按档位**：满 ¥1000 减 ¥100、满 ¥3000 减 ¥400、满 ¥5000 减 ¥800，单笔封顶 ¥800，可配置；不用「首单免运」试水。
2. **企业首单按工厂一次**：按 `buyer_org` 算，不按餐厅重复算。
3. **新建工厂由运营后台审核**：用户可以自助提交创建/加入申请，审核动作在运营后台完成。
4. **待审核工厂允许下企业单**：可以下单，但不享首单；审核通过后才享。

配套默认（未单独否决，按计划执行）：

- 加入已有工厂：邀请码/分享卡免审，搜索申请需厂长或运营审。
- 已支付即消耗首单；全额退款不恢复。企业首单只消耗「下单时主体已审核通过」的已支付单（`order_info.buyer_org_audit_status=1` 快照）。
- 船供首单按船一次，不按采购员账号；船供提交权限以 `vessel_member.can_confirm` 为准，发起人/采购确认人/业务员默认具备。
- 个人新人资格只看 `purchaseScene=1` 的个人已支付单，不受船供/企业单影响。
- 历史岸上车不强制迁移，显示「主体未绑定」，不参与首单。
- 首单活动种子默认草稿，运营按租户确认档位/预算后发布；首单立减可与优惠券叠加（`coupon_stackable=1`），不与单品新人价叠加（场景隔离）。
