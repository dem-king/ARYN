## 5. 上线顺序

1. **备份** `aryn_boot` / `aryn_promotion`；记录 `shared_cart`、`order_info`、`promotion_activity`、`promotion_lock` 行数。
2. **预检**：
   - `SELECT COUNT(*) FROM shared_cart WHERE cart_type='2' AND status='2' AND del_flag='0';`
   - `SELECT COUNT(*) FROM order_info WHERE purchase_scene='3';`
   - `SELECT id, purchase_scene FROM promotion_activity WHERE id='3170000000000000501';`
3. **执行 SQL**：P0 执行 boot 225 → 226 → 227；cloud 237 → 238 → 239。P1 引擎代码发布后再执行 228/240，禁止提前插入首单活动。
4. **重建全量 SQL**：`node db/boot/build-full-sql.mjs` → `node db/boot/verify-full-sql.mjs`（P0 先含 225/226/227，P1 再加 228）。
5. **后端发布**：`aryn-boot`（cloud 模式发布 order/promotion/vessel 三个服务）。
6. **管理端发布**：菜单/权限已入库，发布 buyer-org 页面。
7. **小程序发布**：新 tab/工厂页/岸上车选择器；旧版本保留个人 tab 能力，但岸上车创建会被服务端拒绝。
8. **灰度**：先内部租户/测试工厂跑 3 个场景；观察 1–2 天首单核销、订单主体为空比例、接口错误率。
9. **全量**：打开船上/企业 tab；发布首单活动。

禁止在生产直接 `DROP TABLE` / `TRUNCATE`；如需清理测试数据，走单独脚本并先备份。

## 7. 风险清单

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 索引重建锁表 | 中 | 岸上车短时不可写 | 低峰执行；备份库演练；准备在线 DDL 方案 |
| 伪造工厂 | 中 | 首单预算损失 | 审核 + 信用代码唯一 + 首单上限 + 预算 |
| 采购员多厂被旧索引挡住 | 高（若不改） | 第二家工厂无法建车 | P0 必须改唯一索引，不能延后 |
| 首单锁并发 | 中 | 同一主体两单都减 | Redis/DB 锁 + 唯一索引兜底 |
| type 7 引擎改动回归 | 中 | 现有船供活动算价异常 | `firstOrderOnly` 默认 false；全量促销单测；灰度 |
| 历史订单无主体 | 高 | 首单统计偏差 | 历史单不参与；新单强制；报表标注 |
| 旧客户端不传 buyerOrgId | 中 | 岸上车创建失败 | 发版引导；服务端错误文案明确「请升级/绑定工厂」 |
| 退款套利 | 中 | 首单重复 | 已支付即消耗；全额退款不恢复 |
| 菜单权限漏配 | 中 | 后台页面不可见 | SQL 幂等 + 上线 checklist + 超管兜底 |
