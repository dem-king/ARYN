## 4. ⑥ 自定义 HTML 组件（custom-html）

### 4.1 组件契约

- 类型：`custom-html`
- Props：`{ html: string, height?: number }`，默认 `{ html: '', height: 300 }`
- 分类：基础组件；非数据源驱动（不进 `DATA_DRIVEN_TYPES`）、可多次放置（不进 `SINGLETON_TYPES`）。

### 4.2 后端（阻断式 XSS 校验）

- `PageDesignComponentTypes` 注册 `CUSTOM_HTML = "custom-html"` 并入 `KNOWN_TYPES`。
- 探查结论：全仓 `pom.xml` **无** jsoup / OWASP HTML Sanitizer 依赖，故采用「危险特征正则/子串匹配，命中即**阻断发布**」（错误码 `CUSTOM_HTML_UNSAFE`），位置 `DefaultPageDesignDocumentValidator#validateCustomHtml`。

**阻断的危险特征（小写匹配）：**

| 类别 | 特征 |
|------|------|
| 危险标签 | `<script`、`<iframe`、`<form`、`<object`、`<embed`、`<link`、`<meta`、`<base`、`<svg` |
| 危险伪协议 | `javascript:`、`vbscript:`、`data:text/html` |
| 危险调用 | `eval(`、`expression(` |
| 事件处理器 | 正则 `\bon\w+\s*=`（覆盖 onerror/onload/onclick/onmouseover 等） |

- 空 `props.html` 放行；允许展示型标签/属性（div/span/p/a/img/h1-h6/列表/表格/strong/em/br/hr/style，href/src 仅 http/https 等）。
- **单元测试 5 例**：合法 HTML 通过、含 `<script>` 阻断、`href='javascript:'` 阻断、`onerror=` 阻断、无 html 字段放行。

### 4.3 管理后台（DOMParser 黑名单净化）

- 项目**未引入 DOMPurify**，采用与现有富文本同风格的 DOMParser 黑名单净化（`sanitize-custom-html.ts`）：
  - 整体删除 `script/style/iframe/object/embed/svg/form/template/math` 危险容器；
  - 移除所有 `on*` 事件属性；
  - `href/src/poster/action/formaction` 收敛到安全协议（http/https/mailto/tel，媒体放行 `data:image` 与站内相对路径）；
  - 过滤 `style` 中的 `expression / javascript: / url() / @import / behavior / -moz-binding`。
- **净化执行两处**：① 预览渲染前 `index.vue` 中 `sanitizeCustomHtml(html)` 后再 `v-html`；② 保存入 schema 前 `setting.vue` 的 deep watch 对 html 字段再净化一次。
- 属性面板：HTML textarea（10 行，非空且 ≤50000 字符）、高度 `el-input-number`（100–2000）、XSS 自动过滤提示文案。

### 4.4 C 端（mp-html 跨端渲染 + 正则兜底）

- 新增 `components/diy/diy-custom-html/index.vue`，复用项目已引入的 `mp-html`（与 `diy-rich-text` 同源），跨端支持 H5 / 微信小程序 / App。
- 容器行为：`height>0` 时固定高度 + `overflow:hidden` 裁剪；无 height 自适应内容；过滤后为空显示「暂无内容」占位。
- 渲染器分发：`components/diy/index.vue` 新增 `import DiyCustomHtml` 与 `v-else-if="item.type === 'custom-html'"` 分支（位于 rich-text 之后、search-bar 之前，不会落到 UnknownComponent）。
- **正则兜底过滤**（不引入新依赖）：移除 script/style 标签块、HTML 注释、`javascript:` 伪协议、双/单/无引号三种 `on*=` 事件属性，`data:text/html` 降级为 text/plain。

### 4.5 XSS 防护三层方案

| 层 | 位置 | 措施 |
|:--:|------|------|
| 第一层 | 管理后台保存前 | DOMParser 黑名单净化（画布预览 + 入 schema 各净化一次） |
| 第二层 | 后端发布校验 | 阻断式危险特征匹配，命中即拒绝发布（`CUSTOM_HTML_UNSAFE`） |
| 第三层 | C 端渲染前 | mp-html 自带解析过滤 + 正则兜底 |

### 4.6 剩余风险

- 后端为**阻断式校验**（无净化库），命中危险特征即拒绝发布，不做标签级白名单改写，运营自由度受黑名单严格度约束。
- 小程序端 `rich-text` / mp-html 能力边界：不支持任意自定义交互脚本，复杂布局在小程序端可能受限（见第 10 节）。

## 10. 已知限制与后续建议

1. ~~模板市场菜单 SQL 待补~~ **已补齐**：boot `84template_market_menu.sql` + cloud `85template_market_menu.sql`，含菜单+下载按钮+租户/角色推导补授，boot full.sql 已重生成（11577 行）。
2. ~~前端市场接口路径单复数不一致~~ **已修复**：管理后台 `api/promotion/page-design.ts` 5 处市场接口已从单数 `/pagedesign/template/` 修正为复数 `/pagedesign/templates/`，与后端对齐，`type-check` 复跑通过。
3. **「创建者租户名称」未展示**：市场列表返回 `tenantId` 作为来源标识；要展示可读的租户名称需关联 upms 租户表，cloud 模式跨库不可 JOIN，留待后续通过 Dubbo RPC 补充。
4. **自定义 HTML 小程序端能力边界**：微信小程序 `rich-text` / mp-html 不支持任意脚本与部分 CSS（如 position 复杂定位、表单交互），复杂动效/交互在小程序端可能降级；XSS 为阻断式（无标签级净化改写），运营自由度受黑名单严格度约束。
5. **区块级懒渲染待优化**：当前 C 端图片组件已懒加载（P0），但装修区块级（整屏可视区外的 DiyPage 区块）懒渲染尚未做，长页面首屏仍会渲染全部区块。
6. **模板 pageType 语义未扩展**：`PageDesignTemplate.pageType`（微页面/首页/通用）与页面 `pageType`（含分类/个人中心）解耦；若后续模板市场需按「分类页/个人中心页」归类模板，再单独扩展模板枚举。
7. **registry 运行时未统一**：C 端 `componentRegistry` 当前无运行时调用方（渲染器走硬编码 v-if 链），故 `custom-html` 未在 C 端 registry 补登；如需统一注册表分发，可后续补登。
