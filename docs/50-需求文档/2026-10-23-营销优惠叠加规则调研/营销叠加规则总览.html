活动价 × 优惠券 × 积分抵现
叠加规则总览

拼团、限时折扣、秒杀、新人专享四类活动商品，能不能用优惠券、能不能积分抵扣？本页是调研结论、竞品证据与建议规则的「一页纸」版本，完整论证见同目录 README / 01 / 02 / 03。

2026-10-24 现状：四类活动全部可叠（代码） 建议：秒杀 / 新人专享不叠，拼团 / 折扣可配

01 · 现状 vs 建议

悦航购

当前代码对四类活动价「一视同仁」：优惠券与积分都在活动价之后计算，没有任何活动维度排除；唯一按 SKU 排除的是整船/整单优惠。秒杀规则页已写「不支持优惠券」，但代码未强制——这是必须收口的矛盾。

拼团

现状：券 ✓现状：积分 ✓
建议：券 ✓ 可关建议：积分 ✓ 可关

拼团是裂变拉新，券可促成团；平台电商平行满减默认可叠；与现状兼容。

限时折扣

现状：券 ✓现状：积分 ✓
建议：券 ✓ 可关建议：积分 ✓ 可关

常规促销，叠券是行业默认；有赞/微盟均为「可配」，靠限购/库存防薅。

秒杀

现状：券 ✓现状：积分 ✓
建议：券 ✗ 强制建议：积分 ✗ 强制

有赞官方：秒杀不支持和任何活动叠加；秒杀价已击穿、限购 1 件，规则页已对外承诺。

新人专享

现状：券 ✓现状：积分 ✓
建议：券 ✗ 默认关建议：积分 ✗ 默认关

新人价已最低，叠券易出 0 元单/被薅。注意：竞品无「新人价商品不可用券」硬规则（有赞体验价甚至可与秒杀/拼团搭配），默认禁叠是悦航购自定策略。

口径说明：「拼团/折扣默认开」是兼容现状的推荐值；若更看重毛利安全，只需把默认值改为「关」（对标有赞/微盟）， 能力不变、可租户灰度。秒杀为服务端强制，不开放放开。

03 · 关键官方原文

可直接作为需求依据
「秒杀活动不支持和任何营销活动叠加，所以不支持使用优惠券。」 有赞帮助中心《秒杀的商品可以用优惠券吗？》· A 级 · 2026-10-24 访问
「限时折扣可以与优惠券叠加使用。」条件：活动勾选「优惠叠加→优惠券/码」，且券取消勾选「仅原价购买可用」；顺序「先计算限时折扣，然后计算是否满足优惠券门槛」。 有赞帮助中心《限时折扣能否与优惠券叠加使用？》· A 级
「创建多人拼团活动时自主设定是否可叠加使用优惠券/优惠码。」 有赞帮助中心《多人拼团订单可以使用优惠券吗？》· A 级
「结算时，先计算其他的营销优惠，最后计算积分抵现。」 有赞帮助中心《积分抵现可以跟哪些营销优惠叠加吗？》· A 级
「换购品以换购价格购买时，不支持使用东券。」「京豆和优惠券、京东卡是独立的可以一起使用。」 京东《京东优惠券规则》《京豆说明》· A 级
「营销优惠叠加规则称为平行满减优惠叠加规则……第一步计算单品级优惠，第二步计算店铺级和跨店级优惠、其他类优惠。」 抖音电商《营销优惠叠加规则》· B 级（官方页 JS 渲染，第三方逐字转载）

04 · 落地五步

完整规格见 03-规则设计说明书
  1. 前置修复：确认页券列表没有返回券适用商品明细，指定商品券会恒判「本单无可用商品」；券行展示也不看可用性。先修这两处，再谈规则。
  2. 数据模型：四张活动表统一新增 coupon_stackable / points_stackable；存量数据按「拼团/折扣=开、秒杀/新人=关」回填；双模式增量 SQL。
  3. 计价改造：活动价计划带「活动类型 + 两个叠加开关」；券/积分按 SKU 过滤 eligible 明细，门槛、分摊、20% 上限都只作用于 eligible；新增 0.01 元最低实付兜底（可配置）。
  4. 三端展示：C 端券行/积分行置灰 + 原因、明细活动标签；管理端 4 个活动表单加开关（秒杀只读）+ 列表列；规则页文案与代码同步。
  5. 灰度回滚：promotion.stack-policy.enabled 全局开关，默认关（行为不变）→ 测试租户 → 全量；回滚只需关开关，不滚 SQL。
