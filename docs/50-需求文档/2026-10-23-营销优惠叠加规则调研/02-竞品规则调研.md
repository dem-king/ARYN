## 0. 结论先行（TL;DR）

### 0.1 最关键的 10 条竞品事实

1. **「活动商品默认禁用券」不是行业通用做法，行业是分三档的**：
   - **默认可叠**（平台强制按"平行满减"计算）：抖音电商《营销优惠叠加规则》、京东"平行优惠"（2019-02-15 全量上线）、淘宝/天猫官方立减；
   - **商家可配**（SaaS 主流）：有赞多人拼团、有赞限时折扣、微盟店铺优惠券，均由商家在活动/券上勾选是否可叠；
   - **强制互斥**：有赞「秒杀」（官方明文"不支持和任何营销活动叠加"）、有赞积分商城（积分兑换）、微盟"限量抢购"与"限时折扣"选品互斥。
2. **秒杀是唯一被 SaaS 强制互斥的活动类型（最值得抄）**：有赞官方《秒杀的商品可以用优惠券吗？》原文——"**秒杀活动不支持和任何营销活动叠加，所以不支持使用优惠券**"；有赞官方《新版营销插件叠加互斥表》中「秒杀」这一行的全部单元格均为 ❌（含优惠券码、积分抵现）。这是"价格击穿"风险最高的活动，头部 SaaS 选择直接锁死。
3. **SaaS 的默认可配值是"不叠"，需要商家显式开启**：有赞券叠加功能"默认设置为不勾选"（即默认不可叠加券）；有赞限时折扣需要"下单同享优惠"勾选券/码 + 券侧取消勾选"仅原价购买时可用"，双向配置才生效；微盟券需要勾选"券叠加其他优惠"才能与限时折扣等促销共享，否则"若某商品参与了限时折扣，未开启允许叠加，则无法使用当前优惠券"。
4. **叠加顺序有官方标准答案：单品级活动价 → 会员折扣 → 券（按活动价/折后价判断门槛）→ 积分抵现最后算**。
   - 有赞：先算限时折扣，再判断券门槛；先算会员折扣，再判断券门槛；"**结算时，先计算其他的营销优惠，最后计算积分抵现**"。
   - 抖音：平行满减——第一步算单品级，第二步算店铺级/跨店级/其他类；门槛用"单品优惠价"判断。
   - 京东：以东券可用商品的"京东价总金额"判断门槛（平行式）。
5. **金额保底：有赞明文是「最低 0 元」，不是 0.01 元**。有赞《优惠券叠加使用说明》原文："叠加后的总优惠金额受系统价格保护限制，**优惠后订单实付金额最低为 0 元**"。京东东券规则："若东券总金额大于订单需支付的商品金额，**差额不予退回**"（等效保底 0 元）。→ **本次调研未找到任何平台官方明文写"不低于 0.01 元"**（详见 §9 与 §11）。
6. **券叠加有硬上限，这是最便宜的防击穿手段**：有赞同一订单最多叠 **3 张**券、且折扣券/随机金额券/CRM 券不支持叠加；微盟最多叠 **5 张**；京东全品类东券每单最多 1 张、同商品三类东券只能用 1 张（系统自动选力度大的）；抖音一个子订单最多生效 1 个"同类型"店铺优惠、同商品同 SKU 同时段仅 1 个单品活动。
7. **「仅原价购买时可用」是券侧最关键的开关（对应我们的"活动商品不可用券"）**：有赞官方原文——勾选后"若商品参与**限时折扣、多人拼团、满减/送**等营销活动，则不可使用此优惠券"；且"优惠券一旦能被领取，商家后台优惠券也不能编辑改动"（创建后改动有约束）。这是"券 × 商品 × 活动"三维排除的现成产品形态。
8. **「新人专享」在竞品里不是独立活动类型，而是"资格限制"或"券模板"**：有赞「新人专享券」= 券模板 + 领取人自动限制为店铺新客；有赞「限时折扣」支持"客户限制 = 店铺新客"（2025-12-18 上线）；有赞「满减送」支持"指定客户参与 = 仅店铺新客"。→ 新人价与券是同层可组合的两个优惠对象，需要单独定义互斥策略。
9. **积分/虚拟资产与券的关系在各平台相反**：
   - 京东京豆：官方明文"**京豆和优惠券、京东卡是独立的可以一起使用**"；
   - 有赞积分抵现 × 优惠券 = **默认 ✅ 叠加**；有赞「会员折扣 × 积分抵现」也是默认 ✅ 且**没有**开关（商家反馈"能否配置为可配关系"被明确的 FAQ 记录，说明确实无开关）；
   - 微盟：券模板里勾选"下单可抵扣：积分/余额/储值卡"才可叠，**不勾选则不可叠**；
   - 淘宝淘金币：经验帖显示大促/特供商品"屏蔽金币抵扣"，**未找到官方原文**。
10. **防价格击穿是"配置矩阵 + 监控 + 限购"的组合拳，不是单点开关**：有赞/微盟用"互斥/可配/默认叠"三态矩阵；抖音有《营销价格的风险管理&预警》；京东商家后台有"优惠监控"系统并会对"优惠叠加风险"的促销做人工审核；有赞秒杀用"独立库存 + 每人限购 + 未支付 5~10 分钟自动取消"。

### 0.2 对悦航购最推荐的一套规则组合（可直接进需求）

| 层 | 规则 | 依据 |
|---|---|---|
| 优惠层级（顺序固定） | 原价 → ①单品级活动价（拼团/秒杀/限时折扣/新人专享）→ ②会员折扣 → ③优惠券（平台券/店铺券）→ ④积分抵现/红包 → ⑤支付优惠 | 有赞（限时折扣→券门槛、会员折扣→券门槛、积分最后）；抖音（单品级→店铺/跨店）；京东（平行优惠） |
| 活动级开关（每个活动 2 个布尔） | `allow_coupon_stack`、`allow_point_deduction`，**默认 false（不叠）**，商家需显式开启 | 有赞"默认设置为不勾选"；微盟"未开启允许叠加则无法使用" |
| 秒杀 | **强制互斥**：禁止叠券、禁止积分抵现、禁止叠其他活动（后台只读展示，不可改） | 有赞秒杀官方原文 + 互斥表整行 ❌ |
| 拼团 / 限时折扣 | 可配：默认不叠，可开启"同享优惠券/积分抵现"；最多叠 1 张券（严于有赞 3 张，降低客诉与亏损） | 有赞、微盟 |
| 新人专享 | 与"普通券"可配、与"新人券/新人价"互斥（同一用户只吃一次新客补贴）；新人价以"活动 + 客户限制=新客"实现 | 有赞新人专享券 + 限时折扣新客限制 |
| 券侧开关 | 券增加「仅原价可用」布尔；开启后活动商品列表页/商详页/下单页均不可用并给出理由 | 有赞「仅原价购买时可用」 |
| 金额保底 | 优惠后实付 **≥ 0.01 元**（业务自定，比有赞 0 元更严，理由：0 元单无法走支付渠道、易被刷单），差额按分摊规则回退到最后一个优惠 | 竞品多为 0 元/差额不退；0.01 元为悦航购自定策略，**非竞品普遍做法** |
| 限购 | 活动级限购（每人/每单）+ 活动独立库存（秒杀）+ 未支付超时取消（秒杀 5~10 分钟）+ 券每人每日使用张数上限 | 有赞秒杀/券；京东每单 1 张全品类券 |
| 展示 | 下单页默认勾选"最优优惠组合"，≥2 张时打"可叠加"标签；不可用券置灰 + 文案"已享活动价，不可使用优惠券"；活动标签 2~5 字 | 有赞下单页"最优组合/可叠加角标"、秒杀活动标签规范 |

## 2. 有赞（证据最充分，产品设计首选参照）

> 结论：**有赞把"活动 × 券 × 积分"做成了三态矩阵（默认叠 ✅ / 默认不叠 ❌ / 商家可配），并额外提供"券级仅原价可用"开关和"活动级同享优惠"开关，双向配置才生效。秒杀是唯一强制锁死的活动。**

### 2.1 官方《新版营销插件叠加互斥表》（A 级，2026-08-05 更新）

- 页面：https://help.youzan.com/displaylist/detail_4_4-2-49295
- 官方附件（xlsx，本次已下载解析）：`https://file.yzcdn.cn/3/doc/2025/08/07/10/12/00/营销叠加互斥关系表唯一准确版-2025.8.7.xlsx`
- 官方图例原文：
  - "**可配**：指两种插件可以自定义配置是否叠加"
  - "**✅**：两种插件默认优惠叠加"
  - "**❌**：两种插件默认优惠不叠加"
- 官方特别注意原文：
  - "**默认不与任何活动叠加的插件：赠品、助力定金膨胀**"
  - "**限时折扣和加价购**：若限时折扣的折扣商品和加价购的换购商品为同一件商品，则不可叠加……"
  - "**注：同一个商品支持同时参加积分兑换与秒杀活动，消费者从不同入口进入可参与不同的活动**"（即"不同入口不同价"，不是同一笔订单叠加）

要点：
- **秒杀整行全 ❌**（与任何活动、券、积分抵现都不叠）；
- **拼团、限时折扣、优惠套餐、打包一口价、满减送、加价购换购、定金膨胀** 与券/积分抵现都是 **可配**；**砍价 0 元购** 是"券 ❌ / 积分抵现 可配"（不对称，选品时务必注意）；
- **券 × 积分抵现 = 默认 ✅**；
- **积分商城（积分兑换）与券/积分抵现 = ❌**（兑换是"另一条购买路径"，不是叠加）。

### 2.2 优惠券 × 优惠券（A 级）

- 《优惠券叠加使用说明》：https://help.youzan.com/displaylist/detail_4_4-2-68355 （更新 2026-06-10）
- 原文要点：
  - 支持商家配置"是否允许用户在同一笔订单中叠加使用多张优惠券"；**"默认设置为不勾选"**，未勾选即该券不可与任何券叠加。
  - 适用券类型：**满减券、商品兑换券**；"**折扣券、随机金额券、CRM 优惠券不支持叠加使用**"。
  - 数量上限：**"同一笔订单内……最多可使用 3 张"**。
  - 价格保护：**"叠加后的总优惠金额受系统价格保护限制，优惠后订单实付金额最低为 0 元"**。
  - 三种叠加维度（券模板级配置）：①可与自身叠加（同一活动多张）②可与同类型券叠加 ③可与不同类型券叠加。
  - 生效时间口径：已创建券在有效期内仍可编辑"优惠叠加"，"用户下单时是否可以叠加以优惠券的最新设置为准"。
  - 分摊逻辑（对研发有用）：自身/同类型叠加 → "将适用商品价格降序排序，依据券过期先后顺序，一一分摊"；跨类型叠加 → "优先考虑商品兑换券……再考虑满减券，将其优惠均摊至剩余未被兑换的商品上"。
  - 下单页：默认勾选"最优组合"，≥2 张有标签提示；"如果未选择的券可以与所选券叠加，会出现可叠加角标"。
- 相关（B 级，仅检索摘要，未抓正文）：《优惠券的优惠叠加设置(叠加规则)后台没有设置入口》 https://help.youzan.com/displaylist/detail_4_4-1-302433 —— 叠加规则被收纳在编辑页"更多功能"抽屉中。

### 2.3 限时折扣 × 优惠券 / 积分抵现（A 级，双向配置）

- 《限时折扣能否与优惠券叠加使用？》：https://help.youzan.com/displaylist/detail_4_4-1-22249 （2024-11-13）
  - 原文："**限时折扣可以与优惠券叠加使用。**"
  - 叠加条件（原文）："创建限时折扣时，勾选优惠叠加，勾选优惠券/码，**且在优惠券/码中取消勾选"仅原价购买可用"**"。
  - 计算顺序（原文）："**先计算限时折扣，然后计算是否满足优惠券门槛**"。
- 《限时折扣与优惠券同享需要怎么设置？》：https://help.youzan.com/displaylist/detail_4_4-1-288309 （2026-08-18）
  - 原文："限时折扣配置路径：商城电脑端后台 - 应用 - 营销玩法 - 限时折扣 - 编辑 - **下单同享优惠勾选优惠券/码**"；"优惠券配置路径：……- 优惠券 - 编辑 - **不要勾选仅原价购买**"。
- 《限时折扣使用教程》（B 级，摘要）：https://help.youzan.com/displaylist/detail_53_53-2-276158 —— "**下单同享优惠：支持与优惠券、积分抵现、储值卡同享优惠**"，即活动侧一个开关可同时放开券与积分抵现。

## 3. 微盟（SaaS 第二参照，配置项比有赞更"券为中心"）

### 3.1 店铺优惠券《叠加规则》（A 级）

- 原文要点（"叠加规则"章节）：
  1. **下单可抵扣**："商户可勾选**积分、余额、储值卡**；例如：商户若未勾选余额，当用户下单使用余额进行抵扣金额时，则**无法使用当前优惠券叠加优惠**"；
  2. **叠加优惠券**："若勾选允许叠加，用户的同一订单中，可同时使用多张优惠券进行叠加"；"商户可选择**允许相同券叠加**以及**允许不同券叠加**，允许不同券叠加时可**指定仅部分券可参与叠加**；同时商户可限制订单**最多可叠加的优惠券数量，最多可叠加 5 张**"；
  3. **券叠加其他优惠**："商户可选择当前优惠券**是否与其他促销类活动共享**，例如：若某商品参与了**限时折扣**，若未开启允许叠加，则**无法使用当前优惠券**"。

## 5. 京东

> 结论：**京东是"平行优惠 + 券种类互斥 + 京豆独立可叠"的典型。活动价（换购价/秒杀价）对东券有明确限制；京豆与券官方明文可同时使用。**

### 5.1 官方《京东优惠券规则》（A 级）

- https://help.jd.com/user/issue/169-1077.html （检索快照 2026-05-16）
- 原文要点：
  - "**京东发放的商品优惠券仅能在京东提交订单时抵减应支付商品金额（不能抵减运费）**……**换购品以换购价格购买时，不支持使用东券**"（→ 这就是"活动价商品不可用券"的官方明文，落点是"换购价"）。
  - "**使用全品类东券、限品类东券、店铺东券**提交的订单……"（券三大类）。
  - 叠加规则："订单中有多款商品，可用店铺东券、限品类东券、全品类东券的情况下，**按照店铺东券、限品类东券、全品类东券使用顺序，依次扣减东券金额**。**同一订单的同一商品上，店铺东券、普通限品类东券、全品类东券仅可使用一张**（PLUS 专享等特殊场景的东券不受此限制）。"

### 9.3 一眼结论（跨平台）

- **"活动价能不能叠券"在头部平台几乎都写成"可以叠，但有门槛/上限"**（抖音、京东、淘宝均是平行满减）；**"强制不叠"只出现在：秒杀（有赞）、换购价（京东）、积分兑换（有赞）、百亿补贴（淘宝，未证实）**。
- **"积分能不能抵"关键看平台把积分放在哪一层**：京东 = 与券并列的独立支付手段（可叠）；有赞 = 最后计算的抵扣（可叠、有上限、可与券叠）；微盟 = 券模板下的"下单可抵扣方式"（需勾选）；淘宝淘金币 = 商品级开关（活动商品可关）。
- **没人用"全局一刀切禁用券"**；都是**活动级/券级/商品级三层开关的组合**。

## 10. 共性规律与反例

### 10.1 共性规律（8 条，可直接写进产品规范）

1. **价格计算是分层的，且层序固定**：原价 → 单品级活动价 → 店铺级促销（满减送/会员折扣）→ 券 → 积分抵现 → 支付优惠。所有平台都明确"积分/抵扣类最后算"。
2. **券门槛用"活动价"判断，不用原价**：淘宝（官方立减后价格）、抖音（单品优惠价）、京东（京东价，促销后平行计算）都是"平行式"，即"活动价仍可满足券门槛"。这是 2018 年后行业统一转向的方向（淘宝 2018-05-24、京东 2019-02-15）。
3. **默认可配值是"不叠"**：SaaS 层（有赞/微盟）默认不叠，需要商家显式勾选；这既符合"防亏损"直觉，也解释了为什么商家普遍觉得"活动商品用不了券"。
4. **秒杀/抢购类活动被单独锁死**：有赞整行 ❌；微盟旁证"限量抢购商品不可同时参加限时折扣"。
5. **数量与限购是标配**：券叠加张数（3/5 张）、单类型券每单 1 张、活动限购（每人）、独立库存、未支付超时取消（5~10 分钟）。
6. **展示层"默认最优 + 可叠角标"**：有赞下单页自动勾选最优券组合，≥2 张打"可叠加"标签；未选券若可叠会出现角标。
7. **平台保留"下单页试算"作为最终解释权**：京东"以提交订单时是否可选择使用为准"；抖音"如有其他活动规则，以具体活动规则为准"。
8. **平台/商家会区分"费用承担方"**：拼多多/京东的券由平台券或商家券承担不同成本；这决定了叠加规则的经济边界（商家券不能让平台补贴买单）。

### 10.2 反例（打破直觉，避免设计踩坑）

| 直觉 | 反例 | 启示 |
|---|---|---|
| "活动商品都应该禁用券" | 抖音/京东/淘宝活动价商品默认可叠券（平行满减） | 默认禁用会损失转化，应做"可配"而非"一刀切" |
| "金额保底是 0.01 元" | 有赞官方写"**最低 0 元**"；京东东券"差额不退" | **0.01 元保底是我们的业务自定，不是行业惯例**，需要写清理由（防 0 元单/支付渠道限制） |
| "积分抵现一定和券互斥（都是让利）" | 有赞券×积分抵现默认 ✅；京东京豆与券"独立可一起使用" | 积分是"资产消耗"不是"活动让利"，默认应允许叠加，用上限控风险 |
| "会员折扣天然可以和活动叠" | 有赞：会员折扣**不支持和秒杀、优惠套餐、打包一口价、限时折扣**叠加；限时折扣 × 会员折扣在矩阵中是"⬇️ 特殊折叠" | 会员价与活动价需要单独定义"取优/互斥/折叠"三选一 |
| "券只要商家勾选就能叠" | 有赞/微盟都是**双向配置**：活动勾"同享" + 券侧取消"仅原价"（或券侧开"叠加其他优惠"）才生效 | 我们的配置要明确"AND 关系"，并在后台做双向校验/提示 |
| "新人专享是独立活动" | 有赞 = 新人券模板 + 活动"仅新客参与"；美团系 = 新人券包 | 新人权益优先用"券 + 客户资格"实现，避免再开一套独立定价引擎 |
| "秒杀只是打折特别狠" | 有赞秒杀：独立库存、SKU 维度、限购取低、5~10 分钟未支付取消、标签 2~5 字 | 秒杀是"活动 + 库存 + 防刷"的组合体，不能复用普通折扣模型 |

## 11. 对悦航购的落地建议（规则设计草案）

> 以下为**基于竞品证据的建议**，不是竞品事实。凡竞品未证实的部分，均已标注为"悦航购自定"。

### 11.1 建议的数据/配置模型

```
活动(activity)
  ├─ type: 拼团 / 限时折扣 / 秒杀 / 新人专享
  ├─ allow_coupon_stack        boolean  -- 默认 false；秒杀固定 false 且不可改
  ├─ allow_point_deduction     boolean  -- 默认 false；秒杀固定 false 且不可改
  ├─ allow_member_discount     enum     -- 允许 / 互斥 / 取优（默认"取优"）
  ├─ customer_limit            enum     -- 全部客户 / 店铺新客 / 指定人群
  ├─ purchase_limit_per_user   int      -- 每人限购（与商品限购取最小值）
  ├─ stock_mode                enum     -- 共享库存 / 独立活动库存
  └─ pay_timeout_minutes       int      -- 秒杀 5~10 分钟

优惠券(coupon)
  ├─ original_price_only       boolean  -- “仅原价可用”，开启后活动商品不可用（有赞同款）
  ├─ stackable                 boolean  -- 是否允许与本单其他券叠加（默认 false）
  ├─ stack_scope               enum     -- 自身 / 同类型 / 不同类型
  ├─ stack_limit_per_order     int      -- 建议 1（竞品 3~5，从严）
  └─ claim_limit_per_user_day  int      -- 每人每日使用/领取上限

订单(order)
  └─ 优惠明细：按 [活动 → 会员折扣 → 券 → 积分 → 支付] 逐层记录，券按
     “商品价格降序 + 券过期先后”分摊（有赞官方分摊逻辑）
```

### 11.2 建议的默认策略表（悦航购 v1）

| 活动 | 叠券 | 积分抵现 | 会员折扣 | 与新人专享 | 理由 |
|---|---|---|---|---|---|
| **秒杀** | ❌ 强制 | ❌ 强制 | ❌ | 互斥（秒杀商品不参与新人价） | 有赞秒杀整行 ❌，价格最易击穿 |
| **多人拼团** | 可配（默认 ❌，开启后限 1 张） | 可配（默认 ❌） | 可配（默认取优） | 新人可参团但不再享新人价 | 有赞拼团可配；拼团价本身已让利 |
| **限时折扣** | 可配（默认 ❌，开启后限 1 张） | 可配（默认 ❌） | 取优（默认） | 新人专享活动可指定"仅新客" | 有赞限时折扣可配 + 新客限制 |
| **新人专享** | 与"普通券"可配、与"新人券"强制互斥 | 可配 | 取优 | — | 新客只补贴一次；券包路径（美团/有赞）优于改价 |

> 说明：悦航购若希望"更激进地拉转化"，可把拼团/限时折扣的 `allow_coupon_stack` 默认设为 true；**但建议不要**：SaaS 头部（有赞/微盟）默认都是不叠，且客服/亏损风险主要由运营承担。

### 11.3 防价格击穿 Checklist

1. **活动互斥矩阵中心化**：用一张"活动类型 × 优惠类型"的三态表驱动校验（默认叠/可配/强制互斥），而不是散落在各 Service 的 `if` 里。
2. **券侧 "仅原价可用"**：活动商品在商详页、券列表、下单页三处都要"不可用 + 原因文案"；混合订单按有赞口径——"券适用商品满足门槛即可整单用券"（活动商品不参与分摊或分摊为 0）。
3. **金额保底 0.01 元**：优惠后应付 `< 0.01` 时，按"最后叠加的优惠"回退差额（先回退积分抵扣，再回退券）。**注意：这是我们自定策略，不是竞品普遍做法（有赞 0 元）**。
4. **叠加张数上限**：订单内券 ≤ 1~3 张（建议 1，竞品 3/5）；同类型店铺优惠 ≤ 1（抖音口径）。
5. **活动库存与限购**：秒杀独立库存 + 每人限购 + 未支付自动取消；活动商品与普通商品库存分离。
6. **券发放与使用上限**：券每人每日使用张数上限（有赞能力）+ 活动总预算/补贴上限。
7. **试算与监控**：下单页"优惠试算"接口返回逐层明细（活动价、会员折扣、券、积分、支付），后台提供"活动叠加后的到手价"看板；对"活动价 + 券 + 积分"同时命中的订单打风险标记（对标京东"优惠监控"、抖音"营销价格的风险管理&预警"）。
8. **费用承担方标识**：券要区分"平台承担/商家承担/混合"，决定活动能否叠券（拼多多/京东都在承担方上做差异）。
9. **配置校验**：活动勾"同享优惠券"而券未关"仅原价可用"时，后台给出"不会生效"的即时提示（有赞是双向配置且仅能查 FAQ，容易踩坑——这里有体验改进机会）。

### 11.4 文案与展示惯例

| 场景 | 竞品惯例 | 悦航购建议文案 |

## 附录 B：一页纸速查（给产品/研发对齐用）

```
活动价能用券吗？
├─ 秒杀（有赞口径）      → 不能，且不能叠积分（强制，无配置项）
├─ 换购价（京东口径）    → 不能（换购价不支持东券）
├─ 拼团/限时折扣（SaaS） → 商家可配，默认不叠；开启后先算活动价再算券门槛
├─ 抖音/淘宝/京东活动价  → 能叠，按"平行满减"（活动价作为券门槛）
└─ 积分兑换（有赞）      → 不能，兑换是独立购买入口

积分能抵吗？
├─ 京东京豆 → 能，与券独立可同时用
├─ 有赞积分抵现 → 能，最后计算，有"抵扣金额上限"
├─ 微盟 → 券模板勾选"下单可抵扣-积分"才可叠
└─ 淘宝淘金币 → 商品级开关，活动商品可被屏蔽（经验帖，未证实）

防击穿五件套：互斥矩阵 + 券"仅原价"开关 + 叠加张数上限 + 活动限购/独立库存 + 价格风险监控

保底金额：有赞官方"最低 0 元"；0.01 元需悦航购自定并说明理由
```
