# 商详信息层补位可行性分析

2026-11-20 · 原提案评估，后续决定以实施记录为准。[实施记录](首版实施记录.md)

## 结论

方案可行。首版建议一并交付商品参数卡、现有商详接口的品牌和类目补齐、样板商品资料回填，以及有图文时的详情入口。单做前端能完成页面结构，但银鹭花生牛奶的现有数据只能支撑「1 件起订、按 1 件递增」。交易保障按真实履约场景和租户规则展示，优惠提示各自满足结算口径后再上线。

| 模块 | 可行性 | 上线条件 |
| --- | --- | --- |
| 商品参数卡 | 现有 SKU 能支撑部分字段 | 商详返回品牌、类目名称，运营补齐样板品牌和实物参数 |
| 交易与履约保障 | 可复用现有配送信息 | 船舶时段注明是当前靠港安排，开票与售后由业务政策驱动，条目按适用性展示 |
| 详情入口和装修 | 可在首版交付，无需新增请求 | 有有效图文才显示入口，展开、收起及装修加载后校准滚动锚点 |
| 食品参数维护 | 可复用现有商品编辑链路 | 楼层已具备展示位置，仍需补读写、双模式 SQL 和运营录入 |
| 阶梯价下一档 | 已有接口和计算函数 | 按当前 SKU、可购数量与实际价格优先级给出提示 |
| 买赠、满量满额、定向券和评价增强 | 适合各自排期 | 买赠与满量满额需要各自的门槛语义，券依赖完整订单上下文，评价标签与问答需要独立数据来源 |

## 1. 商品参数

- **本机 Boot 样本。** 按商品名查询并请求银鹭花生牛奶 450ml 的详情。接口返回了两级类目 ID，品牌 ID 为 `0`，品牌和类目名称为空。唯一 SKU 的 `salesUnit=件`、`minOrderQty=1`、`stepQty=1`，`specsArr`、`unitSpecText`、`baseUnit` 和 `baseQtyPerSalesUnit` 均为空。该租户的商详装修接口也返回空内容。
- **品牌与类目。** `selectApiSpuById` 无品牌、类目关联，服务层也未补名称。列表查询已有名称关联可参考，在原详情接口按当前租户补齐名称即可，二级分类缺失时用有效一级分类。样板商品还需绑定银鹭品牌，名称关联无法替代资料录入。[商品 Mapper](../../../aryn-mall-java/aryn-product/aryn-product-biz/src/main/resources/mapper/GoodsSpuMapper.xml#L294) · [C 端详情服务](../../../aryn-mall-java/aryn-product/aryn-product-biz/src/main/java/com/aryn/cloud/product/service/impl/GoodsSpuServiceImpl.java#L644)
- **规格与包装。** SKU 查询已投影度量字段，且只过滤逻辑删除。规格数按符合弹层销售状态的 SKU 组合计算。单规格使用初始化前的真实 `specsArr`，有明确 `unitSpecText` 时可回填规格显示，避免读到页面注入的「默认」。多规格完成选择后才显示该 SKU 的包装和起订量。基准单位换算也可能表达重量或体积，只有确认销售单位和包装换算时才使用箱规措辞，未知换算时隐藏该行。规格入口使用现有弹层的显式打开模式，`handleBuyAction(2)` 在单规格分支可直接加购。[SKU Mapper](../../../aryn-mall-java/aryn-product/aryn-product-biz/src/main/resources/mapper/GoodsSkuMapper.xml#L10) · [测量规则](../../../aryn-mall-java/aryn-product/aryn-product-api/src/main/java/com/aryn/cloud/product/api/support/ProductMeasurementRules.java#L56) · [商详打开弹层](../../../aryn-mall-uniapp/src/sub-pages/product/goods-detail/index.vue#L826)
- **数据回填。** 优先通过已有商品编辑和 SKU 度量功能维护样板 SKU。涉及修改销售单位、起订量或步长时，需根据真实在售计价单位评估。若现价按瓶销售，把销售单位直接改成箱会改变数量语义及买家预期，箱内数量可先作为独立的实物包装说明。建议把「至少一个样板 SKU 有有效品牌、类目和真实规格或包装」作为首版内容验收项。[SKU 度量编辑](../../../aryn-mall-ui/apps/web-ele/src/views/product/goods-spu/sku-measurement-editor.vue) · [购物车数量校验](../../../aryn-mall-java/aryn-order/aryn-order-biz/src/main/java/com/aryn/cloud/order/service/impl/ShoppingCartServiceImpl.java#L497)
- **食品参数落库。** 对所有规格共用的配料、产地、储存条件等，用 SPU 上限 12 项的参数列表可行。按规格变化的净含量、箱规继续归 SKU，条码也应先厘清是否复用已有 SKU 标识及其审核状态。建议在管理端详情与 C 端商详的显式查询、结果映射中加入字段，避免把 JSON 加进共用列表 SQL。服务端同样校验行数、去重及文本长度，明确旧客户端未提交字段时保留数据、显式提交空数组时清空。首屏展示 8 行，展开保留其余行。固定参数标签可用分包词条，自由录入值与标签的英文内容取决于运营是否提供翻译。[管理端编辑入口](../../../aryn-mall-ui/apps/web-ele/src/views/product/goods-spu/form.vue#L442) · [商品保存服务](../../../aryn-mall-java/aryn-product/aryn-product-biz/src/main/java/com/aryn/cloud/product/service/impl/GoodsSpuServiceImpl.java#L149) · [SKU 标识管理](../../../aryn-mall-ui/apps/web-ele/src/views/product/goods-spu/sku-identifier-panel.vue)
- **数据库。** 沿用现有商品接口，无需新增请求地址。按现有编号约定新增 Boot 和 Cloud 幂等脚本，补齐 Cloud 商品库初始化链路，Boot 登记并重新生成全量 SQL。若在 Cloud 商品基线表定义中直接加列，同步给该表的现有种子 `INSERT` 补显式列名或对应值，保持全新初始化可执行。新后端部署前先完成该环境迁移，商品 Mapper 查询依赖新列。[Boot 汇总脚本](../../../aryn-mall-java/db/boot/build-full-sql.mjs#L213) · [Cloud 商品基线](../../../aryn-mall-java/db/cloud/8aryn_product.sql#L257)

## 2. 保障、详情入口和装修

- **交易承诺。** 起订文案按销售单位，只有箱售且数据明确时用「整箱起订」。靠港部分复用 `resolveDeliveryRow` 的船名、港口、泊位与时段，只在船供场景且船舶、靠港上下文齐备时展示，文案用「当前靠港安排」。现有配送行已展示相同信息，建议保障条把时段放进展开说明或引用现有配送行。现有企业权益的 `invoicingEnabled` 只表明具备申请企业发票的资格。现有退款申请和装修承诺的数据结构不足以证明全租户支持增值税专票、对公结算或 48 小时包赔。首版展示有依据的项目，开票、理赔待租户确认文案和适用对象后再展示，验收由固定四项改为按实际配置显示。[配送行](../../../aryn-mall-uniapp/src/sub-pages/product/goods-detail/components/GoodsInfo.vue#L418) · [船舶上下文](../../../aryn-mall-uniapp/src/store/shipContextStore.ts#L39) · [企业开票权益](../../../aryn-mall-java/aryn-user/aryn-user-api/src/main/java/com/aryn/cloud/user/api/vo/EnterpriseBenefitsVO.java#L52) · [退款申请](../../../aryn-mall-java/aryn-order/aryn-order-biz/src/main/java/com/aryn/cloud/order/controller/app/AppOrderRefundController.java) · [装修服务承诺结构](../../../aryn-mall-ui/apps/web-ele/src/views/promotion/page-design/components/extension/types.ts#L232)
- **装修。** `pageType=2` 查的是当前租户下唯一生效的商详装修，请求参数没有 SPU。方案中「逐商品配置、该款漏配」应改为「租户没有生效的商详装修」。发布版可能含服务承诺楼层，新增原生保障条时需和该楼层约定展示归属，避免同屏出现两套政策。管理端画布目前是主图区、装修槽位、评价区，需同步原生区域的结构示意。[装修读接口](../../../aryn-mall-java/aryn-promotion/aryn-promotion-biz/src/main/java/com/aryn/cloud/promotion/service/PageDesignPreviewService.java#L51) · [C 端装修加载](../../../aryn-mall-uniapp/src/composables/usePageDecoration.ts#L38) · [画布骨架](../../../aryn-mall-ui/apps/web-ele/src/views/promotion/page-designer/components/canvas-page-shell.vue#L215)
- **锚点和加载。** `updateTabListPositions` 已调用 `measureDetailSections`，参数卡折叠、保障展开、装修落位及价格区异步变高后统一触发一次重测。现有 `boundingClientRect().top` 是相对视口的坐标，`pageScrollTo` 使用文档坐标，滚动途中重测要加上滚动偏移。详情入口仅在描述含有效图文、锚点可定位时展示。现有 `mp-html` 未传懒加载参数，组件默认 `lazyLoad=false`。验收写为沿用现有加载行为，专项验收懒加载则需要单独验证实现。[详情滚动与测量](../../../aryn-mall-uniapp/src/sub-pages/product/goods-detail/index.vue#L792) · [富文本挂载](../../../aryn-mall-uniapp/src/sub-pages/product/goods-detail/index.vue#L1200)

## 3. 优惠和评价

- **阶梯价。** 已有 `nextLadderTier`，结算页已用它并校验下一档确实低于当下单价。商详目前用旧字段 `moq` 计算默认数量，弹层接线也未传 SKU 的起订量和步长。选过 SKU 加购后，再打开弹层改规格时还要同步更新当前 SKU，避免沿用上次加购记录。提示按当前 SKU 的 `minOrderQty + n × stepQty` 取能到档的最小合法量，检查库存及当前和目标数量的价层竞争。例如起订 2 箱、步长 3 箱，档位从 6 箱起，用户当前买 5 箱时必须加 3 箱才可合法下单。展示接口取最高档单价最低的一组活动，结算按实际数量取优惠，活动重叠或目标数量会触发其它价层时应只展示档位规则，精确到手价提示须满足结算口径。[下一档函数](../../../aryn-mall-uniapp/src/utils/ladder-price.ts#L65) · [商详当前 SKU 与件数](../../../aryn-mall-uniapp/src/sub-pages/product/goods-detail/index.vue#L452) · [结算页阶梯提示](../../../aryn-mall-uniapp/src/sub-pages/order/order-confirm/components/ShopOrderItem.vue#L304) · [档位展示服务](../../../aryn-mall-java/aryn-promotion/aryn-promotion-biz/src/main/java/com/aryn/cloud/promotion/service/impl/LadderPriceService.java#L83)
- **买赠和满量满额。** 类型 5 按订单商品基价合计判断金额，赠品按 SKU 和数量配置。类型 7 按可参与明细计算金额与件数，同时配置两种门槛时需同时满足，并受首单资格等条件影响。因此展示接口输出应分别表达赠品 SKU 的名称、数量，以及满量满额活动的数量、金额及减免档位。多规格商品的指定 SKU 提示需要当前选中 SKU 或明确展示适用规格。范围判断可复用 `matchesScope`，活动还需要已发布且在有效期及档期内。游客只看明确公开的活动，登录态的船舶、靠港、港口与岸上采购主体范围由服务端校验和补全。商品页只展示适用规则，购物车及结算负责判定能否享受。[适用范围](../../../aryn-mall-java/aryn-promotion/aryn-promotion-biz/src/main/java/com/aryn/cloud/promotion/service/impl/PromotionScenarioEvaluator.java#L491) · [类型 5](../../../aryn-mall-java/aryn-promotion/aryn-promotion-biz/src/main/java/com/aryn/cloud/promotion/service/impl/PromotionScenarioEvaluator.java#L664) · [类型 7](../../../aryn-mall-java/aryn-promotion/aryn-promotion-biz/src/main/java/com/aryn/cloud/promotion/service/impl/PromotionScenarioEvaluator.java#L373)
- **接口与定向券。** 若做 `goods-hints`，Cloud 客户端路径为 `/promotion/app/goods-hints/{spuId}`，Boot 改写为 `/boot/app/goods-hints/{spuId}`。按两种模式配置公开请求和可选登录态，避免使用会丢弃 token 的 `skipToken`。已有 `coupon-usability` 是结算侧的纯函数，依赖券列表、订单金额及叠加规则。商详缺少这些输入，首版避免展示「下单可用企业券」的确定性结论。[双模式改写](../../../aryn-mall-uniapp/src/api/core/boot-url.ts#L8) · [请求登录态](../../../aryn-mall-uniapp/src/api/core/instance.ts#L39) · [券可用性计算](../../../aryn-mall-uniapp/src/utils/coupon-usability.ts#L44)
- **评价。** 计数已请求，可做零评价与少量评价的不同展示。1 到 2 条应如实显示已有评价，「已售 N 件」与现有累计销量展示口径冲突。当前商详只加载两条评价，标签聚合应基于全量统计或显式标签。「大家问」需单独确定问答来源及维护方式。分类回流仍可复用现有入口，只有确有整箱优惠时才用「整箱更划算」。[评价加载](../../../aryn-mall-uniapp/src/sub-pages/product/goods-detail/components/GoodsComment.vue#L54) · [销量展示规范](../../../aryn-mall-uniapp/src/utils/stock-display.ts#L1)

## 4. 交付边界与已验证项

1. 半天的阶段 0 估算适用于只使用现有字段的前端展示。以解决样板商品的信息空白为验收时，需把详情名称补齐和样板数据维护也算进首版。详情入口可随首版交付。
2. 参数落库可单独发布。上线条件是双模式初始化和增量可执行、后台新增与清空能回显、小程序能正确展示空值与展开后的行。建议先手工维护样板，再用实际商品数量决定是否扩展导入模板。
3. 阶梯价适合在修齐 SKU 数量状态后独立发布。买赠和满量满额待展示口径与结算对齐后交付，评价聚合与问答单独估算。
4. 本机 Boot 已完成样板商品详情、选货目录和商详装修只读验证。UniApp 类型检查通过，商详、规格购买、阶梯价、船舶上下文和双模式路径相关的 12 个测试文件共 112 项通过。本次验证覆盖现有基线，Cloud 运行态、微信真机及商品目录中其他 SKU 的资料覆盖率仍待核对。
