## 2. 已确认的下一阶段目标

### 2.1 内部组件重构（优先，纯前端、行为等价）

目标文件：`apps/web-ele/src/views/message/service/service-desk.vue`（约 2100 行，含模板 + scoped 样式）。建议分 4 小步，每步 `typecheck + 单测` 通过再继续：

1. `MessageTimeline.vue` + `MessageBubble.vue`：时间线渲染项（日期分隔/未读边界/聚合组首/失败重发/已读回执/复制消息）、上翻加载、新消息提示、接收 `.timeline` 滚动相关 props/emits；CSS 一并迁移。
2. `Composer.vue`：输入区（textarea/Enter 发送/字符提示/快捷回复入口/快捷键入口/连接提示）。
3. `ConversationRail.vue` + `ConversationItem.vue`：品牌区/独立窗口与主动联系入口/reception 状态/搜索/页签/列表/骨架屏/空错态；CSS 迁移。
4. `ChatHeader.vue` + `DeskNotice.vue`：会话头（标题/状态/负责人/操作按钮/返回列表/会话信息入口）与单条提示。

要求：**不改交互与视觉**；每步把对应 scoped CSS 一并搬到子组件（保留 `--desk-*` 令牌），避免样式作用域失效。样式搬迁后需在开发环境 1280/1600 两档目检一次（需真实登录）。

### 2.2 P2-A：接口增强（需后端，建议先出契约再实现）

按方案 §6.2，优先：
1. 会话列表 `keyword` / `statuses` / `assignedStaffId` / `queueCode` / `unreadOnly`（DTO + SQL，无 DB 变更）；
2. `ConversationVO` 增加 `createTime/waitingSince`（mapper alias，无 DB）；
3. `GET /message/staff/agent/roster`（含 presenceStatus / 当前在办 / 上限，供转交/强制分配选人）；
4. 队列统计 `GET /message/staff/conversation/queue-stats`。

后续批次：引用/撤回（字段已有，补校验/接口/回显）、图片发送（建议新增 message 专用上传，勿直接放开 `upms:material:add`）、会员/订单上下文（跨模块：`aryn-order-api` 新增远程接口 + message 聚合）。

## 6. 易踩坑/架构约束

1. `active` ref 由 `service-desk.vue` 持有并传入 `useDeskMessages`（actions 依赖 active，避免循环/QSS 声明顺序问题）；拆分组件时不要把 active 私有化到子组件。
2. 跨窗提醒宿主：`isServiceDeskAlertSuppressed()` 仅在主窗口且独立窗口存活时抑制；独立窗口 `role='desk'` 必须发声。不要改回双响。
3. `html.desk-theme` 由 `service-desk.vue` 挂载/卸载管理；占位页靠自身 `--el-*` 映射，不依赖该 class。
4. 独立窗口 401 依赖 `meta.sessionInvalidModal` + 壳内 `<SessionInvalidModal />`，别移除。
5. 消息域打开会话有请求代际校验（`isCurrentOpen`）与滚动锚点，拆分时保持。
6. 深色样式由 scoped（页面）+ 全局 `desk-tokens.css`（弹层）组成；拆 CSS 时保持 `--desk-*` 令牌，别硬编码色值。
7. `store/service-window.ts` 不得 import `store/message.ts`（避免循环）；消息 store 可以 import 协同单例。
8. P2 新增 API 必须以 `/message/...` 微服务域开头，前端统一走 `parseOpenBoot/rewriteBootUrl`；新增表/权限必须 boot/cloud 双份增量 SQL 并登记 `build-full-sql.mjs`。
