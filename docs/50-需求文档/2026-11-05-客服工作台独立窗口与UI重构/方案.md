## 0. 结论摘要（TL;DR）

**问题**：客服工作台 `/message/service` 占用整个管理端内容区，坐席处理其它工作（查订单、配货、看报表）时无法同时盯会话，切走就看不到新消息；同时现有工作台存在 8 个会「错发消息/漏消息」的硬伤，以及深色台内白底弹层、列表信息不足等体验问题。

**方案**：

1. **独立窗口**：点击工作台顶栏「弹出独立窗口」，用 `window.open` 打开同源静态路由 `/message/service-window`（`noBasicLayout`，无侧边栏/顶栏/tabbar），主窗口继续处理其它工作。**P0 零后端改动**——后端 WS 已支持同一 staff 多连接（`MessageWebSocketHandler.java:25,52-91`），presence 为 staff 级 Redis 租约、心跳幂等（`AgentServiceImpl.java:38-39,132-145`），已读游标单调不回退（`ConversationServiceImpl.java:262-287`）。
2. **多窗口协同**：新增 `BroadcastChannel('aryn-service-desk')` 协同总线 + 兜底通道，解决「一条消息响两遍、铃铛定位不到独立窗口、双窗未读/已读不一致、会话失效被错误登出、登出/租户切换/锁屏不同步」六类问题。**提醒宿主规则：独立窗口打开时由独立窗口发声/弹桌面通知，主窗口静默刷新；独立窗口关闭后主窗口接管。**
3. **UI/UX 重构**：先拆（1566 行单页 → `ServiceDesk` + 5 个 composable + 11 个组件），再重构。保留已登记为品牌视觉的**固定深色工作台**，但把 `--el-*` 变量作用域到窗口内，消灭白底下拉/弹窗；布局改为容器宽度驱动的三栏 → 两栏 → 抽屉 → 单栏；补齐搜索/筛选/分组/计数、时间线聚合与日期分隔、按会话隔离草稿、历史消息上翻、滚动跟随暂停、可搜索转交选人、presence 胶囊与容量、快捷键与无障碍。
4. **分期**：P0 独立窗口 + 页面拆分 + 8 个硬伤修复（前端，约 10 人日）；P1 视觉/交互重构（前端，约 7 人日）；P2 效率增强（需后端契约，另开需求排期）。

**需要拍板的 5 个决策**见 §11，其中「深色工作台保留」「独立窗口形态」「提醒宿主规则」建议按本文推荐执行。

### 1.2 硬约束（方案必须遵守）

1. **同账号单会话**：`aryn-boot/application.yml` 配置 `sa-token.is-concurrent: false`。独立窗口必须**同源复用 localStorage 中持久化的 accessToken**（`packages/stores/src/modules/access.ts:102-110`），**禁止在独立窗口重新登录**，否则主窗口会被顶下线。
2. **hash 路由**：`VITE_ROUTER_HISTORY=hash`（`apps/web-ele/.env.development:15`、`.env.production:13`），新窗口 URL 必须是 `/#/message/service-window` 形态。
3. **布局由路由 meta 决定**：`noBasicLayout` 路由直接 `router.addRoute`，不套 `BasicLayout`（`accessible.ts:38,56-58`）；不能用 `?standalone=1` 去掉布局。
4. **会话失效弹窗只挂 BasicLayout**：`isBasicLayoutContext()` 对 `noBasicLayout` 返回 false（`api/session-invalid.ts:204-216`）→ 401 会降级 `logout()` 并清掉持久化 token（`store/auth.ts`、`store/setup`），会**连主窗口一起登出**。独立窗口必须补挂弹窗并扩展该判定（见 §6.4，阻断点）。
5. **深色工作台是已登记品牌视觉**：管理端 UI 统一文档明确「客服工作台整页深色品牌台」保留、不随主题切换（`docs/50-需求文档/2026-10-22-管理端UI统一/README.md:66,86`）；重构不得推翻，但需把深色作用域做完整。
6. **双模式**：前端请求路径必须由 `parseOpenBoot`/`rewriteBootUrl` 生成（`src/api/boot-url.ts`），P0 不新增任何 API 路径；后端改动必须同时适配 boot/cloud（若 P2 需要）。
7. **契约测试**：`src/store/message-alert-auto.contract.test.ts:41-45` 断言 `layouts/basic.vue` 含 `messageStore.start()`；本轮不能删除主窗口启动链路（独立窗口另行调用 start）。

## 2. 目标与非目标

### 2.1 用户故事

> 坐席在处理订单/配货等其它工作时，把客服工作台弹到第二块屏（或独立窗口），会话列表、新消息提醒、未读计数、回复输入都可用；主窗口继续正常办公。两个窗口不会重复响铃、不会互相顶下线、铃铛点开的消息能定位到正确窗口。

### 2.2 P0 验收口径

1. 工作台顶栏点击「弹出独立窗口」→ 打开独立浏览器窗口（非页签），完整铺满窗口，无管理端侧边栏/顶栏/tabbar；再次点击只聚焦已开的窗口，不重复开窗。
2. 独立窗口刷新、收藏、直接粘贴 URL 均可用；登录态复用，不触发重新登录。
3. 双窗口同时在线：新消息两窗都能收到（WS 各连一条）；**声音/语音/桌面通知只响一次**；无未读提醒重复。
4. 主窗口铃铛点击客服会话 → 独立窗口被聚焦并打开该会话；独立窗口不存在时维持现状（主窗口打开）。
5. 独立窗口关闭/收回后，主窗口提醒恢复；主窗口打开工作台页显示「已在独立窗口运行」横幅与「聚焦/收回」按钮。
6. 会话失效（被顶下线/过期）在独立窗口内弹窗原地重登，**不整页登出**；主窗口同步弹窗（既有 session-sync 行为）。
7. 深色工作台内的下拉/弹窗/抽屉/MessageBox 全部深色，无白底闪屏。
8. 8 个 S0 硬伤修复（草稿串会话、历史消息无法上翻、列表错误静默、滚动被拽底、转交手输 ID、独立窗口不推送、提醒重复、铃铛定位失效）。
9. `pnpm check:type`、`pnpm test:unit`、`pnpm lint`（改动文件）通过；`VITE_OPEN_BOOT=true/false` 两模式下独立窗口可达且 WS 地址正确。

### 2.3 非目标（本期不做）

- 多坐席共享同一窗口、一次并排多个会话、会话转 AI/机器人。
- 移动端/小程序客服工作台。
- 消息撤回、输入中状态、团队快捷回复、会员/订单上下文聚合（P2，需后端）。
- 浏览器 `Document Picture-in-Picture` 置顶浮窗（P2 可选增强，Chrome/Edge only）。

## 3. 总体方案

### 3.1 窗口拓扑

```
                        同一浏览器 / 同一 origin / 同一 token
   ┌────────────────────────────┐        ┌────────────────────────────┐
   │ 主窗口（BasicLayout）       │        │ 独立窗口（noBasicLayout）   │
   │ · 其它业务页面              │        │ · 客服工作台 ServiceDesk    │
   │ · 铃铛 / 站内信             │        │ · 顶栏：状态/容量/收回      │
   │ · WS + HTTP（被抑制提醒）   │        │ · WS + HTTP（提醒宿主）     │
   └───────────────┬────────────┘        └──────────────┬─────────────┘
                   │  BroadcastChannel('aryn-service-desk')│
                   │  hello / alive / bye / locate / read  │
                   │  changed / reclaim / logout / lock    │
                   └───────────────────┬───────────────────┘
                                       │ HTTPS / WSS（同一 accessToken）
                             ┌─────────▼──────────┐
                             │ aryn-message 服务   │
                             │ WS 多 session 推送  │
                             │ presence Redis 90s  │
                             └────────────────────┘
```

### 3.2 关键技术选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| 窗口形态 | 独立浏览器窗口（`window.open` + features） | 可放到第二块屏/其它应用旁边；页签无法满足「同时看到」 |
| 路由 | 前端静态路由 `/message/service-window` + `noBasicLayout` | 有 PageDesigner 先例；不新增后端菜单/SQL；boot/cloud 天然一致 |
| 开窗安全 | **不设 `noopener`**（保留 opener 句柄），命名窗口 `aryn-service-desk` | 可靠去重/聚焦/关闭/reload 后重取句柄；同源固定内部 URL，无用户可控内容，reverse-tabnabbing 风险可忽略。若安全基线强制 `noopener`，退化方案见 §9.4 |
| 跨窗通道 | `BroadcastChannel` 为主，`localStorage` storage 事件兜底，最后 `localStorage` 租约轮询 | 与既有 `session-sync.ts`、`agent-presence.ts` 模式一致 |
| 提醒宿主 | 独立窗口优先；独立窗口不存在时主窗口 | 确定性规则、无需 Web Locks/安全上下文；与用户认知一致（专用工作台负责提醒） |
| WS 连接 | 两窗各连一条 | 后端已支持多 session；保证任一窗口数据新鲜；P2 可优化为单连接 + BC 转发 |
| 深色主题 | 固定深色 + 窗口级 `--el-*` 作用域映射 | 品牌已登记；长时阅读区；避免推翻产品决策 |
| 登录态 | 同源 pinia persist 共享 | `is-concurrent:false` 下唯一安全做法 |

## 4. 独立窗口详细设计

### 4.1 路由与组件结构

新增静态路由（`apps/web-ele/src/router/routes/modules/message.ts`）：

```ts
export default [
  {
    name: 'MessageServiceWindow',
    path: '/message/service-window',
    component: () => import('#/views/message/service-window.vue'),
    meta: {
      title: '客服工作台',
      hideInMenu: true,
      hideInBreadcrumb: true,
      hideInTab: true,
      noBasicLayout: true,
      sessionInvalidModal: true, // 新增 meta：401 走页内弹窗，不降级登出
      keepAlive: false,
    },
  },
]
```

> 说明：`modules/**/*.ts` 默认导出数组，由 `mergeRouteModules` 合并；`accessMode='backend'` 下前端模块路由仍会追加（`accessible.ts:88`），无需后端菜单。`hideInMenu/hideInTab` 保证不出现在菜单与页签。`sessionInvalidModal` 为新增 meta，需同步在 `packages/@core/base/typings/src/vue-router.d.ts` 的 `RouteMeta` 中补类型声明。

组件结构（双壳复用）：

```
#/views/message/service/index.vue          // 嵌入壳（保留给后端菜单 component=message/service/index）
#/views/message/service-window.vue         // 独立壳（新路由）
        └─ 二者都渲染 #/views/message/service/service-desk.vue（props: mode = 'embedded' | 'window'）
```

`index.vue` 保留为薄壳后，后端菜单 `component='message/service/index'`（`db/boot/20message_menu.sql:29-30`）无需改动。

### 4.2 开窗 / 聚焦 / 收回

**开窗**（必须在 click 事件同步调用，`await` 之前）：

1. 若 `deskAlive`（BC 心跳状态）或 `deskWindow && !deskWindow.closed` → 直接聚焦，不重复开窗。
2. URL：`${origin}/#/message/service-window`，可选 `?conversationId=当前会话`；生产带 `VITE_BASE`。
3. `window.open(url, 'aryn-service-desk', features)`；features 建议：
   `width=min(1440, availWidth*0.8), height=min(900, availHeight-80), left=居中偏右, top=60, resizable=yes, scrollbars=yes, menubar=no, toolbar=no, location=no, status=no`。
4. 返回 `null`（被拦截）→ 不静默失败：`ElMessageBox` 提示「浏览器拦截了弹窗」，并提供**用户手势可点的 `<a href target="_blank">`** 降级链接。
5. 记录 `deskWindow` 句柄；`deskWindow` 只代表「本窗口打开的那个」，跨窗口真相以 BC 心跳为准。

**聚焦**：`deskWindow.focus()`；主窗口刷新后句柄丢失时，若 BC 判定存活，用 `window.open('', 'aryn-service-desk')` 重取（命名窗口且未导航）。浏览器拒绝 focus 时降级为 toast「工作台已在独立窗口打开」。

**收回**：主窗口按钮 → BC `reclaim` → 独立窗口在 `pagehide` 前 `window.close()`；`window.close()` 仅对脚本打开的窗口可靠，若失败（用户手动输入 URL 打开）→ 独立窗口 `router.replace('/message/service')` 变成嵌入形态 + toast「无法自动关闭，请手动关闭此窗口」。

**重复窗口防护**：独立窗口启动时广播 `hello`；若 500ms 内收到另一个 `desk alive` → 自认重复：脚本打开的自我 `window.close()`（并广播 `focus` 给已有实例）；无法关闭时显示遮罩「已在另一个独立窗口打开」。主窗口侧再用 `deskAlive` + 开窗中标记双保险。

### 4.3 跨窗口协同协议（核心）

新增 `apps/web-ele/src/store/service-window.ts`（模块单例，不依赖 message store，避免循环依赖）：

- 通道：`BroadcastChannel('aryn-service-desk')`；兜底 `localStorage` key `aryn-service-desk-event` 的 `storage` 事件；再兜底 `localStorage['aryn-service-desk-lease'] = {tabId, role, at}` 每 2s 刷新、对端每 3s 轮询。
- 每个窗口启动生成 `tabId`（同 `session-sync.ts:38-60` 模式）；角色由宿主显式声明：`layouts/basic.vue` 挂载时 `main`，`service-window.vue` 挂载时 `desk`。

**消息协议**

| type | 方向 | payload | 用途 |
|---|---|---|---|
| `hello` | 双向 | `{from, role, at}` | 启动握手；主窗口启动后据此获知独立窗存活 |
| `alive` | desk→main | `{from, at, conversationId?}` | 每 2s 心跳；主窗口判定 `deskAlive`（超时 8s 置 false） |
| `bye` | desk→main | `{from, at}` | 主动关闭，主窗口立即恢复提醒 |
| `locate` | main→desk | `{conversationId}` | 铃铛点击定位会话，desk `focus()` 并打开；P1 扩展到桌面通知点击 |
| `focus` | main→desk | `{}` | 主窗口请求聚焦（focus 被浏览器拒绝时静默） |
| `reclaim` | main→desk | `{}` | 收回工作台 |
| `read` | 双向 | `{conversationId, lastReadSeq}` | 对端 `refreshNotifications()` 收敛未读 |
| `changed` | 双向 | `{conversationId, kind}` | 领取/转交/关闭后对端刷新列表与当前会话 |
| `logout` | main→desk | `{}` | 主窗口登出，desk 自关（失败则跳登录页） |
| `lock` | main→desk | `{locked}` | 锁屏状态同步（desk 显示遮罩） |
| `tenant` | main→desk | `{tenantId}` | 租户切换，desk `location.reload()` |

**提醒宿主状态机**

- `service-window.ts` 暴露 `alertsSuppressed: Ref<boolean>`（或回调注入）。
- `store/message.ts` 的 `alertOnUnreadIncrease()` 开头：`if (serviceWindow.alertsSuppressed.value) return;`（只影响声音/语音/桌面通知，不影响未读计数与 notify 列表刷新）。
- 规则：`desk` 角色启动即 `alertsSuppressed = false`，主窗口收到 `hello/alive(desk)` 后置 `true`；收到 `bye` 或 8s 无 `alive` 后置 `false`。主窗口启动时主动发 `hello`，desk 回 `alive`。
- 兜底：若通道全部不可用，主窗口与独立窗口都会响（可接受降级，文档标注）；租约轮询兜底可把重复率降到极低。

**铃铛定位分流**（`src/layouts/basic.vue:156-173`）：

```ts
if (item.kind === 'conversation') {
  const target = item.link === '/message/direct' ? 'direct' : 'service';
  if (item.conversationId) {
    if (target === 'service' && serviceWindow.deskAlive.value) {
      serviceWindow.locateConversation(item.conversationId); // BC locate + focus
      return; // 主窗口不跳转
    }
    messageStore.requestConversation(item.conversationId, target);
  }
  void router.push(item.link || '/message/service');
  return;
}
```

**已读/会话变更收敛**：工作台 `markActiveRead()` 成功后除现有 `refreshNotifications()` 外，额外广播 `read`；领取/转交/关闭成功后广播 `changed`。对端收到后：`refreshNotifications()` + 若当前会话相同则重拉；跨窗已读无需后端新事件。

**presence**：沿用既有 `aryn-agent-presence` 频道（`store/agent-presence.ts:18,89-104`），两窗各自 30s 心跳续同一 Redis 租约，幂等、关窗不掉线（已验证）。

### 4.4 独立窗口宿主（`service-window.vue`）职责

1. `onMounted`：`messageStore.start()`（音频解锁 + 未读基线 + 连接；`use-conversation-push` 也会幂等 connect）、`agentPresenceStore.activate()`、`serviceWindow.startDeskRole()`（握手 + 心跳 + 接收 locate/reclaim/logout/lock/tenant）、按 `route.query.conversationId` 打开会话。

### 4.5 会话失效处理（阻断点，必须同步修改）

3. `service-window.vue` 挂 `<SessionInvalidModal />`（弹窗挂载点）。
4. `app.vue` 根兜底条件（`loginExpired && matched.length === 0`）不需要改：独立窗口 route 已 matched，由壳内实例承载。
5. 同步更新契约测试：`api/request-session-invalid.test.ts`（新增独立窗口用例）、`store/message-session-invalid.test.ts`（如涉及），并在 `request-session-invalid.test.ts` 的源码断言中登记新 meta 文案。

### 4.6 生命周期与边界

| 场景 | 期望行为 |
|---|---|
| 主窗口切到其它页面 | 独立窗口不受影响；主窗口提醒静默，独立窗口发声 |
| 主窗口关闭 | 独立窗口继续工作（自己 WS/心跳/提醒宿主）；铃铛不存在，无影响 |
| 独立窗口关闭 | 主窗口 8s 内恢复提醒宿主；嵌入工作台页横幅消失 |

| 独立窗口刷新 | 同 URL 直接重载；登录态/路由/WS 恢复；若带 `conversationId` 可恢复选中会话 |
| 直接粘贴 URL 打开 | 可用；无主窗口时自行成为提醒宿主；「收回」无法自动关闭时降级提示 |
| 重复点「独立窗口」 | 聚焦已开窗口，不新开 |
| 浏览器拦截弹窗 | 明确提示 + 可点链接降级 |
| 租户切换 | 主窗口 reload，BC `tenant` 让独立窗口 reload |
| 主窗口锁屏 | 独立窗口显示锁屏遮罩，不可操作 |
| 主窗口登出/被顶下线 | BC `logout` 关闭独立窗口；失效推送本身已有 session-sync 兜底 |
| Redis 不可用 | presence 降级 OFFLINE（后端既有行为），已分配会话仍可收发，UI 文案说明 |

## 8. 风险与兜底

| 风险 | 影响 | 兜底 |
|---|---|---|
| 弹窗被浏览器拦截 | 功能不可用 | 明确提示 + 用户手势可点链接降级；独立窗口按钮旁注明「如未弹出请允许弹窗」 |
| 提醒宿主竞态（desk 刚开/刚关） | 可能短时双响或漏响 | 8s 心跳超时 + `bye` 立即恢复；兜底租约轮询；P1 可加「提醒窗口」设置项 |
| `noopener` 取舍 | focus/close 受限 | 推荐保留 opener（同源固定 URL）；若安全要求 noopener，退化 BC-only（§9.4） |
| `window.close()` 失败（手动 URL 打开） | 收回不彻底 | 降级 `router.replace('/message/service')` + 提示手动关闭 |
| 会话失效误登出 | 主窗口一起被登出 | 阻断点必修：meta 白名单 + 壳内弹窗（§4.5） |
| 同账号单会话 | 独立窗口重登会把主窗顶下线 | 同源共享 token，禁止重新登录；重登走既有 session-restored 广播（两窗一起恢复） |

| 隐藏 tab 定时器节流 | 心跳/租约延迟 | 心跳 30s、租约 90s 有 3 倍余量；desk 后台运行时 WS 事件仍可触发 |

## 9. 备选方案与取舍

### 9.1 应用内浮窗（不推荐）

在主窗口内挂可拖拽浮层，路由切换不卸载。优点：单 WS、零协同。缺点：只在当前标签页内有效，切到其它浏览器标签/应用就看不见，不满足「一边处理其它工作一边回复」；且遮挡业务页面。仅作为弹窗被企业策略禁用时的备选。

### 9.2 新浏览器标签页（不推荐）

`target=_blank` 打开带 BasicLayout 的工作台页。缺点：无法控制窗口尺寸/位置，通常与主窗口同屏抢占；tabbar 会多一个「客服工作台」页签，共享主窗口焦点；仍需同一套多标签提醒协同。可作为极简降级。

### 9.3 置顶浮窗（P2 增强）

`documentPictureInPicture.requestWindow()` 把工作台 DOM teleport 到系统置顶小窗（Chrome/Edge）。适合「必须常驻眼前」的坐席；实现需复制 Element Plus 样式到 PiP 文档、跨 document teleport 与响应式适配，成本高，列为 P2 可选。

### 9.4 `noopener` 安全口径

推荐**不设 `noopener`**：同源、固定内部路由、URL 无用户可控参数、打开的是自家管理端，reverse-tabnabbing 不成立；换来可靠的去重/聚焦/关闭与主窗口刷新后句柄重取。若安全基线强制 `noopener`：保留 §4.3 的 BC 协议作为唯一协同通道，去重改「重复实例自关」、聚焦改「desk 收到 focus 后自我 `window.focus()`（浏览器可能忽略）」，收回改「BC reclaim + 自关」，功能可用但边界体验略降。
