## 一、目标态

1. **专区商品管理页**（新页面）：以专区为主体管理商品集合——查看/筛选专区商品、添加商品、批量设置规则、批量移出、查看生效状态、操作记录与撤销。
2. **列表页批量操作弹窗 v2**：打开即预检（已在/未加入/规则将变/无变化、SKU 精调、异常），动作拆分为「加入/更新规则、移出专区、不修改」，提交后展示结果面板（成功/无变化/失败/同步状态），支持失败重试、查看本次商品、撤销批次。
3. **单商品专区标签**：编辑页「专区标签」改走专用接口，支持 SKU 级精调与显式清空，不再依赖通用商品保存。
4. **后端能力**：批量预检、批量执行变更识别与结果明细、按筛选取 ID、专区商品分页、批量状态查询、批次记录/撤销、同步状态与手动重试；修复幽灵历史、同步失败清空活动、批量/单商品校验不一致、审计缺 operator。
5. **一致性**：批量与单商品共用同一套规则校验；批量 ≤200/请求，前端超过自动分片；服务端 SQL 固定排序。

非目标（本期不做，文档留待后续）：服务端异步批次任务（用前端分片替代）、价格预览接口（列表展示基础生效状态即可）、独立权限点（复用 `product:goodsspu:edit` / `promotion:shipactivity:page`）、标签/规则分离的 `ruleOnly` 能力。

## 二、后端接口契约

约定：以下均为 `Result<T>` 包装后的 `data`；写接口沿用现有权限点 `product:goodsspu:edit`，读接口 `product:goodsspu:page`/`product:goodsspu:get`；cloud 路径首段为 `product`，boot 模式由前端 `rewriteBootUrl` 改写，后端不得硬编码 `/boot`；租户一律由拦截器注入。

### 2.1 批量预检（只读）

`POST /product/goodsspu/tags/batch/preview`

请求：

```json
{
  "spuIds": ["id1", "id2"],
  "memberAction": "ADD | REMOVE | NONE",
  "memberDiscountRate": 0.9,
  "memberPriceFixed": null,
  "clearanceAction": "ADD | REMOVE | NONE",
  "clearancePrice": null,
  "clearanceDiscountRate": 0.9,
  "clearanceExpireTime": "2026-12-31 23:59:59",
  "overwriteSkuRules": false
}
```

- `spuIds` 去重后 1–200；超限返回业务错误「单次最多处理 200 个商品，请分批提交」。
- `*Action` 为 `NONE`/缺省表示该专区不修改；`ADD` 表示加入（已在则更新规则）；`REMOVE` 表示移出。
- `ADD` 时规则字段可空（空=沿用旧规则/专区默认折扣）；`REMOVE` 时忽略规则字段。

响应：

```json
{
  "summary": { "total": 10, "add": 2, "update": 0, "noChange": 8, "remove": 0, "invalid": 0, "warningCount": 2, "skuOverridesWillClear": 3 },
  "zones": [
    { "zone": "member", "existing": 8, "willAdd": 2, "willUpdate": 0, "willRemove": 0, "noChange": 8, "withSkuOverride": 3, "invalid": 0 },
    { "zone": "clearance", "existing": 1, "willAdd": 0, "willUpdate": 0, "willRemove": 0, "noChange": 10, "withSkuOverride": 0, "invalid": 0 }
  ],
  "items": [
    {
      "spuId": "...", "spuName": "...", "spuStatus": "1",
      "before": {
        "memberTag": 1, "memberDiscountRate": 0.8, "memberPriceFixed": null, "memberPriceFloor": null,
        "clearanceTag": 0, "clearancePrice": null, "clearanceDiscountRate": null, "clearanceExpireTime": null,
        "skuOverrideCount": 2
      },
      "changes": [
        { "zone": "member", "type": "UPDATE", "warnings": [{ "code": "SKU_OVERRIDE_PRESERVED", "message": "3 个 SKU 保留已有精调" }] },
        { "zone": "clearance", "type": "NO_CHANGE", "warnings": [] }
      ],
      "warnings": [{ "code": "OFF_SHELF", "message": "商品已下架，打标后 C 端不展示" }]
    }
  ]
}
```

- `type` 枚举：`ADD | UPDATE | REMOVE | NO_CHANGE | INVALID`。
- `INVALID` 表示该专区本次动作会被拒绝（如出清 ADD 无规则且专区未配置默认折扣）；提交时该商品该专区失败并返回错误码。
- `warnings[].code` 固定集合：`NO_RULE / ZONE_DEFAULT_RATE / INVERTED_PRICE / OFF_SHELF / EXPIRED / RECENT_SALES_INCREASE / SKU_OVERRIDE_PRESERVED / SKU_OVERRIDE_CLEARED / MEMBER_FIXED_KEPT`。

### 2.2 批量执行（替换原响应结构）

`POST /product/goodsspu/tags/batch`

请求：沿用 `GoodsZoneTagBatchDTO` 旧字段（`memberTag:true/false/null`、`clearanceTag`、规则、`overwriteSkuRules`），语义：

- `memberTag=true` → 加入/更新会员专区规则；`false` → 移出；`null`/缺省 → 不修改。
- `clearanceTag` 同理；`overwriteSkuRules=true` 时才清空 SKU 精调，同时也会把 SKU 显式排除 (`is_*_item=0`) 重置为继承。
- 至少一个动作，否则业务错误「请选择会员或出清标签操作」。

响应：

```json
{
  "batchId": "批次号（落库，可撤销）",
  "summary": { "requested": 10, "success": 10, "changed": 2, "added": 2, "updated": 0, "removed": 0, "noChange": 8, "failed": 0 },
  "zones": [
    { "zone": "member", "added": 2, "updated": 0, "removed": 0, "noChange": 8, "failed": 0 }
  ],
  "sync": { "status": "SUCCESS | FAILED | SKIPPED", "message": null, "finishedAt": "2026-11-04 10:00:00" },
  "items": [
    {
      "spuId": "...", "spuName": "...", "success": true,
      "changeType": "ADD | UPDATE | REMOVE | NO_CHANGE | INVALID",
      "changes": [{ "zone": "member", "type": "ADD", "before": { }, "after": { } }],
      "message": "OK",
      "errorCode": null,
      "warnings": [{ "code": "NO_RULE", "message": "未配置商品规则，将使用专区默认折扣" }]
    }
  ]
}
```

- `sync.status=FAILED` 时 `message` 给失败原因；前端不得再显示「价格已同步」，要提示「标签已保存，价格同步失败可重试」。
- `errorCode`：`SPU_NOT_FOUND / INVALID_RULE / NO_ORIGINAL_PRICE / EXPIRED_TIME / ZONE_TAG_LIMIT / SYNC_FAILED（仅 sync）/ NO_ACTION`。
- `changeType=NO_CHANGE` 的条目允许 `changes` 内为对应 zone 的 `NO_CHANGE`。

### 2.3 批量读取专区状态

`POST /product/goodsspu/tags/query` 请求 `{ "spuIds": [...], "withSkus": true }`（≤200）
响应 `items[]`：同 2.1 的 `before` + `changes: []`（全为 NO_CHANGE 不返回）+ `skus[]`（`withSkus=true` 时：`skuId/specsName/salesPrice/originalPrice/isMemberItem/.../hasOverride`）。

单商品详情沿用并增强 `GET /product/goodsspu/tags/{spuId}`：新增 `skuOverrideCount`、`warnings[]`（同 warning code），SKU 行新增 `hasOverride: boolean`。

### 2.4 单商品专区标签保存（增强）

`PUT /product/goodsspu/{spuId}/tags`

请求在 `GoodsZoneTagSaveDTO` 基础上新增：

- `clearMemberRule?: boolean`：显式清空 SPU 会员规则（折扣/固定价/下限），不影响标签；
- `clearClearanceRule?: boolean`：显式清空 SPU 出清规则（价格/折扣/到期时间）；
- `replaceSkuRules?: boolean`：为 `true` 时，`skus[]` 中出现的 SKU 按提交值**精确覆盖**（null=清空该字段，恢复继承），未出现的 SKU 不动；为 `false/缺省` 时沿用旧语义（null=不修改）。

### 2.5 按筛选条件取 ID（支撑全选筛选结果 / 换一批）

`POST /product/goodsspu/ids`

```json
{
  "zoneType": "member | clearance | none | not_member | not_clearance",
  "name": "", "categorySecondId": "", "brandId": "", "status": "",
  "limit": 500
}
```

响应：`{ "total": 18, "ids": ["..."], "truncated": false }`；服务端固定 `ORDER BY id ASC`，`limit` 默认 500、上限 1000。

- `zoneType` 新增 `not_member`（`is_member_item` 为 0/NULL）与 `not_clearance`（`is_clearance_item` 为 0/NULL），供「添加商品」候选筛选；原 `member/clearance/none` 保持。

### 2.6 专区商品管理分页

`GET /product/goodsspu/zone/page?zoneType=member&current=1&size=10&name=&categorySecondId=&brandId=&status=`

响应 `IPage<ZoneGoodsRowVO>`，`records[]`：

```json
{
  "id": "...", "name": "...", "subTitle": "...", "spuUrls": [], "categoryName": "...", "brandName": "...",
  "salesPrice": 39.9, "originalPrice": 59.9, "status": "1", "stock": 100,
  "isMemberItem": 1, "memberDiscountRate": 0.9, "memberPriceFixed": null, "memberPriceFloor": null,
  "isClearanceItem": 0, "clearancePrice": null, "clearanceDiscountRate": null, "clearanceExpireTime": null,
  "skuOverrideCount": 2,
  "state": "NORMAL | NO_RULE | INVERTED | EXPIRED | OFF_SHELF",
  "stateLabel": "生效中 | 未配规则 | 倒挂不生效 | 已到期 | 已下架",
  "effectivePrice": 35.91,
  "zoneType": "member"
}
```

- `state` 口径：`OFF_SHELF` 优先（status != '1'）；出清 `EXPIRED`（截止时间 ≤ now）；`NO_RULE`（SPU 与知有 SKU 均无可用规则且专区默认折扣为空）；`INVERTED`（按 SPU 规则算出的价 ≥ 售价，且无更低 SKU 覆盖）；否则 `NORMAL`。
- `effectivePrice` 按 SPU 级规则计算（member：`min(sales*rateOrZoneDefault, fixed)`；clearance：`fixed` 或 `original*rateOrZoneDefault`；有 SKU 覆盖时展示 SPU 口径并在前端加「含 SKU 精调」标记）。

### 2.7 批次记录与撤销

- `GET /product/goodsspu/tags/batch/page?current=1&size=10` → `IPage<ZoneTagBatchVO>`，`records[]`：`{batchId, operatorName, createTime, total, changed, failed, noChange, memberAction, clearanceAction, syncStatus, undoStatus, undoTime}`
- `GET /product/goodsspu/tags/batch/{batchId}` → `{...header, items: ZoneTagBatchItemVO[]}`
- `POST /product/goodsspu/tags/batch/{batchId}/undo` → `{batchId, restored, skipped, conflicts: [{spuId, spuName, reason}]}`；仅当商品当前值仍等于该批次 after 值才回滚，冲突项跳过并报告；撤销后原批次 `undoStatus=UNDONE`。

### 2.8 专区同步状态与手动重试（promotion 域）

- `GET /promotion/zone/sync-status` → `{ "zones": [{ "zone": "member", "enabled": true, "activityId": "...", "activityStatus": "PUBLISHED", "rulesSkuCount": 18, "lastSyncTime": "...", "lastSyncStatus": "SUCCESS | FAILED | UNKNOWN", "lastError": null }], "checkedAt": "..." }`
- `POST /promotion/zone/sync` → 触发当前租户重算，返回同上结构。

同步状态落 `mall_zone_setting` 新增字段：`last_sync_time`、`last_sync_status`、`last_sync_error`。

### 2.9 关键后端语义修复（与接口配套，必须一起交付）

1. `RemoteGoodsZoneTagServiceImpl#listZoneSkus` 查询失败**不得再吞异常返回空列表**；`syncTenant` 收到异常即失败，不得用空快照覆盖非空 rules（G13）。
2. `recordSpuTagChanges` 只记录本次真正触碰且值发生变化的字段，禁止对未触碰专区写「旧值→null」幽灵历史（G22）；`operator` 从登录态写入（G23）。
3. 批量与单商品共用同一套校验（`GoodsZoneTagRuleValidator`）：出清 `ADD` 无规则时，若专区默认折扣存在则允许并告警，否则该条 INVALID/失败（G5）。
4. 批量使用批量查询（一次 SPU IN 查询 + 一次 SKU IN 聚合）替代逐条 N+1；仅在 `changed>0` 时触发同步；同步结果写入批量响应（G10/G11/G13）。
5. `@SysLog` 切面与监听器注册为 Bean，并写入 `requestParams` 摘要（batchId、动作、规则、spuIds 截断）（G21）。

### 3.3 共享组件（T2 owner，T1 直接 import）

1) `src/views/product/zone-batch/components/ZoneBatchDialog.vue`

```
props:
  visible: boolean
  spuIds: string[]
  zoneScope?: ZoneType | 'both'   // 默认 'both'
  mode?: 'standard' | 'remove'    // 默认 'standard'；remove 用于「移出专区」
  defaultAction?: ZoneAction      // 2026-11-04 补充：默认 'NONE'；standard 模式下对 zoneScope 范围生效，

  title?: string
emits:
  update:visible
  done: [{ batchIds: string[]; summary: ZoneBatchResult['summary'] | null; failedCount: number }]
```

行为要求：

- `visible=true` 时调用 `previewZoneTags`，展示顶部汇总 + 分专区状态（已在/未加入/规则将变/无变化/SKU 精调/异常）；
- 每个专区动作单选：standard 模式只允许 `加入/更新规则`、`不修改`；`mode='remove'`（「移出专区」独立入口）只允许 `移出专区`、`不修改` 且默认移出；
  （2026-11-04 验收调整：移出为破坏性动作，从普通规则设置弹窗中拆出，避免入口重复与混排误操作）
- `加入/更新规则` 时展示规则字段（会员：折扣率/固定价；出清：出清价/折扣率/截止时间），并展示「不填=沿用旧规则/专区默认折扣」提示；
- 底部实时影响汇总（新增/更新/移出/无变化/失败预警）与确认按钮（`确认：加入 2 件 / 更新 8 件`、`确认移出 10 件`）；
- 提交时按 200/片分片调用 `batchZoneTags`，展示进度；全部完成后切到结果面板：成功/无变化/失败明细 + `sync.status`（失败时提示价格同步失败，不显示「已同步」）+ 操作按钮：`复制失败清单`、`重试失败 N 件`、`查看本次商品`（打开明细表）、`撤销本批次`（单批次时）、`完成`；
- 全部无变化时确认按钮禁用并提示「所选商品均无需变更」；
- `done` 在用户关闭结果面板时触发；刷新由使用方在 `done` 后自行调用。
- 不负责「选择商品」，只接收 `spuIds`。

2) `src/views/product/zone-batch/components/ZoneSkuEditor.vue`


行为要求：
