```

      + 订单配送上下文(way=4) + 支付幂等 + 共享购物车 + 履约波次
      + Web工作台 + 小程序上下文/结算/船供目录
```

## 2. 核心领域概念（先读）

| 概念 | 取值 | 说明 |
|---|---|---|
| 购买场景 `purchase_scene` | 1 海员个人购买；2 船供采购 | **订单级**快照，决定展示、数量规则与活动匹配 |
| 商品销售范围 `sale_scope` | 1 仅个人；2 仅船供；3 两者均可 | **商品级**，与订单场景相互独立 |
| 配送方式 `delivery_way` | 1 普通快递；2 上门自提；3 商城配送；**4 公司港口/船舶内部配送** | 4 = 公司自有司机按靠港计划送到港口/船舶，无快递单号 |
| 靠港计划 `vessel_call` | ETA / ETD / 泊位 / 配送时间窗 | 一切配送安排的时间基准；仅“计划中”状态可修改 |
| 靠港状态 | 1 计划中 2 靠泊中 3 已完成 4 已取消 | 已离港（ETD 已过）/已完成/已取消的靠港**不能作为新订单配送计划** |

**关键强制规则**
- `purchase_scene=2`（船供采购）**必须**使用 `delivery_way=4`。
- 船供可见商品（sale_scope=2/3）必须提供 IMPA/ISSA/内部编码**之一**，且每个 SKU 必须有采购单位、MOQ（≥1）、步长（>0），MOQ 必须是步长整数倍。
- 内部配送结算时服务端校验：下单用户必须是该船**在船成员**、靠港计划未离港、靠港与船舶匹配。
- 订单/配送/营销全部落**快照**：改商品、改 ETA、改活动都不影响历史订单记录。

## 3. Web 管理端功能

### 3.1 商品中心增强

**位置**：商品管理 → 全部商品（页面内切换“船供目录”视图）；商品编辑页新增“船供资料”Tab。

#### 3.1.1 船供目录视图
1. 商品列表页点击右上角 **「船供目录」** 按钮，切换为船供视图。
2. 筛选：销售范围（仅船供/个人+船供）、编码/英文名关键词（匹配 IMPA、ISSA、条码、内部编码、中英文品名、搜索别名）。
3. 列表列：商品信息（中英文）、销售范围、IMPA/ISSA、内部编码、采购单位、箱规、MOQ、步长、库存、售价、资料完整度。
4. 点击 **「导出」** 按当前筛选导出 Excel（14 列，文件名“船供商品目录.xlsx”）。

接口：`GET /product/goodsspu/ship/page`、`GET /product/goodsspu/ship/export`
权限：`product:goodsspu:page`

#### 3.1.2 船供资料维护（商品编辑 → 船供资料 Tab）
1. 打开商品编辑页（修改已有商品）→ 切到 **「船供资料」** Tab。
2. 填写：销售范围（必选）、IMPA/ISSA/内部编码（三者至少其一，船供可见时必填）、条形码、英文品名、储存条件（常温/冷藏/冷冻/危险品/其他）、保质期天数、温度要求、搜索别名、船供说明。
3. 下方 SKU 表格逐行填写：采购单位、箱规、MOQ、步长。
4. 页面实时显示**资料完整度**（按关键字段填充比例 0–100%）与发布检查结论（不满足项红字提示，“保存船供资料”按钮置灰）。
5. 点击 **「保存船供资料」**——资料/SKU 包装/编码映射**同一事务**保存。
6. 顶部「发布检查清单」始终显示是否满足进入船供目录的要求。

规则细节：
- 个人商品（sale_scope=1）不强制 IMPA，数量规则仅在填写时校验。
- 编码映射采用“同键复活”策略：同租户同编码全生命周期一行，重新启用更新原行，不产生重复。
- 新增商品需先保存基本信息，再维护船供资料。

接口：`GET /product/goodsspu/profile/{spuId}`、`POST /product/goodsspu/profile`
权限：`product:goodsspu:edit`（保存）、`product:goodsspu:get`（查看）

#### 3.1.3 Excel 批量导入（四步流程）
1. 商品列表页点击 **「批量导入」**，弹窗内先点 **「下载 Excel 模板」**（服务端生成 .xlsx，首行为中文标题）。
2. 选择填写好的 `.xlsx` 文件上传 → **服务端解析**（EasyExcel，按标题行映射字段），解析行落库 `product_import_row`。
3. 页面即时显示预览汇总：总行数 / 可导入行数 / 错误行数，错误明细表（行号、错误类型、说明）。
4. 点击 **「确认导入」**——服务端从解析行**重新校验**后写入有效行，变更写入审计日志 `product_change_log`。

错误类型（10 类）：空名称、同批次重复编码、同批次重复 SKU、非法价格、非法库存、MOQ/步长不合规、未知类目、未知品牌、更新目标不存在、跨租户编码。

规则细节：
- 更新商品只能按 **SKU ID / IMPA / 内部编码** 匹配（matchType 列），**禁止按名称覆盖**；名称仅作展示信息同步。
- 同一租户同一编码只能绑定一个有效 SKU；跨租户编码直接拦截。
- 单次上限 10000 行（超出请拆分文件）；预览时有效的行在确认时若数据已变化会被重新校验拦截。
- CSV 为兼容路径（前端解析），推荐统一使用 Excel。

接口：`GET /product/product-import/template`、`POST /product/product-import/upload`、`POST /product/product-import/{jobId}/confirm`、`GET /product/product-import/{jobId}/errors`
权限：`product:import:template` / `product:import:preview` / `product:import:confirm`

### 3.2 船舶与靠港（菜单：船供运营 → 船舶档案 / 靠港日历）

#### 3.2.1 船舶档案
1. **新增船舶**：名称必填，可填英文名、IMO、呼号；同一租户 IMO 不可重复。
2. **修改/停用/恢复**：行内操作；停用后船舶不再出现在 C 端“我的船舶”。
3. **成员管理**：输入商城用户 ID + 角色（普通船员/采购确认人）绑定；绑定即授权该用户在 C 端访问该船上下文与共享购物车。**绑定必须由后台操作，不开放用户自助搜索。**
4. **靠港计划**：港口编码/名称必填、ETA 必须早于 ETD、配送时间窗必须落在 ETA–ETD 之间；仅“计划中”可修改。

接口：`GET /vessel/admin/page`、`POST /vessel/admin`、`PUT /vessel/admin/{id}`、`GET|POST /vessel/admin/{id}/members`、`GET|POST /vessel/admin/{id}/calls`、`PUT /vessel/admin/calls/{id}`
权限：`vessel:vessel:page/save/update`、`vessel:member:list/save`、`vessel:call:list/save/update`

#### 3.2.2 靠港日历
1. 菜单进入，默认加载本月~次月；可自定义起止时间（yyyy-MM-dd HH:mm:ss）。
2. 列表按 ETA 升序展示区间内全部船舶的靠港（含船舶名、泊位、时间窗、状态），用于排产与调度总览。

接口：`GET /vessel/admin/calls/calendar?start=&end=`

#### 3.2.3 ETA 修改自动提醒（零成本方案）
1. 在靠港计划中点击 **「修改」** 保存 ETA/ETD/泊位/时间窗任一变化时：
   - 系统自动写入变更日志（旧值/新值/操作人，表 `vessel_call_change_log`）；
   - 自动计算影响面并**站内信通知**受影响用户（该靠港下未完成订单的下单用户 + 收集中/待确认共享购物车的发起人与确认人），内容含新旧时间对照与涉及订单号；
   - 通知失败不影响保存（fail-open），消息处理失败由 MQ 重试（幂等）。
2. 修改前可点 **「影响面」** 按钮预览：未完成订单数（前 10 单号）、共享购物车数、拣货波次数——辅助决定是否调整。
3. **快照原则**：已支付订单的配送上下文不会被自动改写，仅提醒用户重新确认安排。

接口：`GET /order/fulfillment/vessel-call-impact?vesselCallId=`

### 3.3 履约作业（菜单：船供运营 → 拣货波次 / 履约异常）

#### 3.3.1 拣货波次全流程
```
新建波次 → 订单加入 → 扫码拣货 →（短装登记）→ 复核 → 交接司机
```
1. **新建波次**：必填目的港口编码；可关联靠港计划与计划交付时间。同港口订单才会被允许加入（时间窗相近的订单合并作业）。
2. **加入订单**：波次明细弹窗输入订单 ID 加入；订单必须是待发货状态、目的港口与波次一致、且未加入过其他波次。加入后波次进入“拣货中”，按订单明细生成拣货明细（含条码快照）。
3. **扫码拣货**：输入明细 ID + 条码（或 SKU ID）+ 数量。SKU 不匹配拒绝、累计数量超应拣拒绝；拣满自动转“已拣”。
4. **记录短装**：输入明细 ID、实际数量、原因（缺货/破损/错发）与说明——**原因必填**；自动生成待处理履约异常。
5. **复核**：全部明细已拣/短装后才允许；复核通过进入“已复核”。
6. **交接司机**：复核通过后操作；**交接后仓库不能再修改明细**（扫码/短装/加单均拒绝）。

接口：`POST /order/fulfillment/wave`、`GET /order/fulfillment/wave/page`、`GET /order/fulfillment/wave/{waveId}/items`、`POST /order/fulfillment/wave/{waveId}/orders?orderId=`、`POST /order/fulfillment/pick/scan`、`POST /order/fulfillment/pick/short`、`POST /order/fulfillment/wave/{waveId}/review`、`POST /order/fulfillment/wave/{waveId}/hand-over`
权限：`fulfillment:wave:page/save/pick/review/hand-over`

#### 3.3.2 履约异常与照片留证
1. 波次明细弹窗点 **「异常上报」**：选类型（缺货短装/错发/破损/替代/其他）、订单 ID、描述、**上传证据照片**（多张，存入素材服务，URL JSON 落 `fulfillment_exception.evidence_urls`）。
2. 履约异常列表：展示类型/订单/描述/波次/**证据缩略图**（点击放大）/状态/处理说明。
3. **关闭异常**：填处理说明后关闭（已关闭不可再操作）。

接口：`POST /order/fulfillment/exception`、`GET /order/fulfillment/exception/page`、`POST /order/fulfillment/exception/{id}/close`
权限：`fulfillment:exception:page/save/close`

#### 3.3.3 港口配送看板
1. 输入港口编码 + 日期（默认今天）刷新。
2. 汇总卡片：波次总数 / 待拣·拣货中 / 已交司机 / 短装明细数。
3. 下方波次明细表按计划交付时间排序——用于当日出车调度总览。

接口：`GET /order/fulfillment/port-board?portCode=&date=`

### 3.4 共享购物车管理（菜单：船供运营 → 共享购物车）
1. 分页查看全部共享购物车（编号/靠港/发起人/状态/截止时间/生成订单），支持编号与状态筛选。
2. **详情**双 Tab：
   - 成员：用户、角色（发起人/成员/确认人）、是否可确认、加入时间；
   - 明细：SPU/SKU、申请数量、核定数量、成员备注、状态、来源成员——用于核对多人合并采购。
3. 只读管理视图；提交动作仍由 C 端确认人完成。

接口：`GET /order/shared-cart/page`、`GET /order/shared-cart/{id}`
权限：`sharedcart:page` / `sharedcart:get`

### 3.5 营销中心（菜单：船供运营 → 船供活动）

#### 3.5.1 活动类型与规则格式
| 类型 | 规则 JSON | 语义 |
|---|---|---|
| 4 船供阶梯价 | `{"ladders":[{"minQty":50,"unitPrice":24},{"minQty":10,"unitPrice":26}]}` | 单 SKU 数量达到 minQty 后按档位单价成交；**单价必须随数量递减** |
| 7 船供整船优惠 | `{"tiers":[{"minAmount":2000,"discountAmount":100}]}` | 整单商品基价达 minAmount 减 discountAmount；优惠随门槛不减少 |
| 5 买赠 | `{"minAmount":1000,"gifts":[{"skuId":"xxx","quantity":2}]}` | 整单满额送赠品（0 元独立明细，不混入付费数量） |
| 常购专属价（用类型 4 + 范围 8） | `{"ladders":[{"minQty":1,"unitPrice":25}]}` + scopeType=8 + scopeValue=SKU 列表 | 用户近 90 天买过的指定 SKU 享受专属单价 |

适用范围 scopeType：1 全场 / 2 指定 SKU / 4 指定场景 / 5 指定船舶 / 6 指定靠港 / 7 指定港口 / **8 常购用户**；可另限定购买场景（个人/船供）。

#### 3.5.2 活动生命周期操作
1. **新建**：名称、类型、范围、限定场景、起止时间、规则（结构化编辑，自动转 JSON）→ 保存为草稿。
2. **发布**：先做规则结构校验（档位重复/单调性/赠品完整性），再做**冲突检索**（同类型、时间重叠的已发布/暂停活动）——有冲突弹确认框列出重叠活动名，确认后强制发布（运行时同类型取最优，不会错价）。
3. **暂停/编辑/删除**：已发布活动**核心规则与范围不可改**（只能暂停或新建版本）；草稿/暂停可编辑；已发布需先暂停才能删除。

接口：`GET /promotion/ship-activity/page`、`GET|PUT|DELETE /promotion/ship-activity/{id}`、`POST /promotion/ship-activity`、`GET /promotion/ship-activity/{id}/conflicts`、`POST /promotion/ship-activity/{id}/publish?force=`、`POST /promotion/ship-activity/{id}/pause`
权限：`promotion:shipactivity:page/save/publish`

#### 3.5.3 优惠计算规则（交易侧自动执行）
- 计算时序：**结算 preview → 下单 reserve → 支付成功 confirm → 取消/超时 release**，全部以“订单+活动”维度幂等。
- 同类取最优（同类型多个命中取优惠最大者）；跨类型固定顺序：**阶梯价改 SKU 成交基价 → 会员折扣 → 优惠券 → 整船优惠按可折金额占比分摊到明细** → 买赠追加 0 元赠品明细。
- 订单落 `promotion_snapshot` 快照：历史订单金额不随活动修改/结束/删除变化。
- 营销服务不可用时按无优惠继续交易（不阻断下单），常购画像查询失败按不命中处理（不误发优惠）。

### 3.6 订单管理增强
- 订单列表新增**购买场景**筛选与列（船供采购/个人购买）。
- 订单详情页顶部显示：**内部配送上下文**（船舶 · 港口 · 泊位 · 时间窗 · 场景）与**营销优惠块**（整单优惠金额 + 命中活动明细列表，来自营销快照）。
- 接口：`GET /order/promotion-snapshot/list?orderId=`（权限 `order:orderinfo:get`）。

## 4. 小程序功能

### 4.1 首页船舶工作台
登录后自动加载“我作为在船成员的在营船舶”并选择默认靠港：
- 顶部卡片显示 **当前船舶 + 下一靠港（港口/泊位/时间窗起点）**；
- 三个入口：**船供采购**（切场景 2 并进入采购页）、**个人购买**（切场景 1 进商品页）、**常购**（进常购清单）；
- 未登录或无船舶成员关系时不显示工作台（走普通零售路径）。

上下文持久化于本地（`shipContextStore`），但**仅用于恢复界面，权限事实以服务端结算校验为准**。

### 4.2 船供采购页
1. 顶部显示当前船舶/靠港；搜索框支持 **IMPA / ISSA / 条码 / 内部编码 / 中英文品名**。
2. 列表行直接展示：IMPA、内部编码、箱规、采购单位、起订量、步长、售价。
3. 行内直填数量 → **加入购物车**：本地即时校验 MOQ（“未达最小起订量 X”）与步长（“数量需为 X 的整数倍”），服务端结算仍会再次校验。
4. 数据接口：`GET /product/app/goodsspu/ship/page`、`GET /product/app/goodsspu/search?scene=2&keyword=`。

### 4.3 常购清单
- 首页 → 常购：展示近 90 天购买过的商品（累计件数/次数），“再来一份”按历史数量一键加购。
- 接口：`GET /mall-order/app/orderinfo/frequent-purchase`。

### 4.4 商品详情（船供视图）
- 有船供资料的商品在详情页展示 **ShipProfileCard 卡片**：IMPA/ISSA/内部编码、储存条件、采购单位、箱规、MOQ、步长，以及“公司司机按靠港计划送达港口/船舶”配送说明。
- 接口：`GET /product/app/goodsspu/ship-summary/{spuId}`。

### 4.5 购物车防串船分组
1. 每次加购自动携带**当前船舶/靠港/场景**归属（API 层统一注入，无需页面关心）。
2. 购物车页按靠港分组显示：**当前船舶组排前**，其他靠港的组标注红字“（结算前请切换船舶）”；历史无归属的行归入“未指定配送计划”组（放行兼容）。
3. 结算拦截：购物车下单（createWay=1）且当前已选靠港时，所选行中如有属于**其他靠港**的商品，支付被拦截并提示“有 N 件商品属于其他靠港计划，请切换船舶或调整购物车”。

### 4.6 结算与下单（内部配送）
1. 已选靠港时结算默认 `delivery_way=4`，页面显示**配送上下文卡片**（船舶、港口、泊位、时间窗、“公司司机按靠港计划送达”）。
2. 收货地址选择仅普通快递/商城配送显示；way=4 不要求地址。
3. 支付前校验：way=4 必须已有船舶+靠港上下文，否则提示“请先在首页选择船舶和靠港计划”。
4. 请求参数自动携带 `purchaseScene / vesselId / vesselCallId`；服务端再次校验成员身份、靠港可用性并落快照。
5. 结算返回**营销优惠明细**：阶梯价（提示“明细已按档价计价”）、整船优惠（名称 + 金额）、整单优惠合计。

### 4.7 订单跟踪与再购
- **配送进度时间线**：内部配送（way=4）与商城配送共用时间线组件，展示支付→配货→司机取货→到港→签收各节点。
- **再来一单**：订单详情“再来一单”按钮 → 预览原明细当前可购状态（现价/现库存/可购标记与原因）→ 可购项一键加购，不可购项提示原因跳过。**不直接下单**——必须重新确认船舶/靠港/价格/库存后走正常结算。
- 接口：`GET /mall-order/app/orderinfo/{id}/reorder-preview`。

### 4.8 共享购物车（C 端）
1. 发起人（船舶成员）创建：绑定船舶+靠港（创建后不可变），进入“收集中”。
2. 邀请成员：发起人按用户 ID 邀请，可设“采购确认人”角色。
3. 成员各自添加/修改/移除**自己的**明细（数量 + 备注），无法触碰他人明细。
4. 确认人（canConfirm）可调整各明细**核定数量**后统一提交 → 生成**一个整船订单**：同 SKU 数量自动合并、明细保留贡献者与备注快照；提交前服务端校验 MOQ/步长/价格/库存/成员关系。
5. 提交幂等（重复确认返回原订单）；发起人可关闭未提交的购物车。
6. 接口：`POST /mall-order/app/shared-cart`、`GET .../{id}`、`GET|POST .../{id}/members`、`GET|POST|PUT|DELETE .../{id}/items`、`POST .../{id}/confirm`、`POST .../{id}/close`。

### 4.9 司机模式
- 沿用同一小程序的司机身份体系（配送资格免密换取）。
- 配送任务详情新增**配送上下文卡片**：船舶（含场景标签 船供采购/个人购买）、港口+泊位、时间窗快照——司机按快照执行，不依赖实时档案。
- 任务流程不变：取货 → 到港 → 签收拍照 → 异常上报。

### 4.10 消息通知
- 靠港计划变更（ETA/ETD/泊位/时间窗）自动向受影响用户发送**站内信**（小程序消息中心可见），含新旧时间对照与涉及订单号。
- 支付成功、派单等既有通知保持不变。

## 8. 关键行为边界与容错（运维/排障必读）

| 场景 | 行为 |
|---|---|
| 支付回调重复投递 | 订单状态条件更新 + 配送任务唯一键（tenant+order）双保险，只产生一个任务；已取消订单拒绝补建 |
| 营销服务不可用 | 结算/下单按**无优惠**继续（fail-open），日志告警 |
| 常购画像查询失败 | 常购专属价按**不命中**处理（fail-closed，防误发） |
| ETA 变更事件发布失败 | 变更日志已落库，仅告警；消息消费失败走 MQ 重试（eventId 幂等） |
| 靠港已离港 | 不可作为新订单配送计划（查询与校验双拦） |
| Excel 超一万行 | 拒绝并提示拆分（异步任务化列入后续） |
| 已发布活动改规则 | 拒绝（暂停或新建版本）；时间重叠发布需 force 确认 |
| 购物车跨靠港结算 | 小程序端拦截提示；服务端结算按当前上下文校验兜底 |
| 权限不生效 | 授权后重新登录（登录快照机制） |

## 9. 试点验收清单（摘要，全文见《试点上线清单.md》）

1. **个人购买链路**：选船 → 个人商品 → 支付 → 配货 → 派司机 → 到港 → 签收（结算默认 way=4、重复支付回调单任务）。
2. **船供采购链路**：船供搜索 → 批量加购 →（共享购物车多人合并）→ 提交 → 波次拣货 → 交接 → 船上签收（MOQ 拦截、合并正确性）。
3. **司机链路**：免密进司机模式 → 任务含船舶上下文 → 扫码/拍照 → 异常上报。
4. **营销链路**：配置阶梯价/整船优惠 → 结算金额与快照一致 → 取消后优惠释放。
5. **ETA 链路**：改靠港 ETA → 受影响用户收到站内信 → 影响面数字与实际一致。
6. **防串船**：船 A 加购 → 切船 B → 结算被拦截。
7. **零售兼容**：普通租户地址配送/优惠券/购物车不受影响。
