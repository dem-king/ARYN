# 一期实现契约（三端共用 · 冻结版）

> 状态：**一期已按此契约实现并验证（2026-10-28）**，可作为二期/后续改动的冻结基线。
> 用途：管理端 / 移动端 / 后端三条并行实现流共用同一份口径，**任何字段名、枚举值、文案、行为不得私自变更**；如需变更先单独立项评估。
> 上游设计见 [README.md](README.md) §4.4 / §5.1 / §5.2 / §5.6 / §6 / §7 / §8。
> 范围：仅一期（reason 契约 + 被顶下线新设备信息 + 两端弹窗）。二期内容（subReason 细分、多标签页同步、WS 主动推送）不在本次实现。

## 1. 响应契约

- **HTTP 状态保持 200**（不改成 401），沿用现有 `body.code` 约定。
- **响应体必须是合法 JSON**（2026-10-29 boot 部署实测修复）：Sa-Token 过滤器用 `String.valueOf(errorHandler.run(e))` 写响应，而 `SaResult#toString()` 不会 JSON 序列化嵌套 `data`（会输出 `{reason=NOT_TOKEN}`），因此 boot/cloud 过滤器必须返回
  `SessionInvalidResponse.toJson(reason, data)` 预序列化字符串，**不得**直接返回带嵌套 `data` 的 `SaResult`；MVC 兜底走 Jackson 不受影响。
- 401 响应体（boot 过滤器 / cloud 网关过滤器 / MVC 兜底 handler 三个出口必须完全一致）：

```json
{
  "code": 401,
  "msg": "账号已在其他设备登录",
  "data": {
    "reason": "BE_REPLACED",
    "invalidAt": "2026-10-28T21:32:07+08:00",
    "device": {
      "os": "Windows 10",
      "browser": "Chrome 120",
      "location": "上海市",
      "ip": "1.2.3.4",
      "loginTime": "2026-10-28T21:32:05+08:00"
    }
  }
}
```

- `reason` 取值（wire 值，大小写敏感）：

| wire 值 | 语义 | `msg`（后端固定文案，脱敏） |
|---|---|---|
| `NOT_TOKEN` | 未携带 token | 登录状态已失效，请重新登录 |
| `TOKEN_INVALID` | token 无效（含 logout 后、映射丢失、未知场景） | 登录状态已失效，请重新登录 |
| `TOKEN_EXPIRED` | 自然过期 | 登录已过期，请重新登录 |
| `BE_REPLACED` | 被顶下线 | 账号已在其他设备登录 |
| `KICK_OUT` | 被踢下线 | 登录状态已失效，请重新登录 |
| `TOKEN_FREEZE` | token 冻结 | 登录状态已冻结，请重新登录 |
| `NO_PREFIX` | token 前缀不符 | 登录状态已失效，请重新登录 |

- 除 `reason` 外全部可空：`invalidAt` / `device` / `device.*` 缺失即省略或置 null，前端必须兼容。
- **响应体与 `msg` 中不得出现**：`token`、`loginId`、`tenantId`、手机号、密码；完整 IP 仅允许出现在 `device.ip`（2026-11-01 产品决策放开，见《四期实现契约-设备信息含IP与移动端地点.md》），其它位置仍不得出现。
- `subReason` 字段一期不返回（命名已预留，二期再加）。

## 2. Redis 失效记录（后端内部，不下发给前端）

- key：`satoken:login:invalid-reason:{tokenValue}`（`CacheConstants.SESSION_INVALID_KEY`）
- value（JSON，字段名冻结）：

```json
{
  "reason": "BE_REPLACED",
  "invalidAt": "2026-10-28T21:32:07+08:00",
  "device": {
    "os": "Windows 10",
    "browser": "Chrome 120",
    "location": "上海市",
    "loginTime": "2026-10-28T21:32:05+08:00"
  }
}
```

- TTL：**7 天**（覆盖"旧设备隔天才回来操作"的窗口，成本可忽略）。
- 写入者：登录链路（新登录成功、旧 token 被 Sa-Token 标记 `-4` 之后）。
- 读取者：三个 401 出口。读不到 / 解析失败 / Redis 异常 → 只返回 `reason`（无 `invalidAt`/`device`），**不得改变 401 状态与 msg**。
- 写入失败只 `log.warn`，**绝不影响登录主流程**。

## 3. 一期行为矩阵

| 场景 | 管理端 | 移动端（C 端） | 移动端（配送端） |
|---|---|---|---|
| `BE_REPLACED` | 弹窗「账号已在其他设备登录」+ 设备行；**不跳转**；重登成功关闭弹窗回原路由 | 弹窗 + 设备行；**不自动跳转**；点「重新登录」→ 写 `redirectPath` → 清态 → `reLaunch` 登录页 | 同 C 端，文案改「配送账号已在其他设备登录」，目标页 `/pages/delivery/login` |
| `KICK_OUT`/`TOKEN_EXPIRED`/`TOKEN_INVALID`/`NOT_TOKEN`/`TOKEN_FREEZE`/`NO_PREFIX` | 同一弹窗，标题/正文按 reason 取文案；重登/退出 | 同左，标题/正文按 reason | 同左 |
| 401 但无 `data.reason`（旧后端） | 按 `TOKEN_INVALID` 通用文案走 modal | 同左（保留现有免登/403 语义） | 同左 |
| 免登请求 401（`publicRequest`/`skipToken`） | 保持现状：不清态、只提示 | 保持现状：不清态、只 toast | 同左 |
| 401 且本次请求**未携带 token**（游客 / 从未登录） | —（管理端无游客态） | **不进入会话失效**：不置失效态、不弹窗、不冻结请求，只 toast「请先登录」；受限页自行展示游客态并引导登录 | 同 C 端 |
| 403 权限不足 | 保持现状：不清态、只提示 | 保持现状：不清态、只提示 | 同左 |
| 已处于失效态时再来 401 | 静默 reject，不重复弹/不清态 | 静默 reject，不重复弹 | 同左 |
| 用户点「退出登录」 | 清本地态 → 登录页 | 清态 → 首页/登录页（**不写** redirectPath） | 清态 → 配送登录页 |

- **一期明确不做**：「稍后处理」按钮、新设备确认顶号、多标签页同步、主动推送、subReason 细分。
- 弹窗**不可关闭**（无右上角关闭、点遮罩/ESC 无效），唯一出口是「重新登录」或「退出登录」。

## 4. 文案表（两端逐字一致，中文）

| reason | 标题 | 正文 |
|---|---|---|
| `BE_REPLACED` | 账号已在其他设备登录 | 当前账号于 {time} 在另一台设备登录，你已被迫下线。{deviceLine}重新登录会使那台设备下线。 |
| `TOKEN_EXPIRED` | 登录已过期 | 登录状态已过期，请重新登录。 |
| `KICK_OUT` | 登录状态已失效 | 登录状态已失效，请重新登录。 |
| `TOKEN_INVALID` / `NOT_TOKEN` / `TOKEN_FREEZE` / `NO_PREFIX` / 无 reason | 登录状态已失效 | 登录状态已失效，请重新登录。 |

- `{deviceLine}`：仅当 `data.device` 存在时渲染，**缺失整行隐藏**（不显示"未知设备"）：
  - 管理端：`登录设备：{browser} · {os}｜地点：{location}｜IP：{ip}｜时间：{HH:mm}`
  - 移动端：`设备：{os} · {browser}｜{location}｜{HH:mm}`
  - `browser`/`os` 任一为空则省略该片段；`location`/`ip` 为空省略对应片段（移动端不渲染 IP）；`loginTime` 按 `HH:mm`（跨天 `MM-dd HH:mm`）展示。
  - UA 解析兜底值 `Unknown` 各端一律按缺失处理（后端写入侧与前端读取侧双重过滤）。
  - `ip` 段为 2026-11-01 增量（四期），移动端不渲染 IP；旧后端无 `ip` 字段时自然隐藏。
- 按钮文案：主按钮「重新登录」，次按钮「退出登录」；移动端次按钮可为「退出」。
- 移动端需中英双语（项目已接 vue-i18n），英文文案可自拟但语义一致；管理端按现有 locale 组织方式补 key。

## 8. 补充（2026-10-29 修复）：游客态 401 不属于会话失效

> 本节只补充既有契约未覆盖的「从来没登录过」分支，**不改** §1 的 wire 契约、§3 其余矩阵行与 §4 文案表。

**缺陷（C 端实测）**：未登录游客在购物车空态点「常购清单」→ 页面用裸 `uni.navigateTo` 打开
（`uni-mini-router` 的 beforeEach 只拦 `router.push/replace`，裸跳转绕过 `router/index.ts` 的 `WHITE_LIST` 守卫）
→ 常购清单页 `onMounted` 无条件请求 `GET /mall-order/app/orderinfo/frequent-purchase`
→ 服务端 401 + `data.reason=NOT_TOKEN` → 移动端把 401 一律当会话失效，弹出「登录状态已失效」。
游客本来就没有可失效的会话，文案与行为都不成立；也与需求包 README §1 第 5 行
「未登录/伪造 → 直接去登录页，不弹『被顶』」、§7.4「未登录用户进受限页不弹『被顶』文案」相违背。

**根因**：移动端只能看到「401」，看不到「这次请求到底带没带 token」。`NOT_TOKEN` 是服务端对
**未携带 token** 的判定，而客户端在发出请求时就知道自己有没有带凭证，只是没把这个事实传给响应层。

**规则**：

- 请求层（`src/api/core/instance.ts`）在 `beforeRequest` 给请求打 `meta.hadToken`
  （本次请求是否真的写了 `satoken` 头；`skipToken` 免登请求恒为 `false`）。
- 响应层（`src/api/core/handlers.ts`）新增 `isGuestRequest(method)` = `meta.hadToken === false`：
  401 命中游客时**不** `sessionStore.invalidate()`、不弹「登录状态已失效」、不冻结请求，
  只 `toast(「请先登录」)` 并 reject；`handleAlovaError` 在 publicRequest / 403 判定之后同样短路
  （只透传错误、不二次 toast）。`meta.hadToken` 缺失（旧代码 / 既有单测直接构造 method）按
  「携带凭证」处理，既有 401 语义不变。
- 带 token 的 401（`TOKEN_INVALID` / `TOKEN_EXPIRED` / `BE_REPLACED` / `KICK_OUT` …）仍按 §3 弹会话失效窗；
  免登请求 401 与 403 语义不变。**后端没有改动**（wire 契约同 §1）。
- 不依赖请求层自动跳登录页（背景轮询/可选接口跳转会打断浏览）：受限页自己兜底游客态。
  常购清单页 `fetchPage` 首行 `if (!authStore.isLoggedIn)` 直接返回不发请求，模板展示
  「登录后查看常购清单」+「去登录」（写 `redirectPath`，登录成功回跳）；`onMounted` 改 `onShow`
  以便登录后返回自动加载。**禁止依赖路由守卫保证游客不进受限页**（裸 `uni.navigateTo` 会绕过）。

**文案**：`app.request.needLogin`（中「请先登录」/ 英「Please sign in first」）、
`catalog.frequentGuestTip`、`catalog.frequentGoLogin`，移动端中英双语同步。

**回归**：`aryn-mall-uniapp/src/api/core/guest-request.test.ts`
（游客 401 不置失效态/只 toast 一次；`hadToken=true` 的 401 仍弹窗；`handleAlovaError` 游客短路；
`isGuestRequest` 标记语义；instance/handlers/常购页/i18n 源码契约）。

### 8.1 同类入口收口（2026-10-29 第二轮）

请求层只解决「不再误报」，游客点需要登录的按钮仍然没有后续动作。第二轮把入口层守卫统一到
`src/composables/useRequireLogin.ts`：

| API | 行为 |
|---|---|
| `ensureLoggedIn(redirectPath?)` | 已登录返回 `true`；未登录写 `redirectPath`（默认当前页完整路径，**含 query**）→ `uni.navigateTo('/pages/login/index')` → 返回 `false` |
| `goLogin(redirectPath?)` | 仅执行「记录回跳 + 打开登录页」，供页面级游客态按钮使用 |
| 幂等 | 已在登录页不记录/不跳转；连点期间只跳一次（`navigating` 标志在 `complete` 复位），避免叠登录页/回跳成环 |

接入清单（**点击型入口守卫在函数首行、任何请求/副作用之前**；页面级入口用 `authStore.isLoggedIn` 判空 + 游客态，不自动跳转）：

- 领券：`components/diy/diy-coupon-receive`、`components/diy/diy-coupon-ladder`、`sub-pages/promotion/coupon/coupon-list`（领取前 `ensureLoggedIn`；已领取/达上限分支优先，不弹登录）
- 消息：`components/diy/diy-search-bar`（铃铛未登录整节点不渲染）；`sub-pages/message/notice`（三个取数函数未登录早退 + 游客态「登录后查看消息/去登录」）；`sub-pages/message/chat`、`sub-pages/message/notice/detail`（深链未登录先跳登录，不建 WS/不拉详情，`loading` 收起避免骨架屏卡死）
- 交易：`sub-pages/product/goods-detail`（多规格弹层加购 `addCart`、收藏 `handleCollect`、在线客服 `toCustomerService`；单规格加购与 `goods-detail-sheet` 原有守卫不动）；`sub-pages/order/shared-cart/detail`（微信分享卡片直达：`onLoad` 未登录先跳登录且**回跳路径保留 `id`/`token`**，`onShow` 未登录不发 3 个详情请求）；`sub-pages/promotion/group-buy/group-buy-detail`（`handleOpenGroup`/`handleJoinGroup`；看活动不需要登录）

**回归**：`src/composables/useRequireLogin.test.ts`（6 例：游客记录含 query 回跳/已登录放行/显式回跳/登录页不重复跳/连点不叠页/不把登录页当回跳目标）、
`src/require-login-contract.test.ts`（9 例源码契约：守卫存在性 + 每个入口接入位置 + 分享页回跳带 token + 铃铛隐藏 + 消息页游客态 + **旧式裸跳登录全部收口** + **模板必须显式 `goLogin()`**）。

**回归修复（同日，独立验证发现的缺陷）**：

- **游客态按钮必须显式调用**：模板 `@tap="goLogin"` 会把事件对象当第一个实参传给 `goLogin(redirectPath?)`，
  在 `redirectPath.startsWith` 处抛 `TypeError`、点击无反应。统一写 `@tap="goLogin()"`，并要求契约测试
  对模板绑定做负向断言（`@(tap|click)="goLogin"` 一律禁止）。
- **旧式裸跳登录全部收口**：原先 `uni.navigateTo('/pages/login/index')` 只挡住了请求、不写 `redirectPath`，
  游客登录成功会被兜底送回首页（商详单规格加购、商品快览加购、共享车列表/导入向导、船舶绑定/港口车辆等）。
  现全部改走 `useRequireLogin`，导入类页面 onLoad 显式带 `cartId` 回跳。
- `message/notice/detail` 无 `id` 的深链：已登录时也要复位 `loading`，否则骨架屏永转。
