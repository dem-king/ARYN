# 三期实现契约：WS 主动推送（秒级感知）+ 登录设备管理页

> 状态：**已实施并验证（2026-10-29）**，可作为后续改动的冻结基线
> 基线：一期/二期契约继续有效（响应 `code=401 + data.reason/subReason/device`、Redis 失效记录、脱敏红线、零 DDL、双模式一致）。
> 范围：① 被顶下线/被踢下线时通过已建立的 WebSocket **主动推送** `SESSION_INVALID` 事件（不等下一次 HTTP 401）；② 「登录设备」页（管理端弹窗 + 移动端 sub-page）：展示当前账号活跃会话与最近登录记录，支持下线非当前会话。
> 明确不做：多端并存、历史设备指纹库、第三方登录设备。

## 1. WS 推送契约

### 1.1 事件（服务端 → 客户端）

复用现有消息推送通道与 WS 入口（`/ws/app` = TOC、`/ws/staff` = TOB；boot 模式 `/boot/ws/**`），事件类型为 `SESSION_INVALID`，JSON 字段：

```json
{
  "eventType": "SESSION_INVALID",
  "tenantId": "123",
  "recipientType": "SYS_USER",
  "recipientId": "1001",
  "reason": "KICK_OUT",
  "subReason": "ACCOUNT_DISABLED",
  "invalidAt": "2026-10-29T09:12:33+08:00",
  "device": { "os": "Windows 10", "browser": "Chrome 120", "location": "上海市", "loginTime": "2026-10-29T09:10:00+08:00" }
}
```

- `recipientType`：`SYS_USER`（TOB，管理端/配送端）或 `MALL_USER`（TOC）。
- `device` 仅 `reason=BE_REPLACED` 时可能带（新设备信息），其它原因省略。
- `subReason` 规则同二期：仅 `reason=KICK_OUT` 时可能出现。
- **不得包含** token、loginId、IP、手机号；`recipientId` 是账号 userId（仅用于服务端路由，前端不使用）。
- 客户端对未知 `eventType` 必须忽略（现有 `CONVERSATION_MESSAGE`/`NOTICE_RECEIVED` 等继续按原逻辑处理）。

### 1.2 服务端发送时机与放弃策略

- **被顶下线**：登录链路写失效记录后推送（`reason=BE_REPLACED` + 新设备信息）→ 旧设备 WS 秒级弹窗。
- **被踢下线**：各踢人调用点（停用/改密/删除/管理员强退/租户停用/配送撤销/会员禁用）在 kickout **之前**写原因并推送（`reason=KICK_OUT` + `subReason`）。
- 推送为**尽力而为**：Redis/通道异常只 warn，不影响登录与踢人；WS 未连接时前端仍靠下一次 HTTP 401 兜底（一期/二期链路不变）。
- 客户端收到后**幂等**：复用 `sessionStore.invalidate(...)`；已处于失效态则忽略。

### 1.3 服务端实现约束

- 事件发布者位于 `common-security`（踢人/登录链路可达），**不得**依赖 `aryn-message-api`；通道名/事件类型/wire 字段放在 `common-core` 常量，`aryn-message-biz` 侧引用同一常量，避免漂移。
- 复用现有 `message:push:events` Redis 频道与 `MessageWebSocketHandler` 的 `tenantId:identityType:identityId` 路由；`MessagePushEvent` 增加可选字段 `reason/subReason/invalidAt/device`（向后兼容）。
- 发布实例的 `originInstanceId` 使用随机值（不能等于任一 message 实例 id），确保所有实例的 Redis 订阅者都尝试投递（只有持有该会话的实例有连接）。
- 双模式一致：boot（同 JVM 也走 Redis 频道）与 cloud（auth/upms 发布 → message-biz 投递）同一实现。

## 2. 登录设备 API 契约

### 2.1 活跃会话列表

`GET /auth/session/devices`（boot 改写为 `/boot/session/devices`）——需登录，当前账号自身会话。

```json
{"code":0,"data":[
  {"id":"a1b2c3d4e5f6","deviceType":"TOB","browser":"Chrome 120","os":"Windows 10",
   "location":"上海市","loginTime":"2026-10-29T09:10:00+08:00","current":true}
]}
```

- `id`：**token 的 SHA-256 前 12 位**（不可反推、不可重放），用于下线接口定位会话。
- 不出现在线记录里的原始 token / ipAddr / tenantId / userName。
- 排序：`current` 在前，其余按 `loginTime` 倒序。
- 当前单点策略下列表通常只有 1 条；接口按多会话设计，未来放开多端无需改契约。

### 2.2 下线指定会话

`DELETE /auth/session/devices/{id}`

- 仅能下线**自己**的会话：服务端用当前 loginId+deviceType 的候选 token 计算 hash 匹配，匹配不到返回业务失败。
- **禁止下线当前会话**（返回"当前设备请使用退出登录"），当前会话退出走既有 logout。
- 成功返回 `{"code":0}`；被下线设备和现在一样在下一次请求收到 401 `KICK_OUT`（无 subReason，通用文案）。

### 2.3 我的最近登录记录（管理端）

`GET /upms/sysloginlog/my?current=&size=`（boot 改写 `/boot/sysloginlog/my`；分页参数沿用仓库 `PageArgumentResolver` 约定 `current`/`size`）——需登录，**不需要** `upms:sysloginlog:page` 权限。

- 固定按当前登录用户名 + 当前租户过滤，按 `createTime` 倒序；`pageSize` 上限 20。
- 字段：`createTime / status（0失败 1成功）/ browser / os / location / ipAddr（脱敏或省略）/ msg`；**不得返回其他账号记录**。
- C 端（TOC）无登录日志表数据，移动端不展示登录记录。

## 3. 前端契约

### 3.1 管理端（`aryn-mall-ui/apps/web-ele`）

1. **WS 事件**：`store/message.ts` 的 `message` 回调解析 JSON，`eventType==='SESSION_INVALID'` 时：`sessionStore.invalidate(payload)` + `accessStore.setLoginExpired(true)`（多标签广播/锁屏解锁由 session store 既有逻辑负责），随后 `disconnect()`，并**不要再触发** `refreshNotifications()`。
2. **登录设备弹窗**：用户下拉菜单（`<UserDropdown :menus="...">`）新增「登录设备」项 → 打开 app 级弹窗：
   - 活跃会话表：设备/系统、地点、登录时间、当前标记；非当前行提供「下线」按钮（二次确认）；无其他会话时展示说明「同一账号仅允许一处登录，其他设备登录会自动顶掉本设备」。
   - 「最近登录记录」表（10 条）：时间、结果、浏览器/系统、地点。
   - 加载失败/为空要有空态与错误提示，不阻塞页面。
3. 新增 API 模块（如 `api/core/session-devices.ts`）：`getMyDevices/removeDevice/getMyLoginLogs`；路径 `/auth/session/devices`、`/auth/session/devices/{id}`、`/upms/sysloginlog/my`（交给统一 `requestClient` 自动做 boot 改写）。
4. 测试：WS 事件处理（mock WebSocket 收到 SESSION_INVALID → 落状态 + 弹窗 + 不刷新未读）、设备列表渲染/下线确认、空态、API 契约。

### 3.2 移动端（`aryn-mall-uniapp`）

1. **WS 事件**：`store/messageStore.ts`（C 端）/`deliveryMessageStore.ts`（配送端）收到 `SESSION_INVALID` → `sessionStore.invalidate(payload, target)`，并断开连接；不得再把它当普通消息触发未读刷新。
2. **登录设备页**：新增 `src/sub-pages/user/login-devices/index.vue`（`definePage` 自动注册，`navigationBarTitleText: '登录设备'`）：
   - 当前设备卡片（系统/浏览器、地点、登录时间、「当前设备」标记）；
   - 其他会话列表 + 「下线」（二次确认，调 DELETE）；
   - 说明文案：「同一账号仅允许一处登录，其他设备登录会自动顶掉本设备」；
   - 底部「退出登录」（复用设置页既有退出逻辑）。
   - 入口：个人中心设置入口（`user-setting` 页或 `user-center` 设置区域）新增「登录设备」项。
3. 文案中英双语（项目已接 i18n），错误用既有 `useGlobalToast`，确认框用 `useGlobalMessage`。
4. 测试：WS 事件处理、页面逻辑（列表/空态/下线调用/当前设备不可下线）、i18n key 完整性。

## 4. 红线

- 零 DDL、零 sa-token 配置变更、零 token 存储介质变更；双模式一致。
- 响应/WS/日志不得出现 token、loginId、完整 IP、手机号；设备列表的 `id` 只能是 hash。
- 单点策略不变（本期不放开多端）；登录设备页必须如实说明当前策略。
- 不得为了通过旧断言删改语义；测试演进需说明理由；不回退用户未提交改动，不 commit。
