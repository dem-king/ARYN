# 二期实现契约：细分「被踢」原因（subReason）+ 管理端多标签/WS/锁屏边界

> 状态：**已实施并验证（2026-10-28）**，可作为后续改动的冻结基线
> 基线：一期见 [一期实现契约.md](一期实现契约.md)（响应形态、reason 枚举、Redis key、脱敏红线全部继续有效，本文件只做**增量**）。
> 范围：`subReason` 机器可读细分 + 两端文案/按钮规则 + 管理端多标签页同步 + 管理端 WS 治理 + 锁屏边界。不含 WS 主动推送、登录设备管理页（不排期）。

## 1. 后端增量：`data.subReason`

在一期 `{"code":401,"msg":"…","data":{"reason","invalidAt","device"}}` 基础上**新增一个可空字段**：

```json
{"code":401,"msg":"登录状态已失效，请重新登录",
 "data":{"reason":"KICK_OUT","subReason":"ACCOUNT_DISABLED","invalidAt":"2026-10-28T23:50:12+08:00"}}
```

- `subReason` **只在 `reason=KICK_OUT` 时出现**；`BE_REPLACED` / `TOKEN_EXPIRED` / `NOT_TOKEN` 等不带。
- wire 值（大小写敏感、不得改名）与触发点：

| wire 值 | 含义 | 后端触发点 |
|---|---|---|
| `ADMIN_KICK` | 管理员强制下线 | `SysOnlineUserController#kickoutByToken` |
| `ACCOUNT_DISABLED` | 员工账号停用 | `SysUserServiceImpl#updateUser`（正常→停用） |
| `PASSWORD_CHANGED` | 密码修改 | `SysUserController#editPwd` |
| `ACCOUNT_DELETED` | 账号删除 | `SysUserServiceImpl#delUser`；C 端 `UserInfoServiceImpl#deleteUser` |
| `TENANT_DISABLED` | 租户停用/到期/套餐变更/删除/平台强制下线 | `TenantSessionRevoker#revokeTenant`、`SysTenantServiceImpl#kickoutSessions` |
| `DELIVERY_REVOKED` | 配送资格撤销 | `DeliveryAccessGuard#revokeDeliverySessions` |
| `MEMBER_DISABLED` | C 端会员禁用 | `UserInfoServiceImpl#updateStatus`（正常→禁用） |

- Redis 失效记录（`satoken:login:invalid-reason:{token}`）JSON 增加 `subReason` 字段；读取时未知值丢弃（按无 subReason 降级）。
- 兼容：旧客户端忽略新字段；新前端拿到未知 `subReason` 必须按"无 subReason"处理，不得报错/空白。

## 2. 文案与按钮规则（两端逐字一致）

| reason + subReason | 标题 | 管理端正文 | 移动端正文 | 可重新登录 | 单按钮文案 |
|---|---|---|---|---|---|
| `KICK_OUT`+`ADMIN_KICK` | 已被管理员下线 | 管理员已强制将你下线。如非本人预期，请联系管理员。 | 管理员已将你下线。 | ✅ | —— |
| `KICK_OUT`+`PASSWORD_CHANGED` | 密码已修改 | 密码已修改，请使用新密码重新登录。 | 密码已修改，请使用新密码重新登录。 | ✅ | —— |
| `KICK_OUT`+`ACCOUNT_DISABLED` | 账号已被停用 | 该账号已被停用，无法继续使用。如有疑问请联系管理员。 | 该账号已被停用，请联系管理员。 | ❌ | 返回登录 |
| `KICK_OUT`+`ACCOUNT_DELETED` | 账号已被删除 | 该账号已被删除，无法继续使用。 | 该账号已被删除。 | ❌ | 返回登录 |
| `KICK_OUT`+`TENANT_DISABLED` | 所属租户已停用 | 你所属的租户已被停用或已到期，请联系平台管理员。 | 账号所属店铺已停用。 | ❌ | 退出 |
| `KICK_OUT`+`MEMBER_DISABLED` | 账号已被禁用 | （管理端不出现） | 该账号已被禁用，请联系客服。 | ❌ | 返回登录 |
| `KICK_OUT`+`DELIVERY_REVOKED` | 配送资格已变更 | （管理端不出现） | 你的配送资格已变更，请重新登录配送端。 | ✅ | —— |
| `KICK_OUT` 无 `subReason` / 未知值 | 登录状态已失效 | 登录状态已失效，请重新登录。 | 登录状态已失效，请重新登录。 | ✅ | —— |
| 一期其余 reason（`BE_REPLACED` / `TOKEN_EXPIRED` / …） | 沿用一期文案 | 沿用一期文案 | 沿用一期文案 | ✅ | —— |

**按钮规则（硬要求）**：

- `可重新登录=true`：两个按钮「重新登录」（主）/「退出登录」（次），行为同一期。
- `可重新登录=false`：**不渲染「重新登录」**（重登必然失败，避免用户白试），只渲染一个主按钮，文案取「单按钮文案」，点击执行"退出登录"（清态 → 登录页）。
- 「返回登录」与「退出」的底层动作相同（清凭证 + 回登录页），仅文案不同；不写 `redirectPath` / 不留回跳。

## 3. 管理端（`aryn-mall-ui/apps/web-ele`）二期增量

### 3.1 多标签页同步

- 通道：`BroadcastChannel('aryn-session')`；不支持时退化为 `localStorage` 的 `storage` 事件（key：`aryn-session-event`）。
- 每条消息带 `from`（随机 tabId，内存生成，模块级唯一）与 `at`；**收到自己发的消息必须忽略**，避免回环。
- 消息协议：
  - `{type:'session-invalid', from, at, payload:{reason, subReason, invalidAt, device, detectedAt}}`
    → 其它标签页：`sessionStore.invalidate(payload)` + `accessStore.setLoginExpired(true)`（不重复 toast、不 logout）。
  - `{type:'session-restored', from, at}` → 其它标签页：`window.location.reload()`（token 已持久化，刷新后恢复；这是最简单可靠的恢复方式）。
- 发送时机：本标签页首次进入失效态（`invalidate` 返回 true）时广播 invalid；重登成功 `sessionStore.reset()` 前广播 restored。
- 要求：`BroadcastChannel` 不可用（旧浏览器/SSR 测试环境）时不得抛错，静默降级。

### 3.2 WebSocket 治理

- `store/message.ts`：`connect()` 与 `onClose` 的重连定时器回调入口都要先判 `sessionStore.invalid`，为真则**不再重连**；会话失效时主动 `disconnect()`（可在 basic.vue 的 watch 或 store 内部集成，需说明落点）。
- `refreshNotifications()` 必须整体 `try/catch`（或调用处 catch）：401 交给统一会话失效链路，其它错误 `console.warn`，不得产生 unhandled rejection。
- 不影响既有 `message-push` / 未读基线 / 语音播报逻辑；既有单测必须继续绿。

### 3.3 锁屏边界

- 触发点：会话失效时若 `accessStore.isLockScreen === true`，先 `accessStore.unlockScreen()` 再弹窗。
  （原因：`LockScreen` 是 `z-[2000]` 全屏层，会话失效弹窗固定 `z-index:1000`，不解除锁屏用户只能看到锁屏页。）
- 该动作只发生在"已确认会话失效"之后，不得影响正常锁屏/解锁流程。

### 3.4 测试

- subReason → 标题/正文/按钮表驱动（含未知值降级、`可重新登录=false` 只渲染一个按钮）。
- 多标签：mock `BroadcastChannel`，断言 invalid 广播、收到其它 tab 的 invalid 后落状态、restored 触发 reload、忽略自己消息。
- WS：mock WebSocket，断言 invalid 时 connect 不建立/onClose 不排重连、refreshNotifications 失败不抛 unhandled。
- 锁屏：mock access store `isLockScreen=true`，失效后调用 `unlockScreen`。
- 既有 `login-security.test.ts` 等断言不得改语义。
