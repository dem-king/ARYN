# 商城配送履约

## 目标

为悦航购新增商城自有配送闭环。客户下单时可以选择商城配送；支付成功后生成配送任务；管理员指定配送员；配送员在独立小程序中逐项配货、确认取货、配送、上传现场图片或上报异常；客户确认收货或超时后订单完成。

## 已确认范围

- 第一阶段采用管理员指定配送员，不支持抢单或自动派单。
- 配送员使用独立 `aryn-mall-delivery-uniapp`，使用 TOB 员工身份，不与客户商城 TOC 身份混用。
- 订单配送方式新增 `3 = 商城配送`，仅配送范围内的地址可选。
- 配送范围按租户配置省/市/区县白名单，后端在结算和创建订单时双重校验。
- 商城配送沿用现有订单运费规则和 `freightPrice` 金额口径。
- 配送员按订单商品逐项勾选，全部核对后才能确认取货。
- 正常送达必须上传 1 至 6 张 JPEG/PNG 图片，可以填写备注。
- 配送异常由配送员上报，管理员负责重新派送、改派或关闭。
- 配送员提交送达只完成配送任务；客户确认或达到 `orderAutoConfirmDays` 后订单才完成。
- 派单提醒同时进入员工消息中心、WebSocket 实时提醒和微信订阅消息；通知失败不得回滚派单事实。
- 取货前退款成功直接关闭任务；取货后必须确认商品退回仓库，才能完成退款。

## 架构结论

1. 配送任务作为 `aryn-order` 内的独立子域实现，不复用第三方快递表 `order_delivery`，第一期也不拆成独立微服务。
2. 订单状态和配送任务状态分离；“已送达”不等于“订单已完成”。
3. 每个租户的一张商城配送订单只创建一个配送任务；改派和再次配送使用同一任务及递增的 `attempt_no`。
4. HTTP/数据库是任务事实来源，消息中心、WebSocket 和微信订阅消息只负责提醒。
5. 配送员身份使用当前租户下拥有配送执行权限的 `sys_user`；所有工作人员接口显式要求 TOB 登录端。
6. 图片以 UPMS 素材 ID 关联配送凭证，订单域不保存客户端提交的任意外部 URL；查看时按任务访问权生成短期访问地址。
