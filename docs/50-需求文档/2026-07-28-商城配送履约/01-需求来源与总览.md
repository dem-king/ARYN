# 需求来源与总览

> 证据：2026-07-28 用户需求澄清与同目录设计文件；复核于 2026-08-31；置信度：已验证（需求基线），实现一致性见本目录 README。

## 原始请求

客户在商城下单后，商城根据配送方式将需要自配送的订单推送给指定配送员。配送员前往仓库完成配货后配送，送达时上传现场图片；无法送达时上报异常，由管理员处理。

## 产品定位

本需求不是给现有快递发货单增加一个配送员字段，而是新增一套商城自有履约能力：

1. **交易订单**：继续负责金额、支付、退款、确认收货和交易完成。
2. **配送任务**：负责派单、配货、取货、配送、送达、异常、退回和履约证据。
3. **第三方快递发货单**：现有 `order_delivery` 继续负责物流公司、运单号和快递轨迹。

这三个概念不得共用一套状态机。“已送达”是配送事实，“已完成”是交易事实。

## 功能目标

- 客户在结算页选择商城配送，并在下单时获得服务范围和运费的服务端校验。
- 支付成功后幂等创建待派单任务，不因重复支付回调产生重复任务。
- 管理员按租户选择有效配送员，支持派单、改派、异常处理和退回确认。
- 配送员只查看本人任务，完成逐项配货、确认取货、送达凭证和异常上报。
- 客户在订单详情查看公开配送进度、送达凭证并确认收货。
- 派单通知可靠落入员工消息中心，同时提供在线推送和微信订阅消息。
- 配送状态与退款、自动确认收货、订单完成事件保持一致。
- Boot/Cloud 数据结构、租户表配置、菜单和权限保持同步。

## 非目标

- 不支持配送员抢单、自动派单或路线规划。
- 不支持配送员实时定位、轨迹回放或预计到达时间计算。
- 不建设多仓、库位、批次、波次、条码出库等 WMS 能力。
- 不支持多张订单合并为一个配送批次。
- 不实现配送员计件工资、运力结算或第三方运力平台接入。
- 不要求客户电子签名。
- 不把配送任务拆成新的 Java 微服务。
- 不改造现有第三方快递轨迹回调语义。

## 影响范围

| 端/模块 | 主要影响 |
|---|---|
| `aryn-order-api/biz` | 配送方式、配送任务聚合、状态机、范围校验、订单/退款/自动收货联动 |
| `aryn-upms-api/biz` | 配送员资格查询、员工微信绑定、配送凭证上传和素材访问 |
| `aryn-user-api/biz` | 复用小程序账号配置，提供 jsCode 换取 openid 与订阅消息发送网关 |
| `aryn-message-api/biz` | 派单业务通知、WebSocket 推送、微信订阅通道任务与重试 |
| 管理后台 | 配送任务、配送范围、派单、改派、异常、退回和订单详情 |
| 客户 UniApp | 商城配送选择、可用性提示、配送进度、凭证与确认收货 |
| 配送 UniApp | 独立员工登录、任务工作台、配货、送达、异常、消息与微信授权 |
| SQL/租户/菜单 | 新表、索引、字典、动态菜单、权限、套餐和双模式一致性 |

## 非功能目标

- 派单、改派、取货、送达、异常和退回确认必须幂等并可审计。
- 任务状态更新使用状态、版本、租户和当前指派人条件更新，不依赖分布式锁。
- 图片单张不超过 10 MB，正常送达要求 1 至 6 张 JPEG/PNG。
- 普通任务查询 p95 目标小于 200ms，状态写入 p95 目标小于 300ms。
- 消息中心事实不可因 WebSocket、Redis、RocketMQ 或微信接口短时失败而丢失。
- 地址、电话和现场图片不得跨租户或跨任务泄露。

## 关键约束

- 不同 biz 模块不得直接依赖其他 biz，只能依赖 `*-api` 并通过 Dubbo 或 RocketMQ 通信。
- 所有新业务表包含 `tenant_id` 和 `del_flag`，并登记 Boot/Cloud 租户白名单。
- 配送员接口从安全上下文获取当前 `SYS_USER`，禁止客户端提交当前配送员 ID。
- 客户接口从安全上下文获取当前 `MALL_USER`，禁止仅凭订单 ID 查询配送信息。
- 管理端菜单由数据库动态下发，新增页面必须同步菜单、权限、套餐和存量租户授权。
- 修改认证、实体、菜单、公共存储或请求层前，实施阶段必须先做 Graphify 影响审计；工具不可用时记录替代证据。
