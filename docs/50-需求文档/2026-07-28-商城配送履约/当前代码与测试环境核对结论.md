# 当前代码与测试环境核对结论

> 初次核对日期：2026-07-28；完成核对日期：2026-07-29。配送功能已经完成代码和本地自动化验收，以下仍明确区分实现前基线、本地证据和运行态联调。

## 实现后结论

- 订单域已新增独立商城配送子域，覆盖范围校验、支付后幂等建任务、派单/改派、配送员配货取货、送达凭证、异常、退回和客户公开进度。
- UPMS 已提供权限驱动的配送员资格、员工微信绑定、配送凭证专用上传、素材预占/确认/释放和短期访问能力。
- 消息域已将派单事实写入员工收件箱，并增加 WebSocket 提醒、微信订阅通道任务、退避重试和恢复任务；提醒失败不回滚派单。
- 管理后台、客户 `aryn-mall-uniapp` 和独立 `aryn-mall-delivery-uniapp` 均已接入对应工作流；三类接口分别使用 TOB 管理权限、TOB 配送权限和 TOC 订单归属。
- Boot/Cloud 增量 SQL、租户表配置、配送方式字典、动态菜单、套餐/租户授权和 Boot 全量 SQL 已同步。

## 已有可复用能力

- `order_info.delivery_way` 已区分快递和自提，支付事件会把非自提订单置为待发货。
- `OrderInfoServiceImpl` 已在创建和结算时读取会员地址、计算运费并保存收货快照。
- 订单已有支付幂等、库存扣减、确认收货、订单完成事件和自动确认天数配置。
- `order_delivery` 和 `order_delivery_logistics` 已支持第三方快递公司、运单号和快递100轨迹。
- UPMS 已有 `sys_user`、角色权限、TOB 登录、文件上传、素材表和租户对象存储配置。
- 消息域已支持 `SYS_USER` 收件箱、业务通知命令、WebSocket 本实例推送、Redis 跨实例广播和命令幂等。
- 管理后台已有订单列表、发货弹窗、订单详情和动态字典展示。
- 客户 UniApp 已有结算、地址、订单列表/详情、确认收货、图片上传和消息中心。
- 后端已有 RocketMQ、XXL-JOB、Dubbo、租户上下文和 Boot/Cloud 双模式基础设施。

## 实现前缺失能力（本需求已补齐）

- 未发现配送任务、配送员、配货核对、送达凭证、配送异常、退回确认或配送范围数据模型。
- 现有 `order_delivery` 是第三方快递发货单，字段和回调状态不适合商城配送任务。
- `CreateOrderDTO` 和 `SettlementOrderDTO` 只允许配送方式 `[12]`；订单创建仅在普通快递时读取地址和计算运费。
- 自动确认收货任务统一使用 `order_info.deliver_time`，不能正确表达商城配送的送达起算时间。
- 当前退款审批不校验商品是否已由配送员取走或是否退回仓库。
- UPMS 只具备通用员工和角色查询，没有“有效配送员”远程契约。
- 当前移动上传只返回 URL，素材缺少稳定对象键、上传业务归属和受控短期访问能力。
- 未发现员工微信 openid 绑定、微信订阅消息通道任务或重试恢复能力。
- 客户 UniApp 是 TOC 单应用，不能直接作为 TOB 配送工作台。
- 未发现独立配送 UniApp 项目。

## 现有代码中的关键改造点

- `CreateOrderDTO`、`SettlementOrderDTO`、`MallOrderConstants`：增加商城配送常量和校验。
- `OrderInfoServiceImpl.createOrder/settlementOrder`：让快递和商城配送共同读取地址、计算运费，并额外校验配送范围。
- `ArynOrderPayEventListener`：在支付状态事务中幂等创建配送任务。
- `OrderInfoServiceImpl.receiveOrder` 和 `OrderJobHandler`：保持确认收货幂等，并按配送方式选择超时起算时间。
- `OrderRefundServiceImpl`、`ArynRefundListener`：增加取货后退回前置条件，不能仅检查快递发货单数量。
- `SysUploadController`、`UploadFileValidator`、`SysMaterial`：增加配送凭证专用策略和稳定对象键。
- `MessageSendCommand`、`MessageCommandServiceImpl`：保留站内信事实并扩展微信订阅通道。
- 管理端 `views/order/order-info`、客户 UniApp `order-confirm` 和 `order-detail`：接入第三种配送方式与配送摘要。

## 需要重点保护的现有约束

- 第三方快递发货和快递100回调不得因商城配送改造而改变语义。
- 上门自提支付后直接待收货的既有流程不得回归。
- 订单支付、库存、优惠券和退款事件已涉及跨域一致性，新增配送写入必须保持事务和幂等。
- `ArynOrderPayEventListener` 当前通过条件更新防止重复支付处理；配送任务必须与该成功路径绑定。
- `MessageSendCommand` 已按来源和收件人双重幂等，派单事件 ID 必须包含任务和尝试号。
- TOB/TOC 已由 `SecurityUtils.requireUser(DeviceTypeEnum)` 区分，配送接口不能只依赖普通登录态。
- 新增菜单、实体、认证和公共存储能力影响范围较大，实施前必须检查 Graphify；当前工作树中的历史 Graphify 生成目录不可作为已存在工具链声明。
- 当前工作树已有与本需求无关的未提交文件，实施时不得回退、覆盖或顺带暂存。

## 公共存储与素材影响检查（任务 8）

- 当前环境未安装 Graphify，也未发现可执行入口；因此本次不能声明完成 Graphify 图分析。
- 替代检查使用 `rg` 扫描 `ArynUploadFileHandler`、`AbstractUploadFileHandler`、`LocalUploadFileHandler`、`S3UploadFileHandler`、`StorageFactory`、`SysUploadController`、`SysMaterial` 及其调用方，并通过 Maven 依赖树核对 UPMS、订单域对公共存储和 UPMS API 的依赖方向。
- 已确认的历史上传调用方包括管理端/移动端通用上传接口和支付配置上传；它们继续调用 `uploadFile(...) -> String`，普通素材仍接受真实 JPG、PNG、GIF、BMP、WEBP，未被配送专用规则收窄。
- 公共存储新增 `uploadObject(...) -> StoredObject` 默认扩展；旧 `uploadFile(...)` 契约保留。历史实现类不修改即可继续工作，新版 Local/S3 实现额外返回稳定对象键。
- `SysMaterial` 新字段均为可空增量字段；历史素材查询和普通上传不要求对象键、业务类型或绑定状态。
- 配送专用上传单独要求 TOB 身份和 `order:delivery:execute` 权限，仅接受真实 JPEG/PNG，并保存对象键、上传员工、租户和 `UNBOUND` 状态。
- 订单域采用“UPMS 原子预占 → 本地 `PENDING` → 事务提交后确认 → 定时恢复”的跨库一致性流程；超时未提交的 UPMS 预占由独立清理任务释放。
- 替代验证覆盖 `StorageFactoryCompatibilityTest`、`LocalUploadFileHandlerTest`、`S3UploadFileHandlerTest`、`UploadFileValidatorTest`、`DeliveryEvidenceUploadTest`、`RemoteMaterialAccessServiceImplTest`、`DeliveryTaskStaffServiceTest` 和 `DeliveryEvidenceBindingRecoveryJobTest`。
- 未覆盖风险：当前短期访问描述包含五分钟过期时间且不泄露对象键/密钥，但历史存储配置生成的 URL 可能仍是公开地址；真正的对象存储签名 URL 和本地受控代理仍需在部署配置与端到端联调中验证。
