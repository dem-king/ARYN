# 接口与数据变更

## 模块边界

配送任务保留在订单域，建议在现有模块中按子域分包：

```text
aryn-order-api/src/main/java/com/aryn/cloud/order/api/delivery/
├── dto
├── entity
├── enums
└── vo

aryn-order-biz/src/main/java/com/aryn/cloud/order/delivery/
├── controller/admin
├── controller/staff
├── controller/app
├── mapper
└── service
```

订单域不得直接依赖 UPMS、用户或消息 biz；配送员资格和素材通过 UPMS API/Dubbo，微信能力通过用户 API/Dubbo，业务通知通过 RocketMQ。

## 核心表

### `order_delivery_task`

保存任务号、订单 ID、状态、当前配送员快照、指派人、`attempt_no`、乐观锁 `version`、开始配货/取货/送达/退回/关闭时间、当前异常摘要和租户审计字段。

关键约束：

```text
UNIQUE (tenant_id, order_id)
UNIQUE (tenant_id, task_no)
INDEX  (tenant_id, status, create_time)
INDEX  (tenant_id, assignee_id, status, update_time)
```

一张订单永久只对应一张任务；改派、重试和关闭都不新建第二张任务。

### `order_delivery_task_item`

保存 `task_id`、`order_item_id`、当前尝试号、是否核对、核对人和核对时间。唯一键为 `tenant_id + task_id + order_item_id`。

### `order_delivery_evidence`

保存 `task_id`、`attempt_no`、凭证类型（送达、异常、退回）、`material_id`、绑定状态、排序、上传人和审计字段。订单域不保存客户端外部 URL。

### `order_delivery_task_log`

追加保存动作、原状态、目标状态、尝试号、操作人类型/ID/名称快照、原因编码、说明和受控 JSON 摘要。业务代码不提供删除日志接口。

### `order_delivery_area`

保存租户可配送的省/市/区县编码、名称快照、启用状态和审计字段。首期按最细已配置层级匹配：区县优先，未配置区县时可由城市级规则覆盖。

### `sys_user_wechat_binding`

归 UPMS 所有，保存员工 ID、小程序 `app_id`、`openid`、绑定状态和时间。唯一约束阻止一个有效 `openid` 在同租户同应用绑定多个员工。

### `message_channel_task`

归消息域所有，保存站内通知 ID、收件人、通道、模板编码、受控参数、状态、重试次数、下次重试时间和错误摘要。微信未授权等终止错误不无限重试；网络和限流错误按退避策略重试。

## 管理接口

建议前缀 `/order/delivery/admin/**`，Boot 模式继续由现有前端路径改写到 `/boot/**`：

```text
GET  /tasks                         任务分页
GET  /tasks/{id}                    任务详情
POST /tasks/{id}/assign             首次派单
POST /tasks/{id}/reassign           改派/再次配送
POST /tasks/{id}/close              关闭异常任务
POST /tasks/{id}/return-pending     进入待退回
POST /tasks/{id}/return-confirm     确认商品退回
GET  /staff/candidates              配送员候选列表
GET  /areas                         配送范围列表
POST /areas                         新增配送范围
PUT  /areas/{id}                    修改配送范围
DELETE /areas/{id}                  逻辑删除配送范围
```

权限建议：

```text
order:delivery:page
order:delivery:get
order:delivery:assign
order:delivery:reassign
order:delivery:exception
order:delivery:return
order:delivery:area
order:delivery:execute
```

## 配送员接口

建议前缀 `/order/delivery/staff/**`，全部显式要求 `DeviceTypeEnum.TOB`：

```text
GET  /tasks
GET  /tasks/{id}
POST /tasks/{id}/picking/start
PUT  /tasks/{id}/items/{itemId}/checked
POST /tasks/{id}/pickup
POST /tasks/{id}/delivered
POST /tasks/{id}/exception
POST /wechat/bind
POST /wechat/subscription/consent
```

接口从安全上下文读取当前员工 ID。任务详情和写操作必须同时校验租户、指派人、状态和版本。

配送图片文件流由 UPMS 员工专用接口接收：

```text
POST /upms/file/staff/delivery-evidence/upload
```

该接口要求 TOB 配送权限，返回 `materialId`；配送员提交送达或异常时只向订单接口传 `materialId` 列表。

## 客户接口

建议前缀 `/order/delivery/app/**`：

```text
GET /availability?addressId=...     查询商城配送可用性
GET /orders/{orderId}               查询本人订单的公开配送进度
GET /evidence/{evidenceId}/access   获取本人订单凭证短期访问地址
```

结算和创建订单接口仍为现有 `/app/orderinfo/settlement` 与 `/app/orderinfo/create`，但 `deliveryWay` 校验扩展为 `[123]`，并对 `3` 执行服务端范围校验和现有运费计算。

## 跨域契约

### UPMS

新增 `RemoteDeliveryStaffService`：

- 按当前租户分页查询有效配送员。
- 校验员工是否启用并拥有 `order:delivery:execute`。
- 查询员工微信绑定，但不返回其他租户或无关敏感字段。

新增 `RemoteMaterialAccessService`：

- 批量校验素材租户、上传人、类型、大小和占用状态。
- 为已通过业务权限校验的素材生成短期访问描述。
- 不把存储密钥或长期公开地址返回订单域。

### 用户域微信网关

复用 `social_account` 中按租户配置的小程序账号，新增最小远程契约：

- 根据 `appId + jsCode` 换取 `openid`，不创建 TOC 会员。
- 按模板编码发送微信订阅消息。
- 调用方不接触 `appSecret`；凭证继续由用户域管理。

### 消息域

扩展 `MessageSendCommand` 的可选通道和模板字段。订单域派单事务提交后发送收件人为 `SYS_USER` 的命令：

```json
{
  "eventId": "delivery-assigned:{taskId}:{attemptNo}",
  "recipientType": "SYS_USER",
  "category": "DELIVERY_TASK",
  "bizType": "ORDER_DELIVERY_TASK",
  "bizId": "{taskId}",
  "channels": ["IN_APP", "WECHAT_SUBSCRIBE"],
  "templateCode": "DELIVERY_TASK_ASSIGNED"
}
```

消息域先持久化站内通知，再创建微信通道任务；WebSocket 和微信失败都不改变配送任务状态。

## 图片存储兼容

当前 `SysUploadController.appUpload` 只返回 URL，`SysMaterial` 也缺少稳定对象键和按业务授权生成临时访问地址的能力，不能直接满足配送凭证要求。实现阶段需要：

- 为配送凭证使用独立员工上传入口，并保存 `sys_material` 记录。
- 在素材中保存稳定 `object_key`，兼容历史只有 URL 的素材。
- 素材采用 `TEMPORARY -> RESERVED -> BOUND` 生命周期；预占使用任务和请求幂等号，阻止同一素材并发绑定多个任务。
- 订单事务先写入 `PENDING` 凭证；事务提交后确认素材绑定，失败时由订单域恢复任务重试，成功后把凭证置为 `BOUND`。
- S3/本地存储都提供受控短期访问方式。
- 订单凭证表只关联 `material_id`。
- 对未关联任务的临时配送素材设置清理任务。

## SQL、租户和菜单

- 新增 Boot/Cloud 增量 SQL，包含订单配送表、员工微信绑定、消息通道任务、字典、菜单和权限。
- 将新表加入对应 Nacos/Boot 租户配置和 `TenantConfigurationConsistencyTest`。
- 更新 `build-full-sql.mjs` 来源清单、`verify-full-sql.mjs` 关键令牌及建表总数后重新生成全量 SQL。
- 动态菜单新增“配送任务”和“配送范围”；配送执行权限通常只授予配送员角色，不需要管理页面菜单。
