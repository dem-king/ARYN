# 订单级运费规则（满额包邮）

> 状态：已实施（2026-11-12）；后端单测通过，管理端/小程序类型检查通过；真实库与真机验收见「六、待验收」。

## 一、原始请求

系统当前没有「满多少包邮」的设置，而小象超市、盒马都有这类门槛限制。本商城的业务以船供为主，
同时覆盖海员个人购买与企业/工厂采购，需要一套能同时适配三种场景的运费方案，而不是照抄同城零售的单一阈值。

## 二、改造前现状

| 项 | 改造前 |
|---|---|
| 商品级运费 | `goods_spu.freight_type` 只有 `0 包邮 / 1 固定运费`，且 `fixed_freight_price × 购买件数` 线性叠加 |
| 订单级减免 | 只有会员权益 `member_benefit.benefit_type='2'`（值必须 =1），命中后整单运费清零 |
| 门槛 | **不存在**，无法表达「满 X 元免运费、不满收基础运费」 |
| 计费范围 | 仅配送方式 `1 普通快递`、`3 公司配送（岸上）` 计运费；`2 上门自提`、`4 公司配送（到船）` 不计 |
| 顺序 | 运费在活动价 → 会员折扣 → 券 → 积分之后最后相加 |

## 三、设计口径

### 3.1 三层叠加

| 层 | 管什么 | 实现 |
|---|---|---|
| 计费层 | 商品该不该收运费 | `freight_type` 扩为 `0 包邮 / 1 固定运费 / 2 随订单规则` |
| 门槛层 | 订单金额够不够免运费 | 新表 `freight_rule`，按「场景 + 配送方式 + 省份」匹配 |
| 权益层 | 会员免邮直接免 | 复用现有会员权益，优先级高于门槛 |

### 3.2 关键口径

| 项 | 口径 | 理由 |
|---|---|---|
| 门槛基数 | 只统计 `freight_type='2'` 明细的 `totalPrice`（活动价后、券与积分前） | `0` 商品永远包邮、`1` 商品独立计费，三者互不干扰，存量商品零行为变更；券前口径避免「凑单用券反而不包邮」与确认页金额漂移 |
| 固定运费 | **每个 SPU 每单只收一次** | 原按件 × 数量叠加，买 10 箱收 10 次运费，属于成本口径错误 |
| 门槛运费 | 每单只收一次基础运费，分摊到金额最大的参与明细 | 保证「订单实付 = 明细实付之和」守恒，退款基数不虚高 |
| 分摊 | 独立运费落对应 SPU 第一行；门槛运费落金额最大的参与行 | 明细级退款扣减运费时，能定位到真正承担运费的行 |
| 会员免邮 | 整单清零，`freight_discount_price` = 减免前合计 | 门槛与会员不重复记账，免邮成本可核算 |
| 自提 / 到船 | **永远不进计费**，运费恒 0，仅回填原因 | 到船成本与金额无关（司机 + 港区 + 装卸），按金额设门槛只会白送大单 |
| 封顶 | `max_freight` 只作用于规则基础运费，独立计费商品不封顶 | 大件/冷链按实际成本收取 |
| 未配规则 | 视为不收运费，不阻断下单 | 配置缺失不能变成下单故障 |
| 门槛为 0 | 视为不设门槛，始终收基础运费 | 与「满 0 元免运费」区分开 |

### 3.3 三场景建议值（种子数据，可后台调）

| 场景 | 配送方式 | 规则 | 依据 |
|---|---|---|---|
| 海员个人 | 普通快递 | 满 59 免运费，不满 6 元，封顶 20 | 客单价低、快递实发 5–8 元；门槛让运费占比 <10% |
| 企业采购 | 公司配送（岸上） | 满 300 免运费，不满 15 元，封顶 60 | 批量采购兜底门槛，后续可走客户协议 |
| 船供采购 | 公司配送（到船） | 不建规则（恒免运费） | 真实成本按靠港次数，不按金额；靠港服务费列为 P2 |

### 3.4 规则匹配优先级

`priority` 数值大者优先；**指定省份的规则整体优先于全国规则**（偏远地区加价靠这条生效）。
规则可配 `province_codes`（逗号分隔，空=全国）；配送方式只允许 `1`/`3`，配 `2`/`4` 会被后端拒绝。

### 3.5 结算页「还差 X 元」点击跳凑单

| 项 | 口径 |
|---|---|
| 入口 | 只有「未达门槛、仍在收运费」的文案可点，文案尾部追加主题色「去凑单 ›」；已免邮/会员免邮/自提/到船不出现入口 |
| 可点范围 | **仅购物车下单（createWay=1）**：结算页的商品是购物车勾选快照，加购后可以安全并入同一单；即时购买/导入船供/拼团的快照不是购物车勾选项，不加点，避免把商品悄悄塞进另一类订单 |
| 商品池 | 只拉 `goods_spu.freight_type='2'` 的在售商品，按售价升序 —— 只有这类商品会抬高门槛基数，包邮/固定运费商品加进来不改变差额 |
| 加购 | 复用统一快捷加购（多规格弹层、MOQ/步长、库存、共享车去向判定）；加购同时把新行追加进结算快照，返回后结算页按 SKU 合并重建清单并重新结算 |
| 金额 | 凑单页不做任何金额计算；门槛/差额由结算页透传，返回后的运费与应付一律以服务端重新结算为准 |
| 返回 | 加购过才触发重算事件，纯浏览返回不发多余结算请求 |
| 空态 | 没有 `freight_type='2'` 商品时明示「只有设置为『随订单规则』的商品才参与满额包邮」，引导运营配置 |

## 七、边界

- 本次不做：重量/体积计费、首重续重、靠港配送服务费（P2）、企业客户协议运费、免邮券。
- 退款后不足门槛**不追收**运费；`freight_discount_price` 仅用于成本核算，不进退款链路。
- 历史订单无 `freight_base_price` / `freight_free_reason`，管理端按下单时 `freight_price` 展示，不做回填。
- 结算页未选地址时仍不计算运费（沿用改造前行为），因此不展示门槛提示。
- 凑单入口只对购物车下单开放：即时购买/导入船供/拼团的商品快照不是购物车勾选项，加购商品无法安全并入同一单，因此只展示文案、不提供跳转。
