# 代码审查 P0 修复设计

## 目标

核验并修复 `docs/代码审查报告-2026-07-21.md` 中的 P0 问题。报告结论仅作为待验证假设：保留真实缺陷，合并重复项，拒绝会破坏现有业务协议或已被当前代码修复的建议。

## 范围

### 后端

- 修复系统用户修改密码时 BCrypt 参数顺序和新密码写入错误，并增加回归测试。
- 管理端登录改为由同源 `/api` 反向代理承接 HTTPS 传输，服务端继续使用 BCrypt 校验；移除前后端共享的固定 AES 登录密钥和 ECB 登录链路。
- 文件上传限制为空文件、10MB 上限和常见位图格式，使用文件头识别而不是只信任扩展名/MIME；管理端素材上传复用现有 `upms:material:add` 权限，移动端上传继续由全局登录认证保护。
- 本地文件预览限制租户 ID 和文件名格式，做规范化路径根目录校验，并恢复进入控制器前的租户上下文。
- Boot 与 Gateway 的 CORS 改为显式 Origin/请求头白名单，允许域名由 `hx.cors.allowed-origins`/`HX_CORS_ALLOWED_ORIGINS` 提供；请求头覆盖管理端和 UniApp 实际使用的 `satoken`、`tenant-id`、`platform-type`、`app-id` 等字段。
- Gateway 显式依赖 `aryn-common-security`，避免 Cloud 模式单独编译时缺失共享 CORS 属性。

### 管理后台

- 删除登录页测试账号通知和自动填充。
- 删除登录密码 AES 加密调用及公开密钥配置，登录参数采用不可变复制。
- 修复字典 store 的空 key 判断、重复 key 更新和删除返回值，并补类型。
- 修复字典标签对 `undefined` 的字符串比较。
- 抽取并测试 Boot URL 重写函数，移除重复赋值和请求期 `JSON.parse`。
- 请求发出前移除 `isToken`、`isSwitchTenant` 等客户端控制标记，避免将其误发为 HTTP 请求头。
- 为验证码组件样式增加 `scoped`，不在本轮重写整个遗留验证码组件。

### UniApp

- 移除路由守卫中的用户态和导航调试日志。
- 安全解析 Alova 响应，并基于解析后的 `resp.code` 处理 401/403。
- 三种账号登录在写入状态前统一校验 `tokenValue`。
- 排除 loading/toast/message 等瞬时 store 的持久化。
- 微信小程序开启合法域名校验。
- 使用 `onUnload` 和具名回调解绑订单页面事件总线。
- 抽取并测试与管理端语义一致的 Boot URL 重写函数。
- 使用 `skipToken` 完成客户端判定后立即删除该控制标记，避免 H5 预检携带无效自定义头。

## 核验后不修改的报告项

- J-C2 的 ThreadLocal 清理：当前过滤器已经使用 `try/finally`，且已有成功/异常路径测试。无 Token 的 `tenant-id` 是公开商城选择租户的现有路由输入；让 L1 `common-mybatis` 直接依赖 L4 `SysTenantService` 会违反项目分层。
- M-C6：相关 loading 已在 `finally` 中关闭；全局请求错误处理已负责提示，额外 catch 会重复提示。
- M-C8：每个字典 key 在调用 `toRefs` 前已经初始化，返回的 `ObjectRef` 能跟随异步赋值更新；报告对 Vue 响应式机制的判断不成立。
- X-C1：管理端平台租户切换与面向单租户商城的编译期租户配置是不同业务场景，不强行共享实现。
- X-C3：后端不存在 `/token/refresh`，管理端 `enableRefreshToken` 默认也是关闭状态；单独给 UniApp 增加刷新会形成不可用协议。
- X-C5：后端 `CommonConstants.TOKEN_KEY` 当前值就是 `satoken`，与两端一致。
- U-C2 中验证码组件的 AES：它属于验证码服务协议，不承载登录密码；本轮只移除登录密码固定 AES 链路。

## 测试策略

- Java：控制器/安全属性/上传校验单元测试先失败再实现；随后运行相关模块测试和 `mvn test -pl aryn-boot -am`。
- 管理后台：为字典、Boot URL 和安全源代码契约补 Vitest；运行定向测试、类型检查、单测、lint 和构建。
- UniApp：为 token 校验、持久化排除、响应解析和 Boot URL 补 Vitest；运行定向测试、全量单测和类型检查。
- 最后检查 `git diff`、空白错误和未跟踪文件，确保不覆盖用户已有文件。

## 最终验证结果

- 后端：密码、认证、上传与路径相关定向测试通过；`CorsPropertiesTest` 2 个用例通过；`mvn -pl aryn-gateway -am -DskipTests compile` 通过。未跟踪的 `ArynLogEventListener.java` 将 `ArynLoginLogEvent` 的 getter 误写为 `getSysLoginLog()`，已在本地改为 `getLoginLog()` 以解除源码扫描阻断，但该未注册且与现有配置重复的实验代码仍排除在提交之外。非沙箱环境运行 `mvn test -pl aryn-boot -am` 通过，41 个 Reactor 模块全部成功。
- 管理端：`pnpm check:type`、完整 Vitest、变更文件 ESLint/Prettier、`pnpm build:ele` 通过。全仓 `pnpm lint` 仍被 19 个与本轮无关的历史格式/规则文件阻断。
- UniApp：复用管理端 Vitest 运行全量测试通过；排除测试文件后的生产源码 `vue-tsc` 通过；变更文件 ESLint 无错误，仅保留订单列表既有 UnoCSS 排序警告。原生 `pnpm type-check` 因当前 Node 20 低于项目要求的 Node 22，且本地安装目录缺少 Vitest 类型而失败。
- 部署：生产管理端默认使用同源 `/api`，部署层必须在 HTTPS 站点反向代理该路径；跨域部署必须通过 `HX_CORS_ALLOWED_ORIGINS` 配置精确 Origin，禁止使用 `*`。
