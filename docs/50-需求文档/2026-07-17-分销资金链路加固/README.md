# 分销资金链路加固

## 目标

统一支付、退款、结算和提现口径，使分销资金变化幂等、可追踪、租户隔离，并确保佣金基数不含运费。

## 验收范围

- 支付只创建待结算佣金，到期后释放；释放前优先抵扣佣金欠款。
- 一级、二级佣金按同一业务订单号和不同层级保存，退款同时回退且按退款号幂等。
- 部分退款累计封顶；退款先于支付不丢失；余额不足的回退形成欠款。
- 支付/退款状态在事务内更新，成功 MQ 在事务提交后发送；发送或处理失败可重试，所有租户上下文均可靠清理。
- 配置比例、结算周期和提现限额由服务端校验，启用配置保持单例。
- 提现账号密文落库、接口脱敏；审核通过必须填写唯一打款流水号。
- 未清资金、待审核提现、真实有效下级或可退款佣金订单阻止删除；逻辑删除后允许重新注册和首次绑定邀请人。
- 定时补偿按租户、退款记录和佣金订单隔离失败，单条坏数据不得阻塞后续记录或租户。
- 提现申请备注按 255 字符上限校验并落库。
- 管理端与 UniApp 类型、页面字段、状态和正负金额展示与后端一致。

## 数据与配置

- 新库使用更新后的 Boot/Cloud 初始化 SQL；存量库执行 `db/*/13distribution_financial_hardening.sql`。
- `DISTRIBUTION_WITHDRAW_ACCOUNT_KEY` 必须是 Base64 编码的 32 字节密钥，不得写入仓库。
- 佣金基数字段历史值保留 `NULL`，避免错误假设历史运费口径。

存量提现账号按以下顺序迁移：先配置并备份 `DISTRIBUTION_WITHDRAW_ACCOUNT_KEY`，再执行存量 SQL，最后由具有 `promotion:distributionwithdraw:audit` 权限的管理员调用 `POST /distribution/withdraw/reencrypt-legacy-accounts`。接口仅处理当前租户下不以 `v1:` 开头的账号，每批 200 条，可安全重复调用；返回值为本次重加密数量，返回 `0` 表示当前租户已处理完成。迁移后不得更换或丢失原密钥。
