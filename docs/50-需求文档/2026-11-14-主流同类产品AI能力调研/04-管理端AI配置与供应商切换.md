# 管理端 AI 配置与供应商切换

> 日期：2026-11-15。
> 用户补充需求：以后更换 AI 供应商，直接在管理端配置完成。
> 关联：[代码可行性评估](./03-结合当前代码的可行性评估.md)。本文设计已于2026-11-15落实为配置页面、版本接口、RPC及双模式增量；本地协议/隔离验证通过，真实供应商与Cloud部署仍待验。实际配置和操作以[部署运维手册](./06-部署迁移与运维手册.md)及[验收记录](./05-验收用例与验证记录.md)为准。

## 1. 目标与使用方式

管理后台新增“平台配置 → AI 配置”，支持维护多家供应商，并按业务用途选择模型。对已经支持的协议和能力，更换供应商、API Key、模型及接口地址无需改业务代码、重打包或重启服务。

推荐操作流程：

1. 新增供应商配置，填写名称、协议、接口地址、API Key。
2. 添加该供应商可用的模型，选择能力与必要参数。
3. 测试指定能力，查看鉴权、协议、结构化输出或向量维度等结果。
4. 为一个或多个业务用途选择该模型，保存并启用配置版本。
5. 新任务使用新版本；可查看调用状态并切回上一版本。

测试调用应展示会产生少量模型用量，使用固定样本，不发送真实客户清单。连接成功只说明对应测试通过，不代表模型在实际业务上一定准确。

## 2. 页面内容

| 页面 | 主要内容 |
|---|---|
| 供应商 | 名称、协议类型、基础地址、密钥设置状态、启停状态、连接测试 |
| 模型 | 所属供应商、模型 ID、支持能力、超时、输出限制、可选参数、能力测试 |
| 用途配置 | 清单解析、候选排序、营销方案/文案、发品、商品向量、图片识别、语音识别、图片生成分别选择模型 |
| 调用记录 | 用途、模型/供应商、配置版本、耗时、用量、成功/失败、脱敏错误 |

表单按协议和能力显示字段，不要求运营填写无关参数。支持预设供应商模板和自定义兼容地址；模板只是帮助填写，不替代协议验证。没有模型列表接口的供应商允许手动填写模型 ID。

可用同一供应商的不同模型，也可混用多家。例如清单解析使用一个文本模型，商品向量使用另一家的 Embedding 模型；具体供应商以实际可用能力和测试为准。

## 3. 按能力配置，避免一个开关绑定全部 AI

| 能力 | 用途示例 | 切换要求 |
|---|---|---|
| 结构化文本生成 | 清单解析、活动草稿、商品文案 | 支持对应输出协议；校验结果；新任务使用新版本 |
| 向量化 | 商品目录语义召回 | 向量模型、维度及索引版本匹配；完成索引重建后切换 |
| 图像理解 | 图片/扫描 PDF 清单 | 支持图片输入、文件大小与页数限制 |
| 语音识别 | 录音报货 | 独立音频接口、格式/时长限制 |
| 图片生成 | Banner/海报 | 独立生成协议、尺寸和结果存储适配 |

“支持 Chat Completions”不等于支持 Embedding、图片生成或语音，也不保证所有兼容实现接受相同参数。当前 `ChainAiAssistant` 固定发送 `thinking` 等字段，`EmbeddingClient` 发送 `dimensions`，改造时应由协议/模型能力控制这些参数。

一期先支持现有调用所需的兼容文本和 Embedding 协议，定义能力与用途结构，后续随多模态功能补对应适配。已有适配协议内的供应商切换走后台；全新协议仍需开发适配，不能承诺任意供应商只填地址即可使用。

## 4. 权限与租户口径

一期由平台管理员统一管理公共 AI 连接，复用现有平台身份守卫并配置独立的查询、编辑、测试、启用权限。普通租户不能读取平台密钥或更改共享模型。

租户侧可以逐步开放本租户 AI 功能开关、额度、用量和允许范围内的模型选择。“租户自带 Key”作为后续能力：配置、凭证、额度、缓存都按租户隔离，不能将普通租户上传的连接自动用于其他租户。

平台配置记录绑定系统识别出的平台租户，不硬编码 tenant ID；内部读取须经受控配置接口，不靠放开通用租户拦截实现全局可见。模型选择不改变原业务的租户、采购主体或会话权限。

## 5. 后端改造落点

当前两个客户端用构造器注入最终配置，运行时从管理端修改数据库不会自动生效。因此需要替换配置读取方式，不能只增加一张配置表。

- `ChainAiAssistant`：移除供应商/密钥/模型的固定构造器依赖，按用途取得有效配置快照，保留解析和候选校验逻辑。
- `EmbeddingClient`：使用向量用途配置快照，并验证返回维度；目录缓存绑定模型与索引版本。
- `aryn-common-ai`：负责协议适配、能力校验、调用、超时、用量和错误归一化；通过传入配置或注入接口取得配置，不直接依赖 upms。
- upms：维护供应商/模型/用途配置、版本、权限与管理端接口；在 `upms-api` 定义受控的内部配置读取契约。
- 各 biz：通过领域侧配置适配取得授权的配置快照，再调用公共 AI 模块，保持低层不依赖高层。

不新增独立 AI 微服务。Boot 使用既有聚合与本地 Dubbo，Cloud 通过 upms 的内部契约读取；业务代码统一消费同一配置协议。

建议新增的持久化概念如下，具体表结构随实施确定：

| 数据 | 内容 |
|---|---|
| 供应商配置 | 归属租户、协议、地址、加密凭证、状态、修订号 |
| 模型配置 | 供应商、模型 ID、能力、经白名单校验的参数 |
| 用途绑定及版本 | 用途 → 模型、启用版本、历史版本、修改人和生效时间 |
| 调用记录 | 业务任务、配置版本、模型、耗时、用量、结果与脱敏错误 |

## 6. 生效、回滚与向量切换

后台保存先形成草稿，启用以配置版本原子切换；新任务读取启用版本。发布后通知各实例失效缓存，缓存有短 TTL 并校验版本，不能只更新当前实例内存；页面显示生效版本及同步状态。只有版本有效才建立模型调用，失效通知丢失时也须在启动新任务前确认当前启用版本。

进行中的任务固定使用启动版本，避免一份清单处理到一半换了模型。旧版本配置按在途任务需要保留；紧急停用可以阻止后续调用和重试。人工恢复/重跑时明确选择原版本或当前版本，并留下记录。

Embedding 切换采用“构建新索引 → 验证维度与目录覆盖 → 切换引用”的顺序。旧向量不能交给新查询模型使用，即使两者维度相同也不能混用。重建期间继续使用成套旧索引/旧模型；旧模型不可用时回退字面匹配，并显示语义召回暂不可用。页面展示各租户索引准备情况，未准备好的租户不得使用不匹配的新模型。切回旧配置时同样确认对应索引仍有效。

一期不默认自动切换到另一家供应商；失败沿用业务现有规则降级。后续确需配置备用模型时，由管理员显式配置，区分结构化生成重试与 Embedding 索引切换。

## 7. 凭证与配置约束

API Key 支持在后台录入和替换，保存后只返回“已设置”及掩码，不返回完整值；保留、替换、清除应是明确操作，不能把掩码当真实 Key 回写。模型调用从后端发起，移动端和浏览器不接触密钥。

数据库凭证使用带认证加密，主密钥由部署 Secret/环境变量注入，首次部署配置一次；以后更换供应商及 API Key 直接操作后台。可参考支付材料已有 AES-256-GCM 与 keyId 轮换做法，但禁止从其他 biz 直接 import 支付实现，应抽取合适的低层凭证能力或提供独立适配。

现有操作日志敏感字段正则未覆盖 `apiKey`，实施时应补齐请求、响应、异常的脱敏，测试结果不回显供应商原始鉴权错误正文。配置自定义地址还需校验协议和目标地址；默认禁止访问内网/云元数据地址，本地模型只能通过部署侧明确授权的地址使用，防止测试按钮成为任意服务端请求入口。

数据库配置作为启用后的唯一运行来源。现有环境变量用于一次性迁移/初始化，不能与数据库长期保持不清晰的覆盖关系；AI 主密钥、网络准入和部署基础设施仍归部署配置。

## 8. 双模式与验收

管理端接口可采用 `/upms/ai-config/**`，经现有重写后 Boot 为 `/boot/ai-config/**`。Controller 使用既有去服务域后的映射。配置 DDL、菜单权限、种子与租户配置按 Boot/Cloud 双份同步，全量 SQL 重生成与校验。

验收至少包括：

1. 在后台将文本用途从 A 配置切到 B，无重启，新任务的调用记录准确显示 B 及新版本，已有任务保持约定行为。
2. 同时使用不同供应商处理文本与向量，不相互覆盖；不支持的能力和参数在启用前给出明确错误。
3. 错误 Key、失效模型、超时、无效结构化输出不会破坏已启用配置；启用测试失效后运行时仍能受控降级。
4. 多实例生效、并发编辑、回滚、紧急停用和任务重试均使用可追溯的配置版本。
5. 向量模型切换及回滚不混用向量空间，目录完整性与索引状态可见。
6. 平台/租户权限隔离、密钥不回传、日志脱敏、缓存与内部配置读取范围均验证。
7. Boot/Cloud 路径、配置读取及调用行为一致。

一期范围登记为“公共 AI 适配 + 管理端供应商/模型/用途配置”，与文本和向量改造一起完成；完整租户自带 Key、多模态供应商适配与自动备用切换按后续场景增加。
