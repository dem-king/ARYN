# 船供化改造 · 端到端验收清单（可执行版）

> 日期：2026-09-19
> 配套：`README.md`（交互调研与竞品对标报告）、`dev-tools/smoke-ship-supply.sh`（接口冒烟脚本）
> 目的：把《试点上线清单》里长期处于「待试点执行」的端到端验收，拆成**可逐条打勾**的用例

---

## 0. 为什么必须有这份清单

《试点上线清单》§5 的「真机/浏览器端到端三链路验收」一栏，状态长期是**「待试点执行」**。而这期间：

- 后端 90+ 单测、`mvn compile`、`pnpm type-check`、小程序 45 项单测**全部通过**
- 但结算页的配送方式选项里**根本没有「公司港口/船舶内部配送」**
- 订单详情把这个方式显示成**「无需配送」**
- 船供目录搜索因为两个 SQL 条件被 AND 掉，**按 IMPA 码或中文名单独搜索都返回 0 条**

**这些都是一用就能发现的问题。测试覆盖率不能替代真实用户路径验证**——这正是本清单存在的理由。

本清单分两部分：
- **自动化部分**（第 2 节）：`dev-tools/smoke-ship-supply.sh` 覆盖接口层可断言的内容
- **人工部分**（第 3 节起）：UI 交互、跨页面状态、真机表现，必须人走

## 1. 前置条件

### 1.1 环境

| 项 | 要求 |
|---|---|
| 后端 | Cloud 模式（`./dev-tools/start-all.sh`）或 Boot 单体模式（`mvn spring-boot:run -pl aryn-boot`） |
| 管理端 | `http://localhost:5777` |
| 移动端 | H5 `http://localhost:8888`；真机建议微信开发者工具 + 真机预览各走一遍 |
| Gateway | `http://localhost:9999` |
| 数据库 | 增量脚本 42~61 已执行；`aryn_boot_full.sql` 已重新生成并校验 |

### 1.2 账号

| 角色 | 要求 |
|---|---|
| 海员 A | 商城用户，已在「船舶档案 → 成员管理」绑定为**悦航1号**在船成员 |
| 海员 B | 商城用户，同一艘船成员（用于共享购物车多成员场景） |
| 未绑定用户 C | 商城用户，**不绑定任何船舶**（用于验证未绑定态） |
| 多船用户 D | 商城用户，绑定**两艘及以上**在营船舶（用于验证切换；若无此数据需临时补） |
| 调度/管理员 | 管理端账号，拥有 `vessel:*`、`fulfillment:*` 权限 |
| 司机 | 有配送资格的员工账号 |

> **权限提示**：菜单与权限在登录时快照进 token session，SQL 授权后**必须重新登录**才生效。

### 1.3 数据

| 数据 | 要求 |
|---|---|
| 船舶 | **悦航1号**（在营），另有**一艘第二船舶**（供多船用户 D 切换） |
| 靠港计划 | 悦航1号下**至少两个**未离港的靠港计划（用于验证靠港选择；只有一个时该项无法验证） |
| 船供商品 | 至少 30 条（验证分页需 > 20 条），且**必须包含**：有 IMPA 码的、有内部编码的、中文名不含编码的、英文名不含编码的 |
| 仅船供商品 | 至少 1 条 `sale_scope=2`（仅船供采购） |
| 下架商品 | 至少 1 条船供商品被下架（`status≠1`） |
| 阶梯价活动 | 1 个已发布的船供阶梯价活动（验证结算优惠） |
| 待审核绑定申请 | 1 条，申请人须**不是任何在营船舶的成员**（G15~G22 依赖） |
| 未绑定账号 | 至少 1 个未绑定船舶的商城账号（G4、G10、G30~G33 依赖） |

> 以上绑定相关数据由 `./dev-tools/seed-acceptance-data.sh` 一并铺设：
> 它会建一个验收用申请人（手机号 13800009701）并留一条待审核申请。
> 收尾用 `--clean` 移除。

## 2. 自动化冒烟（接口层）

```bash
# Cloud 模式
./dev-tools/smoke-ship-supply.sh

# Boot 单体模式
MODE=boot ./dev-tools/smoke-ship-supply.sh

# 无密码登录凭据时，直接用已有 token
TOKEN=<satoken> ./dev-tools/smoke-ship-supply.sh
```

脚本覆盖：

| 编号 | 断言 | 对应修复 |
|---|---|---|
| S1 | `GET /vessel/app/my-vessels` 返回 200 | 船舶域可用 |
| S2 | `GET /vessel/app/{id}/calls` 返回 200 | **P1-1** 靠港计划接口 |
| S3 | 船供目录返回的记录 `status` 全为 `1` | **P0-6a** 下架商品泄漏 |
| S4 | 按 **IMPA 码**搜索 `total > 0` | **P0-3** 搜索条件被 AND |
| S5 | 按 **中文名**搜索 `total > 0` | **P0-3** |
| S6 | 按 **内部编码**搜索 `total > 0` | **P0-3** |
| S7 | 零售列表按船供商品名检索，**不含**该仅船供商品 | **P0-6b** `sale_scope` 未生效 |
| S8 | `GET /mall-order/app/shared-cart/my` 返回 200 | **P0-5** 列表接口 |
| S9 | 共享购物车详情含 `viewerIsOwner` 等字段 | **P0-5** 权限标记 |
| S10 | 创建 → 详情（发起人识别）→ 成员 → 明细 → 关闭 全链路 200 | **P0-5** |

**S4/S5/S6 是本次修复最关键的回归点**：修复前它们会返回 `total = 0`。

船舶自助绑定有独立的冒烟脚本（21 条断言，覆盖三条通道与权限收敛）：

```bash
./dev-tools/smoke-vessel-bind.sh
```

| 编号 | 断言 | 对应风险 |
|---|---|---|
| V1 | 已绑定用户可读我的船舶 / 成员列表 | 成员访问权 |
| V2 | 成员列表手机号已脱敏 | 隐私泄漏 |
| V3 | 普通船员(2) 加人 / 生成邀请码 / 检索候选**均被拒** | **权限收敛** |
| V4 | 采购确认人(3) 可检索候选、可生成邀请码 | 管理角色能力 |
| V5 | 邀请码为 6 位且不含 `0/O/1/I` | 口头/手抄传递 |
| V6 | 已是成员时重复申请被拒 | 重复绑定拦截 |
| V7 | 非法 `applyRole` 被拒 | 角色白名单 |
| V8 | 不存在的邀请码被拒 | 校验 |
| V9 | 已是成员时兑换邀请码被拒 | 重复绑定拦截 |
| V10 | 非生成人撤销邀请码被拒；生成人可撤销 | 越权与清理 |
| V11 | C 端 token 访问管理端审核接口被拒 | 端侧权限边界 |

> 该脚本会自行写入 Redis 短信码用于登录、并在结束时清理自己创建的邀请码，
> 可重复执行。它**不覆盖**「审核通过建船」这类需要管理端 token 的路径，靠 §7.1 人工验证。

> 脚本只覆盖接口层。它**不能**验证 UI 交互、跨页面状态、真机表现——继续往下走。
