# 微信群接龙报货粘贴导入

> 2026-10-11 落地。船员报货接龙发在微信群，工作人员在小程序创建共享购物车代为下单：
> 整段粘贴接龙 → 服务端解析成「人 × 商品 × 数量」→ 报告页逐行核对 → 并入购物车 →
> 走既有核定+提交流程生成整船订单（明细按人拆行、贴姓名标签）。

## 背景与关键判断

- 接龙里的人**大多不是小程序用户**（没登录过、甚至没注册）。因此「归属」不解析成
  用户账号，只作为**姓名标签**：整条购物车由工作人员（确认人）提交成一条
  货到付款的整船订单，接龙人名落在明细的 `attributed_name` 上，配送贴标签、
  按人分装认的是这个名字。
- 系统已有「外部清单 → 解析落行 → 人工处置 → 确认并入 → 提交」的完整流水线
  （补给单 Excel 导入），本功能是它的**兄弟入口**：复用导入任务表、报告 VO、
  确认端点、`matchRows` 商品匹配与 `confirmAndCreateOrder` 提交链路，
  只新增自由文本解析器和「人」维度。
- 商品匹配 P0 不动 product 模块：`matchRows` 已有「品名精确 + 包含兜底」；
  口语品名匹配不上的行走报告页人工补选（既有 `/product/app/goodsspu/search`）。

## 数据模型（增量 SQL：boot 121 / cloud 122）

| 表 | 变更 | 说明 |
|----|------|------|
| `shared_cart_import_row` | + `source_type`（EXCEL/CHAIN，存量默认 EXCEL） | 导入来源 |
| | + `person_name`（接龙人名原文，纯职务称呼按原文保留） | CHAIN 来源 |
| `shared_cart_item` | + `attributed_name` varchar(64) NOT NULL DEFAULT '' | 归属人姓名快照；空串=归属即 user_id 本人（与既有行为逐行等价） |
| | 唯一键扩列 `(tenant,cart,user,sku)` → `+ attributed_name` | 两个人在同一车订同一种商品靠归属姓名区分，否则同 SKU 撞键 |

订单侧零改动：`order_item.contributor_name` 本就是字符串快照，`splitByMember`
归属姓名优先于成员姓名链（成员自填姓名 → 昵称 → 用户+后6位）。

## 归属解析规则（确认并入时）

1. 人名**精确**命中成员自填姓名（`shared_cart_member.display_name`，同名多人放弃
   自动归属）→ 明细挂真实成员（`user_id`=成员），不带标签，成员自己能看到/改这行；
2. 命中不上 → 明细挂操作者 + `attributed_name`=人名原文；
3. 报告页可逐行修正归属人（RowAction.personName，修正值落回解析行留痕）。

## 解析器（`ChainOrderTextParser`，纯函数，order-biz/support）

- **格式判定**：出现序号标记（`1.`/`1、`/`（1）`/`①`）或「人名+商品」同行 →
  人员名单排版；整段都没有 → 纯购物清单，裸短行按商品处理（不误当人名）。
- **人名**：行首第一个分隔符前的短文本（≤12 字、不含数量标记）；支持「先报名、
  换行报货」的暂存接续；「香蕉3斤，苹果2斤」这类首段含数量的行判为无人名。
- **数量**：数字/中文数字（一~九十九，含「两」「十X」「X十Y」）+ 单位表
  （斤/公斤/箱/包/瓶/罐/串/个/盒/袋/桶/件/听/支/把/份/条/只/张/卷/块/提/扎/双/副）。
- **连写合并**：「600ml*24瓶4箱」「青岛啤酒500ML12罐 2箱」→ 规格里的数量标记
  拼回品名、以后一个数量为准；「橙子4斤青岛清爽24罐装一箱」无分隔连写拆成两个商品；
  「香蕉3斤（青）」括号规格归回本商品（紧贴单位的括号才算，带空格的
  「3斤 （青）苹果2斤」的括号属于下一个商品名）。
- **不猜的原则**：数量缺失/小数/「半斤」不进位，置空或默认 1 + 解析疑点写进
  `resultMessage`，由报告页人工核对；「红和黄 各一斤」拆不出两个商品，
  品名去「各」并提示核对口径。
- 数量解析失败的行默认按 1 处理（不能让人卡死在粘贴这一步），疑点随结果说明带出。

## 商品模糊匹配（二字组，2026-10-11 补层）

实测暴露的缺口：商城叫「国产香蕉」、接龙写「香蕉」或「青香蕉」对不上。两层原因、两层修复：

1. **候选从不下发**：`LIKE '%香蕉%'` 能捞出「国产香蕉」，但多候选归类「未匹配」时
   `SharedCartImportRowVO.candidates` 从未被赋值——用户看到的就是「匹配不上」。
   现在 `previewChainImport` 把商品域返回的候选透传到报告行，报告页一键采用。
2. **修饰词夹心包含失效**：「青香蕉」对「国产香蕉」双向包含必失败。接龙行启用
   `ReplenishImportMatchDTO.fuzzy`：品名拆相邻二字组（青香/香蕉）再做一次 LIKE
   召回（独立索引，Excel 行为逐字节不变），`bigramScore` 按
   max(目标覆盖率, 候选覆盖率) 打分：
   - **≥ 0.75 且唯一最高分 → 自动命中**（红富士冰糖心→红富士苹果冰糖心 0.8）；
   - **≥ 0.5 → 候选一键确认**（青香蕉→国产香蕉 0.5、麒麟无籽西瓜→麒麟西瓜 0.67）；
   - < 0.5 视为噪声。
   0.5 档不自动定品的原因：它混着「小番茄→番茄酱」「老冰糖→黄冰糖」这类
   修饰词不同、商品真不同的误配，宁可让人点一下也不冒错单风险。

## 名称变体与单字兜底（2026-10-11 第二轮实测补层）

实机报告页又暴露三类缺口（商城真实名录已用 SQL 核对）：

| 接龙原文 | 商城在售 | 病因 | 修复 |
|----------|----------|------|------|
| 卤牛腱子**优质** | 原切牛腱子肉 | 尾部形容词掺进品名 | `nameVariants` 剥尾部/头部质量形容词（优质/新鲜/精品/特级/上等/精选/优选/正宗/超大），变体参与打分 → 核心词重叠 0.67 进候选 |
| 上海盐汽水**600ml\*24瓶** | （暂无盐汽水） | 规格串掺进品名 | `nameVariants` 循环剥尾部规格（数字+单位+\*N+包装单位+装），剥出「上海盐汽水」；商品一建档即可同名命中 |
| 橙子 | 赣南脐橙 | 口语词与商城名**连二字组都不共享** | 短名（≤3 汉字）补**单字召回** + 单字兜底层：按共享汉字给候选（共享「橙」→ 脐橙/橙汁家族），**只建议不自动**（单字噪声大，人来把关） |

规则：打分取「原文/剥修饰词/剥规格」各变体的最高分；展示与留痕仍用原文；
变体剥完不足 2 字符（名字本身是规格串）时保留原样。


## AI 助手接入（OpenAI 兼容协议，2026-10-11 第三轮；现用 DeepSeek）

四条架构线（决定「好用」还是「翻车」）：

1. **一次粘贴 = 一次调用**：`ChainAiAssistant`（order-biz/support，JDK HttpClient
   直连 OpenAI 兼容协议，fastjson2 解析，零新依赖；实测智谱 glm-4.7-flash 为推理
   模型且免费档频繁 1305 过载、数秒延迟不可用，已切 DeepSeek——请求
   `deepseek-chat` 路由到最快的 deepseek-flash，实测 0.8 秒返回）提供两个批量能力——
   `parseChain`（接龙原文 → 「人 × 商品 × 数量」JSON 数组，复用
   `ChainOrderTextParser.ParsedItem` 行结构，管道其余零改动）与
   `pickSkus`（对「未匹配但有候选」的行从候选里挑最像的）。
2. **AI 管理解和选品，不管钱**：价格/库存永远来自数据库；选品有**反幻觉校验**——
   模型返回的 skuId 必须真的在该行候选集里、行号必须真实存在，否则丢弃。
   AI 选品只做两件事：候选排到首位 + 打 `aiPickedSkuId` 标记，采用与否仍由人在
   报告页决定（「采用全部 AI 推荐（N）」一键采纳，逐行可撤销）。
3. **规则是兜底**：`aryn.chain-ai.enabled=false` 或 api-key 留空 → `isAvailable()=false`
   → 整条链路自动走纯规则（解析器 + 二字组/变体/单字匹配），与接入前逐字节一致；
   AI 调用失败（超时/非 200/JSON 不合法/解析为空）→ 单次降级规则并 warn 留痕。
4. **全配置化**：`aryn.chain-ai.{enabled,api-key,model,base-url,timeout-ms}`，
   boot 与 order-biz 两份 yml 都带 env 占位符（变量名中性 AI_*，默认
   DeepSeek）；compose-boot.yml 透传 `AI_API_KEY/AI_ENABLED/AI_MODEL/AI_BASE_URL`，
   在 `aryn-mall-java/.env`（已 gitignore）放 key 后 `--force-recreate` 容器即
   启用；换供应商只改 .env 的 base-url/model；cloud 模式在 Nacos 的 order
   服务配置或环境变量里给同一组键。

防御式解析：模型输出剥 ```json 围栏/前后废话后截取 JSON 块；解析为空/非法抛错
触发回退；quantity 非法兜底 1；单测覆盖围栏剥离、废话包裹、幻觉丢弃、可用性门。
