# 价格政策（协议价）· 使用说明

> 适用页面：管理端「营销管理 → 价格政策」（`/promotion/price-policy`）
> 适用版本：2026-11-15（B2B 价格与会员体系 P1）
>
> **一句话**：价格政策 = 给指定采购主体 / 船舶 / 客群签的长期合同价。发布后，命中的 SKU 直接锁定成交基价，优先级高于档期特供、阶梯价、会员价 / 出清价。
>
> 当前环境已预置 4 条示例政策（船队年度框架价 / 单船酒水专项 / 快消补充折扣 / 年度续签草稿），可直接改价复用。

---

## 一、先理解设计（5 条）

### 1.1 它在价格体系里的位置

| 优先级 | 价格层 | 说明 |
|:--:|---|---|
| 9 | **协议价**（本文） | 按主体 / 船舶 / 客群圈定的长期合同价，命中 SKU 锁成交基价 |
| 8 | 档期特供价 | 档期内限量特惠 SKU，活动级限量 + 每人限购 |
| 7 | 阶梯价 | 按购买数量分档单价，买得越多越便宜 |
| 6 | 会员价 / 出清价 | 等级身份价 + 临期出清价，逐 SKU 取低 |
| — | 商品售价 | 兜底价格 |

只有协议价是「合同价」，长期有效、不走活动发布；其他都是「活动价 / 身份价」。协议价一旦命中，后面的价格层都不再覆盖这个 SKU。

### 1.2 三个配置要素

| 要素 | 说明 |
|---|---|
| **圈定对象** | `1 采购主体`（岸上企业 / 工厂餐厅）/ `2 船舶` / `3 客群标签`；可多选，存 ID 集合（英文逗号分隔） |
| **价格模式** | `1 固定协议价`：每个 SKU 填一口价；`2 折扣率`：对当前售价打折，如 `0.9400` = 94 折，结果两位小数向下取整 |
| **起订量** | 正整数，买够件数协议价才生效；C 端展示「N 件起」，结算按购物车件数校验 |

一条政策只能选一种价格模式，不能 SKU 级混用。固定价适合「合同写明一口价」，折扣率适合「指定品类统一折扣的补充协议」。

### 1.3 同 SKU 命中多条政策时怎么判

1. **优先级取大**：`priority` 大的政策赢；
2. **同级取低价**：优先级相同，协议价更低的那条赢；
3. **倒挂保护**：协议价 ≥ 当前售价（倒挂）时**不落价**，公开售价继续生效；
4. **起订量门槛**：购物车件数未达 `min_qty` 时协议价不生效，按售价成交。

> 优先级建议：单船 / 单客户专项 `15~20` > 船队 / 企业框架 `10` > 补充折扣 `5`。越专属越优先。

### 1.4 生命周期

```text
草稿(0) ──发布──> 生效中(1) ──停用──> 已停用(2)
   ↑                  │                  │
   └──────编辑─────────┘（生效中不可编辑）←┘
```

- 新建保存后默认是**草稿**，不参与 C 端查价 / 计价；
- **发布**校验：至少 1 条 SKU 明细、生效时间窗合法且结束时间晚于当前时间；
- **生效中不可修改**基础信息和明细（合同价稳定性优先）；要改价先「停用」→「编辑」→ 再「发布」；
- **删除是逻辑删除**，页面无恢复入口；删除生效中的政策会立即停止生效，重要政策建议先停用观察；
- 时间窗到期后自动不参与查价 / 计价，但列表状态仍显示「生效中」——需要手工停用，或新建下一期。

### 1.5 和其他功能的关系

- 协议价命中后，该 SKU 的**档期特供、阶梯价、会员价、出清价都不再覆盖**；
- 协议价 SKU **不占用档期特供的活动限量**；
- 企业权益里的「协议价政策池」（`benefit_type=3`）可按会员等级自动套用政策，不需要每单手工圈；
- 企业场景不参与积分抵现（现有规则不变）。

## 二、页面导览

入口：管理端 → 营销管理 → 价格政策。

| 区域 | 说明 |
|---|---|
| **新建政策** | 打开新建弹窗，配置对象 / 模式 / SKU / 时间窗 |
| **政策名称**搜索框 | 按名称模糊查，回车或点「查询」 |

## 三、新建一条政策的完整步骤（约 5 分钟）

### 3.1 填基础信息

- **政策名称**：建议「对象 + 年份 + 协议类型」，如 `悦航1号·2027年度酒水协议价`，上限 64 字；
- **优先级**：0~999，默认 0；按 §1.3 的层级设计填；
- **备注**：写清合同依据、签约人、适用说明，方便审计和交接。

### 3.2 选适用对象

1. 先选**类型**：采购主体 / 船舶 / 客群标签；
2. 再选**对象**（多选、可搜索）：
   - **采购主体**：来自「订单管理 → 采购主体」（`/order/buyer-org`）的档案。没建档时下拉为空；
   - **船舶**：来自船舶档案。当前环境有 `悦航1号 / 2号 / 6号 / 7号 / 验收测试船`；
   - **客群标签**：来自「会员管理 → 会员标签」（`/user/member-tag`）。当前库为空，需要先建标签并给用户打标；
3. 未出现在下拉里的 ID 可以直接输入（输入框支持手工创建），但必须是**真实有效**的 ID；
4. 切换类型会清空已选对象，需要重新选。

> 适用对象下拉为空不是页面故障，是基础档案还没建。采购主体 / 客群标签维度先把档案补齐，再回来配置。

### 3.3 选价格模式

| 模式 | 适用场景 | 填法 |
|---|---|---|
| 固定协议价 | 年度框架价、单船专项、合同写明一口价 | 每个 SKU 填 `policyPrice`，必须 > 0 |
| 折扣率 | 框架外的品类统一折扣、补充协议 | 每个 SKU 填 `policyRate`，区间 `(0, 1]`，如 0.94 |

折扣率算价：`协议价 = 当前售价 × 折扣率`，保留两位小数、向下取整（与限时折扣同口径）。售价变化时，折扣率政策的协议价跟着变。

### 3.4 加 SKU 明细

两种方式：

- **从商品库添加**：搜索 SPU → 勾选 → 展开该 SPU 的全部 SKU → 添加；
- **批量导入**：粘贴 SKU ID，支持换行 / 逗号 / 空格分隔；导入后自动带出商品名称与售价，未匹配到的 ID 会在下方列出。

明细表字段：

| 列 | 说明 |
|---|---|
| 商品 / 规格 | 只用于展示，不落库 |
| SKU ID | 唯一明细键，`(租户, 政策, SKU)` 唯一 |
| 售价 | 当前售价，仅作倒挂参考，不落库 |
| 协议价 / 折扣率 | 按价格模式二选一填写 |
| 起订量提示 | 正整数，默认 1；参与结算校验 |
| 移除 | 从本条政策明细中删除 |

填写建议：

- 固定价建议**高于成本价**；低于成本时预检会提示 `COST_RISK`，系统不阻断但需运营决策；
- 协议价必须**低于当前售价**，否则倒挂不生效；
- 起订量按实际合同填（如劳保按箱 10 件、酒水按箱 2 件）；`min_qty=1` 的政策才会直接出现在商品卡上。

### 3.5 选生效时间窗

- 开始 / 结束时间精确到秒；结束必须晚于开始，且晚于当前时间，否则发布失败；
- 长期合同建议**一年一签**（如 `2026-01-01 00:00:00 ~ 2026-12-31 23:59:59`），便于年度调价；
- 未签约的下一年度合同可以先配好、存草稿，到时间再发布。

### 3.6 保存 → 预检 → 发布

1. **保存**：新建保存后是草稿（不生效）；
2. **预检**：在列表点「预检」，逐个 SKU 看冲突 / 倒挂 / 成本风险；
3. **发布**：草稿或停用 → 生效；发布后 C 端查价立即按新政策（有缓存时下拉刷新或等待缓存过期）；
4. **改价**：生效中 → 停用 → 编辑 → 再发布。历史订单已落价格快照，不受后续改价影响。

---

## 四、预检结果怎么读

预检只解释「按当前配置，哪个政策会赢」，**不阻断发布**。多个结论可能同时出现（逗号分隔）。

| 结论 | 含义 | 处理建议 |
|---|---|---|
| `OK` | 当前配置无冲突，协议价低于售价 | 可直接发布 |
| `INVERTED_SALES` | 协议价 ≥ 当前售价，或售价取不到（商品下架 / 远程失败） | 调低协议价；确认商品是否在售 |
| `SHADOWED` | 同 SKU 有更高优先级或同级更低价的其他政策，**本政策不赢** | 看「对手」政策名；调整优先级 / 价格，或合并政策 |
| `SHADOWS_OTHER` | 本政策会**压住**其他政策 | 确认是否符合业务意图，避免误伤其他合同价 |
| `COST_RISK` | 协议价低于该 SKU 成本价 | 系统不阻断；战略客户 / 清库存可接受，否则调价 |

「对手：xxx」列展示同 SKU 冲突的政策名称，便于直接定位。

## 五、四套常用配置模板（含本次预置示例）

| # | 政策名称 | 圈定对象 | 模式 | 优先级 | 状态 | 覆盖 |
|---|---|---|---|---|---|---|
| 401 | 船队年度框架协议价（2026） | 悦航1/2/6/7号（4 艘在营船） | 固定价 | 10 | 生效中 | 12 个 SKU：劳保 8 + 日用 3 + 速食 1 |
| 402 | 悦航1号·酒水专项协议价 | 悦航1号（单船） | 固定价 | 15 | 生效中 | 5 个 SKU：白酒 / 红酒 / 啤酒 |
| 403 | 船队快消品补充协议（94折） | 悦航1/2/6/7号 | 折扣率 0.94 | 5 | 生效中 | 8 个 SKU：水饮 / 纸品 / 个护 / 零食 |
| 404 | 悦航2号·2027年度协议价（待签） | 悦航2号 | 固定价 | 10 | 草稿 | 6 个 SKU：酒水 |

价格示例（当前售价 → 协议价）：

- 401：春秋工作服 `89.00 → 79.00`；钢头劳保鞋 `89.00 → 79.00`；抽纸整箱 `39.90 → 35.90`；
- 402：茅台迎宾酒 `169.00 → 158.00`；百威啤酒 `89.90 → 83.90`；
- 403：可口可乐 `39.90 → 37.50`；东方树叶 `62.90 → 59.12`（按 94 折向下取整）；
- 404：青岛啤酒 `49.90 → 45.90`（草稿，发布后才生效）。

### 5.1 船队年度框架协议价（多船 / 固定价）

适用：多船统一采购、年度合同。做法：类型选「船舶」→ 多选在营船 → 固定价 → 优先级 10 → 年度时间窗 → 劳保 / 日用 / 速食等高频补给品 → 起订量按箱 / 包设置。

### 5.2 单船专项协议价（单船 / 高优先级）

适用：某条船的招待、节庆、特殊需求。做法：类型选「船舶」→ 单船 → 固定价 → 优先级 15（高于框架价）→ 专项品类（酒水等）→ 时间窗可跨年。

### 5.3 船队补充折扣协议（多船 / 折扣率）

适用：框架价之外的快消品统一折扣。做法：类型选「船舶」→ 多船 → 折扣率 `0.94` → 优先级 5（低于框架价）→ 水饮 / 纸品 / 个护 / 零食 → 起订量按 1~3 件。

### 5.4 年度续签草稿（未来时间窗 / 草稿）

适用：下一年度合同未签完，先配好待发布。做法：目标船 → 固定价 → 优先级 10 → 时间窗设为下一年度 → **保存草稿，不点发布**。

### 5.5 采购主体 / 客群标签维度

- **采购主体**：适合岸上企业、工厂 / 餐厅采购。先建 `buyer_org` 档案并维护成员，再按主体圈定；主体成员才能看到合同价；
- **客群标签**：适合「船供大客户 / 新客体验 / 特定行业客户」等分层。先建 `member_tag` 并给用户打标签，再按标签圈定；
- 当前库这两类档案为空，所以示例未预置；建好后可复制 401~404 的配置方法。

## 六、C 端怎么生效、怎么展示

### 6.1 查价链路

- C 端调用 `POST /promotion/app/policy/prices`，传 `skuIds` / `spuIds` + 当前上下文 `vesselId` / `buyerOrgId`；
- 接口**免登可访问**，但服务端会做上下文净化：游客清空主体上下文；登录用户校验是否是该船 / 该企业成员，非成员清空该维度（防止越权窥探他人合同价）；
- 返回字段：`policyPrice`（协议价）、`originalPrice`（划线基准）、`minQty`（起订量）、`policyName`（政策名称）。

请求示例：

```json
POST /promotion/app/policy/prices
{
  "skuIds": ["9750000000000000083"],
  "vesselId": "9610000000000000001"
}
```

命中 402 政策时返回：

```json
[{
  "skuId": "9750000000000000083",
  "spuId": "9740000000000000083",
  "policyId": "9000000000000000402",
  "policyName": "悦航1号·酒水专项协议价",
  "policyPrice": 83.90,
  "originalPrice": 89.90,
  "minQty": 1
}]
```

### 6.2 展示规则

- **商品卡**：只展示 `minQty=1` 的协议价（卡片按 1 件口径），角标「协议价」，划线价为售价；`minQty>1` 的协议价**不上卡**，避免「卡面价 ≠ 结算价」；
- **商详 / 购物车**：按实际件数判断，件数 ≥ 起订量才切协议价；未达量按售价，并提示「N 件起」；
- 协议价低于售价才展示 / 生效；倒挂不落价；
- 游客 / 非成员看不到合同价，按普通售价展示。

### 6.3 命中条件（缺一不可）

1. 政策状态为「生效中」；
2. 当前时间在政策时间窗内；
3. 用户上下文命中 `apply_type` / `apply_value`（或属于企业权益「协议价政策池」）；
4. SKU 在该政策明细中；
5. 协议价 < 当前售价（非倒挂）；
6. 购物车件数 ≥ 起订量（结算 / 购物车口径）；
7. 同 SKU 多政策命中时，本政策按「优先级取大、同级取低价」胜出。

## 七、和活动一起用的注意事项

1. **先查活动，再配协议价**：先看「船供活动」里有没有正在跑的档期特供 / 阶梯价 / 会员价覆盖同一 SKU。协议价优先级最高，配了会把活动价压掉；
2. **确实要锁合同价时**：把活动 SKU 从协议价明细里剔除，或等活动结束再配；
3. **同一 SKU 多条协议价**：用优先级明确胜负（单船专项 > 船队框架 > 补充折扣），同级再比价格；
4. **档期特供限量**：协议价 SKU 不参与档期特供的活动限量占用；
5. **预检的 `SHADOWED` / `SHADOWS_OTHER`** 是「谁赢」的解释，不等于配置错误，按业务意图决定；
6. 券 / 积分按现有营销叠加策略处理，企业场景不积分。

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 价格政策列表为空 | 还没有政策 / 筛选条件过滤 / 不属于当前租户 | 清空筛选；本次已预置 4 条，刷新页面 |
| 新建时「适用对象」下拉为空 | 采购主体 / 会员标签档案为空 | 去「订单管理 → 采购主体」或「会员管理 → 会员标签」建档；也可手工输入有效 ID |
| 保存提示「生效中的政策不可修改」 | 政策正在生效 | 先「停用」，编辑改价后再「发布」 |
| 发布失败「没有配置任何 SKU 明细」 | 明细为空 | 至少添加 1 个 SKU |
| 发布失败「生效时间窗非法」 | 结束时间早于开始，或已过期 | 调整时间窗，结束时间必须晚于当前 |
| 保存提示折扣率非法 | 折扣率不在 `(0, 1]` | 改为 0.0001~1 之间，如 0.94 |
| 保存提示固定价必须大于 0 | 固定价为空 / ≤ 0 | 填正数 |
| 发布后 C 端没有协议价 | 未登录 / 非该船或该企业成员 / 对象不匹配 / 不在时间窗 / SKU 不在明细 / 倒挂 / 未达起订量 / 缓存未刷新 | 按 §6.3 逐项排查；用成员账号验证 |
| 商品卡没有协议价，但商详有 | 该政策 `minQty>1`，卡面按 1 件口径不上卡 | 预期行为；需要卡面展示时把起订量改为 1 |
| 加购 1 件仍按售价 | 未达起订量，协议价不生效 | 加够件数，或把起订量改为 1 |
| 预检显示 `SHADOWED` | 同 SKU 被更高优先级 / 更低价政策压住 | 调整优先级或价格；或合并两条政策 |
| 预检显示 `COST_RISK` | 协议价低于成本价 | 运营自行决策；不接受则调价 |
| 预检显示 `INVERTED_SALES` | 协议价 ≥ 售价，或售价取不到 | 调低协议价；确认商品在售 |
| 删除后想恢复 | 删除是逻辑删除，页面无恢复入口 | 重要政策先停用观察；误删需后台补数据 |
| 政策到期后 C 端没价了 | 时间窗结束自动不参与查价 / 计价 | 列表状态仍是「生效中」，手工停用或新建下一期 |
| 导入 SKU 提示未找到 | ID 不存在 / 已删除 / 不属于当前租户 | 核对 SKU ID；从商品库添加 |
| 「适用对象」列显示 N 个对象 | 按 `apply_value` 逗号分隔计数 | 正常展示 |
| 企业等级客户自动有协议价 | 企业权益「协议价政策池」按等级挂载了政策 | 在「企业会员 → 企业权益」维护 `benefit_type=3` |

## 九、配置前后检查清单

**配置前**

- [ ] 对象档案已存在：采购主体 / 船舶 / 会员标签；
- [ ] SKU 在售、未下架，售价与成本正确；
- [ ] 查过「船供活动」，确认没有正在跑的档期特供 / 阶梯 / 会员价覆盖同一 SKU（或已决定锁价）；
- [ ] 优先级按「单船专项 > 船队框架 > 补充折扣」设计。

**配置后**

- [ ] 固定价 > 成本价，协议价 < 当前售价（无倒挂）；
- [ ] 起订量符合合同，卡面需要展示的政策 `minQty=1`；
- [ ] 时间窗覆盖合同期，结束时间晚于当前；
- [ ] 每条政策「预检」无异常（或异常已确认可接受）；
- [ ] 发布后用**成员账号**在 C 端验证：商品卡 / 商详 / 购物车价格一致；
- [ ] 下一笔测试订单确认成交价 = 协议价，且订单快照记录了政策 ID；
- [ ] 到期政策及时停用或续签。

## 十一、一句话结论

- **要签合同价**：新建政策 → 选对象 / 模式 / SKU / 时间窗 → 预检 → 发布。
- **要改价**：先停用 → 编辑 → 再发布；生效中不可改。
- **C 端没价**：按「对象、时间、SKU、件数、倒挂、成员资格」六项排查。
- **不要给正在做活动的 SKU 配协议价**，除非你确实要用合同价锁掉活动价。
- **单船专项 > 船队框架 > 补充折扣**，优先级按这个顺序设。
