# 购物车与下单链路加固

## 目标

修复购物车、结算、创建订单和订单基础状态流转中的越权、并发和跨服务一致性风险，使服务端成为价格、库存、优惠券和用户归属的唯一可信边界。

## 范围

- 购物车新增、修改、删除、结算后清理和并发唯一性。
- 收货地址归属校验。
- 下单请求校验、服务端计价、库存原子扣减、优惠券原子占用和请求幂等。
- 订单详情、预支付、取消、删除、收货的用户归属与状态条件。
- 延迟取消消息、自动取消、自动收货、自动评价和租户上下文清理。
- Boot/Cloud 两套数据库结构与 UniApp 请求契约。
- 订单评价的订单项归属、客户端字段防伪和并发幂等。
- 支付成功消息重复投递时的商品销量消费幂等。

## 验收标准

1. 用户不能读取、修改、删除、支付、取消或确认他人的购物车、地址和订单。
2. 数量为空、为零或负数时请求失败，库存不足时任何 SKU/SPU 库存都不会变成负数。
3. 同一张用户优惠券不能被两个订单同时占用，取消只释放本订单占用的券。
4. 同一用户重复提交相同 `requestId` 不产生第二张订单或第二次库存扣减。
5. 支付、取消、收货使用状态条件更新，不会无条件覆盖并发状态。
6. 下单只清理已购买 SKU，不影响同 SPU 其他规格。
7. 已支付订单不可删除，收货后订单项状态持久化为已完成。
8. Boot/Cloud SQL、原生构建和目标测试通过；未具备的真实依赖联调必须明确记录。
9. 评价只能覆盖当前订单的完整订单项，客户端不能伪造订单、商品或用户标识，同一订单项不能重复评价。
10. 同一订单的支付成功消息重复投递时，商品销量只累计一次；销量更新失败时消费记录同时回滚。

## 兼容策略

现有 HTTP URL 保持不变。新版 UniApp 始终发送 `requestId`；旧客户端未发送时后端生成请求号以维持可用性，但旧客户端跨请求重试不具备幂等保证，升级客户端后完整生效。

## 完成结果

- 购物车改为显式 DTO，新增、改数量和换规格都读取在售商品快照并校验库存；更新、删除和清理绑定当前用户，下单只清理已购买 SKU。
- 创建订单使用 `requestId`、订单号和有效购物车唯一键建立数据库并发边界；重复 SKU 被拒绝，商品缺失、下架或库存不足直接失败。
- SKU/SPU 库存按足量条件原子扣减并聚合重复请求；用户券按持有人、待使用状态和有效期原子冻结并绑定订单，释放失败会回滚取消事务。
- 订单创建、取消、收货、删除、预支付、评价、退款、地址和物流详情补齐用户归属与状态条件；物流回调不再破坏订单关联并始终清理租户上下文。
- 延迟取消只在订单事务提交后发送，购物车清理和优惠券占用移入全局事务；自动取消/收货/评价状态和租户上下文已修正。
- Boot/Cloud 基础 SQL 与 16 号存量迁移同步，Boot 全量初始化脚本已重新生成；UniApp 复用稳定请求号并阻止重复提交。
- 评价 DTO 增加订单项、评分和内容校验，评价身份字段由服务端订单快照覆盖；移除商品模块直接写评价入口，17 号迁移为有效订单项建立唯一键。
- 商品支付消费者按租户和订单写入唯一消费记录，并与聚合后的 SPU 销量累加共用本地事务；18 号迁移同步消费记录表和租户白名单。

## 验证结果

- `mvn test -pl aryn-boot -am` 通过，38 个 Reactor 模块全部成功。
- 新增购物车、库存、优惠券、请求校验、评价防伪、消息幂等、监听器和物流回调测试；订单模块 22 个、商品模块 7 个测试通过。
- Boot 全量 SQL 静态校验通过，共 3550 行、82 张表；Cloud/Boot 的 16、17、18 号迁移分别除目标数据库名外一致，`git diff --check` 通过。
- UniApp 已恢复 Alova 全局类型生成物并引入 Vite 客户端类型，`pnpm type-check` 全量通过。
- 本机未执行真实 MySQL 8 存量迁移和 RocketMQ/Seata 多进程联调；Cloud 部署执行 18 号迁移后还需将 `product_order_pay_record` 加入商品服务 Nacos 租户表配置并重启，上线前必须在备份克隆库和集成环境演练。
