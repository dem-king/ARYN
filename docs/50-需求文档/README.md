# 50 需求文档

重大需求在本目录下建立 `YYYY-MM-DD-需求名/`，用于实现前评审和实现后复盘。推荐结构：

```text
YYYY-MM-DD-需求名/
├── README.md
├── 01-需求来源与总览.md
├── 02-业务流程与状态.md
├── 03-接口与数据变更.md
├── 04-前端交互与兼容.md
├── 实施拆分与验收清单.md
└── 当前代码与测试环境核对结论.md
```

每个需求包至少写明：原始请求、目标/非目标、影响端、权限与租户、接口和表、兼容策略、验收命令、实际结果与剩余风险。

小型低风险改动可以只在 [需求记录](../90-记录归档/需求记录.md) 登记，但涉及跨端、数据库、认证、租户、支付或状态机时必须建需求包。

当前执行计划保存在 [`docs/exec-plans/active`](../exec-plans/active/2026-07-16-project-onboarding.md)。

## 需求包

- [分类页品牌筛选交互优化](2026-09-29-分类页品牌筛选交互优化/README.md)：**方案 B 已实施并端到端验证**。金刚区分类落地页的品牌 chip 条原先拉全租户 42 个品牌，与当前分类无关——实测水果/海鲜水产/手机数码/家用电器/鲜花绿植/精选冻品/船舶物料共 7 个分类下 **42 个 chip 全部点击必空**，表现最好的分类也有 32/42 是死选项；根因是筛选维度未随结果集收敛（反分面实现）。行业标准做法为「分面导航」：筛选项从当前结果集动态计算、只展示有结果的值、并带计数（Azure/Algolia/ES `min_doc_count=1` 均如此）。已新增 `/app/goodsbrand/filter-list` 按条件聚合接口，品牌条改为分面渲染 + 商品计数 + 无区分度时整条隐藏 + 空结果给解释与出口；实测 13 个分类全部返回品牌**0 死选项**、计数与列表一致。无 DB 结构变更。
