# 站内信与客服会话

## 目标

为悦航购新增独立消息域，同时提供 C 端会员和后台工作人员两套收件箱、可回复的双向会话、共享客服池、群发通知和业务通知，并保持单体/微服务双模式、多租户隔离和现有 TOB/TOC 认证边界。

## 已确认范围

- C 端会员和后台工作人员都拥有通知收件箱。
- 群发通知支持会员、工作人员或两端同时接收；回复通知时为每个回复者创建或复用独立会话。
- C 端会员与客服使用 `CUSTOMER_SERVICE` 会话，后台工作人员之间使用 `STAFF_DIRECT` 一对一会话。
- 客服会话进入共享客服池，自动分配优先，无可用客服时进入待领取池。
- 每个会员在默认客服池中最多有一个进行中的会话；商品、订单、退款等以业务卡片进入该会话。
- 会话关闭后 24 小时内重新咨询时复用原会话，优先回到原客服；超过 24 小时创建新会话。
- 有权限且未超过接待上限的客服可以主动联系指定会员。
- 首期支持文本、图片、商品卡片、订单卡片、退款卡片、通知引用卡片和系统消息。
- 首期不支持语音、视频、普通文件、富文本、工作人员群聊和会员之间私聊。

## 架构结论

1. 新建 `aryn-message-api` 和 `aryn-message-biz`，Cloud 模式独立部署，Boot 模式由 `aryn-boot` 聚合。
2. 通知与会话分别建模；通知回复只产生回复者自己的独立会话，禁止把群发收件人放入同一会话。
3. HTTP 是消息写入的权威通道，WebSocket 只负责实时推送；断线后使用 HTTP 游标分页补拉。
4. MySQL 保存不可丢失的消息事实，Redis 保存在线状态和瞬时推送事件，RocketMQ 接收跨业务域通知命令，XXL-JOB 恢复中断的群发和会话维护任务。
5. 参与者身份使用 `tenant_id + participant_type + participant_id`，其中 `participant_type` 为 `MALL_USER` 或 `SYS_USER`。
6. 首期容量基线为 10,000 个在线连接、200 名在线客服、峰值 200 条消息/秒、单次群发 100,000 名收件人。
