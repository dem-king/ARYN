# 业务流程与状态

> 证据：同目录需求设计、消息状态枚举与服务实现；复核于 2026-08-31；置信度：已验证（静态事实），运行态以需求包验收记录为准。

## 通知发布流程

```text
草稿
  -> 校验发送人权限与当前租户
  -> 冻结标题、正文、受众条件和跳转信息
  -> 创建一个或多个分发任务
  -> 按游标从用户域/UPMS 获取收件人
  -> 分批写入 message_recipient
  -> 更新成功数、失败数和发布状态
```

同一通知可同时面向 `MALL_USER` 和 `SYS_USER`，但必须创建独立分发任务。发布后正文不可编辑，只允许撤回；撤回不物理删除历史数据。

## 通知回复流程

收件人点击“回复/咨询”时：

1. 校验通知收件关系、租户和当前身份。
2. `MALL_USER` 回复时查询默认客服池中的活跃会话；存在则复用，不存在则创建并自动分配。
3. `SYS_USER` 回复内部通知时查询与发布人的 `STAFF_DIRECT` 活跃会话；存在则复用，不存在则创建。
4. 在目标会话插入 `NOTICE_CARD`，只保存标题、摘要和发布时间快照，同时保留通知 ID。
5. 其他群发收件人无法看到该回复和会话。

## 客服会话状态机

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `WAITING` | 无负责人，等待自动分配或领取 | 会员继续留言、客服领取、主管分配 |
| `ASSIGNED` | 已分配客服，尚未首次回复 | 双方发送、转交、关闭 |
| `ACTIVE` | 客服已首次回复 | 双方发送、转交、关闭 |
| `CLOSED` | 会话结束，只读保存 | 24 小时内重开或创建新会话 |

### 创建与唯一性

- 默认客服池中，每个 `tenant_id + customer_id + queue_code` 最多一个活跃会话。
- 使用活跃唯一键和数据库唯一索引阻止用户并发点击产生重复会话。
- 商品、订单、退款入口只插入业务卡片，不创建新的并行会话。

### 自动分配

候选客服必须满足：

- 当前租户内拥有客服资格。
- 实时状态为在线，未暂停接待。
- 开启自动接待。
- 当前活跃会话数小于接待上限。

排序规则为当前负载升序、最后分配时间升序。自动分配失败时会话保持 `WAITING` 并进入待领取池。

### 手动领取与并发

领取使用条件更新：

```sql
UPDATE message_conversation
SET assigned_staff_id = ?, status = 'ASSIGNED'
WHERE id = ?
  AND status = 'WAITING'
  AND assigned_staff_id IS NULL;
```

只有影响一行才算领取成功。自动分配和客服负载变更使用事务、条件更新和乐观锁，不依赖分布式锁。

### 关闭与重开

- 会员、当前客服和主管可以按权限关闭会话。
- 关闭事务必须释放客服负载、清除活跃唯一键、写入关闭原因和系统消息。
- 关闭后 24 小时内重新咨询时复用原会话；原客服在线且有容量时优先回到原客服，否则重新自动分配。
- 超过 24 小时创建新会话，旧会话保持只读。
- 长时间无消息的会话由 XXL-JOB 按租户配置自动关闭。

## 客服主动联系会员

- 仅拥有 `message:conversation:initiate` 权限的客服或主管可以主动发起。
- 已有活跃会话且负责人为当前客服时直接复用。
- 已有活跃会话且负责人为其他客服时禁止直接接管，只能申请转交或由主管强制转交。
- 当前客服达到接待上限时不能主动新建，主管强制操作除外且必须审计。
- 主动发起同样占用客服接待名额。

## 工作人员私信

- 类型为 `STAFF_DIRECT`，只允许同租户 `SYS_USER` 之间一对一沟通。
- 不进入客服池，不参与自动分配，不影响客服活跃会话计数。
- 同一工作人员组合最多一个活跃私信会话。
- 首期不支持群聊、跨租户私信或向会员账号空间发送工作人员私信。

## 已读和未读

- 聊天消息按会话内 `seq_no` 严格递增。
- 参与者表保存 `last_read_seq`；会话未读数由 `last_seq - last_read_seq` 或受控缓存计算。
- 通知收件表独立保存通知已读状态，不与会话已读游标混用。
- 标记已读必须绑定当前租户、身份类型和身份 ID，禁止接受客户端传入任意用户 ID。
