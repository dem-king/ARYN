# 当前代码与测试环境核对结论

> 本文前半部分保留实施前基线；2026-07-22 的实施后状态见文末更新。

## 已有可复用能力

- 管理后台已有通知铃铛组件，但在商城布局中的业务接线处于注释状态。
- UniApp 个人中心有适合增加消息入口和未读角标的位置。
- 项目已有 UPMS 文件上传、租户目录对象存储和 UniApp 图片上传能力。
- 后端已有 Redis、RocketMQ、XXL-JOB、Sa-Token、Dubbo 和多租户传播基础设施。
- 订单、支付和退款已有部分事务后事件与 RocketMQ 使用模式，可作为业务通知接入参考。
- UPMS 已有“在线用户”页面，但其语义是账号登录状态，不能直接作为客服可接待状态。

## 当前缺失能力

- 未发现站内信、通知中心、客服会话、工作人员私信或聊天记录表。
- 未发现商城业务 WebSocket/SSE 后端或客户端基础设施。
- 当前 `ArynUser` 未保存明确的 TOB/TOC 登录端类型，不能安全支撑两个身份空间共用消息接口。
- 用户域现有远程接口不能按标签、等级和游标分页展开群发受众；UPMS 远程接口也不能按角色、部门分页查询工作人员受众。
- 当前商品页客服按钮仍使用微信原生 `open-type="contact"`，装修 `customer-service` 链接没有落到站内会话页面。

## 需要重点保护的现有约束

- 工作树已有商品、租户、请求层、UniApp 工具链和文档等未提交修改，实施时不得回退或顺带格式化。
- 修改 `ArynUser`、`SecurityUtils`、认证登录链路、租户上下文、菜单和公共请求层前必须使用 Graphify 检查影响范围。
- 后端不同 biz 不能直接 import；消息域只能通过 API 模块、Dubbo 和 RocketMQ 访问用户、UPMS、订单等域。
- 新增所有含 `tenant_id` 的表都会触发 Boot/Cloud 租户配置一致性门禁。
- Boot 全量 SQL 由 `db/boot/build-full-sql.mjs` 聚合，新增消息 SQL后必须更新构建清单并重新生成校验。

## 当前可靠验证基线

- 后端：`mvn test -pl aryn-boot -am`。
- 管理端：`pnpm check:type && pnpm test:unit && pnpm lint`。
- UniApp：`pnpm type-check`；微信构建要求 Node 22，并可能受当前工作树工具链状态影响。
- 历史 Harness 验证脚本在当前工作树中已删除，实施计划不得引用为已存在能力。

## 尚未验证

- 真实 MySQL 8 增量迁移。
- WebSocket 经 Gateway 和 Boot 双模式连接。
- 多实例 Redis 推送和断线补拉。
- RocketMQ 业务通知重复投递、乱序和故障恢复。
- 10,000 连接、200 消息/秒和 100,000 人群发容量目标。

以上均应在实现完成后按需求包的验收清单补充实际结果，未执行前不得声明通过。

## 2026-07-22 实施后更新

- 原“当前缺失能力”已由 `aryn-message-api/biz`、Boot/Cloud SQL、Gateway/Nacos/Docker、WebSocket/Redis、管理端和 UniApp 消息页面补齐。
- `ArynUser.deviceType` 与 `SecurityUtils.requireUser` 已建立 TOB/TOC 身份门禁；用户域和 UPMS 已提供消息受众及客服资格 Dubbo 契约。
- 商品客服、订单、退款和装修客服链接均已接入站内会话，并保留商品页原生微信客服灰度开关。
- 订单创建、支付、退款和优惠券领取已接入事务后业务通知；通知保存安全卡片与跳转快照，消费者按来源和收件人双重幂等。
- Graphify 工具在本轮环境不可用，影响分析由 `rg`、模块边界、租户/拦截绕过审计和 Reactor 全量测试替代；集成环境影响复核仍应补做。
- 本地三端验证结果和未执行项以 [实施拆分与验收清单](实施拆分与验收清单.md) 为准。
