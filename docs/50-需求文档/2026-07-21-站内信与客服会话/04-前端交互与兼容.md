# 前端交互与兼容

## 管理后台

### 头部铃铛

复用现有通知组件，接入最近通知、总未读数、单条已读、全部已读和“查看全部”。总未读数需要区分通知、客服会话和工作人员私信来源，点击后进入对应页面。

### 通知管理

- 通知列表：草稿、发布中、已发布、已撤回、部分失败。
- 编辑器：标题、纯文本正文、优先级、目标端、受众条件、安全跳转和发布时间。
- 发布确认：展示预计收件人数和当前租户。
- 发布结果：成功数、失败数、阅读数和回复会话数。
- 已发布正文不可编辑，只能撤回。

### 客服工作台

- 左侧列表分为待领取、我的会话、历史会话。
- 中间区域显示消息时间线、发送状态、已读状态和业务卡片。
- 右侧显示会员资料、最近订单、当前客服、会话状态和操作日志。
- 客服可切换在线、忙碌和暂停接待。
- 普通客服只能查看自己的会话；主管可以查看和操作本租户全部客服会话。

### 工作人员私信

- 提供工作人员搜索和一对一会话列表。
- 内部通知点击回复时自动打开或创建与发布人的私信。
- 不展示跨租户人员，也不提供群聊入口。

### 动态菜单

新增消息中心、通知管理、客服工作台和工作人员私信页面时，必须同步 `sys_menu`、套餐菜单和存量角色授权迁移。头部铃铛读取本人数据不应要求通知管理权限。

## UniApp

### 消息中心

- 个人中心增加消息图标和未读角标。
- 消息中心包含“通知”和“客服”两个页签。
- 通知列表支持已读状态、分类、时间和跳转卡片。
- 客服页展示当前活跃会话和历史会话。

### 聊天页面

- 支持文本、图片和业务卡片。
- 发送时立即展示本地发送态，以 `clientMessageId` 与服务端确认结果合并。
- WebSocket 断开时显示连接状态，但仍允许通过 HTTP 发送。
- 重连后按最后已知 `seqNo` 补拉消息。
- `WAITING` 状态展示排队提示；分配成功后展示客服昵称；关闭后展示 24 小时重开说明。

### 业务入口

- 商品详情现有微信原生客服按钮改为站内客服入口，并发送商品卡片。
- 订单详情、退款详情增加联系客服入口并发送对应业务卡片。
- 装修链接中的 `customer-service` 统一解析为站内客服页面，不再仅返回未落地的 contact 动作。

## 消息内容安全

- 文本以纯文本渲染，禁止直接渲染未经清洗的 HTML。
- 图片仅允许 JPG、PNG、WebP，服务端验证 MIME，单张建议不超过 10MB，一次最多 6 张。
- 图片对象路径必须包含租户 ID，复用现有 UPMS 上传和存储配置。
- 业务卡片只允许预定义类型和字段，不接受任意 URL；点击后由端内路由白名单解析。
- 发送接口按会员、客服和租户进行频率限制，防止刷屏和主动骚扰。

## 兼容策略

- 未升级的旧客户端不展示消息入口，不影响原商品、订单、支付流程。
- 商品页原生微信客服能力替换前应保留配置开关，允许灰度回退。
- WebSocket 不可用时使用 HTTP 发送和定时补拉，功能降级但消息不丢失。
- Boot 和 Cloud 由前端现有 `VITE_OPEN_BOOT` 路径逻辑切换，不在页面中硬编码部署形态。
- 业务卡片展示快照，点击详情时重新查询业务服务，以当前业务状态为准。
