## 3. 改造一：条件渲染维度扩展

### 3.1 新 Schema 类型定义（SectionConditionGroup）

`condition` 字段由旧的字符串联合类型，升级为「字符串简写向后兼容 + 对象组合条件」：

```ts
export type SectionCondition = 'always' | 'guest' | 'login' | SectionConditionGroup

export interface SectionConditionGroup {
  logic: 'and' | 'or'
  rules: SectionConditionRule[]
}

export type SectionConditionRule =
  | { type: 'login' }
  | { type: 'guest' }
  | { type: 'memberLevel'; memberLevelIds: string[] }
  | { type: 'userTag'; userTagIds: string[] }
  | { type: 'timeRange'; startTime: string; endTime: string } // HH:mm
```

### 3.2 向后兼容策略

- **旧字符串值仍可解析**：`'always' | 'guest' | 'login'` 原样保留，不迁移存量数据。
- **两端各自实现 `normalizeCondition()`**（管理后台 `schema/migrate.ts`、C 端 `schema/migrate.ts`）：
  - 合法 `SectionConditionGroup` 对象深拷贝透传；
  - 规则逐项清洗：`memberLevel/userTag` 过滤非字符串 ID，`timeRange` 兜底空串，未知规则类型丢弃，`rules` 非数组归为 `'always'`；
  - 未知格式（含历史脏值如 `'vip'`）统一归一为 `'always'`（即对所有人可见，不致误隐藏区块）。
- 默认值 `condition: 'always'` 维持不变。

### 3.3 后端：新增会员信息聚合接口

| 项 | 值 |
|----|----|
| 方法/路径 | `GET /mall-user/app/member/current-info`（cloud 域为 `mall-user`；boot 改写后为 `/boot/app/member/current-info`） |
| 鉴权 | C 端 Sa-Token 登录，必须登录（未登录走 C 端全局拦截器拒绝） |
| 用途 | 返回当前用户的会员等级 ID+名称与标签列表，供装修条件渲染判断 |

**响应结构 `MemberCurrentInfoVO`：**

```json
{
  "code": 0,
  "data": {
    "levelId": "178xxxx",
    "levelName": "黄金会员",
    "tags": [
      { "tagId": "179xxxx", "tagName": "高净值" }
    ]
  }
}
```

- 未配置会员等级时 `levelId/levelName` 为 `null`；无标签时 `tags` 为空数组。

**涉及文件（后端）：**

- 新增：`aryn-user/aryn-user-api/.../api/vo/MemberCurrentInfoVO.java`
- 修改：`IMemberBenefitService.java`（新增 `getCurrentMemberInfo(String userId)`）
- 修改：`MemberBenefitServiceImpl.java`（注入 `IMemberTagService`，聚合等级 + 标签；二者同处 user-biz 模块，属模块内调用，不违反跨模块 Dubbo 约束）
- 修改：`AppMemberController.java`（新增 `GET /current-info`）

> 探查结论：原 `GET /app/userinfo` 仅含 `levelName` 不含 `levelId`/标签；原 `GET /app/member/benefits` 含 `levelId` 不含标签列表，故需新增聚合接口。

### 3.4 管理后台：section-settings.vue 重构

「条件显示」由 ElSelect 三选下拉重构为两层：

1. **登录态单选**（ElRadioButton 组：全部用户 / 仅登录 / 仅游客）——对应旧字符串简写，选中即写入 `condition` 字符串。
2. **高级条件组合开关**（ElSwitch，默认关闭=折叠）：
   - 开启后展示 AND/OR 组合逻辑单选；
   - 规则列表可增删，规则类型下拉三选一：**会员等级 / 用户标签 / 时间段**；
   - 会员等级、用户标签为 ElSelect 多选 + `filterable` 搜索：
     - 会员等级数据源 `GET /mall-user/memberlevel/list`（值 `id`、标签 `levelName`）；
     - 用户标签数据源 `GET /mall-user/membertag/list`（值 `id`、标签 `tagName`）；
     - 两接口失败时静默降级为空下拉，不阻断装修；
   - 时间段为两个 ElTimePicker（`format="HH:mm"` + `value-format="HH:mm"`），默认 `00:00`–`23:59`。
3. 关闭高级开关时 `condition` 回退为字符串简写；开启时存储 `SectionConditionGroup` 对象。

### 3.5 C 端：userStore 扩展 + sectionVisible() 重写

**`userStore.ts` 扩展：**

- 新增 state：`levelId: string`、`userTags: string[]`；
- 新增 getters：`getLevelId`、`getUserTags`、`hasTag(tagId)`；
- 新增 action：`fetchMemberInfo()`（去重 Promise，从 `tags` 对象数组提取 `tagId` 列表存入 `userTags`）；
- `fetchUserInfo()` 中并行调用 `fetchMemberInfo()`（登录后自动获取）；`clearUserInfo()` 重置 levelId/userTags。

**新增 API：`src/api/user/member.ts`** → `GET /mall-user/app/member/current-info`（需登录 token）。

**`sectionVisible()` 重写（`src/components/diy/index.vue`）：**

- 字符串简写：`always`=true；`login`=`authStore.isLoggedIn`；`guest`=`!authStore.isLoggedIn`。
- `SectionConditionGroup` 按 `logic`（and/or）组合 5 种规则：
  1. `login` / `guest`：同简写判断；
  2. `memberLevel`：`userStore.levelId` 命中 `memberLevelIds`（未登录返回 false）；
  3. `userTag`：`userStore.userTags` 与 `userTagIds` 有交集（未登录返回 false）；
  4. `timeRange`：当前时间在 `startTime~endTime`（HH:mm）之间，**支持跨天**（如 22:00~06:00）。
- 响应式：`sections` 为 computed，依赖 `authStore.isLoggedIn`、`userStore.getLevelId`、`userStore.getUserTags`，登录/退出后自动重算。

### 3.6 两端类型一致性确认

管理后台 `page-designer/schema/types.ts` 与 C 端 `components/diy/schema/types.ts` 的 `SectionCondition / SectionConditionGroup / SectionConditionRule` 定义**逐字段一致**（logic 取值、五种 rule 联合、`memberLevelIds/userTagIds/startTime/endTime` 字段名与类型完全对齐），管理后台产出的 Schema 对象可被 C 端直接解析。

## 4. 改造二：商品详情页模块化装修（pageType='2'）

### 4.1 pageType='2' 三端扩展

- **后端**：`page_design.page_type` 注释/Schema description 新增「2.商品详情页；」。涉及实体与 VO：`PageDesign.java`、`PageDesignVersion.java`、`AppPageDesignVO.java`、`PageDesignEditorVO.java`、`PageDesignVersionVO.java`。
- **管理后台**：`api/promotion/page-design.ts` 的 `PageDesignType = '0' | '1' | '2'`；搭建器 `page-designer/index.vue` 路由 query `type=detail` 映射 `'2'`；`template-dialog.vue` 的 pageType prop 放宽为 `PageDesignType`；组件库面板接收 `:page-type`。
- **C 端**：商详页 `goods-detail/index.vue` 接入 DiyPage（见 4.3）。

### 4.2 后端新增按类型取装修接口

| 项 | 值 |
|----|----|
| 方法/路径 | `GET /promotion/app/pagedesign/type/{pageType}`（boot 改写后 `/boot/app/pagedesign/type/2`） |
| 用途 | C 端商详页取 `pageType=2` 的已发布装修 Schema |
| 鉴权 | C 端公开，无需登录（与首页 `GET /app/pagedesign` 一致） |
| 路由 | `/type/{pageType}` 为字面量段，Spring MVC 优先于 `/{id}` 匹配，与现有 `GET /{id}` 无冲突 |
| 未发布行为 | 抛出「Published page does not exist」，与首页未发布行为一致，C 端捕获后回退默认商详 |

新增服务方法 `PageDesignPreviewService#getPublishedByType(String pageType)`。

### 4.3 C 端商详页接入方式

- `onLoad` 中调用 `fetchGoodsDetailDecoration()` 获取 `pageType=2` 装修 Schema；
- **DiyPage 插入位置**：`ShipProfileCard` 之后、`GoodsComment` 之前；
- 用法：`<DiyPage :page-content-data="decorationContent" :goods-id="String(spuId)" />`（通过 `goodsId` prop 把当前商品 ID 传给装修组件）；
- **加载体验**：加载中显示 `.decoration-skeleton` 骨架屏（300rpx 灰色占位）；
- **降级**：获取失败静默降级为无装修（`decorationContent = null`），不影响商详页正常展示；
- **缓存**：模块级变量 `goodsDetailDecorationCache`，同一次应用生命周期不重复请求。

> 商品上下文由前端把 goodsId 通过 props 传给 diy 渲染组件，后端无需在装修接口返回商品上下文。

### 4.4 商详页可用组件白名单（14 个）

`component-registry.ts` 新增导出 `detailPageAllowedComponents`：

| 分类 | 组件 |
|------|------|
| 商品类 | `goods`、`goods-group`、`goods-scroll`、`goods-waterfall`、`goods-ranking` |
| 图片类 | `image-ad`、`swiper-banner` |
| 文本类 | `title-text`、`rich-text` |
| 营销类 | `coupon-receive`、`coupon-combo`、`limited-activity` |
| 辅助类 | `gap`、`notice` |

组件库 `component-library.vue` 在 `pageType === '2'` 时过滤掉白名单外组件（search-bar、category-nav、tab-nav、countdown、marketing-entry、shop-info、ship-workbench、replenish-card、bottom-nav、video-live 等页面级组件不出现在商详页）。

页面列表同步：类型筛选新增「商品详情页」；新建按钮改为 ElDropdown（微页面/商品详情页）；删除入口由仅 `pageType === '0'` 放宽为 `pageType !== '1'`（首页不可删，商详页可删）。

### 4.5 DB 改动说明

**无需 SQL。** `page_type` 为 `char(2)` 自由列，无 CHECK 约束、无字典/枚举表存储 pageType 取值（已检索 `db/` 全量脚本确认），新增枚举值 `2` 无需 ALTER TABLE、无需 boot/cloud 增量脚本、无需重新生成 `aryn_boot_full.sql`。

> 注：`page_design_template.page_type`（模板表）语义独立，其 `2` 表示「通用」，与本次页面表扩展无关，未改动。

### 5.3 新增 image.ts 工具（`src/utils/image.ts`）

- `withWebp(url)`：为 http(s) 图片 URL 追加 `x-oss-process=image/format,webp` 参数，走 OSS 自动转 WebP；
- `resolveImageSrc(url)`：空值返回占位图；
- `PLACEHOLDER_IMAGE`：SVG 透明占位图。

### 5.4 小程序 / H5 跨端兼容说明

- 仅使用 UniApp 原生 `<image lazy-load>` 属性，**未使用浏览器 IntersectionObserver**，因此微信小程序与 H5 行为一致、无需条件编译；
- `lazy-load` 在小程序端基于页面滚动自动触发展示，在 H5 端同样生效，跨端兼容无差异。

## 11. 2026-09-25 区块样式能力升级与首页品牌区拆分

### 11.1 起因

运营在小程序「商城装修」页给首页区块选了饱和品牌色 `rgb(255,109,109)`，
实机效果是**一条贯穿全屏的粉红色带**——搜索栏、轮播图、金刚区、优惠券、
公告、商品楼层全部浮在同一片饱和色上，与参考图（美团自营 / 小象超市：
彩色页头 + 浅底内容区）观感差距明显。

### 11.2 根因（不是配置问题，是能力缺失）

区块（section）此前只有三个样式字段，且渲染恒定：

| 缺口 | 事实 |
|------|------|
| 无圆角 | `SectionStyle` 无 `radius` 字段，C 端与画布均不输出 `border-radius` |
| 无左右留白 | 无 `marginX` / `paddingX`，区块恒为**通栏全宽** |
| 区块间无间距 | 无 `marginY`，相邻区块紧贴 |
| 单位口径不一致 | 管理端 `paddingY` 按 `px` 编辑，C 端却按 `${paddingY}rpx` 渲染，**同一数值两端相差 2 倍** |
| 背景图属性缺失 | C 端 `.diy-section` 未声明 `background-size/position/repeat`，区块背景图会平铺重复 |

也就是说：**任何背景色都只能画成通栏色带**，运营无从做成卡片——这是功能缺陷，不是选择问题。

### 11.3 三端改动

**Schema（两端同构）**

- `aryn-mall-uniapp/src/components/diy/schema/types.ts`、管理端 `page-designer/schema/types.ts`：
  `SectionStyle` 新增 `marginX` / `marginY` / `paddingX` / `radius`（长度单位统一 **px**）。
- 两端 `defaults.ts` / `migrate.ts`：新增字段默认 0（**旧文档缺省即通栏直角，历史页面视觉不变**）；
  新增 `normalizeSectionLength()` 收敛负数/非数字/超大值（上限 200），渲染层不再防御脏数据。
- 管理端 `defaults.ts` 导出 `CARD_SECTION_PRESET`（12/12/12/12 + 圆角 16），供面板一键套用。

**C 端渲染（`diy/index.vue`）**

- `sectionStyle()` 输出 margin/padding/`border-radius`，`paddingY` 由 `rpx` 改为 **px**，与画布口径对齐。
- 圆角时补 `overflow: hidden` 裁掉子组件溢出的直角背景；
  **横滑区块跳过裁切**（内联 `overflow` 会盖掉 `overflow-x: auto` 禁掉横滑）。
- 有背景图时补齐 `background-position/repeat/size`。

**管理端（编辑器）**

  以及「套用卡片样式」按钮（`groupKey: section-card-preset`，一次 undo 可回退）。

**测试守卫**

- `preview-parity.test.ts` 新增用例：两端必须以 px 输出 `paddingX/paddingY/marginX/marginY/radius`、
  不得再出现 `paddingY}rpx`、圆角的裁切带 `horizontalScroll` 守卫。
- 两端 `migrate.test.ts` 各增 2 例：旧文档缺省为通栏直角；非法长度收敛（负数/字符串/NaN → 0，999 → 200）。

### 11.4 数据库（双模式各一份）

`db/boot/93page_design_section_style_upgrade.sql`、`db/cloud/93page_design_section_style_upgrade.sql`：

把「品牌组件与内容混在同一个上色区块」的畸形结构拆成
