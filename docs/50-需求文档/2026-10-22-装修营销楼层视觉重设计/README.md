## 〇、一页结论

| 项 | 结论 |
|----|------|
| **问题定性** | 不是配色问题，是**缺「促销语义层」**：三个楼层共用「白底 + 1rpx 彩边 + 8rpx 圆角 + 27rpx 灰名 + 30rpx 红价」的通用列表外壳，没有促销色块/徽标/进度/CTA/场次节奏，用户读到的信息量与普通商品列表完全一样 |
| **设计方向** | 建立**统一的促销楼层语言**：`楼层头（倒计时/副标题）+ 促销强调色 + 大价格 + 徽标 + 明确 CTA`；三个模块按**促销强度三级**分工（秒杀强 / 拼团中 / 折扣轻），同屏堆叠不互相稀释 |
| **秒杀** | 场次 Tab + 横滑商品卡（280rpx，图 1:1）+ 深色分格倒计时 + 「已抢 %」/「仅剩 N 件」双态进度 + 马上抢 |
| **拼团** | **单列横排卡**（1 活动 = 1 商品）：双价对比 + 「N 人成团」徽标 + 「省 ¥X」+ 去拼单；双列货架式作为可配置备选 |
| **限时折扣** | **折扣力度即主视觉**：全场型活动用「折扣大牌横幅卡」，商品型活动用活动头大牌 + 双列商品卡；不再用灰字解释空清单 |

| **配置增量** | 新增 3 个**可选**字段：`subtitle`（三个组件）、`layout`（拼团）、`goodsLimit`（折扣）；旧页面零迁移 |
| **工作量** | 约 **4 人日**（关键路径约 3 天），详见 §8.4 |
| **需要拍板** | 5 项，见 §10 |

## 一、背景与目标

### 1.1 目标

1. 三个营销楼层在 C 端「一眼看出是促销」，与普通商品列表形成明确区分。
2. 信息层级正确：价格 / 促销力度是第一视觉，商品名与辅助信息让位；每个模块有明确行动入口。
3. 管理端画布预览与小程序实机**逐值一致**（沿用仓库既有 1rpx = 0.5px 契约）。
4. 多租户主题色（暖橙 / 天空蓝 / 抹茶绿 …）下均成立，不写死单一色值。
5. 只用现有真实数据造氛围；不伪造销量、参团人数、评价数等社会证明。

### 1.2 非目标（本轮明确不做）

| 不做 | 原因 |
|------|------|
| 不改数据源、接口、数据库 | 现有字段足够；后端零改动，风险最低 |
| 不加「更多 ›」跳转 | 需要新增链接选择器与链接类型配置，超出视觉重设计范围 |
| 不做 C 端「秒杀会场页 / 折扣会场页」（`pages/promotion/seckill`、`discount`）重设计 | 页面级改版是另一条线；本期只改首页装修楼层 |
| 不做暗色模式完整适配 | 全站暗色模式未上线（三期）；本期保证颜色走 token，不新增写死色 |
| 不伪造「已拼 N 件 / 还差 1 人成团」 | 无结构化数据；管理员预览与 C 端会不一致 |
| 不改装修画布骨架/拖拽逻辑 | 与本次视觉无关 |

## 二、现状诊断

### 2.1 用户可见问题（对照 visual-before.jpg）

| # | 现象 | 证据 |
|---|------|------|
| 1 | 三个楼层都是白底列表，与普通商品列表无差别；1rpx 浅粉描边 + 8rpx 圆角显廉价 | `diy-seckill/index.vue:136-151`、`diy-limited-activity/index.vue:74-84`、`diy-discount/index.vue:117-137` |
| 2 | 价格 30rpx/700 与商品名 27rpx/500 权重接近，价格「跳不出来」 | 同上 |
| 3 | 秒杀没有场次导航：`count` 默认 1，只有正在看的这一场，其他场次不可发现 | `createSeckillDefaults()` count=1；组件按 session 竖向堆叠 |
| 4 | 秒杀进度条只有「已售 0%」一种表达；库存告急时无「仅剩 N 件」的紧迫文案 | `soldPercent()` 单态输出 |
| 5 | 拼团没有拼团语义：没有成团人数、没有双价对比、没有省额、没有 CTA；和普通商品行几乎一样 | visual-before 第 2 列 |
| 6 | 折扣力度被压缩成 21rpx 浅底小标签（「8 折」），几乎不可见 | `diy-discount/index.vue:124` `.activity-tag` 21rpx |
| 7 | 全场型折扣活动（无商品清单）只显示一行灰字「全场商品参与…」，看起来像空数据/坏数据 | `diy-discount/index.vue:127`（模板 :78） |
| 8 | 三个楼层都没有 CTA，用户不知道「这里能干嘛」 | 三处模板均无按钮 |

### 2.2 量化诊断

| 维度 | 现状 | 主流做法 | 差距 |
|------|------|----------|------|
| 字号层级 | 21 / 22 / 27 / 30 四档，价格与正文同权 | 名 28、价 44、辅助 20-22（详见调研 §5.2） | 价格权重不足 |
| 卡片 | 1rpx 彩边 + 8rpx 圆角 + 无阴影 | 浅底 + 16-20rpx 圆角 + 轻阴影 | 无层次 |
| 促销色 | 仅价格/时间用主色，零面积色块 | 头部色块 / 徽标 / CTA 形成促销面 | 无促销氛围 |
| 信息密度 | 秒杀单列 3 条、拼团单列 4 条、折扣单列 N 条 | 秒杀横滑、拼团单列横排、折扣双列 | 秒杀/折扣浏览效率低 |
| 行动入口 | 无按钮（整卡可点但无提示） | 每模块明确 CTA | 缺引导 |
| 数据表达 | 拼团丢 `groupNum`、无省额、无折扣主视觉 | 成团人数 / 立省 ¥X / 折扣大牌 | 数据未用尽 |

### 2.3 根因

三个组件是「按数据字段平铺」的列表实现，**没有按「促销类型」重新组织信息**：秒杀应表达「抢」（场次 + 倒计时 + 进度），拼团应表达「拼」（成团人数 + 双价 + 去拼单），折扣应表达「省」（折扣力度 + 省额）。因此重设计的核心不是换皮，而是**给每个模块建立自己的信息锤（visual hammer）**。

## 三、市场调研结论（摘要）

> 完整调研（布局变体、信息层级、倒计时/进度/CTA/配色拆解、13 条可复用模式、反模式清单、来源清单）见 [01-市场调研.md](./01-市场调研.md)。

### 3.1 证据等级声明（必读）

本轮外网通道全部不可用（`web_search` 401、autoglm token 服务 502、`web_fetch` 域名拦截），**无法重新抓取主流 App 截图做逐像素核对**。调研采用三条替代证据线并在原文标注置信度：

- `[知]` 行业通识（淘宝/京东/拼多多/美团/抖音/盒马等长期稳定的模块形态，跨年变化小）
- `[推]` 推断（需设计稿/真机验证）
- `[代]` 仓库代码取证（附文件与行号）

结论用于**方向与区间判断**，落地数值以本文 §5 的 rpx 规格为准。

### 3.2 六条关键结论

1. **缺促销语义层**是「不好看」的根因（见 §2.3）。
2. 数据有限时，只能用 **时间（倒计时）、库存（已抢/仅剩）、价差（省 ¥X）、力度（8 折）** 四类真实数据造氛围；不伪造社会证明。
3. **秒杀**：场次 Tab + 横滑精选卡（图 1:1）+ 场次级分格倒计时 + 双态进度 + 马上抢。
4. **拼团**：1 活动 = 1 商品 → 单列横排卡（图左、双价、省额、CTA）；双列只在活动数 ≥4 时有货架价值。
5. **折扣**：折扣力度要放大成主视觉（88rpx 大牌）；无商品清单的全场型活动是独立形态，应换横幅卡骨架，而不是塞灰字。
6. **多租户**：促销色必须走语义 token；1rpx 彩边改浅底 + 圆角 + 轻阴影；触控热区 ≥88rpx；同屏三个楼层必须「一深两浅」区分，否则互相稀释。

### 3.3 对调研文档的两处校正（代码取证）

| 调研原文判断 | 复核结果 | 影响 |
|---|---|---|
| 拼团「无结构化成团人数字段」，首版不显示 `X 人团` | **不成立**：`GroupBuyActivity.groupNum` 存在于实体；C 端 `/promotion/app/groupbuy/activity/page` 返回的 `GroupBuyActivityVO` 已带 `groupNum`；管理端分页返回实体同样带该字段。只是 `retail-normalizers.ts` / admin `retail-data.ts` 没归一化 | 只需**两端前端归一化补字段**，即可显示「N 人成团」徽标，无后端改动 |
| 可考虑「已拼 N 件」 | C 端 `joinCount`（未成团记录数）仅 app 分页 VO 有、管理端分页 VO 没有；语义也偏「正在拼的团数」 | **本轮不做**，避免管理端预览与 C 端不一致 |

## 四、设计总纲

### 4.1 促销强度三级体系（同屏不打架）

同一个首页里三个楼层经常上下相邻（见 visual-stacked.jpg），如果都用同一套渐变彩头会「一路橙到底」，注意力互相稀释。因此按运营语义分三级：

| 级别 | 模块 | 运营语义 | 楼层头 | 信息锤 | CTA | 主色占比 |
|------|------|---------|--------|--------|-----|----------|
| **强** | 限时秒杀 | 限时限量、抢 | 品牌渐变态 + **深色分格倒计时** | 场次节奏 + 已抢进度 + 省额 | 马上抢（实心） | 高 |
| **中** | 拼团 | 邀好友、一起省 | 浅色底 + 主色图标 + 内联倒计时 | 成团人数 + 双价 + 省额 | 去拼单（实心，尺寸略小） | 中 |
| **轻** | 限时折扣 | 限时降价、逛 | 浅色底 + 主色图标 + 内联倒计时 | **折扣大牌** + 省额 | 立即/去逛逛（弱按钮） | 低 |

> 依据：调研 §4.2「秒杀与折扣必须一深一浅」、§5.1「60/30/10 配色」；同时保留全站品牌一致性——三者共用同一套圆角/字号/间距/价格口径，只在「强度」上分层。

### 4.2 色彩角色与 token

| 角色 | 用途 | 取值 | 多租户说明 |
|------|------|------|-----------|
| accent | 价格、折扣大牌、CTA、进度条、选中 Tab、省额 | `var(--wot-color-theme-primary)` | 跟随租户主题色 |
| accent-2 | 渐变第二端、小徽标渐变 | `var(--wot-color-theme-secondary)` | 跟随租户（主色混白 35%） |
| promo-soft | 浅色楼层头、省额胶囊底、图片垫底 | `var(--wot-color-theme-background)` | 页面底色（主色混白 92%），**管理端画布需补下发**（见 §6.4） |
| promo-line | 浅色头/胶囊描边 | `var(--wot-color-theme-background)` 叠深一档不可行 → 用 `accent-2` 20% 视觉近似 | 见 §9 风险 R4 |
| dark-block | 秒杀倒计时块 | **固定 `#1F2329`** | 不随主题，保证亮黄/亮绿主题下也高对比 |
| ink / ink-2 / muted | 标题 / 正文 / 辅助 | `#1F2329` / `#5B616E` / `#8A8F99` | 固定中性 |
| strike | 划线原价 | `#B6B9C0` | 固定中性 |
| line | 卡片描边/分隔 | `#F1F2F4` | 固定中性 |

**渐变头部实现**：`linear-gradient(118deg, secondary 0%, primary 58%, primary 100%)` + 一层 `rgba(0,0,0,.12)` 的暗化叠加 + 右上角淡白同心圆装饰。暗化层同时解决「亮色主题白字对比度不足」的问题（见 §9 R3）。
**禁止**：把主色同时铺满价格、时间、进度、标签四处（现状问题）；**禁止**写死 `#FF2237` 作为促销色。

### 4.3 字号 / 圆角 / 间距规范（750rpx 设计稿）

| 元素 | 规格 | 备注 |
|------|------|------|
| 楼层标题 | 38rpx / 800 | 促销头内，白字或 ink |
| 楼层副标题 | 19rpx / 500 | 半透明白或 muted，单行截断 |
| 场次 Tab | 24rpx / 600，高 60rpx | 选中渐变底白字 |
| 商品名 | 25rpx / 500，行高 34rpx，**2 行** | 替代现状 1 行截断 |
| 促销价 | **42rpx / 800**（¥ 20rpx） | 全卡唯一最大字 |
| 原价 | 20rpx / 400 划线 | 仅当 > 促销价时显示 |
| 省额胶囊 | 19rpx / 600，高 34rpx | `省¥X`，原价缺失时隐藏 |
| 进度/剩余/辅助 | 19-20rpx / 400-500 | 等宽数字 `tabular-nums` |
| 倒计时数字 | 深色块 23rpx / 700；内联时间 22rpx / 800 | |
| CTA | 24rpx / 700，高 56rpx，pill | 秒杀/拼团实心，折扣弱按钮 |
| 圆角 | 楼层头/卡片 20rpx；商品图 16rpx；大牌 20rpx | 现状 8rpx 偏小 |
| 卡间距 / 楼内边距 | 16rpx / 20-24rpx | |
| 卡阴影 | `0 8rpx 24rpx rgba(0,0,0,.05)` | 替代 1rpx 彩边 |
| 触控 | 视觉按钮 56rpx，热区 ≥88rpx；整卡可点 | WCAG 2.5.5 / Apple HIG |

### 4.4 两端一致性口径（强制）

- 管理端预览 px 与小程序 rpx 严格 `px = rpx / 2`（沿用 `preview-parity.test.ts` 契约）。
- 两端独立实现，**样式值必须逐值对齐**；改任一端必须同步另一端，并更新契约测试。
- 小程序 `<image>` 必须显式写宽高（基座自带 `height: 240px` 的坑，现有注释已记录）。

### 4.5 动效与可用性

- 倒计时 1s 刷新：C 端复用 `useCountdownTicker`；管理端预览新增 `now = ref(Date.now()) + setInterval`（仓库已有 `countdown/index.vue`、`newbie-floor/index.vue` 同款约定），组件卸载清理。
- 秒杀横滑：不自动轮播（不引入跑马灯反模式）；第三张卡露出约 45% 提示可滑动。
- 卡片按压态：C 端 `hover-class` 轻量反馈（背景 #FAFAFA），不做缩放动画。
- 数字用 `font-variant-numeric: tabular-nums`，避免倒计时抖动。
- 不做每一个商品卡挂一个倒计时（噪音源，调研 §2.3）。

## 五、分模块方案

### 5.1 限时秒杀（强）

#### 结构

```
┌ 楼层头（渐变 + 深色分格倒计时） ──────────────────────┐
│ [⚡] 限时秒杀   整点开抢 · 限量特价      距结束 [02][:][54][:][22] │
└──────────────────────────────────────────────┘
[ 现在抢 · 进行中 ] [ 午间场 20:32 ] [ 明晚20点 明日 ]   ← 横滑 Tab（仅多场次时）
┌ 横滑商品卡 ─────────────────────────────────────┐
│ [图 1:1｜省¥19.74]  [图 1:1｜省¥6.00]  [第三张露出…]   │
│  乐事薯片70g*10包      星巴克即饮咖啡 270ml              │
│  ▓▓▓▓▓▓▓░░ 已抢73%     ▓▓▓░░░░░░ 已抢35%                │
│  ¥22.90 ¥42.64        ¥9.90 ¥15.90                     │
│  [    马上抢    ]      [    马上抢    ]                 │
└──────────────────────────────────────────────┘
```

#### 规格

| 项 | 规格（rpx） |
|----|-----------|
| 楼层头 | 高 112，圆角 20，padding 0 24，图标 54，标题 38/800，副标题 19/500 |
| 倒计时 | 深色块 40×42，圆角 8，数字 23/700 白，冒号 20/700；前置「距结束」17rpx 半透明白 |
| 场次 Tab | 高 60，pill，padding 0 26；选中：渐变底 + 白字 + 轻投影；未选中：#F5F6F8 + #6B7280 |
| 商品卡 | 宽 280，图 280×280，卡圆角 20，间距 16，卡内 padding 16/18 |
| 价格 | 42/800 + ¥ 20/700；原价 20 划线；省额胶囊 19/600 |
| 进度 | 轨道高 12，圆角 999；文案 19/600 |
| CTA | 高 56，圆角 999，渐变底白字 24/700 |

#### 数据映射与计算

| 展示 | 数据来源 | 规则 |
|------|---------|------|
| 场次 Tab | `session.sessionName` + `session.status` / `startTime` | 顺序：进行中 → 即将开始（按开始时间升序）；已结束场次不进入楼层（沿用现状过滤） |
| 头部倒计时 | 当前选中场次：进行中取 `endTime`、未开始取 `startTime` | `showCountdown=false` 时隐藏 |
| 选中场次 | 默认取第一个「进行中」场次；没有进行中则取第一个未开始场次 | 切换 Tab 只切本地状态，不重新请求 |
| 商品 | `session.goodsList[]`（图/名/秒杀价/原价/秒杀库存/剩余库存） | 横向滚动 |
| 省额 | `originalPrice - seckillPrice` | `originalPrice <= seckillPrice` 或为 0 时隐藏 |
| 进度 | `sold = seckillStock - remainingStock` | `remainingStock < 0` 隐藏整块；`sold% ≥ 80` 显示「仅剩 {remainingStock} 件」，否则「已抢 {sold}%」 |
| CTA | 「马上抢」 | 未开始场次：「即将开始」（浅色禁用态）；点击整卡进商品详情（沿用现状） |

> count 语义不变：`count` = 展示场次数（1-5）。`count=1` 时只有一个 Tab，自动隐藏 Tab 条（调研 M1：单场次无意义需隐藏）。

#### 状态与降级

| 状态 | 表现 |
|------|------|
| 加载 | 头部骨架 + 2 张横滑卡骨架（3 块布局，非现状单条灰条） |
| 空 | 「暂无进行中的秒杀场次」（受 `emptyStrategy` 控制显示占位/隐藏） |
| 失效 | 商品图加载失败用图标占位（保留现有 `#error` 槽）；剩余库存未知隐藏进度 |
| 已结束 | 场次不进楼层；手动选择的已结束场次 → 整场显示「本场已结束」、CTA 置灰 |

### 6.4 管理端画布主题变量补齐（小修）

现状 `phone-canvas.vue` 只下发了 `--wot-color-theme-primary` / `-secondary`，没有 `-background`；而 C 端 `App.ku.vue` 通过 `wd-config-provider` 的 `themeVars.colorThemeBackground` 提供了该变量（= 页面底色，主色混白 92%）。这导致：

- 管理端预览里 `var(--wot-color-theme-background, #fff1ee)` 永远落到**暖色兜底**，天空蓝主题下预览会偏粉；
- 本次浅色楼层头/省额胶囊要用该变量做主题自适应。

**修法**：`phone-canvas.vue` 的 `canvasStyle` 增加 `'--wot-color-theme-background': props.themeVars?.pageBackgroundColor || undefined`；`page-preview/components/preview-canvas.vue` 同步（预览页同口径）。这是一处 2 行的通用修复，会同时改善现有组件（秒杀图垫底、折扣标签等）在非暖色主题下的预览。

### 8.2 新增/更新的契约测试

1. **preview-parity**：三组件的楼层头高度/标题字号/卡片圆角/价格字号/CTA 高度两端逐值相等（px×2 = rpx）。

5. **归一化**：`groupNum` 两端都映射（admin `retail-data.ts` 与 mobile `retail-normalizers.ts` 各一条单测）。
6. **跳转**：折扣全场卡使用 `navigateToUrl('/pages/promotion/discount')`（C 端契约）。

### 12.5 与方案的偏差（均已在实现中说明）

| # | 偏差 | 原因 |
|---|------|------|
| 1 | 拼团双列图实现为 `width:100% + height 343rpx/171.5px`（非严格方形） | 默认 `commonStyle` 下实际卡宽约 321rpx，严格 343 方形需改楼层留白，超出本次范围 |
| 2 | 楼层头图标用「秒/拼/折」汉字字符，而非线性 SVG 图标 | C 端 UnoCSS carbon 图标是 background-image 模式、无法染白；字符图标保证画布与实机一致 |
| 3 | 折扣省额字号 9px ↔ 19rpx（非严格 2×） | 跟随设计规格的 19rpx；视觉差 0.5px 不可感知 |
| 4 | 卡边框管理端 0.5-1px ↔ C 端 1rpx（发丝线） | 小程序 1rpx 即发丝线，两端观感一致，契约测试只锁圆角/尺寸不锁边框宽度 |
| 5 | 管理端倒计时格式 `N天 HH:MM:SS`（C 端 `formatRemainingTime` 同口径） | 两端各自实现但逐值同源，由契约测试守卫 |
