# 客服（消息中心）功能加固与补全 — 执行计划与接口契约

**状态：** 已完成（2026-11-04）。后端 `aryn-message` 124 例单测全绿、`aryn-boot` 聚合编译通过、
`TenantInterceptorBypassAuditTest` 8 例通过；管理端 `typecheck` + 1376 例单测通过；UniApp
`type-check` + 1680 例单测通过；boot/cloud 任务注册 SQL 已补齐并重新生成/校验全量 SQL。

**背景：** 审计发现「接待状态=离线仍可回复」是语义/门禁缺失的表现，并牵出待领取越权、无人回收、自动关闭任务未注册、已关闭会话残留、发送无限流、消息串台、C 端关闭态缺失等问题。

**产品决策（本次实施口径）：**
1. 接待状态只约束「承接新工作」：自动分配、手动领取、普通转交目标、铃铛待领取提醒、共享池排队推送都要求 `ONLINE`。
2. 已分配给当前坐席的会话，离线/忙碌/暂停仍可正常收发消息（exec-plan 8.6 的既有约定），工作台必须用文案明确说明，避免「显示离线却一切照常」的误解。
3. 主管强制转交不受在线限制，但写 `FORCE_ASSIGN` 审计并告知会话双方。
4. 不做「自动上线」：上线仍是显式动作；但坐席上线时回收一轮待领取会话，C 端重复进入 WAITING 会话时重试自动分配，维护任务也会周期性回收。C 端重试放在接口层（会话事务提交之后）执行，避免内层 `TransactionTemplate` 在并发领取时污染外层事务。

## 一、后端接口契约（前端按此对接）

### 1. 会话列表 / 历史会话
`GET /message/staff/conversation?status=&cursor=&limit=`
- `status`：可选，`OPEN`（WAITING/ASSIGNED/ACTIVE）或 `CLOSED`；缺省不过滤。
- 响应 `ConversationInboxPageVO`：`records / nextCursor / hasMore`，`nextCursor` 对前端不透明。
- 排序：`COALESCE(last_message_time, create_time) DESC, id DESC`（最近活跃优先）。

`ConversationVO` 新增字段：
- `customerName`、`customerAvatar`、`assignedStaffName`、`assignedStaffAvatar`（参与者快照）
- `peerLastReadSeq`（Long，对方最后已读 seq，用于「已读/未读」回执）

### 2. 坐席状态 / 待领取
- `GET /message/staff/agent/self`：未配置坐席返回 `null`（不再抛业务错误）；已禁用坐席仍返回 `enabled='0'` 的配置。
- `GET /message/staff/conversation/waiting`：要求调用者是启用坐席（`message_agent.enabled='1'`），并加 `@SaCheckPermission("message:service:agent" OR "message:service:supervisor")`。
- `POST /message/staff/conversation/{id}/claim`：坐席必须 `enabled` 且 `presence = ONLINE`，否则业务错误「当前离线或未开启接待，无法领取会话」；接口加与 waiting 相同的权限注解。
- `POST .../{id}/transfer`、`.../{id}/close`：加相同权限注解；非主管转交目标必须 `ONLINE` 且启用；主管转交允许离线目标但审计动作记为 `FORCE_ASSIGN`；成功转交写入一条 SYSTEM 消息（`{"code":"CONVERSATION_TRANSFERRED"}`，正文「会话已转交」）并同步双方已读游标语义（见下）。
- 坐席上线（presence→ONLINE）后 best-effort 回收共享池待领取会话（上限 10 条，异常只记日志）。

### 3. 消息
- `GET /message/staff/conversation/{id}/messages`：WAITING 会话允许**启用坐席只读预览**（不产生已读游标、不改变会话），CLOSED 会话仍允许参与者读取。
- `POST .../{id}/messages`：
  - 增加频率限制（Redis 分钟桶，默认：同一身份 60 条/分、同一会话 30 条/分、同一租户 1200 条/分）；超限返回「发送过于频繁，请稍后再试」。
  - IMAGE：`mimeType` 仅允许 `image/jpeg|png|webp`，`url` 必须为 http(s) 或站内相对路径、路径必须包含 `/{tenantId}/`，拒绝 `javascript:`/`data:`/协议相对地址；`fileId` 必填且长度受限。
  - 业务卡片：必填业务 ID 校验长度；可选 `image` 走同一 URL 规则；`title/summary/amount/statusText` 限长；不接受任意 URL。
- 会话被分配/被转交后，新坐席的 `last_read_seq` 从 0 开始（历史消息计为未读）。

### 4. 主管视图（新增，权限 `message:service:supervisor`）
- `GET /message/admin/conversation/page?status=&cursor=&limit=`：本租户全部会话（含关闭），复用 `ConversationInboxPageVO`。
- `GET /message/admin/conversation/{id}/assignment-logs`：`List<ConversationAssignmentLogVO>`（`actionType/fromStaffId/toStaffId/operatorType/operatorId/reason/createTime`）。

### 5. 内部契约（定时任务使用，后端实现）
- `ConversationAssignmentService.reassignWaitingPool(String tenantId, int limit)`
- `ConversationMaintenanceService.maintainTenant(String tenantId)`：关闭 24h 无消息会话、回收待领取、校正 `current_active_count` 快照；返回统计 `Map<String,Object>`（`closed/reassigned/repaired`）。
- `NoticeDispatchService.recoverTenant(String tenantId, int limit)`：恢复该租户超时分发任务。

## 二、管理端（web-ele）行为

### 工作台 `/message/service`
- 页签：**我的会话**（`status=OPEN`）、**待领取**、**历史会话**（`status=CLOSED`）；主管额外出现**全部会话**（`message:service:supervisor`），支持强制分配与分配日志抽屉。
- 会话状态机：
  - `WAITING`：可只读预览消息；输入框禁用并提示「领取后可回复」；显示「领取」。坐席离线时领取按钮禁用并提示先上线。
  - `ASSIGNED/ACTIVE`：可回复；显示转交/关闭。
  - `CLOSED`：只读；输入禁用并提示「会话已关闭，会员可在 … 前重开」；隐藏转交/关闭。
- 状态与安全：
  - 接待状态下拉改为受控更新，失败**回滚到服务端确认值**；`未配置坐席` 显示配置引导；`enabled=0` 显示已禁用；离线提示文案改为「离线仅暂停自动分配；已分配的会话仍可回复」。
  - 多标签页用 `BroadcastChannel` 同步状态；心跳失败先向服务端确认再决定覆盖/降级；`visibilitychange/online` 触发静默刷新。
- 竞态与交互：
  - 打开会话/发送/切换页签都带请求代际或 `active.id` 校验，慢网连点不串会话。
  - 发送失败气泡可点击重发（复用原 `clientMessageId`）；中文输入法 Enter 判断 `isComposing`。
  - 铃铛定位：依次在 我的/待领取/历史 中查找，找不到 toast；工作人员私信提醒跳 `/message/direct`。
  - `onActivated` 刷新列表、当前会话、presence。
- 信息面板：会话头展示会员昵称（缺失回退 ID）、负责客服；右侧展示会话信息 + 已读回执（最后一条我方消息显示 已读/未读）。
- 主动联系会员：`message:conversation:initiate` 权限下提供入口（输入会员 ID → 调用 `/staff/conversation/initiate` → 打开会话）。

### 工作人员私信 `/message/direct`
- 打开/发送竞态保护、读后刷新铃铛、`onActivated` 刷新、支持被通知回复跳转定位会话。

### 通知收件箱
- 工作人员通知增加「回复」入口：`POST /message/staff/notice/{id}/reply` 成功后按返回的 `conversationId` 跳到 `/message/direct` 并打开会话。

## 三、C 端（uniapp）

- 进入会话（含深链 `conversationId`）先拉取会话详情，按 `status` 渲染：
  - `WAITING`：排队提示，仍可留言；
  - `ASSIGNED/ACTIVE`：展示客服昵称；
  - `CLOSED`：只读 + 「会话已关闭，可在 24 小时内重新咨询」+ 重开按钮（调 `customer-service` 接口，走 24h 重开逻辑）。
- 会话内提供「结束会话」入口（非 CLOSED 时）。
- 发送失败重试复用原 `clientMessageId`；图片 `mimeType` 按真实文件类型填写，上传失败给提示。
- WS `onOpen` 发出 `message-reconnected` 事件，聊天页收到后按 `afterSeq` 补拉。
- 站内信 `jumpPayload/jumpType` 解析为 C 端站内路由（白名单 `/pages/**`、`/sub-pages/**`，拒绝外链），列表/详情/卡片点击消费。
