# 数据口径字典（管理端概览）

> 适用页面：`/analytics`（分析页）、`/product-analytics`（商品分析）、`/user-analytics`（用户分析）。
> 更新时间：2026-10-20。所有统计均受租户隔离拦截器约束，当前为**租户级**口径，`shopId` 尚未生效。

## 通用约定

- 时间范围：`today`、`7d`、`30d`、`yesterday`；“近 N 天”包含今天，起始为 `today - (N-1) 天 00:00:00`。
- 比率字段：后端统一返回 **0–1 小数**，前端统一乘以 100 展示；禁止在接口层返回 12.5 这类百分数。
- 金额单位：元，保留两位小数。
- 逻辑删除：所有统计均排除 `del_flag = '1'` 的数据。

## 交易指标

| 指标 | 定义 | 计算口径 |
|---|---|---|
| GMV（成交额） | 统计周期内已支付订单金额 | `SUM(order_info.payment_price)`，条件：`del_flag='0' AND pay_status='1' AND payment_time ∈ [start, end]` |
| 支付订单数 | 统计周期内已支付订单数 | `COUNT(DISTINCT order_info.id)`，条件同上 |
| 支付买家数 | 统计周期内有支付行为的用户数 | `COUNT(DISTINCT order_info.user_id)`，条件同上 |
| 客单价（AOV） | 平均每笔支付订单金额 | `GMV / 支付订单数`，订单数为 0 时为 0 |
| 人均消费 | 平均每个支付买家消费金额 | `GMV / 支付买家数`，买家数为 0 时为 0 |
| 售后订单数 | 统计周期内创建的退款单对应的订单数 | `COUNT(DISTINCT order_refund.order_id)`，条件：`del_flag='0' AND create_time ∈ [start, end]` |
| 退款金额 | 统计周期内创建且已到账的退款金额 | `SUM(order_refund.refund_amount)`，条件：`del_flag='0' AND arrival_status='2' AND create_time ∈ [start, end]` |
| 退款率（商品） | 商品退款金额占销售金额比例 | 分子：该 SPU 已到账退款金额；分母：该 SPU 在周期内已支付订单商品金额；结果 0–1 |
| 复购率 | 周期内支付≥2 次的用户占支付用户比例 | `COUNT(user_id HAVING COUNT(*) >= 2) / 支付买家数`，结果 0–1 |
| 老客成交占比 | 周期内老客贡献 GMV 占比 | 老客：在周期开始前已有支付订单的用户；结果 0–1 |

## 用户指标

| 指标 | 定义 | 计算口径 |
|---|---|---|
| 用户总数 | 当前租户全部注册用户 | `COUNT(user_info.id)`，`del_flag='0'` |
| 今日/7 日/30 日/本月新增 | 对应自然周期内注册用户数 | `user_info.create_time` 落在周期内 |
| 周期成交用户 | 统计周期内支付买家数 | 同“支付买家数” |
| 累计成交用户 | 历史至今有过支付行为的用户数 | `COUNT(DISTINCT order_info.user_id)`，`pay_status='1'`，**不传时间参数** |
| 消费次数分布 | 按周期内支付订单数分桶 | 1 次、2–3 次、4–5 次、6 次及以上 |
| 消费金额分层 | 按周期内累计支付金额分桶 | 0–100、100–500、500–2000、2000 元以上 |

## 商品指标

| 指标 | 定义 | 计算口径 |
|---|---|---|
| 商品总数 | 在售 + 下架商品数 | `COUNT(goods_spu)`，`del_flag='0'`；当前系统无“待审核”状态，不计入 |
| 在售/下架商品 | 按 `goods_spu.status` 统计 | `status='1'` 为在售，`status='0'` 为下架 |
| 库存总量 | 在售与下架商品库存之和 | `SUM(goods_spu.stock)` |
| 库存预警 | 库存低于阈值的商品数 | 当前阈值：`stock < 10`，与库存预警列表一致 |
| 动销商品数 | 周期内有销量的 SPU 数 | `COUNT(DISTINCT order_item.spu_id)`，订单需已支付且在周期内 |
| 动销率 | 动销商品数占在售商品数比例 | `动销商品数 / 在售商品数`，结果 0–1；分母为**当前**在售数 |
| 商品浏览量 PV | 商品足迹记录数 | `COUNT(goods_footprint.id)`，`create_time ∈ [start, end]` |
| 商品访客数 UV | 去重访客数 | `COUNT(DISTINCT goods_footprint.user_id)`，条件同上 |
| 好评率 | 好评数占评价数比例 | `COUNT(goods_score >= 4) / COUNT(*)`，结果 0–1 |
| 商品销售额 | 周期内已支付订单商品金额 | `SUM(order_item.payment_price)`，关联已支付订单 |

## 订单状态与风控

| 指标 | 当前口径 | 说明 |
|---|---|---|
| 待付款/待发货/已发货/已完成 | 统计周期内**创建**且当前处于对应状态的订单数 | 属于“周期内创建”，不是当前积压；后续会切换为当前时点积压口径 |
| 售后待审核 | 周期内创建且 `order_refund.status='1'` 的退款单数 | 与“售后申请数”不同，后者包含全部退款状态 |
| 已退款 | 周期内创建且 `arrival_status='2'` 的退款单数 | 到账状态 |
| 超时未发货 | 周期内支付且超过 24 小时仍未发货的订单数 | 对“今日”范围通常为 0，因当日订单不可能超过 24 小时 |
| 负面评价 | 周期内差评数 | 由商品服务远程统计 |

## 周期对比与导出

- 对比模式支持“对比上期”（环比）和“对比去年同期”（同比），可在页面顶部切换。
- 环比按自然日平移：今日对比昨日同一时刻；近 7 天对比前 7 天；近 30 天对比前 30 天；自定义区间按区间天数整体平移。
- 同比取同一区间减一年（例如 2026-10-01 至 2026-10-10 对应 2025-10-01 至 2025-10-10）。
- 环比/同比 = `(本期 - 对比期) / |对比期| × 100%`；对比期为 0 时不展示对比值，避免出现无穷大。
- 导出为 UTF-8 BOM 的 CSV；以 `= + - @` 开头的文本单元格会加 `'` 前缀，防止 Excel 公式注入。

## 交易履约漏斗

按下单时间取同一批订单作为基数，观察后续节点：

| 节点 | 定义 |
|---|---|
| 下单 | 统计周期内创建的订单数 |
| 支付 | 基数订单中 `pay_status='1'` 的订单数 |
| 发货 | 基数订单中 `deliver_time` 非空的订单数 |
| 完成 | 基数订单中 `receiver_time` 非空的订单数 |
| 退款（已到账） | 基数订单中已存在 `arrival_status='2'` 退款单的订单数 |

退款是侧向分支，不与主漏斗顺序相减。

## 用户 RFM 分层

- 统计基数：截至周期结束时间有过支付行为的用户，按用户聚合全部已支付订单。
- R（最近购买）：距最后一次支付 ≤7 天=5，≤30 天=4，≤90 天=3，≤180 天=2，其余=1。
- F（购买频次）：≥10 次=5，≥6 次=4，≥3 次=3，≥2 次=2，其余=1。
- M（累计消费）：≥5000 元=5，≥2000 元=4，≥1000 元=3，≥500 元=2，其余=1。
- 分层：重要价值/重要发展/重要保持/重要挽留/新客潜力/高频低额/高额低频/一般客户。
- 当前为固定阈值规则，后续可按租户行业调整；不是预测模型。

## 用户 Cohort 留存

- 首购 Cohort：以统计截止时间前每个用户的首笔支付月份分组，展示最近 6 个 Cohort。
- 留存：该 Cohort 用户在 Cohort 当月（+0）及后续第 1–5 个月内发生过支付行为。
- 留存率 = 该月留存用户数 / Cohort 用户数；未来月份显示“—”。
- Cohort 分析只使用截止时间，不受统计周期起始时间影响。

## 商品生命周期

| 指标 | 定义 |
|---|---|
| 近 30 天新品 | `create_time >= NOW() - 30 天` |
| 动销商品 | `sales_volume > 0`（商品累计销量） |
| 滞销商品 | 创建超过 30 天且 `sales_volume = 0` |
| 缺货商品 | `stock <= 0` |

商品生命周期基于 `goods_spu.sales_volume` 累计销量与当前库存，不是统计周期内的销量口径。

## 月度目标

- 目标按租户 + 月份（`yyyy-MM`）保存，包含 GMV、支付订单数、新增用户数三个目标。
- 实际值为本月至今：GMV/支付订单来自 `order_info`，新增用户来自用户服务。
- 达成率 = 实际值 / 目标值；目标为 0 时显示 0%。
- 时间进度 = 当前日期 / 当月天数；当前月平均目标进度落后时间进度超过 10 个百分点时提示“进度落后”。
- 目标月份默认当前月，可切换查看历史月或设置未来月；未来月实际值为 0。

## 流量转化漏斗

| 节点 | 定义 |
|---|---|
| 访问用户 | 统计周期内 `goods_footprint` 的去重 `user_id` |
| 下单用户 | 统计周期内创建订单的去重 `user_id` |
| 支付用户 | 上述下单用户中订单 `pay_status='1'` 的去重用户 |

加购环节尚未埋点，当前漏斗为“访问→下单→支付”。

## 渠道贡献

- 订单侧按用户聚合周期内支付订单数与 GMV，再批量获取 `user_info.user_source` 完成归因。
- 来源编码：`0` 微信小程序、`1` H5、`2` APP，缺失归为“未知”。
- 渠道买家数为去重买家数，订单数与 GMV 为对应渠道汇总。
- 当前来源只有 3 个固定值，属于用户来源归因，不是广告投放归因。

## 用户日订单汇总与对账

- `stat_daily_user_order` 按租户 + 日期 + 用户保存当日支付订单数、支付金额与最后一次支付时间。
- XXL-JOB `orderDailyStatJobHandler` 默认每日 01:10 汇总昨天；任务参数 `days` 可回填最近 1–90 天，按租户 + 日期先删后建，保证幂等。
- 对账接口 `GET /order/statistics/daily/reconcile` 对比明细与汇总的 GMV、支付订单数、支付买家数，返回三项差异。
- 对账通过前，概览看板仍使用明细查询；对账一致后再切换交易、RFM 与 Cohort 查询。
- 查询开关：`hx.dashboard.daily-stat.enabled`，默认 `false`。开启后仅对“完整历史多日区间”且覆盖天数完整的请求使用日汇总；单日、含今天或覆盖不完整时自动回退明细。退款类指标仍走明细。

## 缓存

- 订单概览聚合接口使用 Redis 60 秒短缓存，key 包含租户、起止时间、对比区间与 `includeUserAnalytics`。
- Redis 不可用时自动回退数据库；数据最大延迟 60 秒。

## 聚合接口（2026-10-20）

- 分析页与用户页共用 `/order/statistics/dashboard`，一次返回交易、趋势、用户、消费与增长；商品页使用 `/product/statistics/dashboard`；用户规模与来源使用 `/user/statistics/dashboard`。
- 对比期通过 `compareStartTime` / `compareEndTime` 传入，随主请求返回 `compareTrade` 与 `compareConsumption`，不再单独发起对比请求。
- 请求级错误隔离：单个服务聚合接口失败时只影响该服务对应的模块，页面通过横幅提示。

## 积分负债报表（2026-10-24）

- 接口 `GET /pointsconfig/liability-report?beginDate&endDate`（yyyy-MM-dd 可选，默认近 30 天），复用 `user:pointsconfig:page` 权限，零菜单 SQL。
- 口径：`points_record` 按日 GROUP BY 拆六列——新发放 / 退款返还 / 抵现 / 兑券 / 过期核销 / 后台扣减；期末负债 = `user_info` 全体 `SUM(point)`（租户拦截器自动过滤）。
- 金额列按 `ORDER_DEDUCT` 启用规则的 pointValue（积分/元）面值折算；汇率未配置时金额列为 null 不折算。
- 不做预计消耗率折现（行业常见 85%-95% 仅作参考），报表按面值口径展示，由财务按自身口径表外调整。
- 读侧实时聚合、无物化表；`points_record` 单租户过千万级再考虑物化日报表。

## 已知限制

1. `shopId` 目前不是有效筛选条件：订单统计 DTO 未接收该字段，商品统计 SQL 未使用该字段；页面实际为租户级。
2. 流量来源为 `user_info.user_source` 的固定三类（微信小程序/H5/APP），不随统计周期变化。
3. 订单状态总览按创建时间统计，暂未切换为“当前积压”口径。
4. 退款率的分子按退款单创建时间、分母按支付时间，跨期退款会出现分子分母时间窗不完全一致。
