## 常见定位误区

- 管理端只有一个静态 dashboard route；业务页面能否出现还取决于 `sys_menu` 与 `/upms/menu`。
- 单体模式 URL 会从 `/domain/resource` 改写为 `/boot/resource`，不能只按浏览器最终 URL 搜 Controller。
- API DTO/Entity 可能位于 `*-api`，HTTP Controller 和实现位于 `*-biz`。
- 消息域 Cloud 前缀为 `/message/**`，Boot 模式会改写到 `/boot/**`；工作人员与会员接口分别强制 TOB/TOC 登录端，不能只凭用户 ID 判断身份空间。
- `page_design`、拼团、分销和会员模块是当前高变动区域，修改前先检查租户表配置与 SQL 增量脚本。
- 配送、秒杀和折扣活动使用 25/26 号增量 SQL；当前编号存在同号多文件，执行时必须按完整文件名确认，不能只按序号描述。

## 页面装修定位补充

- 管理端统一编辑器：`aryn-mall-ui/apps/web-ele/src/views/promotion/page-designer/`，包含 v2 schema、迁移器、组件注册表、命令历史、草稿自动保存、模板和发布流程。
- 管理端组件预览/设置：`aryn-mall-ui/apps/web-ele/src/views/promotion/page-design/components/`，当前注册 11 个旧组件和 6 个零售组件。
- UniApp 渲染入口：`aryn-mall-uniapp/src/components/diy/index.vue`；`registry.ts` 按 v2 `item.props` 分发，读取旧 `formData` 时先迁移。
- 零售动态数据：管理端由 `common/retail-preview/retail-data.ts` 聚合商品、拼团和门店数据，UniApp 由 `retail-data.ts`、`retail-query.ts` 和 `useRetailData.ts` 负责；商品规则筛选使用 `categorySecondId`，排序参数使用 `asc/desc`。
- 装修链接：管理端与 UniApp 分别通过链接迁移器和 `link-resolver.ts` 统一处理；旧商品/微页面路径读取时迁移，外链、协议相对 URL 和 `javascript:` 路径不会作为站内链接执行。
- 后端草稿/发布：`PageDesignServiceImpl` 管草稿和首页身份，`PageDesignVersionServiceImpl` 管发布、下线、回滚，`PageDesignPreviewService` 管公开快照和短期预览令牌。
